## Warnings (should fix)

### F1：File 的影像設定遺漏 — 靜態確認；動態待驗證

- `modules/file-tools/extensions/file-tools.ts:498–505` 建立影像 read definition 時只傳 operations，沒有 `autoResizeImages`。
- Host `H/core/tools/read.js:46–49、87–90` 預設自動縮放為 true；標準 host `H/core/agent-session.js:2901–2913` 則傳入有效的 `getImageAutoResize()`。設定來源為 `H/core/settings-manager.js:1019–1020` 的 `images.autoResize`。
- 因此有效設定 false 時，覆寫 read 仍可能先縮小需縮放的影像；後續 `agent-session.js:367–371` 的 normalization 無法恢復原始尺寸。這是功能契約差異，不是 hook 訂閱或 direct exposure 漏洞。
- 建議僅補有效設定注入，保留同一 buffer snapshot 與 model resize limits；不改真實 settings、不改工具選取。
- 待驗證：大尺寸圖片、設定 true／false、content 與 structuredContent。已有 tiny BMP 案例 `path-image-regressions.test.ts:274–280` 不足以分辨此差異；父層 SDK／manifest 通過沒有取代這項針對性回歸。

### S1：Shell 以未錨定字串改寫 timeout — 靜態確認；動態待驗證

- `modules/shell-tools/extensions/timeout-ms.ts:106–110` 僅改寫 error.message 中第一個相符的 timeout 文字；host `H/core/tools/bash.js:267–275` 的 error.message 混合命令輸出及最後附加的真正逾時診斷。
- **更正前份流程：** foreground `return await run(signal)` 會經內層 `239–244` 及外層 `260–267` 兩次 catch；background 在 submit 返回 receipt 後才執行 run，沒有再經原 execute 的外層 catch，所以 background 只經內層一次改寫。
- background 的未執行重現設計：保留輸出先含一行 `Command timed out after 999 seconds`，真正 idle timeout 最後附加 `Command timed out after 5 seconds`。內層錯改輸出，真正尾端未轉換；`modules/shell-tools/src/background-jobs.ts:26–29、290–295` 只辨識尾端 idle marker，job-owned signal 未被 idle controller abort，故終態可能錯列 failed 而非 timed_out。foreground 有兩個假診斷時也可漏掉真正尾端。
- 建議僅識別 host 最終診斷並使轉換冪等；更長期使用可信 timeout metadata。不得把普通 command output 升為執行狀態來源。
- 待驗證：用 fake operations／純函式注入文字，分開 background 一次改寫及 foreground 兩次改寫，不用固定 sleep 重測穩定 timeout 行為。`background-jobs.test.mjs:151–166` 目前直接注入已正規化 idle marker，未覆蓋此流程。

### N1：Note 誤拒合法內部 junction — 靜態確認；平台回歸待驗證

- `modules/note-tools/extensions/note.ts:64–68` 用 `inside.startsWith("..")` 判斷 escape，會把仍在 cwd 內的 `..archive` 目錄名稱當父路徑。例如 plan 指向 `<cwd>/..archive` 時，relative 結果沒有 `..` 父目錄 segment，仍被拒絕。
- Host `H/core/extensions/runner.js:630–633` 提供 invocation cwd，`H/core/tools/tool-definition-wrapper.js:12` 傳入 context；host 不會修正模組自身的 containment 演算法。此問題不是 extension hook 錯用。
- 建議按完整父路徑 segment 判斷，保留拒絕外部 symlink／junction 的政策。
- 待驗證：合法兩點前綴內部 junction 的成功案例與外部 junction 拒絕案例成對檢查。`modules/note-tools/tests/note.test.ts:193–199` 只有外部 junction。

## Suggestions (consider)

### H1：File skill snapshot 與 hook 順序 — 條件性結構改善

`modules/file-tools/extensions/file-tools.ts:438–440` 在自身 before_agent_start handler 當下取 skills。`H/core/extensions/runner.js:1121–1164` 按載入／註冊順序讓後面的 handler 繼續修改同一 options，所以後載入 extension 改 skills 時，fallback snapshot 可能落後。這是特定 extension 組合下的待驗證相容性，不是目前已證明普遍發生的錯誤；父層一般 hook fixture 通過不必然涵蓋任意後置 skills 變更。建議用兩種載入順序的小 fixture 確認需求，避免為解決此問題取代整份 system prompt。

### H2：Shell shutdown 與 settled 邊界 — 已確認結構正確，維持即可

`modules/shell-tools/extensions/timeout-ms.ts:286–292` 以 session_start 綁 owner、agent_start 標 busy、agent_settled 解除並排 flush，session_shutdown 返回 cleanup promise。`background-jobs.ts:467–495` 先失效 generation／停止接受，再要求取消及 bounded cleanup。Host replacement `agent-session-runtime.js:102–112` 先 abort active turn 再 shutdown／dispose，reload `agent-session.js:2939–2940` 先 shutdown 再 invalidate；符合契約。

通知在 `background-jobs.ts:365–399` 以 immediate 重新核對 owner／generation／busy，不在 notification-only settled handler 同步啟動模型；sendMessage 是提交而不是 ack。維持 await runtime.dispose 的 SDK 要求，不增輪詢來掩蓋錯誤宿主 disposal，也不把取消等同 descendant 清空。

### H3：Tool availability／nested／codemode — 已確認契約，不列安全漏洞

- Host `agent-session.js:1136–1147` 明確使 active direct tools 可供 nested call；codemode／deferred 則在 registered 時可呼叫。**Direct 暴露本身是契約，不是安全漏洞。**
- Shell `extensions/timeout-ms.ts:155、305` 與 File 搜尋工具 `src/search-tools.ts:24、45、53` 的 defaultActive:false 保留選取。File read/write/edit、Note 沿 host 預設 activation；`defaultTools` 不等於 explicit `tools` allowlist，父層已通過相應 SDK／manifest 驗證。
- 不建議自動啟用原先未選工具，不更改 exposure 來讓 inactive direct tool 可被 nested／codemode 呼叫，也不為了補提示呼叫 setActiveTools。
- File write/edit 沒有 outputSchema，codemode 返回文字是有意且符合契約；read、Shell、Note 使用 structuredContent。Host `H/extensions/codemode/execute.js:350–357` 可讓含 schema 的非零 exit shell error result 返回結構化資料，而 throw／blocked error 拒絕。不要把 details 誤當 structuredContent，也不要把 job 查詢成功誤稱 job 成功。

### H4：Queue、signal 與資源 — 已確認主結構，保留邊界警語

File write `extensions/file-tools.ts:568–579`、edit `634–655` 把 snapshot／驗證／diff／commit 整體放在 queue。Read `417–429` 在 queue 中取 buffer，之後只處理該 snapshot；不必把純解析誤列為 transaction 缺口。Regex `src/file-operations.ts:1164–1176`、diff `src/diff-runner.ts:158–181` 都在 call scope 終止 worker，沒有跨 session worker 需要補 lifecycle hook 的確定證據。

Note `extensions/note.ts:75–88` 包住 exclusive create／write／close；mkdir／realpath 在 queue 外不是既有檔案 read-modify-write transaction 被拆開。Host queue `file-mutation-queue.js:11–49` 不鎖外部 writer 或祖先目錄；Note dir-swap TOCTOU、File hard-link fallback 原子可見性是条件性 filesystem 邊界，未執行 exploit／故障注入，不提升成已動態確認漏洞。

三模組 execute 使用第三參數 signal 符合工具契約；Shell 接受後用 job-owned controller 是有意 detach，不應改用 ctx.signal 追隨主回合取消已接受工作。Note 開始寫入後完成該次寫入亦已文件化。

### H5：純顯示與持久化 — 結構改善，不混入 hook 缺陷

- `modules/file-tools/extensions/file-tools.ts:627` 的完整 diff 展開可很大；可考慮 UI 顯示上限，保留模型結果與 details。
- `modules/shell-tools/extensions/timeout-ms.ts:183–187` 的 receipt timing 可優先使用 context.durationMs，與 host `renderers/bash.js:79–87` 的單調、歷史可用耗時一致。
- Shell widget `src/live-widget.ts:34` 已限制 tui＋hasUI；API interrupted renderer `src/api-interruption-renderer.ts:57–61、132–153` 僅改 UI，不改工具结果。Background journal `src/recovery.ts:238–260` admission 寫失敗拒絕提交，不自動恢復／重跑工作。
- Note 無 lifecycle hook、timer 或 session-memory state；factory 只 registerTool，外部 Markdown 持久化及 outputSchema `{relativePath}` 正確，不需為形式一致新增 session_start／shutdown。
