## Critical (must fix)

以下是 **High 候選**，不是宣稱已有實機重現或獨立確認；分類放在 must-fix 區是因條件成立時可能遺失未提交 memory。

### MISC-001 — High：Pending 寫入失敗被吞掉，cursor 卻可以成功越過未保存 batch

- **位置**：`modules/blackhole/src/om/pending.ts:123–133,161–176,257–264,334–339`；caller `consolidation.ts:1325–1344,771–782`；`runtime.ts:898–906`。同一根因亦影響 `consolidation.ts:1697–1710,2340–2346` 的 reflection/drop commit。
- **觸發／可達性**：memory-on manual pipeline 成功取得 worker 結果，但一次 pending 主檔 `writeFileSync` 發生 ENOSPC／EIO／暫時拒絕；後續 cursor write 或其他 stage write 恢復成功。正常入口是 `agent_start/turn_end → maybeLaunchConsolidation → runObserverStage`，並非任意直接呼叫才有的情境。
- **静態結果**：writer 先把原主檔 rename 成 stale，再直接寫新主檔；write throw 被 catch 吞掉。`savePendingObservation` 沒有成功值或 throw，因此 caller 無條件 `advanceCursor(...,'recorded')` 並可能顯示 recorded。`readSessionState` 不讀 stale，main 缺失／損壞當 empty。隨後 `writePendingCursors` 能建立只有 cursor 的合法主檔；重新載入後 observer 從已跨過的 raw entry 開始，失敗 batch 不會被視為待觀察。再一次 cursor write 可把 cursor-only main 覆蓋 stale，連前一批備份也消失。
- **影響**：未 append 至 ledger 的 observations/reflections/drop tombstones 可能靜默遺失或被跳過；raw transcript 仍在，不宣稱 raw history 全被刪掉。重新推理有成本且沒有保證自動重新處理被 cursor 跳過的 span。
- **既有防護／反證**：generation 與 branch ownership（`1326`）仍有效，但只保護授權，不證明寫入成功；observer chunk、drain、stage attempts 有界，不修補 disk commit。stale backup 可供人工救援，但 `readSessionState` 無自動回復且後續 write 可替換它。`manual-pending.ts:30–33` 的 fingerprint/receipt gate 只保護**已保存、待 compact flush**的 batch，不能回收根本没保存而已推 cursor 的結果。
- **與既有問題關係**：既有 `REPORT-20261009T164230781Z.md` 記錄 post-admission unlink/stale-backup 人工恢復界線；本項是 **pipeline output save failure → cursor advance**，不是重報已修正的 compact admission/commit 或 unlink acknowledgment。
- **確認狀態**：靜態路徑成立；動態故障注入及完整 pipeline 重播未執行。High 依未提交 memory 的資料完整性，不依假設模型已實際被呼叫。
- **最小處理方向（非本輪修改）**：保存結果須有 observable success/failure；失敗不得推 coverage cursor。寫入應保留可用舊 generation，並明確處理 corrupt/current/stale 恢復。避免以另一個 cursor-only save 默默認可缺失 batch。
- **重播**：下方 A 直接驗證 production exported persistence helpers 的故障交錯；之後使用既有 observer mock 對實際 `runObserverStage` 補充 cursor-not-advanced 斷言，不需要真實模型。正反控制：無 fault 時 batch 存在且 cursor 可以前進；單次 fault 時不可 recorded/skip，恢復後兩批仍可讀。

### MISC-002 — High：Orphan 分析將掃描失敗當作「確定沒有 session」，可授權刪除仍活躍的 pending

- **位置**：`modules/blackhole/src/om/cleanup.ts:109–150,184–208,221–246,289–328`；`src/commands/cleanup.ts:267–300,230–236`；公開 command 接線 `src/commands/pi-vcc.ts:120–123`。
- **觸發／可達性**：使用者在 TUI 執行 `/blackhole cleanup`；pending 的合法 session JSONL 因 EACCES/EIO／暫時檔案鎖、header 未完成或任一 session 子目錄無法列舉而未被讀到，使用者接受被標記為 orphan 的刪除。另一條正常配置情境是 session 放在 CLI／env／project 自訂 sessionDir，而 analyzer 只看 default 和 global settings 的 sessionDir；本項以容易隔離的 read-failure 路徑作主要驗證。
- **静態結果**：`scanSessionDir` 在 readdir/stat/read/parse 錯誤時 continue，回傳普通 Set，沒有 incomplete/unknown；`crossReference` 看到未在 Set 內就列 orphaned。TUI 直接以這份列表呼叫 `deletePendingFiles` 或 `deleteOrphanedBatch`，沒有 deletion-time session existence／scan-completeness 重查，甚至不保護 ctx 的當前 session ID。

- **既有防護／反證**：安全 sessionId regex＋path containment 限制 unlink 範圍；non-TUI 僅列舉；delete-all 有確認。這些防止路徑逃逸／自動刪除，但 UI 的「orphan」語意仍源自不完整的存在性查詢；confirmation 不能把 EACCES 轉成不存在證據。Partial unlink success 語意也不是全清理確認（後續可另查），不把它與本分類根因混為一項。

### MISC-004 — Medium：較深 JSON-pointer `$ref` 被接受，converter 卻只驗證 definition 整體而忽略尾端

- **位置**：`modules/json-schema/src/schema.ts:58–63,122–129,153–158,173–178`；實際 dependency `node_modules/zod/src/v4/classic/from-json-schema.ts:137–151`；可達 bypass consumer `extensions/json-schema.ts:154–156,186–198`。Worker 等效 converter 在 `src/validation-worker.mjs:11–14`。
- **最小輸入**：draft-2020-12 root object；`$defs.W={type:'object',properties:{amount:{type:'number'}}}`；required property `x` 的 `$ref='#/$defs/W/properties/amount'`。Pointer 的目標是 number schema，`{x:7}` 應有效、`{x:{}}` 應無效。
- **静態結果**：module 只要求 `#`／pointer 形式、不驗深度；admission 註解明知 converter 只解析 definition name，但沒有拒絕尾段。Zod resolveRef 回傳 `ctx.defs['W']`、忽略 `properties/amount`，所以反而接受 object、拒絕 number。不是 R3 的 sibling validation 漏驗，也不是 R10/C1 的 expanded-work DAG budget。
- **可達性／既有防護反證**：host 的工具參數驗證可能攔住某些錯誤直接 `json_output` input；但模型 prose JSON 的本地 fallback（154–156）與 extraction response 的本地驗證（187/197）不經該 host argument guard，可交付不符合原 schema 的 JSON。pattern worker 只隔離計算，不修 pointer 語意。淺 `#/$defs/W`、recursive `#` 可正常保留；不要求停用全部 refs。
- **影響**：錯誤恢復／best-effort 可能把錯型別資料交付下游，或拒絕合法結果；Medium 資料正確性。未稱此輸入會造成 worker 資源耗盡。
- **既有問題關係**：`REPORT-20261011T132908489Z.md:68–72` 明確只修 converter map admission、不宣稱修所有 reference semantics；本例是可分離的新 deeper-pointer 反例，不重報 dual-map CPU admission。
- **確認狀態**：依現行 converter 精確静態推導，腳本未執行；獨立 verifier 應核對實際 Zod import 及 parser版本，先確認這對正反樣本。
- **最小方向**：無法忠實解析時 startup 拒絕更深／不支援的 pointer；若要支援才實作正確 resolution。禁止 provider schema 仍指深層、本地 silently 改成整個 definition。下方 D 無模型、無 file writes。
