## Warnings (should fix)
以下皆為目前程式的靜態控制流證據；提供觸發輸入，但未執行重現，不冒稱測試失敗。

1. **P2 — required 補欄位改變 additionalProperties 語意。** `modules/json-schema/src/validation-schema.mjs:13`：schema `{"type":"object","required":["k"],"additionalProperties":{"type":"integer"}}` 補成 `properties.k={}`，使 `{"k":"bad"}` 脫離額外欄位整數限制，可能交付非法結果。Zod converter `node_modules/zod/src/v4/classic/from-json-schema.ts:625–640,699–711` 只對未宣告欄位套 catchall。建議以獨立 own-key required guard，不新增改變分類的 properties；或保守拒絕組合。

2. **P2 — `__proto__` required 補入失敗。** `modules/json-schema/src/validation-schema.mjs:12–13`：`required:["__proto__"]`、無 properties 時，普通物件的 `properties[name]={}` 觸發繼承 setter，而非建立 own property；converter 以 Object.entries 建 shape，因而遺失 required，`{}` 可被當作有效。建議使用 defineProperty／null-prototype map，並加入原型鍵回歸。證據為此賦值與 converter TS:636–639；非全域 prototype pollution。

3. **P2 — patternProperties 的合法 required 被誤判無解。** `modules/json-schema/src/schema.ts:70–73`：`{"type":"object","required":["k"],"patternProperties":{"^k$":{"type":"integer"}},"additionalProperties":false}` 的 `{"k":1}` 合法，卻因 k 不在 properties 於初始化拒絕。建議判斷 pattern coverage／獨立 required guard；目前錯誤訊息也不應宣稱 unsatisfiable。

4. **P2 — patterned object 漏驗 schema-valued additionalProperties。** `modules/json-schema/src/schema.ts:57–58,160`：schema `{"type":"object","patternProperties":{"^x":{"type":"string"}},"additionalProperties":{"type":"integer"}}` 未被 admission 拒絕。Zod TS:642–698（CJS:627–685）pattern 分支僅處理 additionalProperties=false，未使用已編譯 additionalSchema；故 `{"other":"bad"}` 不受整數限制。同步編譯與 worker:11 共用 converter。建議補忠實 guard 或啟動拒絕此組合。

5. **P2 — raw snapshot 繞過工具 hook 的資料變更。** `modules/json-schema/extensions/json-schema.ts:84,100–102`：tool_execution_start 先存原值，後續 tool_call 將 `input.secret` 刪除或遮罩，execute 仍驗證／交付舊 secret。Pi agent-loop:598–604,727–737 及 agent-session tool_call 的 `input:args` 接線支持此順序，官方 extensions docs:105 允許 mutation。建議區分 coercion 與明確 hook 修改，或偵測差異 fail closed；不能把工具封鎖與資料修改混為一談。Pi 1.2.0 精確 hook 契約仍待確認。

6. **P2 — extraction 接受首個結果後不檢查剩餘工具。** `modules/json-schema/extensions/json-schema.ts:193–198`：reply content 依序為合法 json_output、其他工具，第一個驗證成功就 return，第二個永不檢查；違反 README:36「其他工具視為失敗」。亦漏掉後續不同 json_output 的衝突。建議先稽核完整 tool-call 集合與一致性，再採用結果。

7. **P2 — 關閉一個 session 取消其他 session 驗證。** `modules/json-schema/extensions/json-schema.ts:232` 與 `modules/json-schema/src/validation-pool.ts:26–29,137`：同 process 共用此 singleton 的兩個 SDK session，A shutdown 無條件 close 全 pool，取消 B queued／active validation，關閉期間新工作亦被拒絕（:34）。建議 per-session pool／owner-tagged drain 或引用計數；保留總容量上限。這是共用 pool 的取消干擾，不是資料外洩，也未證明所有 Pi loader 均共用同一 module instance。
