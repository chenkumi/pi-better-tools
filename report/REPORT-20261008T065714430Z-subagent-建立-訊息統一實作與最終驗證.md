## 最終操作契約

建立：
```json
{ "agent": "worker", "task": "完整委派工作說明", "background": true }
```
成功 receipt 每個 task 提供 `subagentSessionId`，以及不同用途的 jobId／taskId。保留 single／parallel／chain、32 submitted／8 active 上限與既有模型／思考覆寫規則。

後續指示：
```json
{ "subagentSessionId": "<完整穩定 ID>", "message": "依前次結論繼續實作。", "title": "繼續實作" }
```
required 恰為 `subagentSessionId`、`message`；mode 選填，預設 control；title 選填、display-only、最多50 Unicode碼點。message literal、64 KiB UTF-8 上限。

- running interactive：`action:"control"`，保留 messageId、accepted／queued／applied／delivery_unknown 區分，不中斷長工具。
- 無活動 invocation 且 verified ready：`action:"resume"`，非同步接受，新 jobId/taskId、相同 session ID；完成另以 task_result followUp 回報，不二次累加 host usage。
- query：`action:"query"`，僅 live snapshot，獨立 asOf/usage；不啟動主線、不寫 main transcript/checkpoint、不提供可執行 tools。
- queued／startup／finalizing／canceling／busy：明確拒絕，沒有跨 invocation 訊息佇列。
- blocked／owner／cwd／saved config／model／trust／checkpoint 不符：拒絕，不自動新建。
- 拒絕結果提供 status:"rejected"、errorCode、observedState、nextAction、error；不安全確定狀態時為 unknown。
- 已 accepted 或 delivery_unknown 的 control 不自動重送為 resume。

舊 `subagent({resume,...})` 與 jobId/taskId 定址的 message 明確拒絕並提供遷移指引；保留歷史 renderer 相容，不改寫歷史結果。需自行重新載入正確 package 的新 schema；不修改真實 allowlist、settings/auth 或 Pi 安裝。

## 核心實作與安全邊界

模組22個變更路徑與細節見 worker報告：`report/REPORT-20261008T063522297Z-subagents-cp1-cp6-實作交付與驗證證據.md`。主要為 index.ts 的唯一 continueSession preflight/runner 路徑、background.ts 的 locate/submitManaged/admission fence、background-renderer.ts 與新增 message-reservation.ts，以及模組測試／fixtures、worker定義與三個 orchestration prompts。

Parent 核對實際程式及 assertions：
- reservation 保留 continuation preflight/invocation admission；runner 仍須取得 authoritative writer.lock 並重新驗證 checkpoint/config，再經 child guard。
- session 身份配置不代表 child active permit 或 log 已存在；allocation failure 釋放 admission、未受理工作不送假完成通知。
- live lookup 與 control delivery 不跨 await，settlement race 不重送已接受訊息。
- publication 前有最後 tool-abort fence，接受後用 job-owned signal。
- actual child close、transcript/native/spool I/O 與真正 handle close 仍是 ownership barriers；無法安全確認時不提前釋放 writer、rollback 或發布 ready。
- RPC guard 在 get_state 前拒絕時，actual close 後讀既有 authoritative startup.json，避免 model/trust rejection 被誤視可 rollback 的 run-level failure；未新增 startup 格式／重試／deadline。
- child argument builder／exclusions、trust、canonical owner/cwd、generation/reload、durable hostContract:"0.99.1"、query leases/accounting 保留。Process isolation 不是 OS sandbox，取消不是已確認程序樹終止。

4. 新message拒絕queued／startup／finalizing，沒有自動等待queue；checkpoint rollback不撤銷外部工具副作用。
5. 本輪沒有另外跑 root全套test:integration/check、真實付費provider、Pi1.1.0、WSL/SSH或人工作業TUI；不宣稱通過。只支援並驗證Pi1.0.0。
