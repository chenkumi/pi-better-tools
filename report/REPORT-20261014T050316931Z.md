### G7-001：無 items／prefixItems 的陣列長度約束可能被本地回收忽略

- **位置／根因**：`modules/json-schema/src/schema.ts:67–97,155–180` 允許 `{type:"array",minItems:1}` 而未補強或拒絕；本機 `node_modules/zod/v4/classic/from-json-schema.cjs:755–770` 只在有 items 的分支套長度，無 items 分支只有 `z.array(z.any())`。
- **觸發輸入**：schema `{"type":"object","properties":{"xs":{"type":"array","minItems":1}},"required":["xs"]}`；最後助理 prose 為 `{"xs":[]}`。maxItems 可另以 0 與一元素陣列作同根因案例。
- **真實產品路徑**：session_start → compileSchema → message_end → session_shutdown → recover（`extensions/json-schema.ts:154–156`）→ schema.validate → writeJsonFile／writeJsonStdout。prose recovery 不經宿主 TypeBox tool validation。
- **Expected**：拒絕空陣列，不交付它；可接受啟動時明確拒絕不支援 schema。
- **Actual（靜態推導，未觀察）**：validate 可能回 undefined，recover 選取並交付違反 minItems 的資料。
- **嚴重度／影響**：High 候選，結構化結果的有效性承諾被破壞，下游可能以成功結果繼續處理。
- **反證／邊界**：有 items／prefixItems 時 converter 有套用 bounds；`schema.test.ts:21–24` 測的是有 items，不能反證本案例。真實 tool 路徑可能被 TypeBox 阻擋，因此不得只測工具參數路徑或宣稱所有路徑都放行。
- **待驗證**：真實 offline Pi print prose recovery 三次；以有 `items:{}` 的 schema 作對照，逐次記錄檔案／stdout、exit 與 provider request 數。

### G7-002：required 未在 properties 明列的欄位可能不被本地驗證

- **位置／根因**：`modules/json-schema/src/schema.ts:67–68,155–180` 僅檢查 required 的型態；converter CJS `617–625` 把 requiredSet 用在 properties 迴圈，沒有獨立核對未宣告欄位是否存在。
- **觸發輸入**：schema `{"type":"object","required":["must"]}`；最後 prose 為 `{}`。
- **真實產品路徑**：同 G7-001 的本地 prose recovery；啟動 safeParse({}) 的 invalid 結果本就不要求 success，故不能把這個預熱當 required 語意的稽核。
- **Expected**：`{}` 不可被當有效結果；`{"must":1}` 可通過。required 與 properties 不必同時宣告。
- **Actual（靜態推導，未觀察）**：空 shape passthrough 可能接受 `{}`，使其被交付。
- **嚴重度／影響**：High 候選，缺少必填資料仍成功交付。
- **反證／邊界**：現有 required 測試通常同時明列 properties；宿主 TypeBox 對 tool arguments 另有 required 驗證，但不保護 prose recovery。不得以直接 Zod 測試代替完整交付證據。
- **待驗證**：offline host 三次 missing／present 對照；另將 must 明列為 `properties:{must:{}}`，確認不同 schema shape 是否收斂。

### G7-003：物件／陣列 const／enum 的 identity 語意可能拒絕合法 JSON

- **位置／根因**：`modules/json-schema/src/schema.ts:74–83,160` 接受 compound const／enum；converter CJS `436–452` 轉為 literal，Zod core CJS `2045–2060` 使用 `Set.has`，不是 JSON 結構相等。
- **觸發輸入**：schema `{"type":"object","properties":{"x":{"const":{"a":1}}},"required":["x"]}`；資料 `{"x":{"a":1}}`。另以 `const:[1]`、`enum:[{"a":1}]` 為同根因對照。
- **Expected**：結構相等的值通過；或不支援時在模型請求前拒絕 schema。
- **Actual（靜態推導，未觀察）**：schema converter 的 JSON normalization 與工具 clone／prose JSON.parse 產生不同 identity，合法值可能永遠驗證失敗。
- **嚴重度／影響**：Medium 候選，部分結構化任務無法完成；工具重試可能增加回合成本，但本次未量測也未呼叫付費服務。
- **反證／已知來源**：`modules/json-schema/tests/review-regressions.test.ts:29–32` 已指出 object literal identity，刻意只斷言 annotation bytes。這不是通過的語意測試，也提示本項可能屬既有已知限制，不主張全新發現。scalar const／enum 不受此 identity 問題影響。
- **待驗證**：真實產品 compileSchema／工具／prose 路徑三次，scalar const 作控制組；須由主代理核對是否已有正式 issue，再合併證據。

### G7-004：宿主參數 normalization／coercion 可能破壞原始資料交付承諾

### 未覆蓋／值得補證的容量邊界

1. `schema.ts:117–143` 的 admission 不遍歷未引用 definition map；`audit:96` 與 `withoutSchemaDefaults:11` 卻遍歷全部。巨大未引用 definition／annotation 的 bytes、audit 深度與 clone 成本沒有完整資源預算。尚未量測負載與影響，**不列正式效能缺陷**。
2. README 明示 expanded schema budget 不保證任意大型／深層遞迴 instance 的成本有界。不含 pattern 的 safeParse 是同步；含 pattern 也先經宿主同步 validation。需要隔離 process 的 bounded instance 實測，不能推定 worker 解決所有遞迴容量。
3. `extract.ts:36–40` 的 whole／fenced parse 不受 brace-scan 的 64 次／100萬字限制；一次抽取會先保存整個 candidates 陣列。README 的上限只承諾花括號／方括號掃描，不能以未遵守「所有 parse 全域上限」直接報 bug。候選數、transcript／suppressedContent 大小尚無實測。
4. shutdown recovery 拿掉 signal listener 後的 signal／abort 交錯、stdout EPIPE、file handle close 失敗、terminate promise failure、ready handshake 超時皆沒有本次真實觀察。
5. provider 遠端接受 priority／ultrafast／JSON Schema 的行為未驗證；本次刻意不碰付費模型與 credentials。虛擬模型 routing／SDK stale context 的完整 replacement lifecycle 仍未完成查核。
