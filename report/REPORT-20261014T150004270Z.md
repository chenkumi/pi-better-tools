## Warnings (should fix)

### 1. [P2] 檔案大小限制發生在無界讀取之後
- 位置：`modules/file-tools/extensions/file-tools.ts:419-423`；`modules/file-tools/src/file-operations.ts:798-842`（亦見 781-786）。
- 觸發：stat/lstat 通過後，外部寫入者將檔案增長至超過 50 MiB，再進入 readFile；mutation 快照還包含 access 等等待窗口。
- 影響：後置檢查雖拒絕提交，但已配置超限 Buffer；50 MiB 不是讀取配置上限。mutation readFile 沒有 signal，取消也不會中止該次讀取。
- 建議：以同一 descriptor 驗證一般檔案並分塊讀取，累積至上限加一即拒絕；傳遞取消。descriptor 檢查亦可縮小換成特殊檔案的競態，但不宣稱完全消除外部競爭。
- 證據：現碼先查 size、後以 pathname readFile，最後才查 buffer.length；靜態確認，未動態重現。既有大檔測試 `file-operations.test.ts:400-406` 只覆蓋初始即超限。

### 2. [P2] edit 在主執行緒無行數上限地建立整檔索引
- 位置：`modules/file-tools/src/file-operations.ts:258-262,1495-1497`。
- 觸發：允許的 50 MiB UTF-8 檔案全部為 LF，即使只改一個字元或指定小 lineRange。
- 影響：必定建立 52,428,801 個 number entries；發生於 validateEdits 的十秒 deadline 建立前，也不受 diff worker 的 256 MiB 限制。此階段無取消檢查／讓出執行緒，造成大幅記憶體放大；實際 heap 峰值與耗時未測，不能宣稱已重現 OOM。
- 建議：行索引採獨立 admission cap／稀疏索引，或按所需範圍掃描；昂貴建索引階段納入取消及資源預算。
- 證據：由迴圈與精確輸入長度推導；未執行壓力測試。read 的有界頁面修正不涵蓋此 edit 路徑。

### 3. [P2] FFF aux capacity 未計入 pending creations
- 位置：`node_modules/@ff-labs/pi-fff/src/aux-finders.ts:81-112`；整合入口 `modules/file-tools/src/fff-override.mjs:27`。
- 觸發：空 pool 同時 acquire 四個不同 root，create 尚未完成。
- 影響：四次皆看見 entries.length < 3，均啟動建立；完成後四個都 push，超過 MAX_AUX=3，增加索引／watcher／cache 資源。
- 建議：await 前保留名額，pending 與 live 共用容量；失敗／晚到清理完畢才釋放。
- 證據：靜態交錯可證；現存 `fff-aux-capacity.integration.test.mjs:15-39` 為相同 barrier 案例，但標記 known-upstream TODO，本輪未跑，不算通過。這是未修上游問題，非新引入的 wrapper 缺陷。

### 4. [P2] FFF shutdown 後仍發布晚到 finder
- 位置：`node_modules/@ff-labs/pi-fff/src/index.ts:501-508,548-558,857-859`；`aux-finders.ts:33-39,104-113`。
- 觸發：建立／waitForScan pending → session_shutdown → promise resolve。
- 影響：shutdown 只銷毀已發布 entries/mainFinder；晚到主 finder 再賦值，aux 再 push 到舊 pool，均未 destroy。SDK `dist/index.js:1478-1492` 明示 destroy 負責資源及 watching 收尾。
- 建議：generation/stopped fence；晚到物件直接 destroy，不發布，pending ownership 保留至 settlement。
- 證據：兩條續行均無 fence；`fff-shutdown-fence.integration.test.mjs:28-52` 保留主／aux TODO 案例，本輪未跑。未宣稱實測 native DLL 洩漏量。

### 5. [P2] FFF find 缺少工具端 page/output admission 上限
- 位置：`node_modules/@ff-labs/pi-fff/src/index.ts:1175-1178,1215-1232,242-254`。
- 觸發：大型索引，以有效的大 limit 搜尋大量強符合結果。
- 影響：limit 只有 Math.max(1)，原值傳給 native；回傳 items 又全量 map，輸出無 byte/行數上限，弱符合的五筆限制不涵蓋強符合。工具端無法保證有界回覆。
- 建議：整數 schema＋固定最大 pageSize，格式化另設 byte budget 並正確推進 continuation。
- 證據：SDK `node_modules/@ff-labs/fff-node/dist/index.js:1533-1545,935-971` 直接轉送 pageSize；未審 native Rust，因此實際 native 是否另有 clamp、最大返回量及耗時未知，不宣稱必定一次返回整個索引。現有 override probe 僅小型 marker，未覆蓋此界限。

## Suggestions (consider)

### 6. [P3] 失敗的 SDK import promise 永久進入全域 cache
- 位置：`node_modules/@ff-labs/pi-fff/src/sdk.ts:58-76`。
- 觸發：loadFirst 的兩個 SDK import 都失敗，例如 SDK／其原生 binding 的載入依賴不可用。
- 影響：rejected promise 留在 sdkPromise 與 globalThis；後續呼叫甚至 module reload 都不重試 loadFirst。這不同於 FileFinder.create 的 DLL 開啟失敗，不將後者混為此情境。
- 建議：成功 cache 保留；rejection 時只清除仍指向同一 promise 的兩處 cache，允許明確 reload 重試。
- 證據：靜態確認沒有 rejection eviction；未做缺依賴重現，修復依賴後的 Node module-cache 行為亦未驗證。
