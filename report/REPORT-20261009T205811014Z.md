## Warnings (should fix)

### F1：File read 忽略有效的 `images.autoResize:false`

- **位置：** `modules/file-tools/extensions/file-tools.ts:498–505`。
- **確定性：** 靜態可確定；未執行動態影像回歸。
- **問題：** 圖片委派建立 `createReadToolDefinition(ctx.cwd, { operations: ... })`，沒有傳入 `autoResizeImages`。host `H/core/tools/read.js:46–49` 的預設是 true，並於 87–90 把它送入 `processImage`。標準 host 在 `H/core/agent-session.js:2901–2913` 從 `getImageAutoResize()` 取得有效設定，再注入 base read；`H/core/settings-manager.js:1019–1020` 明確使用 `settings.images?.autoResize ?? true`。
- **影響：** 使用者／SDK 有效設定關閉自動縮放時，覆寫 read 仍先縮放。稍後 `H/core/agent-session.js:367–371` 的結果 normalization 雖讀正確設定，也無法還原先前已縮小的影像。因此 README 所稱保留 host 圖片行為並非完整成立；codemode 取得的影像 structuredContent 亦沿用此錯誤。
- **改善方向：** 圖片 definition 建立時將有效的影像設定一併注入，保留本次 buffer snapshot／model resize limits；不要為此直接改寫 settings。
- **測試缺口：** `modules/file-tools/tests/path-image-regressions.test.ts:274–280` 只用 tiny BMP 斷言存在附件，不會辨別開關差異。應增加真實 host、大尺寸影像與 `images.autoResize` true／false 的對照，並核對 content 與 structuredContent；此處只是建議，沒有新增或執行測試。

### S1：Shell 逾時改寫會把命令輸出誤當 host 診斷，甚至漏掉真正尾端逾時

- **位置：** `modules/shell-tools/extensions/timeout-ms.ts:106–110、239–244、260–267`；分類位置 `modules/shell-tools/src/background-jobs.ts:26–29、290–295`。
- **確定性：** 靜態字串流程可確定；未啟動 shell 或等待逾時。
- **問題：** `STALLED` 是未錨定的單次 regex replacement。host `H/core/tools/bash.js:267–275` 把已保留的命令輸出與真正的 timeout 診斷串在同一 error.message；本模組內層 catch 與外層 catch 各最多改寫第一處相符文字。
- **可重現條件（未執行）：** 命令先輸出兩行 `Command timed out after 999 seconds`，再真正觸發 5 秒 idle timeout。host error 尾端是 `Command timed out after 5 seconds`。內層改寫第一行，外層改寫第二行，真正尾端仍保留 host 原文字。
- **影響：** 顯示兩個來自普通輸出的假 idle 診斷，而真正 timeout 未被轉換。background classifier 僅辨認字串尾端的 idle marker；job-owned controller 在 idle timer 觸發時並未被 abort（是內部 timeout controller 被 abort），故此案例終態會落成 `failed` 而非 `timed_out`。不是命令成功、也不是取消失效，但 status／通知／持久 journal 的分類錯誤。
- **改善方向：** 僅轉換 host 最終附加的 timeout 診斷，並使轉換冪等；更長期應將逾時類型作為受信任的執行 metadata，不從任意 command output 推論。不要用 global replacement 改寫所有輸出。
- **測試缺口：** `modules/shell-tools/tests/background-jobs.test.mjs:151–166` 驗證的是已正規化的超長 idle error，未走上述兩層改寫。`timeout-ms.test.mjs:9–39` 只驗證換算／輸入。建議以 fake operations／純函式注入兩個假診斷及真正尾端，不新增 sleep／watchdog 型測試。

### N1：Note 的 containment 判斷誤拒合法、仍在 cwd 內的目錄

- **位置：** `modules/note-tools/extensions/note.ts:64–68`。
- **確定性：** 靜態可確定；未建立 junction 或動態重現。
- **問題：** `inside.startsWith("..")` 把路徑 segment 的父目錄語意與一般名稱前綴混為一談。例如 `<cwd>/plan` 是指向 `<cwd>/..archive` 的內部 symlink／junction 時，`relative(realCwd, realDirectory)` 為 `..archive`，它沒有離開 workspace，卻被回報 `NOTE_DIRECTORY_ESCAPE`。
- **影響：** 合法的內部重導向路徑無法新增筆記；README `modules/note-tools/README.md:26` 的拒絕條件是指向工作目錄外，不是任何名稱以兩個點開頭的內部目錄。
- **host 依據：** `H/core/extensions/types.d.ts:501`／`H/core/tools/tool-definition-wrapper.js:12` 以 invocation ctx 提供工具 context；`H/core/extensions/runner.js:630–633` 提供 runner cwd。host 不會替自訂工具修復此 containment 邏輯，這是模組自身的 filesystem 判定缺陷，而非 hook 契約錯用。
- **改善方向：** 比較完整 `..` segment（等於 `..` 或以 `..` 加平台 separator 起始）與 absolute 情況；保留拒絕外部 junction 的政策。
- **測試缺口：** `modules/note-tools/tests/note.test.ts:193–199` 只測外部 junction，沒有合法內部 junction、兩點前綴目录；應加成功與拒絕的成對案例，不弱化外部 escape 斷言。

## Suggestions (consider)

以下是改善／邊界，不併入上述三項確定缺陷數量。

1. **明確区分 defaultTools 和 allowlist。** `modules/file-tools/extensions/file-tools.ts:441–604` 的 read／write／edit 與 `modules/note-tools/extensions/note.ts:17–35` 沒有 `defaultActive:false`，因此按 host 1.1.0 在 unrestricted defaults 模式自動 activation。`H/core/agent-session.js:2875–2899` 明確容許此行為；`tests/fixtures/sdk-hooks.mjs:41–42、154–177` 甚至有斷言。`defaultTools:["read"]` **不是唯讀授權**，載入 File 可得到 write/edit、Note 可被預設啟用；真正 `tools:["read"]`、`noTools:"all"`、exclude 才會在 registry 層限制。若產品目標是「載入覆寫不增加任何未選工具」，應另行決策 read/write/edit 的 defaultActive，而非把現行行為說成 host 違約。README 建議增加此警語。
2. **Note realpath 檢查不是原子 containment。** `modules/note-tools/extensions/note.ts:64–79` 檢查後仍以原 lexical path open；目錄可在 await／queue 等待時由外部寫入者換成外部 junction。`H/core/tools/file-mutation-queue.js:27–43` 是同 process 按檔案排序，不會鎖住祖先目录。此為需要外部並行改路徑才能觸發的安全邊界，未做 exploit 測試；應在 README 說明威脅模型，必要時採 directory-handle／平台安全開啟策略。簡單再 realpath 一次只能縮小窗口，不可宣稱彻底消除競態。
3. **File 新檔的 hard-link fallback 非全域原子可見性。** `modules/file-tools/src/file-operations.ts:1051–1067` 在不支援 hard link 時以 `wx` 直接寫目標，可保证不覆蓋但外部讀取者可能見到部分內容。參與 queue 的工具會排序；任意外部讀取者不受 queue 保護。`README.md:56、90、114` 應更清楚区分不覆蓋、同 process transaction、完整 payload 原子發布這三種保證。
4. **取消延遲與 UI 資源上限。** File 的 snapshot reread `src/file-operations.ts:796–843` 沒有傳 signal，取消要到下一 checkpoint 才生效；不是缺少取消，但取消 latency 不保證立刻。`extensions/file-tools.ts:627` 展開直接輸出完整 diff，可接近 50 MiB，建議僅 UI 分頁／展示上限，保留 details 與模型原結果；依 `docs/tui.md:106–112` 避免阻塞 interactive render。
5. **File loadedSkillPaths 對 handler 順序敏感。** `extensions/file-tools.ts:438–440` snapshot 只看到本 handler 執行當下的 skills；host `H/core/extensions/runner.js:1121–1164` 讓後面的 handler繼續修改同一 prompt options。後載入 extension 修改 skills 時，本輪 read fallback 可能落後。這不是常規載入場景必現的缺陷，應以相反 extension order 的 fixture 確認需要的行為；不要為此改寫 host prompts。
6. **Shell 歷史 receipt 耗時。** `extensions/timeout-ms.ts:183–187` 只從 render state 的 Date.now clock取得 Accepted in，不使用 Pi 1.1.0 的 `context.durationMs`；host `H/core/tools/renderers/bash.js:79–87` 優先單調、可持久的 durationMs。可考慮 receipt同樣優先使用它，避免 reload／歴史卡片失去耗時；一般結果已直接委派 host。
7. **診斷隱私及 bounded I/O。** File opt-in logging `src/debug-logging.ts:14–58、61–88、113–165` 已遮罩 content／regex 等，但仍保留路徑／診斷且無 retention；非同步 append 沒有自行設期限。Shell README `149–171` 明確說 failure debug log保留命令／輸出，設定來源固定 home 而非 PI_CODING_AGENT_DIR。這是已文件化的 opt-in 政策，不應以契約升級暗中改位置或啟用；可考慮更明確的保留策略與敏感資料提醒。
