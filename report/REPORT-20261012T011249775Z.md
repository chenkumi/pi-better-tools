### index：可抽 finalization 閉包，但不是將 finally 整體移出
- `modules/subagents/extensions/subagent/index.ts:976–1024` — 四個 throw 都落入同一局部 try/catch；此處沒有證據顯示這四個明示 throw 本身逃出該 catch、覆蓋主操作 completion。ESLint 本機實作 :71–89 只沿 AST 找 finally／函式邊界，不以局部 catch 判斷可達覆蓋，因此仍會報告。
- 建議最小抽法：在既有 finally 的原位置直接 `await` async finalization 閉包，將 976–1009 的 try-body 工作放入閉包，讓既有 1010–1024 catch 接住其 rejection；或連同局部 catch 移入閉包，但不得新增吞錯 catch。函式邊界能消除四個明示 throw 的 lint 祖先 finally 關係，且有實質 finalization 工作邊界，並非停用規則。
- 必須保留捕捉同一可變狀態、finalIo／cleanupIo、abort listener 安裝時序、spool iterator return barrier、writerCloseConfirmed 僅成功 close 後設定、commitAttempted 的檢查前時序、diagnostic、errorCode、canResume 與 rollbackEligible 的既有寫入順序。
- :1025–1074 的 rollback／release／lateCleanup／onOwnedSettlement 不應移到 detached promise，不得讓主函式提前回傳。閉包必須被 await，且其 rejection 由原 catch 處理；僅換函式邊界不會令所有 cleanup 自動安全。

### acquisitionFence：後置仲裁可保持語意
- `modules/subagents/extensions/subagent/session-store.ts:286–300` — mkdir fence 失敗仍應直接拒絕，未取得 fence 不得 rmdir。取得後 operation 必須 await 到 settlement，保留泛型 T 的實際值（包括 undefined），捕捉例外但不在 catch 提早 throw；finally 收集 rmdir error。
- 仲裁矩陣：兩者成功 → 回原結果；只有 operation 失敗 → 拋原始 error；只有 rmdir 失敗 → 原訊息的 AggregateError([cleanupError]) 並 cleanupUnsafe=true；雙失敗 → AggregateError([primaryError, cleanupError])，保留順序、巢狀 AggregateError 與原物件 identity。
- 使用獨立 primaryFailed／cleanupFailed 旗標，不以 error 的 truthiness 或 `!== undefined` 判斷失敗：JavaScript 可以 throw undefined/null/false/0。不得提前釋放 writer／nonce，不重試 rmdir、不接管殘留 fence。

### compat 與 SDK：不能照抄單一真值判斷
- `modules/web-tools/scripts/compat.mjs:42–46` — 現況 rm rejection 會阻止 after digest 檢查，清理／完整性錯誤亦可能遮蔽原 operation 錯誤。「同時保留主與清理錯誤」不是現況等價描述，而是明確的診斷改善。主錯誤須捕捉，清理各階段須分別收集，最後於 finally 外決定原錯誤或 AggregateError；保留 rm 的 force/maxRetries/retryDelay 與 before/after checksum 安全檢查。不可讓 rm failure 使 manifest 完整性檢查被默默刪掉，並應確定是否要求該檢查於 rm failure 後仍執行。
- `modules/web-tools/scripts/compat.mjs:41` — 若要求成功訊息代表整體驗證成功，PASS 應待清理及 checksum 成功後才輸出；這是額外輸出語意調整，不能聲稱目前已如此。
- `modules/web-tools/scripts/compat.mjs:10–11,27` — 此腳本仍是舊來源版本相容性流程，根 AGENTS.md:38 只支援 Pi 1.1.0，且複製清單依賴模組本地 lockfile。lint 修正不授權復活 0.85.1／0.99.1 支援、執行 npm install 或替此歷史腳本擴充範圍。
- `tests/fixtures/sdk-hooks.mjs:149–156` — 現況 `if (primary)` 對 falsy thrown value 會漏掉雙失敗主錯誤。重構應保存 primaryFailed、cleanupFailed、原始 error，finally 只 await f.close 並收集；finally 外先雙失敗 AggregateError（既有 name 訊息、[primary, cleanup] 順序），再 close-only／action-only 原物件 throw；兩者成功才 cases.push。
