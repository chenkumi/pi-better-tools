# 專案重構審查：重複邏輯與現行入口之外的程式碼

## 結論

值得做小批次清理，而非建立跨模組通用框架。確認的優先方向是清理現行入口不再使用、但仍被打包的歷史實作；其次合併同一模組的 env parser，最後才統一純 UI binding。這輪只審查，未修改產品程式碼、測試、設定或 provenance。

## 範圍與證據界線

- 檢查根 package.json 的 18 個入口（16 個本地模組與兩個 npm extension），閱讀架構、Blackhole／Shell／Subagents／Fork／Pi Runtime 的相關說明。
- 對 modules 下 291 個 TS/MJS 來源候選（排除 node_modules、tests/test、examples、scripts、skills 與 test/spec 檔）做 AST 函式重複掃描；另建立 modules、scripts、tests 的靜態 import/export 與 literal resource path 圖，從本地 manifest 入口追蹤可達性，再核對重點符號與呼叫端。
- 靜態圖不是任意動態載入、外部 deep import 或使用者自訂 extension 的完備證明；「未接入」指本專案目前可查證的入口與呼叫圖，不表示可不經相容性評估刪除所有 export。
- cwd 為 D:/GitHub/pi-better-tools-main，但沒有 .git；git status --short 回覆 not a git repository。因此無法核對未提交變更或歷史 diff。
- 沒有呼叫外部 provider、付費模型或修改真實全域設定。

## 建議項目

以下優先順序代表維護收益，不是已重現功能錯誤的嚴重度。

### R1｜優先：移除或隔離 Blackhole 不再接入的舊壓縮流程

**證據**
- modules/blackhole/index.ts:29-30、75-84 明確採 Pi-only ownership，不安裝 inline adapter，也不註冊舊 trigger。
- modules/blackhole/src/om/compaction-trigger.ts:128 仍實作 registerCompactionTrigger；它 import inline-compaction，但未被現行 production 入口引用。
- modules/blackhole/src/om/inline-compaction.ts:62-80 保留 private host shape／prototype adapter。
- 兩檔分別 670 與 1117 行；npm pack --dry-run --ignore-scripts --json 確認仍收入 package，合計 62,751 bytes。
- 查到的直接使用者是舊測試：auto-compact-permutations、compaction-trigger、inline-compaction、compact-failed 等。pi-owned-command 的 mock 是禁止 private preflight 的負面防護，不是 production 載入證據。

**建議**
以現行 Pi-only 契約為依據刪除或移到不隨產品打包的歷史位置；不要為了讓它們「有用」而重新掛回入口。逐案分類舊測試，只處理專屬於已移除流程者，保留現行 native compaction、pending commit、失敗／取消與安全防護測試。Runtime 裡可能相關的狀態需另外查引用，不能連帶一律刪除。

**風險／後續驗證**
收益高、執行風險中：涉及匯入來源與既有測試的定位。應跑 blackhole 模組分組、sources:verify；若改 package files 或 tarball 內容，依專案規則跑 cross/package 驗證。保留 immutable origin，於 adaptations 記錄移除／隔離，不覆寫原始來源雜湊。

### R2｜優先：合併完全相同的 env override 引擎

**證據**
- modules/blackhole/src/core/config-env.ts:58-104。
- modules/blackhole/src/pi-base/core/config-env.ts:30-76。
- AST 函式 body 去除空白後完全一致；EnvParser／EnvOverride 型別亦重複。
- 前者由 core/unified-config.ts 使用，後者由 pi-base/config-manager.ts:16、508 等使用；兩邊實際都在使用，不是死碼。

**建議**
保留 pi-base/core/config-env.ts 的通用引擎與型別；core/config-env.ts 保留 Blackhole 專屬 env map、cache retention、timer bound，改為 import／必要時 re-export 同一引擎。只共享通用部分，避免讓通用 pi-base 反向依賴 Blackhole 專用設定。

**風險／後續驗證**
低至中。確保 bool／positive-int／float／custom parser、空白 env、invalid fallback 與不修改 input 的行為一致；保留現有 import 路徑相容，可透過 re-export 達成。執行 blackhole 模組分組與 provenance 驗證。

### R3｜優先：處理未接入的 Pi Runtime 日誌模組

**證據**
- modules/pi-runtime/src/debug-log.ts:13、24、70、83 定義 runtimeDebugEnabled、runtimeLogSnapshot、writeRuntimeFailure、runtimeLogging。
- modules/pi-runtime/src/index.ts:1-5 的入口依賴及整份實作沒有引用它；其 import 閉包也沒有接入。
- 專案查到的直接使用者只有 modules/pi-runtime/tests/debug-log.test.ts，runtimeLogging 物件本身未有呼叫端。
- pack dry-run 確認 debug-log.ts 仍被打包（4,638 bytes）。

**建議**
若 Runtime failure logging 不是仍待交付的需求，刪除此孤立實作及僅驗證它自身的測試；若確實是待辦功能，另列明確需求，不要在清理重構中偷偷接入，因為接入會新增可觀察 I/O 與資料保存行為。本輪未將此項宣稱為功能 bug，因未找到必須啟用該日誌的現行需求。

**風險／後續驗證**
低，但刪除前確認外部 deep import／未記錄需求；執行 pi-runtime 模組分組及必要 native provenance 檢查。

### R4｜低風險：移除已過期且未掛入口的 0.5.2 migration notice

### R5｜中優先：移除 Subagents UI 的雙軌投影與測試專用相容分支

**證據**
- modules/subagents/extensions/subagent/index.ts:1274 實際 bind 使用 jobs.panelJobs(owner, cwd)。
- background.ts:171-177 的 activePanel 舊投影，查到的使用者只有 live-widget.test.ts。
- live-widget.ts:6-20 留有 SubagentWidgetRow、legacyJobs、renderSubagentWidget；:26、30、42 因而接受新舊兩種來源並在 runtime 判斷是否含 kind。
- production 已使用 PanelJob[]，但舊測試仍保留舊輸入格式；這不是 persisted session 格式轉換。

**建議**
確認沒有外部使用者後，把 widget source 收斂為 readonly PanelJob[]，刪除舊 activePanel／legacyJobs／舊 row 型別與純舊介面 render wrapper。把舊測試裡 owner/cwd fencing、metadata bounded/sanitization 等仍有效的斷言移到 panelJobs，不能只刪測試讓它通過。

**風險／後續驗證**
低至中。這一項不應改 receipt、journal 或舊 session render 相容；只處理記憶體內 UI adapter。跑 Subagents 模組與面板相關 cross checks。

### R6｜中優先：合併三份純 UI 的 bind／refresh／clear

**證據**
- modules/shell-tools/src/live-widget.ts:32-60。
- modules/subagents/extensions/subagent/live-widget.ts:23-51。
- modules/fork/src/live-widget.ts:44-73。
- 三份都保存 ctx／owner／source／token／panel，bind 先 clear、只掛 TUI，refresh 查 owner 後投影及 JSON signature/update，clear 清引用並 token-detach，UI failure 都與執行結果隔離。

**建議**
在既有共享 presentation 層抽一個小型 binding helper，由呼叫端提供 kind 與 () => readonly PanelJob[]。各模組繼續擁有自己的投影／job registry／取消／通知／生命週期；不要抽成通用 background execution manager。最好先做 R5，避免把舊相容分支泛化到新 helper。

**風險／後續驗證**
中。owner replacement、stale token、throwing UI、detach 與非 TUI 分支不得變更。三模組變更需各模組及 cross 驗證；少量重複本身不值得犧牲安全界線。

### R7｜低優先：把測試 helper 移出 production src／package

**證據**
- modules/blackhole/src/pi-base/config-test-helpers.ts:1-5 明言 Test-only；內容含 temp fixture、測試 env 修改與 vi.resetModules。
- 已查證直接 import 是同目錄 config-manager.test.ts；不是 production 入口依賴。
- pack dry-run 仍收入 config-test-helpers.ts，4,378 bytes，因根 files 收錄整個 Blackhole src，只排除 *.test.ts。

**建議**
移至測試 helper 目錄並更新實際測試 import，或明確排除打包。這是仍有用途的測試程式，不應誤刪為無用程式。保留原有隔離與 cleanup 邏輯，不擴大一般 helper 抽象。

### R8｜低優先：合併 enum／number 的非搜尋 SelectList submenu

**證據**
- modules/blackhole/src/pi-base/settings/fields/enum.ts:43-118。
- modules/blackhole/src/pi-base/settings/fields/string.ts:251-321。
- render body 完全相同；SelectList 建立、目前選項、reset、空白／數字快捷鍵、invalidate 與 requestRender 流程高度相同，主要差異是 item 建構及 string／number decode。

**建議**
以小型本地 SelectList factory 參數化 items／selectedIndex／defaultIndex／onSelect，避免共用 enum-specific field。只處理非搜尋選單；搜尋、number step/min/max、secret/path 編輯均留在原 renderer。此項收益小，應排最後。

## 明確不建議合併或刪除的項目

- Shell／Subagents／Fork 的 job registry、admission、取消與 close／writer ownership：名稱與流程相似但實際生命週期不同；不應為 DRY 合併。
- 各處 renameWithRetry：File Tools、GPT Speed、JSON Schema、ManagedSession 的取消、同步／非同步與寫入交易需求不同；未證明等價，不列立即共用候選。
- 薄 src/index.ts、child guard／worker 入口：承擔 loader／相對路徑／獨立執行邊界，不能以轉發為由移除。
- Blackhole legacy config 讀取與 durable hostContract: "0.99.1"：屬資料相容契約，不是可以按目前 host 版本直接刪除的殘留。
- barrel、types、安裝 script、worker resource 等單憑 manifest import 圖不可達，不能判死碼；例如 PTY install.mjs 有根 npm script 使用。
