## Critical (must fix)

### R-HTTP-01 — HTTP 101 可讓 headers promise 永不 settle
- **位置：** `modules/web-tools/src/fetch/http.ts:94–98`；影響延伸至 `service.ts:234,390–394,403–413`。
- **狀態／優先度：** 靜態確認，P1；未執行 socket 重現。
- **觸發：** 缺 browser 的 HTTP fallback 遇到公開站點回覆 `101 Switching Protocols`、`Connection: Upgrade`、`Upgrade: websocket`。不需完成 WebSocket 握手，也不涉及私網或 DNS rebinding。
- **程式缺口：** headers promise 只監聽 request 的 `response`／`error`，沒有「response 前 close」或直接 signal settlement。外層 cleanup 只有 promise settle 後才會執行。
- **固定版本事件證據：** Node 22.22.2 的 `parserOnIncomingClient` 在 upgrade 時提前返回；`socketOnData` 設定 req.res，沒有 upgrade listener 時銷毀 socket。`socketCloseListener` 在已有 res 的分支只 emit request close、不 emit request error；之後 destroy 已 destroyed request 直接返回。故這個事件序列不會 settle 產品的 headers promise。citeturn0view0
- **影響推導：** request 已關閉後，deadline 或手動取消不能再靠其 error 事件喚醒等待；queue permit、operationCleanup 不釋放。累積至 maxConcurrency 即耗盡抓取容量；`service.close()` 新增等待 operationCleanup，會連帶卡住 shutdown／reload。這是本次新增 transport 的生命週期缺陷。
- **最小修正：** headers 等待需在尚未交付 response 即 close 時 reject；AbortSignal 亦直接 settle 等待，不只依賴 request 再 emit error。若另處理 upgrade，必須拒絕並銷毀被移交的 socket。保留一次 settlement、listener cleanup 與 request close 後才釋放名額的規則。
- **最小回歸：** 本地 raw TCP／HTTP fixture 回傳上述 101，確認 fetch 直接失敗；再驗證取消、service.close 可完成、operation 集合清空及 queue 可再次取得。使用事件 barrier，不新增固定 sleep timeout 測試。現有 `tests/integration/static-http.test.ts:49–95` 沒有 101 分支。
- **可重查來源：** `https://raw.githubusercontent.com/nodejs/node/v22.22.2/lib/_http_client.js`；原始碼約 463–476、491–519、589–622、645–666 行。

## Warnings (should fix)

### R-SETUP-01 — 相對 browser cache 因 installer cwd 改變而指向另一目錄
- **位置：** `setup/core.mjs:24`；對照同檔 `61–66,88`。
- **狀態／優先度：** 靜態確認，P2；未下載瀏覽器。
- **觸發：** 從非套件目錄 A 直接執行 CLI，`PLAYWRIGHT_BROWSERS_PATH=./browser-cache`，且沒有 INIT_CWD。
- **證據：** doctor 留在 A 載入 Playwright；browserInvocation 卻讓 installer cwd 變成 packageRoot B，且原樣傳入環境。Playwright 1.64.1 registry 對相對 cache 用 INIT_CWD 或 process.cwd 轉絕對路徑。因此 doctor／同目錄 Pi 使用 A/browser-cache，但 installer 使用 B/browser-cache。citeturn1view0
- **影響：** 即使同一安裝實例、同一環境，安裝成功後仍可能缺 browser、持續 fallback 或 selector 失敗；packageRoot 唯讀時也可能新增不必要的安裝權限錯誤。
- **最小修正：** browser 子程序保持呼叫者 cwd；Playwright CLI 已是本實例解析的絕對路徑，不靠 cwd 找依賴。另一做法是在切換前按 Playwright 規則正規化有效 cache 路徑並保留 `0` 特例，但較複雜；不改全域環境或設定。
- **最小回歸：** 任意 cwd、相對 cache、無 INIT_CWD 下，比較 doctor executable 與 installer 子程序所解析的 cache。用唯讀 registry／stub CLI probe 即可，不必安裝。現有 `modules/pty-terminal/tests/setup.integration.test.mjs:16–25`、`scripts/package-smoke.mjs:143` 都使用絕對 cache，不能捕捉此差異。
- **可重查來源：** `https://raw.githubusercontent.com/microsoft/playwright/v1.64.1/packages/playwright-core/src/server/registry/index.ts`，registryDirectory，約 387–405 行。
