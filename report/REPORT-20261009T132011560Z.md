## 3. 精確 SDK 原因與父需要決策之處

Pinned installed source：`node_modules/@earendil-works/pi-coding-agent/dist/core/agent-session.js`。

`_installAgentRequestProjection` 第 434–485 行：

1. native `prepare()`（439–454）重建 canonical projection，並執行 constructor 時捕獲的 previous callback。
2. 第 455 行第一次 await `prepare()`。
3. 第 466 行 native virtual routing 取得 physical model，並保留 route state 等 side effects。
4. 第 481–483 行，physical-model threshold 超標時 await `_runAutoCompaction("threshold", false)`，**沒有檢查其 false/cancelled 結果，就再次執行 `prepare()`**。

公開 threshold cancellation 成功阻止 compaction，但不能阻止第 483 行的 inner previous callback replay。外層 Blackhole public wrapper 等到 previous native wrapper return 時，第二次 callback side effect 已發生；最終 guard 雖能零 provider dispatch，也無法撤銷它。重跑 native wrapper 來更新新 Blackhole summary，更不能被拿來當合規 refresh。

因此，在「no-chain-replay 包含 SDK 自己的這次 replay」的嚴格要求下，現有提案 blocked。若父原意只是禁止 Blackhole 手動再次 delegate，必須明確寫出 SDK-owned existing replay 的 contract 區別；worker 不會自行把它當作允許的例外。

### 選項與建議

- **建議：保留嚴格要求**，由 SDK owner 提供 cancelled threshold 不重播 previous callback、且可正確保留 native canonical projection／physical route 的公開 contract，再授權 Blackhole 接續。這需要另行 owner/scope 決策；本 worker 不改 SDK 或其他模組。
- 若父認為此 SDK-owned replay 本來就屬於「保留原 chain/side effects」而非禁止範圍，請保存精確決策：區分 native existing replay 與 Blackhole-induced replay，並定義 routed threshold cancellation 的驗收 assertion。這不是本 worker 已採用的放寬，也不能把目前兩個診斷綠燈當新 policy 綠燈。
- 不建議透過 private method patch、重新路由、猜測閉包中的 previous callback、暫改 numeric thresholds，或關閉 native overflow 來隱藏問題。

**精確下一步：** 父先 review `before-request-native-chain-final-diagnostic.log` 與 installed SDK 第 481–483 行，決定 strict no-chain-replay 是否包含此 native replay；若包含，指定 SDK owner 解決 public contract blocker。此 worker 已正常退出，不等待常駐 process。
