## C2：recovered manifest close unsafe不再退化為false

### 保留的minimalregression

`modules/subagents/tests/session-store.test.ts`：

`C2 recovered manifest close failure preserves diagnostic and actual writer ownership`

1. 重用該檔真實setup／prepare，commit verifiedcheckpoint並release。
2. 建same-pid orphan nonce的writer.lock，再resolve獨立recovered ManagedSession。
3. Owner.json正常write／sync／close／publish；只攔該session根的 `manifest.json.<ULID>.partial` 真FileHandle.close，丟 `recovered manifest close EIO`，不執行realclose。
4. 先assert injected closeAttempts=1，並用 `retainedHandle.stat()`證明handle仍真正open。
5. 觀測writerowner是否存在／registrynonce量；assert原close診斷、cleanupUnsafe、replacementnonce仍registered、writer／query新lease均SESSION_BUSY。
6. finally恢復mock，真正close該ownedhandle之後才removefixture與自己的testregistrynonce，不盲刪外owner。

### 原碼red3證據

三次皆為assertionfailure，非import／setup／watchdogfailure：

```json
{"handleStillOpen":true,"closeAttempts":1,"writerOwnerPresent":false,"retainedNonces":0,"error":"Error: SESSION_BLOCKED: Stale writer lock checkpoint could not be verified; manual inspection required"}
```

診斷assert期望 `Metadata writer close failed ... recovered manifest close EIO`，實際卻SESSION_BLOCKED；同時diagnostic明確記錄writerowner已刪而handle仍open。每次teardown才realclose。

### 最小fix

`ManagedSession.rollbackToCheckpoint` 的catch：僅對帶 `cleanupUnsafe === true` 的實際closeunsafeerror原樣rethrow；一般checkpoint／validation／publishrefusal繼續returnfalse。`initializeLock`既有cleanupUnsafe檢查因此保留writerlock／live registry，不走補償刪除。

### 同casegreen3證據

```json
{"handleStillOpen":true,"closeAttempts":1,"writerOwnerPresent":true,"retainedNonces":1,"error":"Error: Metadata writer close failed: Error: recovered manifest close EIO"}
```

close診斷及marker原樣保留；後續writer／query拒絕且nonce不变。沒有以fakeclose／receipt拒絕推定cleanup已完成。

### 一般mismatch保持

focused及unit包含原有 `rollback refuses to restore when the checkpointed native prefix was modified`、`a first-run failure without a checkpoint stays blocked even when restore is requested`，仍確認false／blocked拒絕；正常failed/cancelledcontinuation與dead-ownerverifiedrecovery繼續通過。未將一般mismatch升格成closeunsafeexception。

## W1：fence清理故障不再遮蔽主故障

### 保留的minimalregressions

同檔兩個cases：

- `W1 fence cleanup failure preserves owner publish EIO and EACCES: foreign=false`
- `W1 fence cleanup failure preserves owner publish EIO and EACCES: foreign=true`

對ownedownerpublishrename丟原始EIO物件，同时對自己的writer.acquire/rmdir丟EACCES物件；foreignvariant先寫foreign-owner nonce。Assert結果包含primary EIO與fenceEACCES、AggregateError.errors保存實際物件reference及nestedprimaryAggregateError；foreignowner未被盲刪，fence仍存在，後續writer／query都拒絕。

### 原碼red3

兩variant每次都在「不能隱藏primary初始化診斷」斷言失敗：actual為 `Error: fence rmdir EACCES`，expected `/owner publish EIO/`。primaryseam確實已注入，不是單純rmdir故障測試。

### 最小fix

`ManagedSession.acquisitionFence` 保存primaryFailedboolean與primaryError（包含合法undefinedrejection的區分）。如果rmdir再拒絕，throw帶cleanupUnsafe的AggregateError：

- errors保留 `[primaryError, cleanupError]`（primary本身是AggregateError時不丟nested證據）。
- 診斷明說 `Acquisition fence cleanup unconfirmed; writer ownership may remain held`，並保留兩個故障文字。
- 原操作成功但rmdir拒絕時，保留單一cleanupError的AggregateError，不假稱acquisition已安全完成／ownership已釋放。
- 不自動retry、force-rm或接管殘留fence；foreignowner保護不改。

### green與補充分支

核心兩variantgreen3都通過。修正後另保留 `W1 successful initialization with failed fence removal retains writer and refuses new leases`，確認正常ownerpublished但fence移除拒絕時：writer／nonce仍保留，AggregateError及cleanupUnsafe誠實呈現，其他writer／query拒絕。此為補充green分支，不虛構它在原碼跑過red。
