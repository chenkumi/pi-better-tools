## 次優先：資料正確性／結果可靠性
- JSON Schema `src/validation-schema.mjs:12–13`：required補properties改變schema-valued additionalProperties語意；__proto__鍵補入不是own property。`schema.ts:57–73,160`另有patternProperties相關漏驗／合法schema誤拒。優先以純資料測試重現，修正或保守拒絕不忠實組合。
- JSON Schema extraction `extensions/json-schema.ts:193–198`先接受第一個結果，未稽核剩餘工具／衝突；raw snapshot與host工具hook資料修改的關係需真正1.2.0契約確認。
- Fork `child.ts:97–102`、`manager.ts:137–144`缺晚到close reconciliation，已退出仍可永久占permit；finalizing RPC未競速cancel。store先截workspace最新64再篩origin，以及restore繞retention，影響結果恢復與有界性。
- Blackhole `src/om/consolidation.ts:898–957,1266–1284`：Observer raw來源不套有效context-edit omission/replacement，可能把主模型已省略／替換的內容送入背景模型。需區分有效native窗口，不把所有舊context edits當全歷史redaction。

## 次優先：效能／資源界限
- File edit `src/file-operations.ts:258–262,1495–1497`：50MiB全LF可建立52,428,801項number索引，worker cap不保護這段主執行緒工作。大檔不一定多文字，byte cap不能代替行索引cap。
- Subagent catalog `agents.ts:73–85,141–146`：顯示64項是在全量sync read/parse之後，且多scope重複discovery。
- Shell每chunk同步UI重建、Fork Atomics.wait rename retry、Runtime error regex及Blackhole O(m*n)索引key，均可能延後stream drain／取消／TUI；尚無CPU/heap實測，不宣稱已發生OOM或已量到秒級延遲（Fork等待上限為程式算術推導）。
- Subagent晚到I/O及module-local容量、PTY matcher容量與Windows input queue顯示「receipt terminal」與「resource actually settled」需要分開記帳，跨reload更需一致ownership。
- Web browser cleanup與Schedule late-output callbacks須保留失敗ownership並禁止terminal後重新啟動timer，不能以取消要求冒稱實際close。
