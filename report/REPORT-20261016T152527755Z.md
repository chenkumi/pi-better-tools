## 行為與安全邊界
- 只有已知 Playwright executable 缺失診斷可 fallback（Chrome/Chromium）；permission、system dependencies、startup timeout、unknown 各自保留安全診斷，不因失敗永久快取。
- HTTP 使用 node:http/https，agent:false，不共用連線池、不修改 global dispatcher、不新增依賴。
- 每跳重新驗證 URL／所有 DNS addresses，custom lookup 固定已驗證 IP；原 hostname 保留為 Host／TLS identity／SNI。IPv4/IPv6 與 all/single lookup callback 都有測試。
- TLS 真實測試：self-signed 未信任憑證在 HTTP 發送前拒絕；以測試専用 CA 配合相同 pinned options 驗證正確 hostname/SNI 成功、錯誤 hostname 以 ERR_TLS_CERT_ALTNAME_INVALID 拒絕。production transport 沒有 TLS bypass。
- wire bytes 與解壓後 bytes 各 5 MiB，UTF-8 decoded HTML 亦 5 MiB；gzip/deflate/br pipeline 有界，取消／失敗 destroy，等待本地 request close 才釋放 operation。已測 br 成功、gzip bomb、無 content-length oversized stream、損壞 gzip。
- HTTP 保守要求明確 text/html、application/xhtml+xml 或 text/plain content-type；缺 header 會 UNSUPPORTED_CONTENT（刻意比既有 browser 路徑嚴格，不作 sniffing），已有回歸測試。請 parent 同步文件。
- text/plain 先 escape，再包 main/pre 交既有 isolated extractor，不當 HTML 解釋；BOM 優先於 HTTP charset，再採 early HTML meta charset；未知 charset 明確拒絕。
- 不執行 JS、meta refresh、subresources，不存 cookie 或 auth；HTTP/TLS/網站錯誤不重試、不切回其他 transport。
- 同一原始 deadline，mock timer 在 launch 消耗 600ms、HTTP DNS 再消耗 400ms 即到 1000ms 原期限，未以固定 sleep 測試。
- HTTP 連線 pinning 不改變 Chromium 路徑既有盲 SSRF 限制；不能宣稱整個 web_fetch 已成 SSRF sandbox。
