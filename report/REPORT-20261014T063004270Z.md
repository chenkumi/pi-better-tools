# Refactoring 審查：根 runner、File Tools 與 Web Tools

## 範圍與方法

唯讀審查，未修改產品程式碼或測試。讀取根 package.json、scripts/run-checks.mjs、scripts/package-smoke.mjs、docs/architecture.md，以及 File Tools、Web Tools、PTY、Note、Skill Tools 的相關 README 和局部實作。這是候選審查，不是全面缺陷掃描或所有檔案的逐行審計。根目錄 git status 回報不是 Git repository，因此無法確認未提交變更。

## R1：FileToolErrorCode 使用單一宣告來源（低風險，建議先做）

- 位置：modules/file-tools/src/errors.ts:5-27、48-71。
- 證據：同一組 22 個錯誤碼同時宣告為 union type 與 runtime Set。Set 的泛型能拒絕不存在的碼，但不能保證所有 union 成員都列入，維護時仍可能漏同步。
- 建議：保留一份 `as const` tuple，從 tuple 衍生 `FileToolErrorCode`，並建立 `ReadonlySet<string>` 供 runtime 驗證。維持既有 export 型別名、錯誤碼與 parseFileToolErrorText 行為。
- 驗證：modules/file-tools/tests/error-display.test.ts；模組 typecheck。不得因簡化而允許未知錯誤碼或減少 malformed payload 檢查。

## R2：移除 Web provider_stream_event 舊版型別轉接（低風險）

- 位置：modules/web-tools/src/index.ts:155-158；modules/web-tools/src/native-sources.ts:14。
- 證據：目前以 `pi.on as unknown as ...` 轉接事件註冊，註解指向 0.85.1；根 manifest 和安裝的 SDK 均為 Pi 1.2.0，node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts:713-719 已原生宣告 ProviderStreamEvent。
- 建議：直接 `pi.on('provider_stream_event', ...)`，讓宿主型別檢查 handler。ParsedProviderEvent 可以保留為 parser 的最小結構輸入（測試也使用），或在確認符合最小結構契約後從 SDK 型別 Pick 衍生；不需要為了減少型別名而強制測試攜帶無關字段。
- 邊界：這不等於可移除來源資料 runtime validation、response identity correlation、opt-in、abort 清除或 forcedSystemPrompt 合成。index.ts:138-150 的 forced prompt 路徑在既有測試中仍有明確行為，不建議直接刪除。
- 驗證：modules/web-tools/tests/unit/extension.test.ts、native-sources.test.ts，加 Web 模組 typecheck。

## R3：統一建立一般 tsc 任務（低風險，次要）

- 位置：scripts/run-checks.mjs:33-43。
- 證據：四個模組透過 map 建立相同的 tsc task，另九個模組手動重複相同 label、tsc binary 與 tsconfig 路徑。
- 建議：用一個固定順序的模組清單 map 出所有直接 tsc 任務；File Tools 的 moduleTask('file-tools', 'typecheck') 留作例外。不建立新的測試框架或抽象 task manager。
- 契約：保留原本 label、順序、ownerOf 分組、tsconfig 路徑、直接 node 執行與 File Tools 子 manifest script 驗證。保持 evidence 檔名與格式。
- 驗證：比對變更前後 task 投影；實作後依 scripts 變更規則執行 test:cross。這輪未修改 runner，因此未執行該分組。

## 不建議為簡化而改動

- 各模組 src/index.ts 薄入口具有 manifest／相對資源位置契約，不能當作冗餘移除。
- modules/file-tools/src/search-tools.ts 的 ctx.cwd 執行時委派與 null normalization 是明確契約。
- File Tools mutation 的 hash、fingerprint、rename retry 重驗不是同一項檢查；不得合併成僅 stat 驗證。
- PTY 的 deliver 已由 read/write 共用；manager 與 renderer 的 transport／remote tree 警告不等同多餘狀態。
- Skill Tools 實作只有資源註冊，沒有值得新增抽象層的複雜度。
- Note Tools collision retry、exclusive create、取消與部分寫入清理不可只為縮短程式而刪除。
