## 1. 修復與安全不變量

### Core R1：format authority 與 mutable proof 分離

- 新 `src/core/summary-format.ts` 的 `ownedSummaryLayout`／`summaryFormatProof` 要求 actual latest persisted Blackhole writer、已知 v1/v2 details、known prefix grammar、exact previous-summary agreement；新 `blackhole.summaryFormat` version 1 把 `structured-v1`／`literal-brief-v1` 與完整文本 SHA256 綁定。
- `compile` 的 `previousSummaryEntries` 與 `onSummaryFormat`，以及 before-compact 的 final composition metadata，把這個判斷接到真正 native preparation。Generated OM/recall spans 或可辨識 header 本身不能授權 structured extraction／volatile filtering。
- Native、unknown、stale／same-text-latest-native previous prose 仍 literal；合法舊 persisted BH structural format 仍可 merge。Quoted body `[Outstanding Context]`、separator 與 mandatory warning 在 subsequent proven BH generation 仍保留。
- `capLiteralBrief` 不再掃 schema header 刪除前置 literal。原有 120-line brief budget 保留首尾、明示 middle omission；**不是無上限、lossless summary archive**，中段仍可能依 budget 省略。Raw history 沒有改寫或 erasure。

### Core R2：malformed JSON proof 先驗證再使用

`validGeneratedProof` 在排序前逐一確認 span 是 nonnull/nonarray object、合法 kind、safe nonnegative offset／positive length、sum safe、bounds、SHA256、count ≤8、無 overlap、完整 sourceGeneration 相符。`[null,null]`、scalars、arrays、unknown kind、negative/unsafe ranges、zero length、bad digest、overlap/count overflow 皆 false，保留 literal、不 blanket-catch compile。另以有效 nested proof + unknown envelope versions undefined/0/2 原碼補充 red，再要求 version-1 nonarray envelope。Latest owner、summary/trailing、composition、OM checkpoint consumers 與 real Pi preparation hook 都有回歸。

### Wiring R1：fresh public branch authority

`ConfigManager._hostSessionOverrides`／`resolveHostSession`／load、inspect、save 每次取得同步 public cwd/session/file/leaf/branch/entries snapshot，驗證 actual record 在 active ancestry，且 data pre-save leaf 是該 record 的 ancestor。Full-history 裡 descendant/sibling C 或 warmed pre-save P cache 不授權停在 P 的 branch；lookup failure、foreign/stale init 或 cwd mismatch 不沿用舊權威，回 file/env base。Direct initSession recovery 亦只用 supplied actual leaf ancestry。真正 owner-keyed unsaved pending 在 file materialization 後仍可 flush；append 先成功才清 pending，拒絕 append 可重試一次，不宣稱 process transaction／filesystem durability。

新增 actual SDK navigation probe涵蓋 warm P、fresh resolver、**separate cold process**（full entries 含 C、branch 停 P）、sibling、return C、reload、三種 lookup throws、foreign init、cwd mismatch、reset leaf、empty session、notification callback navigation。原 JSONL prefix 未改寫；新 cold child 完整 file bytes 不变。Configuration-pending materialization/refusal/retry 認證只有一次 successful append。Warning notify throws/no UI 不先標 delivered，之後可 retry，正常 reload去重，FIFO cap 512；key 含 cwd。這些是 settings pending，不能冒稱強化了全部 OM pending transaction guarantees。

### Active native-budget UI

`nativeContextDisplay` 只用 public `getContextUsage` 的 tokens/contextWindow；明示 capacity 不是 trigger、未知時 unknown、**native trigger budget unknown**。Status X 與 memory command 不再使用 legacy threshold denominator、preset suffix、guessed ratio/default 或 selected-model guess。O/P memory gauges 與 worker events 保留，memory off 隱藏 O/P，shutdown 清 timers；legacy preset/ratio/fixed/reserve 變更不改顯示，也不發動 compact。
