## Critical (must fix)

### R1 — P1：以 result 工具名稱選擇權威檢查，讓 File call 可經 non-File result 繞過配對

- **位置：** `modules/blackhole/src/extract/file-touch.ts:1227–1229,1261–1275,1280–1285,1307–1312`；傳播點 `modules/blackhole/src/core/build-sections.ts:209–213`、`modules/blackhole/src/extract/files.ts:127–137,179,192–198`。
- **靜態證據：** 第一輪依 call ID 保存 `getTrackedToolActions()` 推導的 read/write/edit 活動。第二輪先取得 `toolCalls.get(toolCallId)`，但僅在 **result 的** `toolName` 屬於 `FILE_TOOL_NAMES` 時才用 `fileResult(pair)` 覆蓋。若 originating call 是 `write` 而同 ID result 是 `bash` 或另一個 non-File 名稱，`pairToolBlocks()` 正確拒絕同名配對，collector 卻保留第一輪 speculative write action。這一分支也只以 truthy `isError` 排除失敗，未要求 explicit false。
- **影響／推論：** 不合法的 result 可把未獲合法 write acknowledgement 的輸入路徑列為 Modified。raw collector 的輸出先進入 `extractFiles()`，而 `rawTouchesAuthoritative=true` 不再用 normalized fallback 重算，因此 block-only 的 fail-closed 不能補救 compact 的原始訊息路徑。此問題不需要正文偽造成功語句，也不涉及 filesystem resolver。這是 B1 指定的 malformed/mismatched authority 邊界缺口，不是宣稱正常 Pi host 必然會產生這種結果，也不是重開非 File legacy shell 行為。
- **最小回歸（未執行；靜態可推導）：**

```ts
const messages = [
  { role: "assistant", timestamp: 1, content: [
    { type: "toolCall", id: "w", name: "write",
      arguments: { path: "ghost.ts", content: "x" } }
  ] },
  { role: "toolResult", toolCallId: "w", toolName: "bash",
    isError: false, timestamp: 2,
    content: [{ type: "text", text: "ok" }] }
];
// Required: collectFilesTouched(messages, cwd) === []
// Required: buildSections({ blocks: normalize(messages), messages, cwd })
//           .filesAndChanges === []
```

  現行路徑會保留 `ghost.ts` 的 write activity；`pairFileMessages()` 本身並沒有成功 result。補測應把 result 移到 call 前、增加 duplicate call/result、省略 isError，並保持同名 unique explicit-false 正例。另確認 normalized block-only、raw compact 與 `mode:touched` 不出現互相矛盾的成功判定。
- **最小修正方向：** 對 originating File call 的 ID 一律套用 unique／same-name／先 call 後 result／explicit-false 權威，不能由不相符 result 的名稱決定是否走 File 驗證。重複 ID 已從 pairs 刪除時也要保留其屬於 File attempt 的拒絕判定，避免掉回 legacy actions。只修這個 adapter 邊界；不要求重寫非 File legacy parser，也不批准任何 filesystem 能力擴張。
- **測試缺口：** `tests/note-file-results.test.ts:115–125` 的 mismatch 是 `note` → `write`，兩者都在 File allowlist，沒有穿過上述 non-File 分支；現有 157／2671 green 不能排除此缺口。
