# Gemini grounding 來源捕捉：實作與真實 API 驗證報告

日期：2026-10-17　範圍：`modules/web-tools`

## 目標

把既有的 opt-in `captureSources`（原本只支援 OpenAI 原生搜尋來源）擴充到 Gemini 的 Google Search grounding，讓 `/web-tools sources` 也能顯示 Gemini 那次回答的來源與 citation offsets。

## 設計決定

| 決定 | 理由 |
| --- | --- |
| 新增 `providers.google.captureSources`（預設 `false`），不改動 `providers.openai.captureSources` | 與既有 per-provider 設定形狀一致；不讓既有設定靜默開始記錄（來源可能含敏感 URL） |
| 只在 `provider: "native"` 且模型是 `google` provider 的 Gemini 3／4 時註冊 | 與注入閘門完全相同，不會記錄到沒注入的請求 |
| 沿用同一個 entry 型別 `pi-web-tools.native-sources`、同一組上限（50 筆／24 KiB）與同一支 `/web-tools sources` | 保持單一儲存格式與單一讀取路徑；`readSourceRecord` 既有的重新驗證直接適用 |
| 只複製 `groundingChunks[].web.uri/title` 與 `groundingSupports[].segment` 的 offsets | 搜尋 query、答案文字、`searchEntryPoint` HTML、raw event 一律不落地（與 OpenAI 路徑同原則） |
| 記錄 `status: 'completed'` | 串流 chunk 沒有 status 欄位；失敗／取消的回答本來就會在 `turn_end` 被丟棄 |
| 不改用 follow-redirect 解析來源原址 | 捕捉必須是被動的、不能發出隱藏網路請求；因此 grounding 的 redirect URL 原樣保留（chunk 的 `title` 通常是來源網域，可作為提示） |

## 變更檔案

- `src/native-sources.ts`：抽出共用的 bounded record builder，新增 `captureGroundingSources`。
- `src/config.ts`：`providers.google.captureSources`（parser 改為 openai／google 共用同一段驗證）。
- `src/index.ts`：`provider_stream_event` 註冊條件與 handler 改為同時支援兩條捕捉路徑；`/web-tools status` 顯示兩個 flag 與「解碼是否 ready」。
- `schemas/web_search.schema.json`：新增 `providers.google`。
- 測試：`tests/unit/native-sources.test.ts`（新增 3 個 grounding 測試）、`config.test.ts`、`extension.test.ts`（capture 閘門與持久化）。
- 文件：module `README.md`、`pi-tools-config` reference、provenance。

## 驗證

### 離線

- `npm run typecheck` 17/17 stages；`npm run lint` 無輸出；`npm test` 19/19 stages；`npm run test:module -- web-tools` 4/4 stages。
- web-tools 單元測試 93/93（新增：grounding 只留 bounded sources 與 offset citations、絕不含 `webSearchQueries`／答案／`searchEntryPoint`；api／provider／model 閘門；responseId 缺失或超長拒絕；`file://` 被丟棄；50 筆上限與 24 KiB 上限；超過 2048 字元的 URL 丟棄）。

### 真實 API（`gemini-4-argon`，`provider: "native"`，`providers.google.captureSources: true`）

兩次嘗試的差異很重要：

1. 第一次（給 `read,web_fetch`）：模型選擇 `web_fetch` 抓 Wikipedia，**沒有觸發 grounding** → 沒有記錄可捕捉。這再次確認「請求被接受」不等於「有搜尋」。
2. 第二次（`-nt` 不給任何工具，問即時新聞）：grounding 觸發，`provider_stream_event` 收到 `groundingMetadata`，且 session 檔內出現 1 筆 entry：

```json
{ "customType": "pi-web-tools.native-sources", "api": "google-generative-ai", "provider": "google",
  "model": "gemini-4-argon", "responseId": "UqzTasS-JeOWosUPzK_AiA4", "status": "completed", "truncated": false,
  "sources": [ { "title": "theguardian.com", "url": "https://vertexaisearch.cloud.google.com/grounding-api-redirect/…" },
               { "title": "google.com", "url": "https://vertexaisearch.cloud.google.com/grounding-api-redirect/…" } ],
  "citations": [ { "url": "…", "startIndex": 3, "endIndex": 383 }, { "url": "…", "startIndex": 388, "endIndex": 841 } ] }
```

   已確認 entry 內**沒有** query 文字、答案文字或其他 raw 欄位。成本：該次 tokens $0.005 + 1～2 次搜尋。

### 未驗證

- `/web-tools sources` 的 TUI 顯示（指令讀同一支 `readSourceRecord`／`formatSourceRecord`，由單元測試覆蓋，但本回合未開互動 TUI）。
- 多個 grounding chunk 分散在不同 stream chunk 的情況（目前同一 responseId 以最後一筆為準，與 OpenAI 路徑相同語意）。
- grounding `groundingSupports` 的 offsets 是否與 Pi 合併後的文字完全對齊（多段 text 回覆時可能偏移；紀錄視為 API 原始值）。
