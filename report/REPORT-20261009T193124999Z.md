## Warnings (should fix)

### W3 — 檔案 scope Delete 後 Save 仍可復活畫面已撤銷的舊值
- `modules/blackhole/src/pi-base/settings/config-flow.ts:400–406` — `deleteEdit` 成功刪檔後只把 fresh lower-layer values 傳给 `activeEditBody.setValues`，沒有更新 `currentValues`。同檔 `saveEdit:307–310` 保存的是 `{ ...currentValues }`，不是畫面 rows。
- `modules/blackhole/src/pi-base/settings/body.ts:208–224` — `setValues` 僅更新 rows／body initialValues／dirty state，不呼叫 config-flow 的 `onChange`，所以不會間接同步外部 buffer。
- **可達靜態 specimen：** Global 檔存 `memory:false`，defaults 為 `memory:true`。進 Global editor 後 buffer 為 false；確認 Delete 成功後畫面回到 true，但 buffer 仍為 false。沒有重新編輯該欄位，接著確認 Save，`ConfigManager.save:937–1007` 讀到不存在的檔案，將舊 false 寫入重新建立的檔案。Project scope 同樣可把已刪除的舊 override 寫回，與顯示出的 inherited global 值不一致；若先改另一欄再 Save，未觸碰的欄位仍會復活。這不是「使用者明確確認畫面上的 fresh 值」：實際寫入值與畫面不同。
- **證據層級：confirmed static，未由本人或本輪提供的測試 runtime 重現。** 這是本輪檢查修過的 Reset-buffer 邏輯時找到的相鄰既存缺陷，不能宣稱是 worker 新引入的 regression；也不使已修的 session Reset W1 重新成立。Session UI 不提供 Delete button（`config-flow.ts:462–474`），因此本 finding 明確限於 Global/Project file editor，不針對 public session delete。
- **最小修正：** 成功 Delete 後，像 `resetEdit:369–370` 一樣清除並以 fresh values 取代 `currentValues`；可抽取共用 refresh helper，讓 reset/delete 的 display、save buffer、dirty state、inspection 同步。刪檔失敗不得刷新為成功狀態。
- **最小 regression：** 使用 actual selector/edit body/confirm callbacks，分別做 Global 與 Project「Delete → 不改欄位 Save」及「Delete → 改另一欄 Save」，斷言顯示值、提交 payload、重新建立檔案與 reload exact 一致；Project 要有不同的 global lower layer。加 Delete cancel／refusal 例，不觸碰真實使用者 config。只檢查 mock custom return 或只呼叫 `deleteScope` 不足以覆蓋本 finding。

## 原 findings 的清除證據

### 原 W1：persisted-session Reset／public Delete — 可清除

`config-manager.ts:1109–1135` 不再只清 cache。Live-host 路徑先以 `_hostSessionOverrides` 重新取 owner/branch snapshot，再 append 合法既有 schema `{ leafId: currentLeaf, config: {} }`，接著重新檢查 latest active settings record、同 session/cwd、pre-save leaf 與真正 empty config，驗證後才清該 owner pending sentinel。Append throw/no-op 或 snapshot lookup failure 不直接報成功；純未 materialize owner 才直接撤銷自己的 sentinel。

`_hostSessionOverrides:582–625` 仍以 fresh branch 作 authority，逐筆檢查 parent chain、unique ID 及與 public entries 的 equality；settings record 自身在 current branch，且其 pre-save leaf 是已看過的 ancestor 才合法。Empty config 現在會成為最新合法 override，而不是被舊 cache 或 full-history C 取代。真正 unsaved owner pending 仍保留；`_tryFlushSession:381–395` 的 append 在 pending 清除之前。Reset 本身不先 flush 舊 pending。

`config-flow.ts:365–374` 同步替換 display 與 save buffer，解決 supplemental Reset→Save 復活舊值。Actual fixture `review3-settings-host.mjs:102–128` 使用實際 SDK session 與真 selector/body/confirm，涵蓋 Save C→Reset R、Reset→Save S、public session delete、reload/fresh manager、回 C／回 R、原 JSONL prefix 不改及七 ignored keys absence；`:82–100` 覆蓋純 pending owner、不同 owner、materialize append refusal 保值與一次成功 empty append。這是讀到的測試實作與 supplied green，不是本人重跑。

因此清除前報 W1 直接根因，但不接受任意外部 writer、跨 process transaction 或 filesystem durability；W3 是另一個 file-editor buffer 缺陷。

### 原 W2：callable no-UI notify 被誤當 delivered — 可清除

`config-manager.ts:557` 缺 callback 直接返回；`:561–563` notify 正常返回後才加 dedup key，throws 可重試。Resolver `:574`、settings-open `:1058` 與 actual factory `index.ts:57` 都要求 public `ctx.hasUI === true` 且 callable notify，不因 Pi no-UI 提供 callable no-op 而標 delivery。Key 包含 config identity、cwd、session owner、message，shared set 跨 manager/reload，FIFO cap 保持 512；未靠移除 mandatory warning 達成 green。

Factory `index.ts:55–65` 保存 unified lower-layer base；outer warning callback 嘗試後再從該 base 同步 public reproject，不把已套用 C override 的 config 作下一次 base。直接 resolver `config-manager.ts:575–576` 亦在 notify callback 後重投影，維持 navigation revocation。

Actual `review3-settings-host.mjs:54–80` 先 bind JSON mode、無 uiContext，直接斷言 hasUI false 且 notify callable；no-UI reload 不標交付，之後 bind UI、reload 同 warning exactly once。另含 missing callback、throw→success、跨 manager、cwd/owner isolation 與 513 FIFO/512 cap。Standalone navigation fixture 明確 hasUI true／false，不以缺 public field 的 synthetic context 宣稱交付。故清除前報 W2。
