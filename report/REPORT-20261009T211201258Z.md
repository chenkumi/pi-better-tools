# Pi 最新正式版 hooks 與 pi-better-tools 全模組調查報告

## 1. 摘要與裁定

**基準：Pi 1.1.0；範圍：12 個本地模組＋2 個 npm 擴充入口。**

調查於 **2026-10-09 UTC／2026-10-10 UTC+8** 執行。實際查詢 npm dist-tag 與 GitHub latest release，最新正式版均為 **1.1.0**；npm 發布時間為 2026-10-07 22:16:26 UTC，GitHub release 為同日 22:26:31 UTC。本機與專案開發依賴也為 1.1.0。GitHub main 可能有未發布修改，不將它混稱為最新正式版。

### 整體結論

1. **頂層結構正確，不需要重建 plugin manager。** Pi 已負責 discovery、載入順序、hook dispatch、工具 registry、reload 與 session lifecycle。現有根 manifest 直接載入 TS、host SDK peers、單一依賴與 lockfile 的設計應保留。
2. **入口及型別相容性已驗證，但不能宣告所有模組完整相容。** 14 個入口皆載入成功，12 個本地模組 typecheck 通過；隔離 SDK fixture 14/14、manifest integration 7/7 通過。這些不覆蓋每個缺陷的觸發條件。
3. **優先阻擋項有五類：Blackhole project trust、Schedule project/child trust、Blackhole 同 session 分支導航下的背景 ownership、Schedule 子 session awaited cleanup、JSON Schema 最終宿主取消後仍交付。** 詳見 D01–D05。它們是本報告的修正優先級，不代表本次已實測完整利用或 production 洩漏。
4. 其他具體問題集中於 RPC/TUI 分界、錯誤結果旗標、settings scope/lock identity、並行資源容量與 shutdown fencing。不是所有問題都源自 hook 錯用；File/Note/Shell 的部分發現是工具功能缺陷。
5. **不建議全面 sequential、增加不必要 lifecycle hooks、直接使用 private runner 或默默啟用工具。** 改善應沿公開 API，保留既有 trust、owner/canonical cwd/generation、工具選取及子行程保障。

### 證據分級

- **靜態確認**：現行模組與實際 Pi 1.1.0 控制流程能推出結果；不等於已動態重現。
- **受控重現**：使用真實模組搭配 fake factory/context、deferred Promise 或隔離 filesystem；只證明該邊界，不擴大成完整 host/OS 證明。
- **待驗證風險／能力限制**：需要額外前提、政策選擇或實測，與確定缺陷分開。
- **未發現確定缺陷**：本次範圍內未確認，不是安全認證。

本輪只調查、驗證與新增文件，**未修改 production 程式、第三方程式、真實 settings/auth/schedules 或歷史 session，也沒有還原既有工作樹**。調查 HEAD 為 `11423a04a95b626cf4fbe6f3c8bde478eee19b2e`，評估對象是當時 dirty working tree，特別包含既有 Blackhole 修改，並非該 commit 的純淨快照。

## 2. Pi 1.1.0 hook 設計：本次對照準則

文件之外，回傳與事件語意以安裝版本的 `dist/core/extensions/types.d.ts`、`runner.js`、`agent-session.js`、`agent-session-runtime.js` 為精確依據。

| 準則 | 1.1.0 語意 | 對本專案的判定標準 |
|---|---|---|
| Factory／資源 | Factory 用於註冊與建構輕量狀態；process/socket/watchers/timers 應於 session_start 或按需建立 | 純記憶體 subscription、讀設定不一概列漏；需啟動／shutdown 的資源必須有 owner 與 cleanup |
| Shutdown | session_shutdown 可 await cleanup；SDK owner 必須 await runtime.dispose() | 同步 session.dispose() 不是發送 shutdown 並等待資源清理的 API；throw 也不是讓宿主永遠保留舊 manager 的協定 |
| Agent 結束 | agent_end 是低階 run 結束；之後可能 retry、compaction、follow-up/continuation | 可以收集逐 run transcript，不能直接判整個 prompt 最終失敗／可交付 |
| Settlement | agent_before_settle 可提出 boundary drafts/continuation；agent_settled 是最終通知，帶 aborted | 不在 settled 返回 continue；分開接受工作、最終取消與通知提交 |
| Session／branch | replacement/reload 使舊 ctx 失效；同 session tree navigation 不等於換 session ID | Session-owned 工作以 generation fence 保護；branch-sensitive 工作額外需要 navigation epoch／ancestry 授權 |
| Prompt | before_agent_start 的 systemPromptOptions 可組合；forced systemPrompt 是合法但較粗的替換 | 優先結構化區段，避免 provider 最終 prompt 與 transcript 結構描述分離 |
| Context | context 對模型訊息投影，Pi 會恢復 system/tools；context_with_system 由 handler 負責完整前綴 | Blackhole 的一般投影應留在 context；不為形式一致改用更強的 hook |
| Tool hooks | input 原地變更可被後續 handler 看見且不重驗；tool_result content replacement 未帶 structuredContent 會移除舊機器內容 | Redaction/transform 要同時思考文字、details、structuredContent；錯誤必須明示 isError 或 throw |
| 並行／檔案 | 同批工具可並行；read-modify-write 應整體進 withFileMutationQueue | 不只 serialize 最後 write；但純搜尋、snapshot 後解析不需不必要的大鎖 |
| Exposure | direct/model-only/codemode/deferred 是可達性；defaultTools 不是安全 allowlist | explicit tools、noTools、exclusions 與 registry 決定授權，不能把隱藏宣告當禁用，也不能自動啟用未選工具 |
| UI | hasUI 不只 TUI；RPC 可支援部分 dialogs/text/status，不支援 TUI component factories/custom overlay | custom editor/footer/component widgets 必須 tui gate；不能因此停止正常 headless 排程 |
| Hook 順序 | Transform 依載入／註冊順序組合；同名工具先註冊者勝 | 每個事件個別分析，不把多 extension 視為無序集合；延後 registerTool 仍會撞名 |
| 新 metadata | tool render context／tool_execution_end 有 durationMs，render context 有 outputPad；settled 有 aborted | 改善 renderer 時可用權威耗時，但不為更新 API 改變 job 終態／receipt 語意 |

**官方 example 的陷阱：** `examples/sdk/06-extensions.ts` 仍示範同步 session.dispose；對需要 awaited shutdown 的擴充，應採官方 session-runtime 設計並 await runtime.dispose，不照抄成 cleanup 保證。

## 4. 五項優先阻擋問題

「優先阻擋」表示在聲稱完成安全／lifecycle 整合前應先修；不是宣稱已動態驗證所有攻擊或資源洩漏。

### D01 — Blackhole 繞過未受信任專案設定邊界

- **來源：** `modules/blackhole/index.ts:50–56`；`src/core/unified-config.ts:780–800`；`src/pi-base/config-manager.ts:654–658,700–707`。
- **問題：** extension 直接以 cwd 讀 `.pi/settings.json` legacy memory layer 與 `.pi/pi-blackhole-config.json`，未使用 `ctx.isProjectTrusted()` 排除 project layer。宿主 SettingsManager 在 trust=false 時不載入專案設定，這裡自行讀取繞過該政策。
- **前提／影響：** Blackhole 從全域或允許來源載入、cwd 未受信任且有相應檔案；可改變 memory／背景模型候選等設定。**不直接等同任意程式碼執行。**
- **較佳方法：** 在有 fresh ctx 的入口決定 project layer admission，runtime/config/UI 共享同一 trust 決策，未知不預設授權。
- **證據：** 父層與 reviewer 靜態交叉確認；尚未執行完整 untrusted CLI probe。
- **下一個測試：** 全域載入＋trust true/false，現代／legacy 兩路；隔離 HOME/agentDir、passive/mock credentials。

### D02 — Schedule project jobs 與子 SDK 未繼承 trust

- **來源：** `modules/schedule-prompt/src/index.ts:44–64`；`storage.ts:43–46,92–119`；`subagent.ts:158–199`；host `settings-manager.js:211–248`、`resource-loader.js:345–364`。
- **問題：** 未查 trust 就載入 `.pi/schedule-prompts.json` 並啟動 enabled/unbound jobs；child 自建 loader/settings、未繼承父 trust，預設回到 trusted。子資源可能重新載入父層拒絕的 project settings/extensions。
- **較佳方法：** 專案排程須 explicit trusted admission／明確 opt-in；child loader 與 SDK 共用一個先設父 trust 的 SettingsManager，再 reload/bind。執行邊界也要確認 ownership/trust，不只 startup。
- **受控證據：** 真實 scheduler＋有效 interval job 確認 start 建立 nextRun；false-trust context 下顯式 fire 攔截到一次 sendUserMessage，trust checks=0、provider calls=0，stop 清 timer。
- **界線：** 不是實際等待 timer，也不是完整 CLI 利用實測；child reload trust 目前由來源確認，不誇稱已執行惡意 extension。

### D03 — Blackhole 同 session tree navigation 不能撤銷舊分支 worker

- **來源：** `modules/blackhole/src/om/consolidation.ts:219–228,544–555,620–632,1266,1304`；`runtime.ts:245–285`；`index.ts:68–69`。
- **問題：** generation 綁 session identity，不綁 branch navigation；現有 session_tree 只重新投影 settings。Pi 在同 SessionManager 切 leaf，session ID 不變；A 的 worker 完成仍通過 guard，`pi.appendEntry()` 會把 A 計算的 OM 資料寫到當前 B。
- **影響：** 記憶污染、coverage/cursor 錯置；in-flight guard 也可延後 B 的工作。
- **較佳方法：** 公開 session_before_tree/session_tree 邊界撤銷 branch epoch、abort/reconcile，append/pending commit 前再次確認 branch 授權。**不能讓普通對話每次 leaf 前進都取消 worker。**
- **證據：** 靜態確認；尚未跑 deferred provider A→B host probe。既有 same-session generation 不變測試不能代替 navigation ownership。

### D04 — Schedule 子 session disposal 沒有 awaited shutdown，父層也不 drain

- **來源：** `modules/schedule-prompt/src/subagent.ts:203–205,258–264`；`scheduler.ts:103–110`；host `agent-session-runtime.js:102–113,296–303`。
- **問題：** child bind extensions 後，finally 只 `session.dispose()`；parent stop 只 abort controllers，不等待初始化／執行中的 child promises。子資源可能缺 session_shutdown，甚至父層 shutdown 後才完成初始化。
- **較佳方法：** 保存 child runtime，idempotent await runtime.dispose；parent 停 admission、abort、drain accepted/initializing children、保留未確認清理狀態。不要把同步 dispose mock 通過當 shutdown receipt。
- **證據：** 靜態確認；未執行真實 child browser/PTY/worker cleanup failure probe。

### D05 — JSON Schema 未觀察 final settled.aborted，取消後仍交付

- **來源：** `modules/json-schema/extensions/json-schema.ts:36–39,88–89,109–142,194–207`；host `agent-session.js:684–691,1458–1463,1909–1918`。
- **問題：** accepted 已存在後，在 agent_before_settle 使用 `ctx.abort()`，可只得到 `agent_settled.aborted=true`，沒有新 aborted assistant 或 SIGTERM。模組沒監聽該最終事件，shutdown 仍輸出／覆寫檔案。
- **較佳方法：** 按高階 run 記錄最終 cancelled/outcome；shutdown 採可靠 final state 決定交付，明訂 multi-prompt reset。不在 notification-only settled 回 continue。
- **證據：** 靜態確認；現有 provider-aborted/SIGTERM fixture 不涵蓋無 process signal 的宿主取消。未將本輪 SDK 通過當成本案例 green。
- **下一個測試：** accepted→before-settle abort→settled.aborted；stdout 空、舊檔不變、其他 shutdown handlers/pool cleanup 仍執行。

## 6. 需驗證的相容性風險、政策與能力限制

### R01 — JSON Schema native retry/overflow recovery 與 fail-fast 政策

`extensions/json-schema.ts:41–45,110,114–116,139–141,203` 在任何低階 error 立即 sticky failure/exitCode1；Pi 可之後 native retry 成功，但 extension 仍不交付。若後續成功是 text，message_end 因 failure 提前 return，還會失去 stdout suppression，普通 print 可能輸出 prose。

- 這些是**靜態控制流程確認，尚未動態重現**；README 把 upstream error 列為不交付條件，接受 recovered success 與否仍需明訂政策，不武斷稱所有 sticky 行為都違反文件。
- 但選 fail-fast 也不應失去 structured stdout 保護，或默默讓 host 繼續有用不了的 retry。
- 較佳方法：分離 attempt error、final run outcome、不可恢復設定/conflict/I/O failure；保留 agent_end transcript，final settled 判 outcome，shutdown 交付。不無條件清 exitCode，避免抹掉其他 extension failure。
- 現有 fixture 關 retry/compaction，不能證明此共存。補成功 tool/text、exhausted、before-settle continuation、overflow、cancel、conflict 的 barrier/mock cases。

### R02 — Subagent approval 與 ready-query admission

- `index.ts:1488` project-agent confirm 未傳工具 signal；需 dialog-open barrier 後 abort，確認關閉與晚到批准不派遣。
- `child-bridge.ts:89` 在 before_agent_start throw；Pi runner catches/continues，所以 throw 不是 admission barrier。正常 ready-query 路徑尚有 guard/exclusions/no-tools，**沒有證明正常 query 可寫入或繞過**。需測意外 RPC prompt/第三方 startup 的實際可達性；process isolation 不是 OS sandbox。

### R03 — Monitor command permission scope

`modules/shell-tools/src/monitor-exec.ts:17–50` 自行 spawn backend，不走 nested bash hooks。需要明定 monitor_start 本身的 command 授權，或在產品需求成立時採 ctx.executeTool；不能假設拒絕 bash 的 policy 自動拒絕 Monitor，也不能偷偷啟用 bash。當前不是已證實權限漏洞。

### R04 — Web 網路隔離不是完整 SSRF containment

`modules/web-tools/src/fetch/service.ts:228–231` route.fetch 在 connected-peer 檢查之前發送，DNS preflight 不 pin 目的 IP；即使拒絕 response use，blind private request 仍可能發生。README/tests 已記載邊界，不列為新發現的完整 sandbox 被攻破。

若要多租戶 public-fetch sandbox，需外部 egress/network containment，或另案設計 pinned transport/redirect/rebinding 策略；不靠一般 response-level route reject 宣稱成立。Web 測試 HOME/USERPROFILE 也需隔離，只有 PI_CODING_AGENT_DIR 不足以隔離固定 home config/debug log。本次未執行瀏覽器實測。

### R05 — Settings/filesystem 與真正模型支援

- Note realpath 檢查後 lexical open 的祖先目錄外部 swap 仍是 TOCTOU 威脅模型；mutation queue 不鎖外部 writer/目錄。本次沒有 exploit probe。
- GPT Speed 用 selected ctx.model，virtual physical route 未必受 tier injection；JSON recovery 用 registry.complete 不自動沿主 Agent provider instrumentation。這是 API/能力界線，需明確承諾與公開機制，不接 private runner。
- 未查證真實服務對 priority/ultrafast、費用/速度或 JSON Schema constraints 的接受性；不把本地型別/validator 當遠端保證。

## 8. 結構改善：哪些值得做、哪些不應做

### 值得做

1. **統一設計原則，不統一成新 plugin manager：** fresh ctx→admission→reserve→accepted work→final outcome→awaited cleanup。可做很小的 shared helper，但 owner/trust 語意仍留各模組。
2. **Session epoch 與 branch epoch 分開。** 對 branch-sensitive producer 額外 fencing；對 task-wide budget保留跨 branch reservation，不一概改 getEntries 成 getBranch。
3. **結果旗標一致。** 工具 rejection/error 明示；job query 成功不等於 job 成功，receipt/close/cancel/submitted 不等於 ack/cleanup。
4. **原子性範圍正確。** 保留 File 完整 mutation queue 與 Note exclusive create；FFF pending capacity 要預留，settings lock 要對宿主同 identity。
5. **Prompt 結構化。** Subagents forced prompt 雖合法，逐步遷 structured sections；File skills snapshot 用兩種順序 fixture，避免整串覆寫。
6. **新 metadata 精準利用。** Shell renderer 可採 context.durationMs；machine consumers需要時才增加 outputSchema/structuredContent。json_output 的 input schema 不能直接當 outputSchema，其 tool result 是 ack，CLI delivery 才是 submitted object。
7. **UI 可降級。** component/editor/footer 確認 tui；RPC 用支援的文字/status/dialog。Open 私有 editor tree、full diff UI 可以設安全 fallback/顯示上限，不改模型資料。
8. **上游第三方問題循正當路徑。** FFF/Schedule 保留來源/license，記錄 adaptations，於整合層拒絕不支援組合；不要手改 node_modules 或把依賴重新授權。

### 不建議

- 為了 API 更新重寫 aggregator/plugin manager 或所有薄入口。
- 把全部工具改 sequential，掩蓋真正容量/transaction 問題。
- 給無 session state 的 Note/Search加無用 start/shutdown。
- 將 agent_end 一律替換成 settled，破壞逐 run messages 收集。
- 把 hasUI 當 TUI、defaultTools當 allowlist、hidden declaration當 tool disabled。
- 取消 requested就聲稱 OS/remote descendants已停；sendMessage callback返回就聲稱持久化/ack。
- 用 private host internals、背景輪詢或跨 reload replay 補破口。
- 對 Blackhole 既有已修的 oldest-first selector、native compaction ownership、settings ancestry重報同一缺陷，或還原程式製造 red。
