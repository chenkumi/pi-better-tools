### R1 修復核對

1. **Explicit open／actual close／pending counter** — `session-store.ts:275–292`
   - `withWriter()` 在 open 前增加 counter，涵蓋 open、operation 與 close 的實際等待；open 失敗也由外層 finally 對稱減計數。
   - operation 失敗仍 await close；close 拒絕時先以 `cleanupUnsafe: true` 保存實際 handle、檔案路徑與 close error，再向上拋出，優先於 operation error。
   - counter 歸零不是 close 成功證明：`writerCloseConfirmed` 同時查看 global unsafe registry（`:258–266`），拒絕的 handle 與 live nonce 持續存在。

2. **Dispatch 的 wx／duplicate 語意** — `session-store.ts:529–540`
   - dispatch 改用 `withWriter(dispatchFile, "wx", handle.writeFile)`，保留 exclusive create、0600、新 dispatch 的 payload 與原 `EEXIST → DUPLICATE_DISPATCH` 分支。
   - open 的 EEXIST 不會產生假 owned handle；正常 close 完成後才建立 run intent／發布 running。
   - dispatch close 拒絕不會被當 duplicate：wrapper error 帶 cleanupUnsafe，已保存 unsafe 身份；即使 begin 尚未使 runner 的 runStarted 為 true，normal release 前的 `assertWriterSafe()` 仍會拒絕。
   - 既有 duplicate ready-preservation case 位於 `tests/session-store.test.ts:98–111`；本次只閱讀，未執行。

3. **兩個 rollback truncates** — `session-store.ts:455–484`
   - native 在需要縮短時、aggregate 按 checkpoint 長度，均透過 `withWriter(..., "r+", handle.truncate)`；未改成建立／覆寫新檔案，也未改變既有 prefix-hash、size 與 native checkpoint 驗證。
   - close 拒絕現在带 cleanupUnsafe，因此 rollback catch 重新拋出，而不是降格為 false／一般 checkpoint mismatch。後續 ready manifest publication 不會越過這個失敗。
   - 正常 operation failure 且 close 已確認時仍可回 false，保留既有「無法證明 checkpoint 就不恢復」語意。

4. **Stale recovery immediate／late** — `session-store.ts:358–377,428–448`
   - recovery 在取得新 lock／nonce 後執行 rollback；truncate close 的 cleanupUnsafe 直接越過 initialization 的一般失敗刪 lock 分支。
   - close 尚未 settled 時 counter 保留；最終拒絕則 global registry 保留 handle／新 nonce，acquisition fence 結束不會釋放 writer.lock。
   - 因 nonce 仍在 live registry，其他 instance 的同 pid stale 判斷不會把該 owner 視為可回收；query acquire 也不作 stale takeover。

5. **Normal／late runner release** — `index.ts:1032–1064`、`session-store.ts:510–518`
   - normal cleanup 在 blocked/release 前檢查 managed unsafe latch；release 自身也檢查 latch 與 pending counter，且讀 owner 後再次檢查。
   - late cleanup 等實際 gate idle／child close／既有 run-local abandon 後仍重新 assertWriterSafe。dispatch close 的延後拒絕不能由 waiting gate settled 或另一個 writer 的 abandon 成功掩蓋。
   - `onOwnedSettlement` 是觀察用 barrier，不自動清除 unsafe registry；未將 settlement 說成全部 descriptor 已關閉。

6. **Query／再 acquire** — `session-store.ts:382–391,428–448`、`index.ts:1318,1329–1345`
   - retained writer.lock 與 live nonce 阻止其他 instance acquire；query lease 遇現存 lock 拒絕，沒有恢復／截短 writer 的旁路。
   - 公開 query cleanup 等 preflight gate idle 再呼叫 managed.release；本輪沒有更改這個 release admission，因此新 latch 同樣適用，而不是提前解鎖。
