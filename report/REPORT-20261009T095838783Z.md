## 逐項修正
### A1：正文與 structural authority 隔離
- `projectNotification()` 先驗證 details，再分開 verified 與 display，structural 直接對 verified details 做 producer-specific projection，不從已混入正文的物件產生。
- 明確 Shape schemas 區分 Shell batch/job、Subagent batch/task/query/result/snapshot、Runtime/error、Schedule、Recovery/job/task；error 只有 Runtime 診斷可作 object container，其他 display error/output 僅 string。
- matching body 只經 `displayOnly()` 補 scalar output/error 與 boolean outputTruncated；不提供 status/cleanup/asOf 來源。正常 scalar error 仍可 ID recall，不入 structural。
- malformed object error 的 failed/exitCode:7 保持；tool、command、default/append summary、第二次 compact 均沒有 BODY_CLAIM／body-origin lifecycle。

### A2：opaque host IDs 與 truthful partial
- pendingToolCallIds／toolCallId 不再使用 persisted-entry ref 的 `[A-Za-z0-9_-]` 規則；保留 `call_A|fc_B`，有界 200 chars，控制碼／bidi/常見 credential 清除。
- 32 record cap、非法值过滤、clean／縮短都明示 projection `partial`，向 parent containers 傳遞。producer 的 pendingToolCallIdsTruncated 保留原值，與新增 projection partial 分別解讀。
- snapshot 支援 nullable entryId/sourceLeafId，sourceTurn ordinals、appliedControlIds；entry evidence ref 仍維持原 namespace 限制。
- 單元涵蓋 1/32/33/64 IDs、invalid/長/控制字串；真實 host fixture 的 top-level query_result 與 task_result nested query 都用 `call_A|fc_B`／sourceTurn ordinals。

### A3：recovery state/outcome
- 只對 recovery schema 納入 task.state／job.outcome；合法 states、task IDs、重複 IDs、kind、processTreeState、finding 關係明確驗證。
- terminal_result_recorded 要 terminal lastKnownState、outcome 等於 lastKnownState、全部 task states terminal；其他 finding 不得帶 recorded outcome。不因 overall job.failed 而抹掉 completed/aborted 混合 tasks，沒有 exitCode 的 aborted task仍保留。
- processTreeState 保持 unknown，不推 cleanup confirmed。

### A4：可核實生成邊界，不信 Markdown
- 新 compaction 可新增窄、optional `details["blackhole.notificationEvidence"] = {version:1,summary:{offset,length,sha256,refs},trailing?:{offset,length,sha256,refs}}`；不改外層 compaction v1/v2，不改 tool schema/config。
- Hook 用實際 fallback/trailing **composition insertion offsets** 捕捉 section；不是 first/last Markdown match。Helper 缺少 insertion knowledge 時要求 section unique，否則不發 provenance。
- Carry/strip 驗證 latest raw Blackhole compaction、精確 stored summary/trailingSummary、bounded span/boundary、SHA-256、refs一致／<=16／無重複，再對 raw branch 投影；不解析舊 prose 來採納 ID。
- Legacy 無 metadata 引用 byte-for-byte 不剝除、無回填；偽 header 在真正 section 前、相鄰正常 section、digest tamper、完全同字的 trailing quotation 都有測試。Strip只刪 verified span，保留其餘 bytes。
- 此 provenance 是既有可信 persisted compaction channel 的來源標記，不是對可偽造整個 compaction details writer 的密碼學身份簽章。無 side index、舊 session migration 或重寫。

### A5：evidence 專用 pre-parse bounds 與分類完整性
- 新 `notification-evidence-scan.ts`：fixed 64 KiB line buffer＋64 KiB chunk，oversized line 在 JSON.parse 前丟棄；總 bytesRead<=32 MiB、最多 100000 lines processed/parsed，callback/payload exhaustion 提前停止，fd finally close。
- 超大行會標 line_limit；有總量餘額時可繼續讀合法尾端。超過 line/entry/byte界限、不合法 JSON／notification、projection fault 的理由分開，不一律報 budget。
- `NotificationEvidenceList` 新增 reasons 與供測試的 scanStats；summary/tool/command 附 truthful incomplete 警告。missing session 檔沿用 fresh-session semantics，其他 I/O error不吞掉。
- 計數測試：100001 lines＋suffix 沒有 parse 超過100000；70000-byte line不parse但合法尾端仍投影；33 MiB giantline只讀32 MiB、0 parsedEntries、buffer<=65536。沒有 idle/sleep 測 timeout。
- **界限分清**：in-memory branch summary 已由 host parse，64 KiB record／4 MiB payload是其投影界限，不是host pre-parse bound；legacy generic message search仍可能走舊scanner，本包沒有宣稱全 recall I/O 都有新界限。

### A6：只有已交付 body 才推 cursor
- 每頁固定保留 worst-case header/footer envelope，selected-body 是exact slice，組裝後不再整段 slice，next只依 delivered body 計算。
- 不能容納 envelope+1 char時零交付、無 nextPage；`isError`／details.notificationEvidence.reason=budget_insufficient、minimumBudget／deliveredChars=0。
- 1-char等極端文字budget無法容納人類句子：content='!'，完整 structured diagnostic 在details；>=19用 Budget insufficient，較大可完整句子。0仍unbounded selected payload；不足回應沒有假cursor。
- 用128-char entry ID與budgets=1/50/200/700/1500/0逐頁重建selected payload；成功頁無漏字，失敗頁無body/cursor。Command ID path同共用vccRecall，維持已文件化 default 48000，未變更其live budget設定差異。
