## 核對結果與可達路徑

### Reservation、draft 合成與去重
- `src/index.ts:77–83,181–190`：先 `reserve`／`persist`，成功後才建構 feedback draft；reservation 失敗只記 pause，不返回 continuation。Automatic 不走 `sendMessage`。
- `src/index.ts:79–80,162–169`：reservation 同步記錄 entry ID、fingerprint 並清除 pending；同一 boundary 再次到達沒有 pending，不能重複花額度。新 error entry 若 fingerprint 相同，仍保存 pending 供人工 review，但 automatic 因 repeated 停止。
- `src/index.ts:190`：使用 `[...event.entries, draft]` 保留既有 drafts 及物件 identity；沒有覆蓋其他 extension entries。後續 handler 仍可撤稿或取消，不退還 reservation。
- 對應單元證據：`tests/recovery.test.ts:78–126` 包含其他 draft 保留、duplicate boundary、同診斷停止、policy/repairable/manual 混合共享2次及 reload；host fixture `:55–64,129–200,216–221` 核對 reservation 在 feedback 和實際 synthetic request 前，以及 withdrawn 不退款。

### Budget、owner、model、abort 與持久化
- `src/index.ts:64–83`：automatic 與 manual 共用相同 eligible/reserve；owned、healthy、enabled、session file、同模型、operation abort、handled entry 及原 error 在 active branch 的 guard 均保留。LIMIT 仍為2（policy.ts:15）。
- `src/index.ts:84–121`：restore 取 active branch task，再合併 session-wide 同 task reservations；無效 state、衝突 fingerprint、過多歷史 fail closed。Tree/reload 不補其他分支 spend；session_start 本身不送 pending 診斷。
- `src/index.ts:122–148`：只有完整頂層 user admission 建新 task；automatic custom-message continuation、extension-triggered run 或排隊 input 不建立新額度。
- `src/index.ts:166–179`：aborted boundary 不提交；不符合資格時保留停止語意。reason 是已明示的優先序，不是宣稱列出所有同時成立的 guard。
- Host `agent-session.js:1536–1558,1941–1951` 在 boundary 後另檢查 abort 並拒絕 continuation；即使 draft 已提交／額度已花，也不等於模型 request 已發出。
