## 已核對的不變量與界線

### 唯讀 capabilities／lifecycle

1. global symbol Map 是窄 rendezvous，不是 plugin manager；只記 provider，不保存可取消 job handle，不 invoke extension factory。registry key 包含 job kind、session ID、canonical cwd；provider generation 由 publisher 的 validity closure 驗證。
2. replace 先令 old provider revoked；revoke 只有 provider identity 相同才 delete；lease snapshot 前後檢查 provider identity、revoked 與 validity。registry 有 64-provider 上限，正常 stop/shutdown 刪除 current entry；沒有確認 registry 保留已撤銷 provider 的漏洞。外部仍持有 old lease 时 closure 仍可達，但該 lease 已不能讀取，不能把這種受持有者控制的生命週期稱為 global registry stale entry。
3. Shell publisher start/stop 組合进既有 lifecycle，不新增另一 dispatcher；`timeout-ms.ts:292` 先同步 stop 再 shutdown。managed child 分支行 275–279 不建背景 registry/publisher。
4. Shell snapshot 讀記憶體 tail、限定 2048-byte，無 lazy owner bind、log read、notification、cancel；回報 processTreeState unknown。capture cwd 失敗使 optional Monitor unavailable，不改原 Shell submission 成敗。
5. Subagents `BackgroundJobs.get` 的 provisional-safe view 是 projection 的來源；不直接讀 private internal result map、不送 query／message 或請求模型。ready query 仍 provisional 時隱去答案、完成／lease release 假象；新 regression 直接建立此情境。
6. Subagents `index.ts:1206` 與 `:1211` 在 shutdown/replacement await 前 revoke；publication 排除 explicit managed child。未見 Monitor 修改 child argument builder、`--exclude-tools subagent`、guard 或原 concurrency/backpressure 契約。
7. Monitor boundary 在 acceptance 前 acquire 並 snapshot；停止 observation 解除取樣 timer，不取消被觀察 job。workspace 真實 host fixture 以既有 status/native completion barriers 證明兩種 job 不被 cancel，涵蓋兩種載入順序。
