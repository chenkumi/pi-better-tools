## Warnings (should fix)
### F1 — P2：背景 Observer 仍傳送 context-edit 已省略／替換的 raw 內容
- 位置：`modules/blackhole/src/om/consolidation.ts:898–957`；傳送點 `1266–1284`。
- 觸發：memory 開啟、Observer 到期且 cursor 後的 source 有目前有效 null／replacement edit。`getBranch()` 取 raw 歷史，`sourceEntriesAfter()` 只過濾 entry type，serializer 不套用 edits。
- 影響：原生主模型已不可見的文字仍進背景模型；replacement 傳舊內容而非新內容。即使後續 compaction 過濾衍生 observation，也無法撤回已送出的 worker input；另浪費已省略嘗試的 token。
- 證據：`serialize.ts:148–163,191–205` 直接讀 raw message/custom content；`progress.ts:16–20,120–124` 同樣計 raw tokens。本機 Pi `session-manager.ts:519–539,550–564` 明確 last-wins null omission／replacement。既有測試 `pi-owned-review.test.ts:55–65` 只驗 compaction，不驗 Observer prompt。
- 建議：背景來源套用相同 eligible edit window 的有效內容投影，保留真實 source ID／coverage 邊界；加入 mock worker 捕獲 prompt 的 null／replacement／inactive-edit 測試。歷史來源不在 native window 不應一概視為 redaction。
- 確定性：raw payload 路徑由靜態程式支持；實際 provider 送達／費用未測。

### F2 — P2：索引 cache 命中仍全量組字串，使批次查找成二次成本
- 位置：`modules/blackhole/src/om/ledger/progress.ts:31–45`；實際批次 caller `src/om/consolidation.ts:263–277`。
- 觸發：manual pending 有 m 個 observation batches、branch 有 n 個 entries；每個 batch 以 `entryIndexForId()` 查 coverage。
- 影響：即使 Map 命中，每次仍執行 `entries.map(...).join(',')`，同一固定 snapshot 共 O(m·n) 掃描／字串配置；m 隨歷史增長時為二次成本，阻塞同步事件迴圈與 abort 回應。
- 證據：caller 的 batch loop 每次回到完整 idsKey 建構；不是假設 Map lookup 本身慢，也不依赖損壞資料。
- 建議：每個 snapshot 一次建 Map，批次函式直接重用；或採具明確失效語意的 snapshot cache，勿每次查找重算全歷史 key。新增無 sleep 的操作次數／固定 snapshot 測試。
- 確定性：複雜度由迴圈支持；未測實際延遲／heap 峰值。

## Suggestions (consider)
### F3 — P3：native identity 命中仍預先序列化所有候選 payload
- 位置：`modules/blackhole/src/core/native-compaction-input.ts:29–40`；caller `src/hooks/before-compact.ts:400–402`。
- 觸發：native preparation 與 projection 共用 message 物件（一般未編輯 message 即符合），window 含大型 image／tool payload。
- 影響：所有候選仍被 `JSON.stringify()` 並以完整字串作 Map key，包括沒有被摘要的 retained tail；exact identity 成功也支付 O(整個 window payload) 同步成本與額外字串記憶體。
- 證據：第 34 行無條件序列化，直到第 39 行才檢查唯一 identity。這是可避免成本，不宣稱已發生 OOM／資料遺失。
- 建議：先解析 exact identities，只為未解析項建立必要的 equality fallback，保持 ambiguous ID fail-closed；用捕獲序列化次數的最小測試驗證。
