# MXC 1.0 包裝 Pi shell：Windows 實測結果

測試日期：2026-10-11（本機 UTC+08:00）。

## 結論

**部分可行，不能視為已完整滿足需求或正式啟用。**

- 本機 MXC BaseContainer 能限制 PowerShell 子行程及其工具的 host 檔案寫入；指定 workspace／真實 ~/.pi fixture 讀寫成功，外部 fixture 寫入及 junction 繞行皆被拒絕。
- 但是 MXC／OS 自動提供額外可寫的 sandbox 私有 TEMP／LOCALAPPDATA，因此字面上的「只有 ./ 與 ~/.pi 可寫」未成立。
- Git Bash 在 sandbox 內初始化失敗（0xC0000142），host 對照正常。PowerShell 5.1／7 在 ui.disable:false 下可啟動。
- Git、Node、Python、rg 的基本實際操作通過；npm 僅部分相容：tarball 安裝與 scripts 通過，file:目錄依賴 symlink 被拒絕。Windows PowerShell 5.1 的 npm.ps1 在 sandbox 發生 AuthorizationManager 錯誤，npm.cmd 的 tarball 流程可通過。
- Lazy shell wrapper 不呈現可辨識的 Pi 啟動劣化；整個 Pi sandbox 化的 RPC-ready 中位數由 7.066 秒升至 15.812 秒。
- 未修改 production shell 實作／manifest／dependencies／使用者全域 settings 或 auth；未呼叫 provider、付費模型、真實 credentials refresh。

## 政策與安全範圍

共同政策：version=1.0.0、containment=processcontainer、fallback.allowDaclMutation=false、telemetry.enabled=false。

- Read-write：C:/GitHub/pi-better-tools，以及 C:/Users/ChenKuanMing/.pi。
- Readonly 對照：僅目前可見磁碟根目錄，以及根目錄加各第一層一般目錄的展開版本。兩種版本都測試。
- 本機 --probe 選到 base-container，needsDaclAugmentation=false；debug 啟動亦顯示 PSEC 1.0 和 processmodel.dll。沒有採用會修改 host DACL 的 fallback。
- 初始預設 UI 政策下三種 shell 皆初始化失敗；改用 ui.disable:false 後 PowerShell 5.1／7 成功，Bash 仍失敗。額外 registryRead、完整 UI 放寬、workspace TEMP 變數的 Bash 對照仍失敗，未找到根因；不能把通用錯誤提示當作已證實的 Win32k 根因。
- 未新增網路放行；工具操作使用離線 fixture，Pi 使用 --offline 和 --no-mcp。不代表已測過 registry fetch、git clone、DNS 或 provider 網路相容性。
- Readonly 是寫入限制，不是秘密資料不可讀。尤其 ~/.pi 的完整讀寫範圍仍涵蓋 auth/settings；本測試只讀寫專用 fixture，不觸碰真正 auth/settings。

TEMP/TMP/LOCALAPPDATA 在 sandbox 中實際被導向：

`C:/Users/ChenKuanMing/AppData/Local/Packages/sandbox.{GUID}/AC[/Temp]`

因此前景 matrix 的程序退出碼是 2：harness 刻意將「預設 TEMP 應不可寫但實際可寫」標記為失敗；不能把 npm／git 成功當作整個權限 suite 通過。已抽查本次四個有 runtime-paths 證據的 private TEMP，在 executor 結束後都已不存在。這不是對所有 OS descendants／資源永久清理的保證。

上述是有限 fixture／路徑樣本，不是全磁碟每個 ACL、alternate stream、UNC、裝置、registry 或所有繞行方式的形式證明。

## Pi 啟動速度

### 方法

- 同機、循序、各組旋轉先後順序；每組排除一次暖身，其後各 7 個獨立 Pi 程序。
- 起點：spawn 呼叫前；終點：stdin 預先送入 get_state，收到 success:true 的 RPC response。
- 再送 get_commands，確認 mxc-check 存在；關閉 stdin，等 Pi orderly shutdown。以下 21 次有效樣本全都退出 0、stderr 空白。
- 隔離 HOME／USERPROFILE／PI_CODING_AGENT_DIR；auth.json 為空、Blackhole passive、offline、no-session、no-mcp、禁 skills/prompts/context discovery。
- 掛載本專案 package。為避免同名 tools 衝突，僅在隔離 settings 的 package filter 排除原 shell-tools 入口，再由實驗 extension 呼叫同一原 shell factory。其餘 package entries 仍載入。未改真實 package 掛載設定。
- baseline：原 shell factory；lazy-shell：同一 factory 的 foreground shell execute 改走 native MXC；whole-pi：Pi Node 程序直接由 MXC 啟動。
- Lazy wrapper 在 factory 階段不建立 sandbox，直到 shell execute 才 spawn executor。
- RPC benchmark 的 extension SHA token 為 6cf9f896204f1310d8739b9e09243700；其後僅修正觀測命令的工具呼叫方式／保存 definitions。不是對完整開機冷快取的 benchmark。

### 結果（毫秒）

| 組別 | n | min | median | max |
|---|---:|---:|---:|---:|
| baseline Pi | 7 | 6444.961 | 7065.697 | 7918.355 |
| lazy shell wrapper Pi | 7 | 6588.914 | 7050.289 | 8758.428 |
| whole Pi sandbox | 7 | 14602.073 | 15811.966 | 21206.944 |

Lazy-shell 與 baseline 中位數相差 -15.408ms，落在觀測變動範圍內，不是已證明 sandbox 更快。Whole-Pi 比 baseline 增加 8746.268ms／123.785%，約 2.24 倍。此數字包含整個 package 載入及 sandbox 私有環境效果，不可當作純 MXC 建立容器 CPU 成本；也未隔離造成差異的每個因素。

另外 PowerShell 7 空指令，排除暖身後各 9 次，baseline 中位數 670.815ms，MXC 中位數 954.868ms，增加 284.053ms／42.344%。這是 shell 完整啟動／執行／退出時間，而非單獨 syscall overhead。

## PTY／Pi 實際觀測

使用 PTY 啟動 Pi 1.1.0，載入隔離掛載設定和實驗 extension，完成 /reload 與 /mxc-check。

- Sandbox tool definition：Bash 回 isError:true、exit_code=3221225794；PowerShell 回 MXC_PI_POWERSHELL_OK、exit_code=0。
- Host baseline：Bash／PowerShell 均退出 0。
- 是已載入 Pi 的 registered definition 前景執行；沒有 provider/model tool-call 交談，也沒有聲稱涵蓋全 tool dispatcher pipeline。
- 初版觀測命令錯將 command context 當 tool context 使用 ctx.executeTool，實際 TypeError；已修正為保留 registered definitions、以當前 command/session context 呼叫其 execute，再 /reload 得到上述結果。
- TUI 可啟動／reload，但 PTY readAfterMs 不是啟動計時；性能表只報 RPC-ready，不報假的 TUI-ready 精準時間。
- 兩個 PTY 都 /quit，pty_wait_exit 確認 exitCode=0。

## 清理、驗證分組與剩餘事項

- 已移除本次三個 ULID 專用真實 ~/.pi fixture、host TEMP readonly fixture，並解除 workspace junction；保留 workspace 測試產物供查閱。
- 沒有 production tracked source diff。原有未追蹤 NOTE.md 保持不動。
- 實際執行：native permission/tool matrix、host/sandbox 功能對照、RPC performance、PTY Pi 啟動/reload/definition probe。
- 未執行：npm test、typecheck、test:module、test:cross、test:integration、test:package、test:browser。理由：此任務沒有改 production module／manifest／scripts／dependencies；研究 runtime probe 才是驗證對象，無關全量 suites 不增加上述 Windows backend 的驗證。這些未執行項不算通過，實驗 TS 也未宣稱靜態型別檢查通過。
- 未完成：Git Bash 根因與解法；strict two-RW-path 政策（private TEMP 例外）；npm symlink／5.1 .ps1 相容性根因；網路依賴安裝；正式取消／background／managed subagent 整合。

建議先維持現有日常工具；若後續實作正式功能，應只以明確 opt-in 的 PowerShell foreground 原型開始，保留 fail-closed、既有 timeoutMs 和 process-tree 語意，不能在 MXC 失敗時默默回退 host。此建議基於本機有限實測，不是跨 Windows 版本支援承諾。
