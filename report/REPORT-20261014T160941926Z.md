## 尚待允許後重新設計／執行的精確邊界與驗收

以下只是尚未執行的驗證條件，不是結果或繞過限制的替代途徑。

1. 大小 admission：初始 1 byte，stat 後受控成長至 `50*1024*1024+1 = 52,428,801` bytes，觀察實際 read 返回配置量後拒絕；不刻意 OOM。修正驗收應在讀取上限加一時停止，不配置全個成長檔案，並驗證 mutation 不提交。
2. 行索引：`X + LF×N`，N = 1000／4000／16000，僅搜尋第 1 行、no-op edit；觀察真實 buildLineMap 的 append/entries 配置操作量，不能推稱實測 50 MiB OOM。修正驗收為明確 admission 或有界／稀疏索引，並涵蓋前置取消／預算。
3. aux：四個不同隔離 root，SDK scan deferred barrier，對真實 pool/factory 觀察 pending/live；修正驗收 pending+live 不超過 3，失敗和晚到清理不漏 ownership。
4. shutdown：真實 pool/factory 及 extension 註冊的 lifecycle handlers，pending scan → shutdown → resolve；minimal API harness 不等於 Pi AgentSession。修正驗收晚到 finder destroy 且不發布，另需真實 host 覆核。
5. native find：只在自有 disposable 600 檔案索引測試，檔名含 145 個填充字元；pageSize 30／300／600／1000000，小索引觀察實際 native clamp 與工具輸出，不外推任意索引。native 無法載入則保持 blocked；修正驗收 page 整數上限、format byte budget 及正確 continuation。
6. SDK cache：受控 resolver 邊界讓兩 SDK 暫不可用後恢復，import 真實 loadSdk 並重新載入模組。須分辨 jiti module recovery 與原生 ESM 負面 cache；修正驗收 rejected promise 自兩個 cache 以 identity guard 清除、成功 cache 保持，且明確 reload 可恢復。
