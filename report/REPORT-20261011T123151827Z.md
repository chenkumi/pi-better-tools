## P1：優先處理

### R1 — 大量短行 edit 已提交，成功 feedback 才拋 RangeError

- **位置**：`modules/file-tools/src/file-operations.ts:1587`；commit 在 `1538`；`modules/file-tools/extensions/file-tools.ts:638–640`。
- **原因**：`compactPatch()` 先 `out.push(...body)`，之後才切40行；byte cap不限制spread的argument count。registered edit先完成atomicWrite，再呼叫formatter，且同一patch格式化两次。
- **重現證據**：原始compactPatch對200000短行、600021-byte patch拋 `RangeError: Maximum call stack size exceeded`。另在隔離目錄執行原始editTextFile插入200000行：磁碟已變為400001 bytes，實際patch為600058 bytes，sha256After為`16fe590dd656a154e9476ab23bb97996`；緊接原始formatEditSuccessFeedback再拋同一RangeError。child exit0表示對上述缺陷的觀察assertion成立，**不是產品回歸測試通過**。
- **影響**：修改成功卻回報工具錯誤，模型可能重試並失去成功hash／結果。
- **最小修正**：不spread無line-count上限body；在formatter內邊統計邊保留有限行，重用單次format結果。成功feedback不得在commit後因合法有界輸入失敗。
- **界線**：已跑actualedit＋actualformatter，順序與註冊tool一致；未跑真實模型／agent tool dispatch。

### R2 — required property有default，缺少它的原始JSON仍被接受

- **位置**：`modules/json-schema/src/schema.ts:121–141`；recovery交付 `extensions/json-schema.ts:154–157,215–218`；worker等效路徑 `src/validation-worker.mjs:10–14`。
- **重現**：schema `{type:'object',properties:{a:{type:'string',default:'x'}},required:['a']}`，原始候選`{}`；原始compileSchema.validate返回undefined（接受），且input保持`{}`。
- **原因／影響**：Zoddefault改變驗證結果，模組只看success卻交付未轉換的input，於recovery／extraction送出違反required的JSON。不是聲稱所有Pi直接toolcalls均能穿透host驗證。
- **最小修正**：validator compilation在schema positions排除default annotation的填值語意，worker相同；不可誤刪enum／const內instance data，也不要默默改交付原始資料。
- **證據等級**：本地同步validator已動態重現；worker／完整recovery仍待對應回歸。

### R3 — $ref同層限制被忽略

- **位置**：`modules/json-schema/src/schema.ts:57–60,80–82,121`。
- **重現**：明示draft2020-12，property `a:{$ref:'#/$defs/s',type:'string',minLength:3}`，s為string；原始validator接受`{a:'x'}`。
- **原因／影響**：audit允許siblingconstraints，但本機Zodref分支early-return，不套用minLength；recovery交付的schema-valid聲明不成立。
- **最小修正**：最小範圍先在audit拒絕converter不能忠實驗證的ref siblings，提示explicit-type allOf；如支援intersection，另處理draft與reference-cycle語意。
- **證據等級**：本地validator已重現；未執行worker／完整recovery／Pi直接argument-validator比較。

### R4 — POSIX回收已退出PTY仍對旧PID發SIGHUP

- **位置**：`modules/pty-terminal/src/pty-manager.ts:212–215,448–470`；reclaim觸發 `218–228`；已安裝UnixTerminal `node_modules/node-pty/lib/unixTerminal.js:228–233`。
- **原因**：dispose無條件kill；UnixTerminal.kill直接process.kill(pid)，不是單純handle-release。OS可能在保留期間重用已退出PID。
- **重現**：隔離child以fakebackend＋模擬POSIXplatform執行原始manager；emit exit後呼叫manager.kill，fakebackend仍收到`SIGHUP`且結果released:true。
- **影響**：在POSIX若PID被重用且權限允許，可誤終止無關程序。
- **最小修正**：已確認exited的POSIXsession不再signal PID；Windows native handle-release另保留其實際需求。
- **界線**：**沒有啟動真實PTY或製造真實PIDreuse，也非Linux實機測試**。signal-after-exit分支已重現，誤殺影響為平台／PIDreuse條件推論。

### R5 — Recall原生backtracking regex可阻塞主event loop

- **位置**：`modules/blackhole/src/core/search-entries.ts:65–70,90–91,538–602`；tool caller `tools/recall.ts:502–503,570–571`。
- **原因**：safeRegex只catch語法錯誤；輸出cap在同步nativeRegExp匹配之後，signal不能打斷執行中的main-threadregex。
- **重現／量測**：原始searchEntriesDetailed、一則user訊息`'a'.repeat(n)+'!'`、query`(a+)+$`，warmup後n=20/22/24耗時 **28.37／110.63／442.98ms**。每多2個字元約4倍成本；這是隔離child／當機器量測，不是跨平台固定時間。
- **影響**：很短輸入即可帶來快速放大的CPU停頓，阻塞TUI／abort／其他callback。
- **最小修正**：安全patternadmission或將完整regex匹配移至可終止、有queue/inputlimits的worker。僅try/catch或加AbortSignal無效。
- **界線**：外部15秒safetydeadline未觸發；沒有在真實sessionhistory或主Piprocess執行危險pattern。

### R6 — stale-lock contender可移走另一contender的新live lock（尚未動態確認）

- **位置**：`modules/subagents/extensions/subagent/session-store.ts:331–353`，stalecheck `272–278`。
- **具體交錯**：A/B都已判舊lockstale → A rename並建live replacement → B繼續用舊判斷rename來源pathname，移走A的新lock → B建立自己lock並rollback。unique stale destination不提供跨contenderelection。
- **影響**：可能在Achild寫入時被Btruncate nativecheckpoint。後續A fail-closed不能撤銷truncate。
- **最小修正**：所有acquire/querylease都尊重短期跨processrecovery fence，在fence內核對identity再接管；單純多讀一次nonce仍存在check-to-renamegap。
- **證據等級**：静態交錯可達；**未執行跨processbarrierrepro，不能稱已觀察nativecorruption**。建議優先先寫deterministic regression確認。
