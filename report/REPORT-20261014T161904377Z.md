## 逐項結果、影響邊界與修正驗收

### F1-menu — confirmed

位置：`modules/schedule-prompt/src/ui/jobs-menu.ts:63–85`。重現 source：`recheck.test.ts:54–69`。三次正式均 passed，對應各 raw log 的 `EVIDENCE F1-menu confirmed`，exit 全為 0。

順序：實際 menu 顯示 A → confirm Promise barrier 明確暫停 → peer 真實鎖內將 command/cwd 改為 B／project 子目錄 → resolve(true) → 真實 store 保存 enabled B → fake clock 前進 1000ms → 真實 interval scheduler 重新讀 store，record-only backend 收到 B 與 peer cwd，runCount=1/success。不是只對 update mock 的參數作斷言。

boundary：已能寫入 trusted project store 的 peer，在同一 UI 確認窗口改動 execution spec；使用者批准 A，實際啟用／派送 B。此例 B cwd 在專案內，因此 fire 不需要 outside approval。不是宣稱任意遠端使用者可突破 project trust。menu 先批准 A，不能防止鎖內保存 B。

修正驗收：確認 spec/session 必須鎖內重新比較；不同就拒絕且不批准／啟用／排程 replacement。保留 peer bytes、完整重問目前 spec；批准與 scheduler 使用實際成功保存版本。加入 no-peer 正常 enable control。

### F4 — confirmed（產品 scheduler callback 邊界；真實 backend/OS 層 blocked）

位置：`modules/schedule-prompt/src/scheduler.ts:874–916`，尤其 `arm/onData :881–888` 與 finally `:912–915`；真實 backend listener 契約對照 `modules/shell-tools/src/monitor-exec.ts:54–70`。重現 source：`recheck.test.ts:120–136`。三次正式均 passed，`EVIDENCE F4 confirmed`，exit 全 0。

實際 interval 啟動 → backend started barrier 後保留完成 Promise/callbacks → stop() abort → fake clock 前進 5000ms → drain 回報 `{pending:0,cleanupFailures:[]}` 且 timers=0 → 直接送 backend 已持有的真實 stdout callback → timers=1 → 前進59999ms仍=1 → stderr callback 再 arm=1。最後為 fixture 清理 resolve backend 並精確前進60000ms，timers 回0。

boundary：取消後 callback 的本地生命週期 gate 缺失；不是以「取消不保證 process tree 停止」推導出的未驗證發現。仍未證明 Pi1.2.0 backend/OS 上必定可產生該 late event，因 backend 被替身化且本機 host 不合規。沒有宣稱 pending=0 表示 descendants cleanup。

修正驗收：settled 後 stdout/stderr/started 不得改 tail 或 arm；drain 後所有 late callbacks 應維持 timer=0。backend 若提供 detach/drain API，需另以 1.2.0＋可控 child streams 驗 listener cleanup，不能把 timeout abandonment 等同 child close／tree stopped。
