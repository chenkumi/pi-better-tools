# File Audit 真實 PTY TUI A/B 與 token overhead 結果

## 結論

在本次隔離 Pi 1.3.0、真實 node-pty TUI、相同腳本與工具配置下，**掛載 File Audit 的估計額外輸入 tokens=0、額外模型請求=0**。B 組的手動 check 能在真正畫面中定位預植入的 provenance mismatch，A 組沒有對應命令或報告，但兩組檔案操作結果相同。

這驗證它是低 context 成本的人工收尾診斷工具，不是自動改善模型解題品質的機制。沒有呼叫真實付費 provider，不能把估值說成真實 API 帳單或所有正式情境永遠零成本。

## 測試設計

- A：`--no-extensions`，明確載入相同 test observer、File Tools、Note Tools；不掛載 File Audit。
- B：其他條件同 A，再明確 `-e modules/file-audit/src/index.ts`。既有選取方式已是開關，未新增 setting。
- regular 模式 A→B；fullscreen 模式 B→A，最終共4個真實 CLI／PTY，獨立 home、agentDir、cwd、空 auth 與最小 OS environment allowlist。
- 不使用 print/RPC 或假 UI 取代 TUI。測試透過 PTY 打字輸入 prompt／slash commands；通知 observer 仍呼叫原本 notify，驗證實際 regular render／fullscreen getScreenLines 及 PTY raw output。
- 檔案 watch、agent_settled、notification、snapshot 作同步證據；不以固定 sleep 判定成功。owned CLI 必須實際退出0並有 shutdown 記錄；成功後刪除工作目錄。
- 合成 provider 執行相同 read/read/edit/note/失敗 read、follow-up、三次 write 與空操作，合計每 arm 12次串流請求。fetch 在隔離 fixture 中禁止；最終 A/B 外部模型／network calls=0。

## 功能差異

| 案例 | A：未掛載 | B：掛載 |
| --- | --- | --- |
| read seed、read control、再 edit seed | 同樣完成檔案操作 | 去重後2檔，seed 呈現 modified |
| note 新增 task | 成功產生文件 | 實際產生路徑納入 created，共3檔 |
| read missing | 明確失敗 | 同樣失敗，不納入候選 |
| 手動增量 check | 無本命令／報告 | mismatch=1、matched=1、untracked=1 |
| 已植入 seed 雜湊不符 | 無 File Audit 專屬診斷 | 兩模式均顯示 mismatch: seed.txt |
| control 保持原內容 | 未提供專屬 hash 診斷 | matched=1 |
| note 沒有 provenance | 文件存在 | untracked=1，不假裝通過 |
| 容量設2後新增3檔 | 正常寫入，無追蹤器 | 真正保留 beta/gamma 共2檔，capacity淘汰事件4次 |
| window=1 後下一 run | 正常回應 | 候選變0，expired事件2次 |
| check 後下一個模型請求 | 正常 context | 沒有報告注入，與A正規化 payload一致 |

每次 check 只讀候選內容14 bytes、metadata302 bytes；最終 regular12ms、fullscreen14ms，兩次平均13ms。這是微型 fixture 的觀測值，不是穩定速度 benchmark，也不是啟用追蹤後 CPU／記憶體 overhead 的完整量測。預植入 mismatch 是 provenance 遺漏，不等同發現程式邏輯 bug。

## Token 與請求統計（最終正式分組）

| 模式／順序 | A請求 | B請求 | A原始序列化輸入估值 | B原始序列化輸入估值 | B−A |
| --- | ---: | ---: | ---: | ---: | ---: |
| regular／A→B | 12 | 12 | 34,946 | 34,946 | 0 |
| fullscreen／B→A | 12 | 12 | 34,946 | 34,946 | 0 |
| 合計 | 24 | 24 | 69,892 | 69,892 | 0 |

- paired delta為[0,0]，平均0 tokens，樣本內增幅0%。樣本只有兩對，不提供統計顯著性、信賴區間或跨模型泛化。
- tokenizer：隔離安裝 `js-tiktoken@1.0.21`，使用 `o200k_base`。沒有新增根依賴、runtime dependency 或修改全域設定。
- Pi 1.3.0 prompt/tool deltas 原本就在 transcript system messages。fixture 使用 `getCurrentSystemPrompt/getCurrentTools` 還原一次，建立包含 systemPrompt/tools/messages 的明確語意 payload，等待 onPayload hooks 後保存；完整未改寫 transcript 另存。
- 原始估值含實際隔離路徑與 note 檔名；正規化只替換受控 home/root 與 note UTC 檔名。正規化後每 arm 34,618 estimated tokens、12個 payload共144,603 bytes；每對逐次SHA256相同，而且跨兩種TUI模式也相同。未移除 File Audit 文字來製造相等。
- baseline/status/check/snapshot 前後 request count 同為6；後續同一 follow-up 為第7次，確認不是只在當下不觸發模型，卻把報告延後塞進 context。
- **這些數字是序列化語意輸入的 tokenizer estimates，不是實際 OpenAI Responses framing、任何 provider 的 reported usage、cacheRead/cacheWrite、帳單或輸出 tokens。** 合成 usage 固定0且未用於 token 統計。
- 統計對象是受測子 Pi 的執行，不含本次開發測試對話、安裝／閱讀專案文件或 AGENTS.md 文件變更本身的 tokens。隔離 A/B 刻意停用 context files/skills 與其他不相關 extensions；不把結果泛化成完整正式配置的全成本認證。
