### 真實執行與 assert

1. 真正 1.2.0 DefaultResourceLoader 載入薄 probe extension。Probe 直接 import 當前產品 BackgroundJobs，不重写計數器或 capacity checks。
2. 真正 AgentSession 綁定 extension。產品 submitManaged 受理 32 submitted，prepare boundary 開啟自己 temporary root 的真實 FileHandle，等待 deferred write barrier；同 generation 新加一 task 被真正產品 BACKGROUND_CAPACITY 拒絕。
3. 呼叫 **真正 `session.reload()`**。Host 發出 shutdown、清 resource cache、重新 Jiti evaluation、重新綁定 extension；assert 舊 shutdown hook 呼叫一次、舊 prepare caller 被取消、actual I/O 尚未 settlement、舊 load 仍 32/32。
4. Host 新 evaluation 的 BackgroundJobs class identity 不同，不是人工 import query string。新 owner 的 load 實際為 0/32。
5. 預期：舊 32 ownership 尚存，新 32-task preparation 應被拒絕。實際：產品新 submitManaged 的 prepare 已進入，另開自己的真正 FileHandle 並等待新 barrier；同 process 舊 load 32/32＋新 load 32/32，合計 owned admission **64**。
6. 兩代 actual settlement 均為 false、runner 及 provider calls 都是 0；三次都相同。
7. 取消新 owner、釋放兩個 write barriers，完成真正 write/close，await 在 shutdown 清 registry 前捕捉的**真正產品 job.done**。兩代 load 回 0/32，再拆自己的 roots。

### Boundary、影響與未擴大之處

- Probe 自建產品 admission owner，並由真實 host reload 管理其生命周期；不是完整公開 subagent tool 派遣／背景 journal integration，也沒有啟動 64 個 child。
- Prepare 的外部 managed allocation 用可控 boundary 代替；確實保留兩個真實 FileHandle／deferred I/O。32／64 是 **task admission ownership**，不是聲稱有 64 個 OS handles。
- Probe shutdown hook 對真正 `BackgroundJobs.shutdown(waitMs)` 傳 **0**，縮短等待預算，避免固定 15 秒 sleep/idle probe。沒有 mock shutdown、计數器、prepare cancellation 或 settlement；未宣稱實際等待產品預設 15 秒。所證明的是 bounded shutdown 返回後仍 owned 的計數跨真實 reload 不共用。
- 直接觀察 actual job.done 僅供 cleanup，不改 pending promise／產品邏輯。首次探索發現重複 shutdown 不能代替已清 registry 的 actual done，已在 probe 修正，不改產品。
- 本次動態確認 **32 submitted 跨 reload 上限可突破**；未啟動 8 active children／8 active queries，不把那兩個延伸 budgets 的靜態形狀也列為已動態確認。

### 修正驗收

真正 process-wide admission owner 應跨 module evaluation 保留尚 owned 的計數。以同一實際 1.2.0 reload＋deferred actual I/O 場景，舊 32 尚未 settlement 時，新 prepare 不得進入；actual close/job.done 後才恢復名額。保留通知/generation 隔離，不復活舊 registry；active child/query budgets 如要納入同修正，另補各自真實 resource barrier 回歸。預設 15 秒 shutdown 可以用受控 clock 驗證，不靠 wall-clock sleep。
