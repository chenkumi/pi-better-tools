#### 建議最小修法：只動 runner-io test／test-local fixture 的 timer seam
1. runner setup 使用 `SUBAGENT_IO_TIMEOUT_MS`（300000）或省略 ioTimeoutMs，保持全部真實配置、allocate／acquire／begin 與非目標 I/O。不要 mock metadata sync、ManagedSession lock 或 ownership outcome。
2. 只在 test-local 以 `t.mock.method(IoGate.prototype, "run", ...)` 做觀測 wrapper：原樣以原 this／operation／label 呼叫原方法，立即 return 原 promise。wrapper 的同步呼叫區間標記 gate／label，讓 test-local global setTimeout mock 辨識這一次真實 IoGate.run 於 `io-gate.ts:50` 建立的 timer。不能改寫 run 的 pending／waiting／stop／whenIdle，不能吞 rejection，不能用 Promise.race 取代原 gate。
3. 所有 timer 起初仍以 300000 排程。既有受阻 mock 在執行原 `entered.resolve()` 前，以 operation-specific barrier 通知 seam；確認 mode、label 及唯一尚未清除的 timer token，再把該 timer 的同一原 callback 改排為 300ms。這樣 create／finalize／read 在到達指定阻塞前的真實 I/O 仍享 production budget，不是只對整個 finalization 提早縮短。
4. 因真實 IoGate closure 保有舊 token，test-local clearTimeout mock 必須將它映射到重排 token，且清理舊 timer。完成、abort 或 restore 都必須真正清掉替代 timer；若 token 已被清除，不得再次 arm。原 callback 呼叫原 gate.stop，因此 pending、late completion 與 whenIdle 全保留。呼叫原 timer 函式避免 mock 遞迴；不使用完整 fake clock 去推動真實 FS／child／inactivity。
5. wrapper 的同步 scope 要以 try/finally 還原；每 test 自有 token map／selection，非目標計時器原樣 passthrough。不可僅依 delay===300000 全域縮短，不可在 entered 後切換所有後續 gate，不可替換 gate instance 或碰 private timeoutMs。`run` 的 timer 建立早於 operation microtask；writer append 與 abandon 亦經 promise chain（`subsession-log.ts:415–428,435–452`），目前可在受阻 barrier 前捕捉原 timer。這是當前實作的 seam coupling，須用 assertion 檢查，不以假設略過。
6. 不直接手動 gate.stop 模擬 deadline；必須由捕捉的原 timeout callback 自然觸發。錯誤文字會仍說 300000ms（closure 使用 production timeoutMs），報告應明示這是 test scheduling seam，不修改產品文字或以 assertion 假裝真的等了五分鐘；現有測試只 match stalled，不依賴數字。
