## CP2：helper ownership teardown

- genuine deterministic red：原 runner helper 只等 prompt deletion，而且 invocation 前取消沒有 taskPath；測試在實際 `owner.json.*.partial` FileHandle.writeFile 上放 deferred barrier，取消 request，root rm 時檢查 actual write／late managed release 尚未完成。原 helper 確實觸發重疊斷言。
- red path 不實際刪除進行中 I/O 的 root；釋放自己的注入 barrier、等實際 managed release，再清理測試 root。
- runner 新增內部 `onOwnedSettlement` observation seam，包含 actual child close、I/O gates idle、spool iterator return、late managed cleanup、prompt cleanup／writer abandonment barrier。不改 ownership election 或 writer lock 釋放規則。helper 等該 barrier，不再靠 prompt deletion timer 或 blind rm retries。
- `createPromptFiles` 只增加内部 cleanup settlement observation，讓 invocation 前取消／晚到 prompt cleanup 也可被 helper 看見，不改儲存格式。
- parent abort precedence 的 status／stopReason／非 timeout 診斷斷言保留，改用 onLiveLog 事件取消，而不是 50ms timer。
- 既有四種 actual close rejection 測試與 late acquire 測試重跑通過；故意保留 live lock，原測試 finally 仍先等注入實際 FileHandle.close 完成才拆測試 root。
- **沒有證明 production premature release，沒有關閉所有歷史 EPERM／ENOTEMPTY 根因。**
