## S5：檢查點策略與同步 fault coverage

### 實作檢查順序

`lstat → readonly open（平台有時 O_NOFOLLOW）→ fstat → raw read → post-read fstat → post-read lstat → close`。

每個 stat 觀測須是 matching owned regular/non-symlink file、相同 bigint dev／ino、size 等於 expected Buffer 長度；mtimeNs／ctimeNs 必須為 bigint，且 lstat／descriptor pre-read、descriptor pre/post-read、descriptor post-read／post-path 的觀測值相等。缺少必要 metadata 不使用弱數值或 identity fallback。所有正常已開啟驗證 fd 在 finally close。

### 24 個同步單元：12 faults × initial-validation／reload

- lstat→open：實際 path replacement、symlink metadata（含 descriptor 可 open 的模擬）、observed metadata change、必要 metadata unavailable。
- open→fstat：實際打開等長 foreign receipt descriptor，拒絕 descriptor identity mismatch。
- fstat→read：實際 path replacement。
- read→post-check：symlink metadata、實際 append size mutation、同 size raw content mutation＋明確觀測到 timestamp delta、純 metadata delta、post-read metadata unavailable。
- post-path-check：查詢後置 lstat 前的實際 path replacement。

Symlink／metadata 使用同步 fault injection，timestamp delta 基於保存的前置 snapshot＋1n，**不依賴 OS clock resolution、sleep 或延長 timeout**；實際 replacement／descriptor／raw writes 發生在隔離 temp directory。Symlink metadata 不是需要 Windows 權限的實際 OS symlink probe。

斷言保留：fault phase 真正觸發；readonly validation 的 verifier write count 為 0（initial 合法 exclusive write 僅 1）；所有已開啟 readonly fd 已 close；原始或變造 evidence 未被 verifier 覆寫。Failed initial validation 後，測試還原原 inode／bytes 作控制，再用同 object 必須 EEXIST，證明沒有偷偷取得 lease；reload 還原後原合法 lease 可再次精確驗證，fresh object 永遠無 ownership。這些還原是 fixture cleanup/control，不是 production 自動修復。

首輪 targeted 82 pass／2 fail、exit 1 的完整 log 保留於 `plan/evidence/child-shell-bytes-targeted-attempt.log`：兩個 append case 的注入者 `appendFileSync` 會委派到 exported `writeFileSync` spy，誤算成 verifier writes。修正為捕捉原 fs fd primitives 進行注入者 append；**未放寬 no-write／no-lease／close 斷言**。最終 84/84 green。

### 精確邊界（亦已更新兩 README）

這是離散檢查點觀測，不是 atomic file snapshot、filesystem lock 或永久禁止外部修改。不能證明兩點間每一瞬間均未變、瞬時修改再還原一定被觀測、或最終 check 後不再修改。固定 expected size 是**accepted-file size check**；`readFileSync` 本身沒有並行增長時的 hard read-allocation cap，本次不宣稱有該上限。沒有降低 inode／metadata 需求來換平台 green。此說明取代前一 handoff 中可能被理解成「整段讀取期間原子穩定」的措辭。
