## 父決策問題（精確）

### Q1：新限縮 request-admission capability

是否核准在現有 captured-owning-session adapter 中串接 **public Agent.prepareRequest + non-throwing guarded Agent.streamFunction**，僅 pinned Pi 1.1.0已確認contract，不新增 private _checkCompaction/_runAutoCompaction patch？

推薦准許但要真 host red/green驗證。prepareRequest保留previous chain／physical route／reservation後，依完整工具配對與owner/session/branch/generation/signal做inline compact，回更新context给同一loop。最後streamguard對已transform的真實system/tools/input/model/outputreserve作fail-closed拒絕，以合規errorstream而非throw，不先呼叫original provider，不重播contexthandlers／Runtimeadmission。Unknown shapes/selection mismatch明確拒絕，不做after-final fallback。需另測stop/refusal是否被native retry/overflow/Runtime誤恢復。

如果不核准此 capability，推薦先取得host public extension request-admission接口，而不是交付看似before-request、失敗仍送出的public-event方案。此phase尚未實測上述adapter，不能宣稱可行性已green。

### Q2：實際採用與config衝突

是否批准在實作及review後由父建立repo-local `.pi/pi-blackhole-config.json` 的最小override：

```json
{
  "compaction": "auto",
  "compactionEngine": "blackhole",
  "compactionTiming": "before-request",
  "midRunCompaction": "resume"
}
```

不改個人global、不變numeric threshold/ratio/reserve、memory、retention或display。新timing提案default legacy兼容舊格式；新mode要求explicit resume，off/pause不能被默默忽略；pi-default尚需選擇限縮unsupported/reject或另設計支持，不默默改engine。manual/off保留明確模式及手動ownership。請父確認這個mode-conflict policy。

唯讀確認此repo projectconfig檔目前不存在，未寫入。`loadUnifiedConfig:756–899` 已確認global unified/legacy → projectfile shallow merge → parse/migrate/defaults → passive/explicit env優先；四個scalar override有效但不能勝過env。Runtime ensureConfig cached，需正確reload；session UI precedence仍待追完後才聲稱全鏈證實。不能僅增加未選timing設定後宣稱用戶已採用。
