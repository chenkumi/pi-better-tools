## Critical (must fix)

### C1 — 必須先鎖定部署契約；「只有來源 A 載入」不能實現 B 的 reload 全域取消

- `plan/PLAN-20261013T035455648Z.md:44–45,55–56` 要求 process-owned registry、跨 cwd，以及每個受支援 session 載入管理 extension，且禁止暗中啟用被排除的 extension。這不是靠 registry 單獨可以解決的需求。
- `P/dist/core/agent-session-runtime.js:102–113,128–145`：A→B 時先 abort A、await A 的 shutdown、dispose A，之後才為 B 的 cwd 建立 runtime。`147–172` 的 new 與 `174–249` 的原生 fork 同樣建立新 runtime。
- `P/dist/core/agent-session-services.js:62–69`：每次服務建立都建立新的 DefaultResourceLoader，再 reload。不是保留 A 的 extension runner。
- `P/dist/core/agent-session.js:2936–2968`：reload 只發給「目前」oldRunner；`P/dist/core/agent-session-runtime.js:296–303` 的 quit 同樣只通知目前 session 的 runner。兩者不搜尋曾載入的 A extension。
- `P/dist/core/resource-loader.js:375–408`：僅載入 enabled extension paths；`noExtensions` 只保留明確 CLI paths。`P/dist/core/package-manager.js:1412–1431` 和 `P/docs/packages.md:123–127`：project package 能替換 personal package；因此僅 global install 也不等於任意 project 永不排除。
- `P/dist/core/extensions/types.d.ts:1162–1383` 的 ExtensionAPI 沒有取得 CLI 所持 AgentSessionRuntime、加入 process shutdown/reload observer、預覽下一個 runtime 的最終 enabled extensions，或保證自己在所有 future sessions 載入的 API。`resources_discover` 也只提供 skill/prompt/theme paths（`538–549`），不是 extension 自動載入後門。

**具體失敗路徑**：A 接受 Fork → A→B 後 A API 已失效 → B 未載入 manager → B `/reload` 不會通知 manager → Fork 仍活著。Node process exit hook 或 child IPC EOF 只能幫助真正退出，不能偵測 parent 仍活著的 B reload。保留 A 的 pi.events 或 A.shutdown callback 不能補洞。

**最小可行決策**：明確規定受支援 CLI invocation 必須由使用者選取同一管理入口，例如明確 `-e` 的絕對入口；原生 CLI 會把啟動時已解析的 paths 帶入每次 runtime factory（`P/dist/main.js:583–587,628–642`）。`P/docs/cli.md:194–197` 說明 explicit -e 不受 noExtensions 的一般 discovery suppression 影響；這是明確選取，不是暗中繞過排除。必須完整驗證 package/CLI filters，不能由 module 自行追加 -e 來覆蓋使用者意圖。

若正式產品只靠可被目標 project 濾掉的 package entry，則本項仍 blocked。無載入 manager 的 session 不可宣稱受支援；如果需求仍包含它，需另行授權 host-owned lifecycle bridge／Pi API 變更，而不是私有 monkey-patch。不能以禁止所有 session switches 偷換跨 session 需求。

## Warnings (should fix)

### W1 — 裸 SDK dispose 不發 shutdown；應限制宿主契約，不可宣稱任意 SDK 都安全

- `P/dist/core/agent-session.js:992–1010`：`AgentSession.dispose()` 同步 abort、invalidate runner、清 listener，但**不 emit session_shutdown**。對應 `P/docs/sdk.md:56` 只描述 invalidate/disconnect，沒有承諾 extension cleanup event。
- 相對地 `P/dist/core/agent-session-runtime.js:296–303` 的 `await runtime.dispose()` 先 await quit event 再 dispose；官方 runtime example 的 finally 使用這一路徑（`P/examples/sdk/13-session-runtime.ts:66–67`）。
- 裸 SDK session.dispose 後，module 的 process registry 可以仍握住 child，binding 也沒機會主動解除；即使下一次呼叫時捕獲 stale error，仍不符合「不保留無效 callback」的原要求。

**動作**：受支援宿主限定為單一 active AgentSessionRuntime、確實 bindExtensions 並 awaited runtime.dispose 的 CLI/SDK host。一般 createAgentSession 後裸 dispose、重新利用已 invalidated ResourceLoader、沒有 bindExtensions、同 process 多個不協調的 live runtimes，不包含在承諾內。ExtensionAPI 看不到 host runtime identity，不能從 session ID 自動推導多宿主 ownership。

### W2 — shutdown 事件是可等待的取消入口，不是無條件 cleanup／退出保證

- `P/dist/core/extensions/runner.js:80–85,813–839`：shutdown handler 被 await，但 handler 例外通常只報錯後繼續；throw 不會強制 host 停止 reload。manager 的取消 fan-out 必須每個 job 都嘗試，個別失敗不能提早中斷其餘 job。
- `P/dist/modes/interactive/interactive-mode.js:3477–3511`：正常 quit 與 graceful signal shutdown awaited runtime.dispose；但 `3513–3519` emergency terminal exit、`3532–3561` uncaught crash 可以直接 process.exit，不經一般 extension cleanup。
- `P/dist/modes/rpc/rpc-mode.js:579–595`：RPC 正常 shutdown await runtime.dispose；再次進入 shuttingDown 時可能直接 exit（`580–582`）。
- `P/dist/modes/interactive/interactive-mode.js:5357–5364`：TUI 忙於 response 或 compaction 時 `/reload` 是拒絕操作，不發 reload shutdown。不要把輸入字串 `/reload` 一律當成已完成 reload，也不要攔截後自行取消 Fork。

**動作**：契約明確區分 cancel requested、child closed、descendants cleanup confirmed。RPC child EOF 是最低成本 lifeline：`P/dist/modes/rpc/rpc-mode.js:639–650` 收到 stdin end 就 shutdown，正常路徑 emit child quit；`P/docs/rpc.md:91–95` 有同樣文件承諾。父程序必須持續讀 stdout/stderr、以受控 pipe/backpressure 管理 child。這能在 parent pipe 真正斷開時要求 child cleanup，不能保證強制 kill、停滯 JS、繼承 pipe 的其他 process、任意第三方 descendants 或 OS process tree 已停止。無須為基本 EOF lifeline 新增背景 daemon；角色握手、metadata、不可重建能力與巢狀 jobs 收尾是後續獨立契約。

## Suggestions (consider)

### S1 — 最小 registry 不依賴 jiti module instance 或 pi.events

**實際 loader 語意**：

1. `P/dist/core/extensions/loader.js:86–101`：host 有 cwd/generation-aware factory cache；同 cwd 可重用 factory，但 cwd 改變即 clear cache。
2. `461–489`：cache miss 建立 jiti instance 並設定 `moduleCache: false`；成功後只 cache factory。
3. `510–522,550–580`：即使 factory cached，仍為新的 extension/runtime 呼叫 factory；factory-local job Map 必然是新的。
4. `P/dist/core/resource-loader.js:352–356`：同 loader reload 會 clear extension cache；跨 cwd 也會 clear。`J/README.md:139–149` 說明 moduleCache:false 允許同 module 再次 import。不要以 top-level Map 或 TS helper 的匯入身份當 process singleton 保證。
5. native ESM imports 的個別 cache 行為不應簡化成「所有相依檔案都一定 reload」；此審查沒有執行 jiti prototype，也沒審查其 minified eval 全實作。

**最少的自有狀態路線（靜態可行提案，不是已驗證成品）**：在同一 Node JS realm 的 `globalThis` 上，以 package-owned、版本化 `Symbol.for` key 保存一個 registry；這是 extension 自己的 JavaScript 狀態，不是存取 Pi 私有 runtime。所有 loader generation 都取得同一物件；不要使用 `instanceof` 跨重載識別舊 class。key 的具體新名稱仍需實作時確定，不把提案冒充現有介面。

Registry 持有 process epoch、admission state、所有來源的 jobs、child handles/controllers/permits、plain origin identity、results/inbox，以及至多一個「目前有效」binding。job 的所有 async callbacks 僅依 registry/job/plain data，不捕獲 pi、ctx、ctx.ui、event bus emit、工具 onUpdate 或 tool AbortSignal。接受工作後轉用 job-owned controller，不因前景工具回合或 parent A 的 abort 而取消。

**生命週期矩陣**：

| 公開事件 | Registry / binding 最小動作 |
|---|---|
| factory | 只註冊 handlers/tools；不開 socket/process/timer，不假設已有有效 session |
| session_start startup/new/resume/fork | 取得 registry，以 fresh pi/ctx 建立唯一 generation-tagged binding；同 owner 才查 inbox |
| session_shutdown new/resume/fork | 先同步撤銷 binding、解除 presenter callbacks；jobs 與 process epoch 不變；在 gap 期間只保存結果 |
| session_shutdown quit/reload | 先關 admission、撤銷 binding；對 registry 內**全部** unfinished jobs fan-out cancel，不依目前 session/cwd/owner 過濾；await 收尾可觀察結果 |
| reload 後 session_start | 新 binding；新 admission epoch；不復活磁碟 runner、不重用舊 pi；未確認 close 的舊 jobs/permits 不可直接丟掉 |
| child settled/close | 只更新 registry/result/inbox；需要通知時重新取得目前 binding；未 match 則不投遞 |

Lifecycle hooks 必須冪等、compare-and-detach 自己的 generation，不能讓 old callback 移除較新的 binding。撤銷應在 handler 第一個 await **之前**；每次 await 回來重新比對 binding token，避免把先前取得的 send/UI callback 帶過 session replacement。卸除 listener 不會中止已在執行的 async handler（runner dispatch snapshot：`P/dist/core/extensions/runner.js:87–89,813–819`）。

`P/docs/extensions.md:54–60` 明確禁止在 factory 開長期 resources；這也防止 trust bootstrap、help／list 等只 load extension 的情境誤開 child。`P/dist/main.js:605–627` 與 `P/dist/core/resource-loader.js:345–350,545–577` 有 pre-trust/final-load passes，不能把 factory 執行誤當 session_start。

### S2 — pi.events 是當代 runtime 的 extension 通訊，不是 process manager

- `P/dist/core/resource-loader.js:240–244`：每個新 loader 預設有新 event bus。
- `P/dist/core/extensions/loader.js:141–149`：invalidate 自動 unsubscribe 所有 tracked event-bus registrations。
- `417–428`：舊 pi.events.emit/on 也先 assertActive。
- `P/dist/core/event-bus.js:5–18`：emit 本身沒有 await handler／durable delivery acknowledgment；safe async handler 將錯誤寫 stderr。

因此不可把 A 的 event-bus subscription 保留為 B 的 quit/reload callback；也不能假設跨 cwd 仍使用同 bus。自有 registry 內部通知可用自有 callback/EventEmitter，但 binding listener 必須 detach；callback 不跨 runtime 存活。沒有需要強制讓 Pi bus 全域化的理由。

### S3 — inactive-origin 結果 routing 可透過 inbox 實作，但 sendMessage 沒有 durable ack

- `P/dist/core/extensions/types.d.ts:222–223` 提供 readonly sessionManager；`P/dist/core/session-manager.d.ts:178` 包含 getSessionId、getSessionFile、getHeader、getCwd、getSessionDir、getEntries 等，因此可先保存 plain origin identity，無須留住 A context。
- `P/dist/core/extensions/loader.js:301–313` 與 `P/dist/core/extensions/runner.js:613–688` 的 action/context 都有 stale guard。fresh B API 的 sendMessage 只送 B，不接受指定 A session 的 routing argument（`types.d.ts:1233–1248`）。
- `P/dist/core/agent-session.js:2703–2711`：ExtensionAPI.sendMessage 對內 async sendCustomMessage 是 fire-and-forget，錯誤走 runner；公開回傳型別是 void。
- `1782–1819`：`triggerTurn:false` 在 idle 追加 custom notice 而不啟動 provider；busy 時進 pendingCustomMessages 待 turn boundary。`deliverAs:nextTurn` 則留待下一回合，不適合當成已即刻保存的完成回報。
- `1821–1838`：實際 append 後才發 message_end；`P/dist/core/session-manager.js:794–813` 是同步檔案追加，沒有 fsync/durable transaction ack；`786–799` 的尚無 user/assistant 空 session 甚至可以保持檔案不存在。

**最小投遞政策**：child 完成先保存 inbox/result；A 不在前景時零 pi 調用、零原生 A journal 寫入、零 parent provider。A 再 session_start 時核對 session ID + canonical native path + canonical cwd + current generation，才以 fresh API 送 `triggerTurn:false` custom notice。如果新檔與舊檔有相同 header ID，不可僅靠 ID routing；原生 fork/new 是新 owner，不把 A 結果自動送進它。

resultId 用來掃描 native getEntries 判斷曾否寫入，包括非 active branch 的歷史通知；「可見 branch」與「曾經送達」不要混成一件事。message_end 後再查 journal，可將狀態提升為 observed journal append；submit void 不當 durable ack。遇 write failure、replacement gap、未知狀態保留 pending/unknown，不 blind replay。不承諾 exactly-once 或 disk crash durability；也不為了投遞開第二個 A writer。

若原 A 不再載入 manager 或永不回前景，只能保留 inbox／讓使用者查結果，不能保證自動通知。這是路由前提，不是理由將結果注入 B。

## CP1 後續可操作驗證（本輪未執行）

1. **先固定支持拓樸**：根 Pi 1.1.0 CLI + 單一 active AgentSessionRuntime + 使用者明確選取管理入口。記錄 global package 是否足够；若不够使用明確 CLI 選取契約，不自行改個人 settings。
2. **offline、隔離 fixture**：以真實 root SDK/runtime、假的 provider/child event barriers 驗證 A→new→A、A→native fork→A、A(cwd1)→B(cwd2)→A；每步核對 dispose 後旧 pi/ctx throws、pi.events listener 移除、registry identity 一致、jobs 不因 replacement abort。
3. **工具與 extension 分開驗證**：B 的 Fork tool 被 exclude／inactive 但 manager 已選取，全部工作仍續行，B 的 quit/reload cancel A 與其他來源全部 jobs，且沒有 setActiveTools 提權。另一 case 明確排除 manager 應展示“不受支援”真實限制，不能 covert reload 它。
4. **jiti 真實 fixture**：同 cwd factory reuse、跨 cwd cache clear、reload 重新 eval 後 registry identity；重複 start/load 不新增 process/signal/listener；舊 epoch child late close 不污染新 epoch。
5. **路由**：child 完成恰在 teardown gap、busy A、inactive A、A resume 後；B journal 無結果內容／provider admission；A journal resultId 至多按已確認狀態追加，write fault 保持 unknown；zero callbacks retained after shutdown。
6. **全域取消與 lifeline**：兩個來源多 jobs，以 child close event barrier 驗證全部收到 cancel；單一 cleanup failure 不阻止其他；RPC stdin EOF、disconnect、late close 及 cleanup 未確認保持 permits。不要用 sleep、shell polling、idle watchdog 當正確性證據。
7. **負面宿主 case**：裸 session.dispose 明確顯示無 shutdown；replacement createRuntime 或 manager factory 失敗之後不假裝仍有有效 binding；新程序不从舊磁碟 registry 自動重啟。

本輪不涵蓋完整 capability snapshot 重建、native writer fence、Subagent 遞迴 guard 的完整可行性；不能由本生命周期評估推導這些 checkpoint 已通過。

## Summary

Pi 1.1.0 已提供區分 new/resume/fork 與 quit/reload 的公開 shutdown/start 事件，可支撐「自有 process registry + 可撤銷 fresh session binding」，不需要 monkey-patch Pi；但這僅在管理 extension 每次確實載入且宿主真的發 shutdown 事件的部署內成立。真正阻塞是尚未鎖定的部署覆蓋契約及尚未執行的真實 offline lifecycle 證據，而不是工具未選取、跨 cwd 或 jiti 重載本身必然不可行；CP1 保留未通過，先驗證上述最小路線再放行後續實作。
