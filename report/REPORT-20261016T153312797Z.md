## Critical (must fix)

### R-HTTP-01 — 101 Upgrade 的 close 不會結束 headers 等待
- **位置：** `modules/web-tools/src/fetch/http.ts:94–98`；影響延伸到 `service.ts:234,390–394,403–413`。
- **狀態／優先度：** 靜態確認，P1；未執行 socket 重現。
- **觸發：** 缺 browser 的 HTTP fallback 遇到公開站點回覆 `101 Switching Protocols`、`Connection: Upgrade`、`Upgrade: websocket`。不涉及私網或 DNS rebinding。
- **證據：** headers promise 只監聽 request 的 response／error。Node 22.22.2 的 upgrade 分支不 emit 普通 response；沒有 upgrade listener 時銷毀 socket，但 req.res 已設定，因此 socket close 分支只 emit request close，不 emit request error。其後 destroy 已 destroyed request 直接返回。這條事件路徑不會 settle 產品的 promise。citeturn0view0
- **影響推導：** deadline／取消無法再靠已關閉 request 的 error 喚醒等待；外層 finally 不執行、queue permit 與 operationCleanup 不釋放。累積至 maxConcurrency 後抓取容量耗盡；close 等待 operationCleanup，使 shutdown／reload 一併卡住。
- **最小修正：** 在 response 尚未交付就 close 時 reject；AbortSignal 直接 settle headers 等待，不完全依賴 request 再 emit error。若顯式處理 upgrade，拒絕該協定並銷毀移交的 socket；保留一次 settlement、listener cleanup 與等待 request close 後釋放名額。
- **最小回歸：** 本地 raw TCP／HTTP fixture 回傳上述 101，以事件 barrier 驗證 fetch 拒絕、取消與 close 完成、operation 集合清空、queue 可再次取得；不新增固定 sleep timeout 測試。現有 `tests/integration/static-http.test.ts:49–95` 未覆蓋 101。
- **固定版本來源：** `https://raw.githubusercontent.com/nodejs/node/v22.22.2/lib/_http_client.js`；`destroy`、`socketCloseListener`、`socketOnData`、`parserOnIncomingClient`，約 462–476、490–519、588–622、645–666 行。

### R-SETUP-01 — installer 改 cwd，讓相對 browser cache 與 doctor／runtime 分離
- **位置：** `setup/core.mjs:24`；對照 `61–66,88`。
- **狀態／優先度：** 靜態確認，P2；未下載瀏覽器。
- **觸發：** 從非套件目錄 A 直接執行 CLI，設定 `PLAYWRIGHT_BROWSERS_PATH=./browser-cache`，沒有 INIT_CWD。
- **證據：** doctor 保留 cwd A；browserInvocation 將 installer cwd 切換成 packageRoot B，環境不變。Playwright 1.64.1 registry 對相對 cache 使用 INIT_CWD 或 process.cwd 解析，所以 doctor／同目錄 Pi 指向 A/browser-cache，安裝卻指向 B/browser-cache。citeturn1view0
- **影響：** 同實例、同環境下安裝可成功但 runtime 仍缺 browser，繼續 fallback 或 selector 失敗；唯讀 packageRoot 還可能引入原本不需要的權限錯誤。
- **最小修正：** browser 子程序保留呼叫者 cwd；CLI 已從本實例解析為絕對路徑，不需依 cwd 找依賴。若選擇預先正規化 cache，須保留 Playwright 的 `0` 特例，不改全域設定；前者較小。
- **最小回歸：** 任意 cwd、相對 cache、無 INIT_CWD，比較 doctor executable 與 installer 子程序的 registry directory；唯讀 registry／stub CLI probe 即可，不必安裝。現有 PTY `setup.integration.test.mjs:16–25` 與 `scripts/package-smoke.mjs:143` 都用絕對 cache。
