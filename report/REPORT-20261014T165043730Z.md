## C5 — confirmed：raw snapshot 越過真正 hook mutation

產品位置：`extensions/json-schema.ts:84–85,100–102`。

三次成功程序中，每次各跑 mutation 與 no-mutation control：

1. Offline provider 產生 `json_output({secret:"RAW_SENTINEL"})`，不是實際秘密。
2. 真 host 發出 tool_execution_start，產品保存 raw snapshot；之後 host 發出 tool_call。
3. 正式註冊的 tool_call hook 將 `event.input.secret` 改成 `REDACTED`，即時 assert 並記錄 `C5-mutation-applied` 的 after 值。
4. 產品 execute 回報 Result recorded／terminate，正常 settled 後，native runtime dispose 寫檔。
5. 檔案三次都仍是 `{secret:"RAW_SENTINEL"}`；每案一個 provider request。無 mutation control 亦正常交付原值。

Rawlogs event list 是 observer 在修改前保存的 snapshot，所以 tool_call 列表仍显示 RAW_SENTINEL；修改後值在獨立 `C5-mutation-applied` 記錄，不把修改前 snapshot 冒充修改後。實際 event 順序 start < tool_call < execution_end < settled < quit shutdown，由宿主產生，不手派。

影響邊界：明確 input 遮罩修改沒有反映於交付。這是 hook mutation 契約／資料轉換問題，沒有真秘密、網路外洩或提權實證；raw 防 coercion 本身是文件化設計，但不能因此當作尊重明確 hook mutation 已驗收。

驗收：明確 mutation 應反映於最後資料，或偵測差異 fail closed；同時保留只因宿主 coercion 而改變的無效模型參數不得放行。此次覆蓋遮罩替換，未聲稱覆蓋 delete、工具 block、所有 extension 排序。

## C7 — confirmed：一個真 session shutdown 取消另一 session 工作

產品位置：`extensions/json-schema.ts:232`；`src/validation-pool.ts:26–34,137`。

三次都使用同 process／同 canonical workspace、兩個真正 loader／SessionManager／AgentSession／AgentSessionRuntime：

- A 先以無 pattern schema 成功記錄 `{secret:"A"}`，尚未 shutdown。
- B 發出八個有效、相同的 json_output `{value:"a"}`，schema 帶保守 pattern `^a+$`，因此 extension execute 使用真 worker pool。
- 以 B 第八個真 tool_call 事件建立 gate；一次 setImmediate 是事件迴圈交接而非 timed sleep／idle probe。assert 尚無 tool_execution_end，然後只呼叫 A 的 native runtime.dispose。
- A 真 quit shutdown 完成交付／產品全 pool close；B 的八個 execution_end 全部回 isError true，內容為 `Validation cancelled: pool shutdown`。
- assert 當時 B 沒有任何 session_shutdown，B 最終 settled.aborted 為 false：不是我們取消／關閉 B。
- B 因工具錯誤多了一次 offline provider request，後續 prose `{value:"a"}` 正常 recover；最後另行 dispose B 並交付有效結果。A 檔案也正常。
- 對照 session 同樣八個 patterned tools、沒有他 session 中途 shutdown：8 個成功、0 errors、只一個 provider request，交付有效資料。

每次結果都是 B errors=8、B providerCalls=2；control errors=0、providerCalls=1。共享產品 module／pool 的干擾由實際兩 session 結果證明，不靠替身 pool 或單純 direct close。Host loader 的同 cwd factory cache（`loader.js:460–489`）與觀察吻合，但不擴張聲稱所有 loader／跨 cwd／跨 process 都共享。

影響邊界：本 witness 覆蓋 in-flight worker 啟動／排隊期間的取消干擾；沒有量測 worker ready 後 CPU-running 的 race，不宣稱該階段全部覆蓋。這次 B 可復原，不是永久毀損或資料外洩；確認多出工具錯誤及一次模型邊界呼叫，並非真費用已發生。

驗收：A shutdown 只能 drain A 的驗證；B 八個 calls 應成功、只一個 provider request、無 pool-shutdown reason；保留 global capacity 上限、各 session 結束 worker cleanup，另補 ready／CPU-active 與 queued owner 分組驗收。
