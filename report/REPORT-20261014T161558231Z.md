### C1 P2 — WS startup 日曆期限：confirmed

位置：`modules/monitor/src/sources.ts:19–36`（29、32、36），`modules/monitor/src/core.ts:54–69`。

真實 import `websocketLaunch`、`prepareEndpoint`、`MonitorRuntime`、`validateStart`。只 mock **node:dns/promises lookup I/O**：受控 resolver barrier 回授公開 8.8.8.8，實際 network validation、來源與 runtime 邏輯均未替換或複製。

Start duration=300000；DNS 進入 barrier 時，fake clock 註冊 relative timer 300000 與 15000。只將 wall 推進600000、mono 推進1000，**不執行任何 timer callback**，再釋放 DNS。三次均觀察 signal 未 abort、elapsedMs=1000，但實際來源 `startupCanceled:true`，runtime completed/source_closed 並 cleanupPending=false；因此不是正確相對期限到達。shutdown 後 fake tasks=0。

Mock boundary：fake wall/mono/timer、DNS I/O；WS constructor 未抵達，不 mock WS／被驗期限邏輯。此證據足以確認早停控制流，不證明實際 DNS／TLS／WS transport 或負向校時後的握手預算。無遠端請求。

### C2 P2 — exit 後舊 PID kill：blocked

位置：`modules/shell-tools/src/monitor-exec.ts:25–27,49–50,58,63–70`；Monitor 使用路徑 `modules/monitor/src/sources.ts:12`，其他共享 adapter 使用者亦受同一入口約束。

真實 import/call `execMonitorCommand` 三次均在 **1.2.0 version fence** 拒絕，settings/loadBackend/spawn 計數全0；沒有執行到 fake child exit→abort→close。Seam 只用作禁止抵達計數，不替換被驗 cancellation 邏輯。這三次 exit0 表示 blocker assertion 通過，不表示 PID 候選 confirmed／refuted。

靜態上 kill 仍僅檢查 closed，exit 僅設定 exited，tracking 留至 finish。**穩定舊 PID kill 呼叫目前尚未動態實證；PID reuse／誤殺更完全未實證**。不得以已有 abort→exit→close 測試充作 exit→abort→close 證據。

下一步：使用真正隔離 Pi1.2.0 安裝後重跑原產品 import，透過既有 loadBackend/spawn seam 送 exit→abort→close，assert exit 後 kill 呼叫與 actual-close ownership，至少三次新 process；不 mock VERSION 或改 adapter gate。

### C3 P3 — command readiness failure 出口：confirmed（測試邏輯層）

位置：`modules/monitor/tests/command.integration.test.ts:15–30`，尤其19、22、24、30；來源 failure `modules/monitor/src/sources.ts:12–16`。
