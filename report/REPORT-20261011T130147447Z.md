## R4：已退出 POSIX PTY 不再 signal 舊 PID

- Repro code：`modules/pty-terminal/tests/exited-dispose.test.ts`。fake PTY backend 以 signals array 記錄 kill 呼叫；emit exit 後分別 explicit kill、retention/list、capacity/spawn、shutdown；模擬 linux 平台期待零 signal，win32 平台期待一次無 signal backend handle-release。
- 原碼三次 red：每次 4 個 linux ケース失敗（actual `["SIGHUP"]`，expected `[]`），4 個 Windows cleanup ケース通過。**沒有**啟動 POSIX 真實 PTY 或製造 PID reuse；只證實 signal-after-exit 呼叫分支。
- 最小修正：`PtySessionManager.dispose()` 只在 Windows 呼叫 backend kill() 釋放 native handles；確認 exited 的 POSIX transport 只移除 manager ownership。running kill/escalation、remote tree unknown、shutdown recovery 全保留。
- README 另澄清 retention 是後續操作時回收，不是背景 timer。
- 最後三次 green：8/8、exit 0。Windows native PTY 也已在原有本機 lifecycle tests 驗證。

## R12：once continuation 的 generation fence／locked settlement

- Repro code：`modules/schedule-prompt/test/review-lifecycle.test.ts` 的 R12 五個原案例。fake clock；實際隔離 CronStorage；同步 `cron:change` listener 在 runCount=1 時重排同 ID 為 once／interval／cron、stop 或 foreign-session；flush timer/microtasks，不 sleep。
- 原碼三次 red：五個案例每次都將新的 enabled:true 覆寫為 false；送出一次 follow-up 的前置 assertion 通過，故不是未觸發假失敗。
- 最小修正：timer generation Symbol，由 update/remove/stop 撤銷；once callback、re-arm、成功及失敗 continuation 均核對 token。cron／interval callback 也拒絕已撤銷 generation。once settlement 在 `updateJobWith` 的同一 lock 下核對原 once schedule/execution configuration、enabled 與 session owner；conditional compute 返回 undefined 時不 rewrite peer bytes。
- supplemental green-only 兩案例：peer 只改 persisted schedule／session、未呼叫本地 reschedule，鎖內 compare 拒絕舊 settlement；enabled 與原 bytes 保留。這兩個補強案例不是原碼 red3 證據，不冒稱另跑 baseline red。
- 不新增 persisted generation 或跨 process ABA protocol；README 明示界線。原有 skipped/no-retry、deadline admission 與 in-process child cleanup contract 保留。

## R13：startup snapshot／單次 locked disabled cleanup

- 原 Repro code：`review-lifecycle.test.ts` 的 R13 startup 與 session-shutdown cleanup；bounded N=10、100。spy 在實際 CronStorage.load/save 邊界，load 每次仍真的 read/parse 全 store；不以 wall latency 判斷。
- 原碼三次 red：startup N=10/100 每次觀察 11/101 次完整 load；shutdown cleanup 亦為 11/101 次 load。原 fail 首先停在 read-count assertion，未將未走到的 write-count assertion冒稱 baseline 已通過。原碼 removeJob 路徑逐筆 save 為可核對的 source evidence。
- startup 修正：scheduleJob 使用已讀 job snapshot 判斷是否 armDeadline，不為每個正常 job 再 getJob；真正 fire admission、deadline mutation仍 fresh-read。past-once disable 分支立即結束，避免 snapshot 仍 enabled 時額外建 deadline timer。
- cleanup 修正：`CronStorage.removeDisabledJobs(sessionId)` 一次 owner-token lock 內 read/filter/write；未刪除時不 save。session predicate 在 mutation 時檢查，不相信過時 UI snapshot。
- 額外原路徑 Repro code：`modules/schedule-prompt/test/review-cleanup.test.ts`。tool、RPC Jobs menu、TUI Jobs view 原產品路徑在尚未修改時各連續三次 red，N=10；確認期間 peer re-enable／rebind，然後以 operation counts 和保留 jobs 斷言。
- tool/menu/view 都改用同一 batch API；只有實際已刪除 jobs 才 unschedule。
- 最後 green：startup 一次 load；shutdown 一次 load／一次 save；tool 一次 load／save，menu/view mutation後 refresh 加一次 load，仍常數；保留 foreign/re-enabled job，8 個實際刪除 job 才通知 scheduler。
- 限制：stale-running／expired deadline 的必要 locked mutation，以及各 deadline recheck timer 的逐筆 fresh-read仍保留；沒有宣稱所有 storage 工作已變成常數或一般 cache。
