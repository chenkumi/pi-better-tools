### W1 — persisted settings 改用 actual branch records 作權威後，Session Reset 仍只清不再被讀取的 cache

**位置／function：** `modules/blackhole/src/pi-base/config-manager.ts:1109-1120` (`resetScope`)，連動 `_hostSessionOverrides:598-616`、`layerValues:670-682`；`deleteScope:1149-1160` 有相同直接 API 問題。UI 真實入口：`src/pi-base/settings/config-flow.ts:344-370,459-464`。

**分類：確定靜態邏輯缺陷，warning／中優先；未獨立執行 runtime reproduction。**

新 host resolver 正確忽略 persisted leaf cache、只讀 active branch 的 actual settings record；但 session reset 仍只 `clearSessionConfig(namespace,cwd,sessionId,leaf)`，沒有新增 reset authority record，也沒有改目前 branch。故以新 actual host path 正常 Save 得到 C，然後按 Session「Reset」：

1. C 的 `data.config` 仍在 active branch。
2. `resetScope` 只刪 Map key，沒有通知新 projection 此 override 已被使用者取消。
3. UI immediately 呼叫 `params.layerValues("session")`；它重新執行 `_hostSessionOverrides`，從 C 取回完全相同 override。Inspect／下一次 reload 亦然。

所以 Reset 看似成功、沒有例外，但設定不回 file/env baseline。若 C 啟用了 memory，使用者無法透過此 Reset 取消 session memory override；這不是 Pi timing trigger 問題，也不是未實測 OM transaction gap。`sm.resetLeaf()` 的 navigation 測試成功不能代替 **settings modal Reset**。

**為何現有 green 未攔住：** `config-manager.test.ts:1253-1280,1720-1767` 的 reset 仍用 direct/cache path 或 mocked append，沒有真 active persisted C 搭配 fresh host binding；新 navigation fixture 完全沒有 `resetScope`。既有 reset assertions 未刪，但驗的是另一套 authority。

**最小修正／回歸：** 對 live-host persisted session 的 explicit Reset 取得 fresh public owner／leaf／branch snapshot，append 一個合法 branch-local empty override／明確 reset record，使最新 saved-record projection回到 lower layers；不要刪除／改寫歷史 JSONL，也不要重新允許 cache 授權。仍未 materialize 的 genuine pending reset 可以清 owner-keyed sentinel。追加隔離真 SessionManager／實際 UI Reset：save C → reset → lower-layer exact values、reload、fresh manager、navigation回 C 和 reset record、append拒絕不得假成功，以及 pending reset；原 JSONL prefix保持不變。`deleteScope("session")` 若仍是公開支援 API，需同樣合理的撤銷語意，雖 session modal沒有 Delete button。
