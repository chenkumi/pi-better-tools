## 實作

- `pairToolBlocks`／`pairFileMessages` 對唯一 toolCallId、相同 toolName、合法先 call 後 result 配對；duplicate／mismatched／missing 結果不提供成功身份。成功需 explicit host `isError:false`。
- `noteResultPath` 驗證 type/content 與成功 details.relativePath 的 confined relative shape；保留原始 arguments，不補 input path，不猜 UTC filename。Created、file search、touched 與 file drill-down 可發現成功 note。
- File activity 用成功 correlated result；read 採返回 actual/corrected path，write 以 created:true 分類，edit 使用 changedCount，防止 diff 內「no changes made」誤判 noop。Call-derived native fileOps seeds 不復活 failed／cancelled／missing／未執行的 attempt。
- Exact-input-path file retry、exact-type/content Note retry 分開 outstanding status 與歷史 error。Unpaired/pathless 同名結果不能消除失敗；成功 Note retry 仍需合法 returned path。歷史 error 與原始 #N 保留。
- FileToolError 實際 multiline `[FILE_TOOL_ERROR]` JSON body，在 host 已標記 error 時，最多解析 16,384 字元並只取 scalar code/message 作既有 bounded display；body status 不決定 outcome。Malformed／oversized body 保留 first-line fallback，raw history 仍可查。
- Modern 32-hex version-token metadata 將檔名視為 literal，不剝除合法 `:10-40`／`#L12` suffix；這不是 filesystem canonical identity proof。
- Note search/extraction 維持 10,240 字元 per-call prefix；full note display 維持 UTF8-safe 50 KiB；default recall response 48,000 字元另行限制。長內容尾端可用 stored-content line paging，不讀取現存 Note 文件。
