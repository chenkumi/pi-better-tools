### W1 — guard 同 process reload 的完整契約尚未證明，既有 `wx` handshake 行為會阻斷重驗證流程

- **嚴重度：Warning；既有行為與本次宣稱範圍的缺口，不歸因為新增 Shell regression。**
- **來源：** `modules/subagents/extensions/subagent/child-guard.ts:19–43`，尤其 `:32` 在每次 `session_start` 都以 `flag:"wx"` 寫同一個 `expected.startupPath`；process-local expected 則由 `modules/shell-tools/src/managed-child.ts:8–15` 保留。Installed Pi `dist/core/agent-session.js:2936–2968` 在 reload 重新載入擴充並發 `session_start(reason:"reload")`；`dist/core/extensions/runner.js:813–838` 將一般 event handler 例外回報為 extension error，而非直接讓整個宿主必然退出。
- **靜態推論，不是本次動態重現：** managed child 首次成功建立 startup file 後，在同 process reload 且檔案仍存在時，第二次 guard handler 將在 `:32` 遇到 EEXIST。這會早於 `:33–43` 的明確拒絕／verified 流程；不能把「global copy 保留 shellMode」等同於「guard reload 成功且再次維持完整拒絕保障」。若重驗證已判定 config/trust mismatch，EEXIST 也會先於明確 `process.exit(1)` 分支。未呼叫 provider，故不宣稱已重現繞過或實際付費請求。
- **目前測試缺口：** `modules/shell-tools/tests/managed-child.test.ts:12,23–25,39–40` 的 `on()` stub 不執行 guard session_start；Shell SDK integration `:15–17,51–54` 僅載入 Shell module，沒有實際 startup guard；CLI integration `modules/subagents/tests/managed-child-shell.integration.test.mjs:28–60` 涵蓋 new/resume/ready-query × 兩種初次載入順序，但每項為新 process，沒有 reload。因此這些 green 不能回答完整 guard reload 的問題。
- **最低建議回歸：** 隔離 Pi 1.1.0 SDK/CLI 同時載入 Shell 與 guard，建立真實 startup file，執行同 process reload，捕捉 extension errors，核對 foreground schema／無管理工具／guard 重驗證的結果；再注入配置或信任不符，確認不只回報 EEXIST 且不進 provider admission。用事件／檔案與 RPC 回覆 barrier，不靠 sleep 或真實 provider。
