## MISC-001 — 確認 High：failed pending save仍將coverage標recorded並持久化

### 精確位置及不變量

`modules/blackhole/src/om/pending.ts:123–133`只讀main，錯誤回empty；`161–176`先rename main為stale，write失敗catch吞掉；`257–264`save無成功值；`334–339`cursor-only state可寫。Production caller `consolidation.ts:1325–1340`manual save之後無條件advanceCursor(recorded)，`771–782`schedule flush；`runtime.ts:898–906`microtask實際寫入，`860–880`reload cursors。

核心預期：未持久化worker observation不可由coverage cursor認可已記錄。正常save才可持久化recorded cursor並跳過同source。

### 最終實際結果

|probe|fault|control|exit|
|---|---|---|---|
|pending-helper|3/3：errors1、batches0、cursor raw-b/recorded、backupContainsA=false|3/3：errors0、batches2、cursor raw-b/recorded、backupContainsA=true|各次0|
|pending-caller|3/3：workerCalls1、errors1、batches0、cursor raw-b/recorded、reloadedDue=false、reloadedWorkerCalls1|3/3：errors0、batches1、cursor raw-b/recorded、reload observer不重跑|各次0|

helper先存A，再於saveB注入一次ENOSPC；观察main缺失、stale仍含A。兩次正常cursor write後A備份不再存在，main只含cursor；不是單憑exception或靜態推導。

caller實際 `runConsolidationPipeline` → production observer stage → production save → production cursor flush；synthetic worker回合法source IDs的fact。新Runtime重新load persisted cursor後，`anyStageDue=false`；重新進同source pipeline觀察worker call count仍1，失敗batch未自動再處理。Control資料實際可讀，並非只mock writer invocation。

原始代表stdout（完整內容及repeat2/3見同stem logs）：

```json
{"kind":"pending-caller","mode":"fault","errors":1,"workerCalls":1,"batches":0,"cursor":{"entryId":"raw-b","state":"recorded"},"reloadedDue":false,"reloadedWorkerCalls":1,"notices":["Observational memory: observer running on ~238-token chunk (of 225 accumulated)"]}
```

### 反證與界限

- generation/branch fence仍保持，fixture是同session／同branch；故障不是foreign ownership問題。
- stale可人工救援，但helper證明後續cursor-write覆蓋；main-only read不恢復stale。Raw transcript未刪，不能稱整個session資料毀損。
- 候選的「可能顯示recorded」**不是本次觀察**。runtime344–353 once info gate先由running通知消耗，recorded通知被抑制；最終fixture同時assert running存在及recorded不存在。這是候選範圍的反證，不動核心data/cursor/reload判定。
- 最小caller是synthetic model resolution及workers，不測真provider success、完整agent_start/turn_end host dispatcher。下游manual reflector/control會執行synthetic empty worker，dropper/reflector仍可能發候選exhaustion診斷；不宣稱全pipeline每stage成功。production尾端flush確實執行。Reflection/drop保存同根因只做原碼定位，**未另動態重播**。
- High依未flush memory靜默缺失且coverage永久跳過，不因假設paid模型已實際呼叫。沒有產品修補。

## MISC-002 — 確認 High：session掃描失敗誤列orphan，公開command可刪live pending

### 精確位置及不變量

`modules/blackhole/src/om/cleanup.ts:109–150`scan在read/stat/readdir/parse故障時skip且不傳incomplete；`201–208`普通Set；`221–246`absence變orphan；`289–328`可刪main/stale。`src/commands/cleanup.ts:267–300`直接使用報告，picker `230–236`Enter刪除；公開routing `src/commands/pi-vcc.ts:43–48,78–85,120–123`。

核心預期：同sid session JSONL已存在但不可讀，不等於證明orphan，不能以此授權破壞性cleanup。

### 最終實際結果

先存合法pending和合法version3 session header；未注fault時同pending active=1。只deny header read後：

|probe|fault|control|exit|
|---|---|---|---|
|orphan-helper|3/3：errors1、active0、orphaned1、deleted1、pendingExists=false、sessionExists=true|3/3：active1、orphaned0、deleted0、pending/session都在|各次0|
|orphan-command|3/3：errors1、opened1、rendered含Orphaned Pending Files、Enter後pending不存在、live session仍在|3/3：opened0、No orphaned pending files found、pending未刪|各次0|

最終command不是直呼helper：用synthetic ExtensionAPI捕獲 **production `registerPiVccCommand`註冊的blackhole command**，執行 `handler('cleanup', ctx)`。ctx.mode=tui、liveContextSession等於該sid；production custom component render，送真正 `handleInput('\r')`，由Pi TUI matchesKey辨認Enter，走production deletion。沒有mock「delete回傳成功」；postcondition是真磁碟檔案已刪。

原始helper stdout：

```json
{"kind":"orphan-helper","mode":"fault","errors":1,"reads":2,"active":0,"orphaned":1,"deleted":1,"pendingExists":false,"sessionExists":true}
```

公開command stdout另保存完整rendered/notices，notices為 `pi-blackhole: All 1 orphaned pending file removed.`，並記錄同 `liveContextSession: verify-live-session`。

### 反證與界限

- SAFE_SESSION_ID_RE和path containment有效，本例合法sid且未越界；其保護不證明session不存在。
- 使用者需要TUI Enter，不是背景自動刪除；正常control不開picker。non-TUI文案路徑只讀的已有防護沒有被否定，本次不測該分支。
- 最小公開command可達已驗證，synthetic UI不測fullscreen renderer／terminal raw input transport，沒有真人誤操作頻率資料。
- EACCES以精確單一路徑mock，並非真ACL／磁碟故障；delete依真FS。不另宣稱custom sessionDir、readdir/stat/parse故障都已動態證明；這些只經原碼核對。
- High依現存session尚未flush memory可以在誤導orphan標籤下被永久unlink。Raw session仍在，不稱raw transcript刪除。未單獨測stale一同刪除，但production接線涵蓋它。
