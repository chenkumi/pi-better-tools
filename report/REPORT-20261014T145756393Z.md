## Warnings (should fix)
### P2 — WS startup 仍以日曆時間判定總期限
- **位置：** `modules/monitor/src/sources.ts:29–36`，尤其第32行；關聯 `core.ts:55–58`。
- **觸發／影響：** DNS 準備尚未完成時，系統時間向前校正超過剩餘 duration。核心的相對 timer 尚未到期、signal 未 abort，但第32行會直接 `closed(startupCanceled)`，不連線；核心最終呈現 completed/source_closed，而非實際期限到達。新的 monotonic elapsed／throttle 修正沒有涵蓋這條 startup 路徑。
- **證據：** 靜態控制流可直接推出：duration=300000，mono 僅前進1000，wall 前進600000，DNS resolve 後 `clock.now() >= deadline` 成立。第29、36行也用相同 wall 差值縮減握手预算。新增 `review-fixes.test.ts:17–34` 只覆蓋 command 核心，未覆蓋 WS。
- **建議：** 傳遞 monotonic 剩餘預算／deadline，日曆 deadline 僅供顯示；以 fake clock、受控 resolver barrier 驗證正負校時，不依賴網路或 sleep。本次未動態重現。

### P2 — shell exit 後仍可能針對失效 PID 要求 kill
- **位置：** `modules/shell-tools/src/monitor-exec.ts:49–50,58,68–70`；Monitor 由 `modules/monitor/src/sources.ts:12` 使用此 adapter。
- **觸發／影響：** shell 已發出 exit，但 descendant 持有 stdout/stderr，尚未 close；此時 stop／duration／shutdown 仍呼叫 `killProcessTree(child.pid)`。PID 若已被回收再分配，有誤殺其他工作風險；detached tracking 也一直保留到 close。
- **證據：** 第68行記錄 exited，但第49行只檢查 closed。安裝 host `dist/utils/shell.js:157–186` 的 Windows taskkill 按數字 PID，POSIX group kill 失敗後會 fallback 正 PID；第141–152行亦按 retained PID 清理。這證實缺少 exit fence；本次沒有實機證明 PID reuse／誤殺。
- **建議：** 分開「shell identity 存活」與「pipes/source close」；exit 後禁止以舊 root PID 作正 PID kill／fallback，仍保留 close ownership 與 unknown descendants 語意。POSIX 可保留安全的 group-only 清理；Windows 需可靠 handle／job ownership 或保守回報未知。新增 fake child exit→abort→close 測試，不以忽略 close 冒稱清理完成。
