## Critical (must fix)

### C1 — Blackhole 直接讀取未受信任專案設定，可改變背景模型與記憶行為

- **位置：** `modules/blackhole/src/core/unified-config.ts:780–800`；入口 `modules/blackhole/index.ts:50–56`。
- **確定行為：** legacy fallback 直接讀取並合併 `<cwd>/.pi/settings.json` 的記憶設定；現代 project override 則無條件讀取並合併 `<cwd>/.pi/pi-blackhole-config.json`。入口只把 cwd 傳入 reloadConfig，未先使用 `ctx.isProjectTrusted()` 排除專案來源。ConfigManager 的 project layer 同樣只依 cwd 讀檔，見 `modules/blackhole/src/pi-base/config-manager.ts:654–658、700–707`。
- **宿主證據：** `node_modules/@earendil-works/pi-coding-agent/dist/core/settings-manager.js:237–240、257–259` 明確在 projectTrusted=false 時不載入 project settings；`dist/core/extensions/types.d.ts:237–238` 提供公開 trust 查詢。全域 `docs/configuration.md:3` 說明 project `.pi` 的 trust 邊界。
- **觸發條件：** Blackhole 從全域或其他已允許來源載入，而 cwd 專案未受信任且含上述專案檔。即使宿主拒絕專案資源，extension 自行讀檔仍會繞過該保護，可能改變 memory、模型候選及相關背景處理設定。不宣稱這本身等於任意程式碼執行。
- **修正方向：** 在可取得公開 ctx 的入口決定是否允許 project layer；runtime 與 settings UI 必須共享同一 trust 決策。不要把未知 trust 預設當已授權，也不要靠未讀 project extension 來推論所有專案檔都安全。
- **缺口：** 加入 globally-loaded extension + untrusted cwd 的真實 host 離線測試；分別覆蓋 unified override、legacy fallback、trust=true／false，provider 必須用 mock 且 HOME／agentDir 隔離。

### C2 — Blackhole 同 session 的 tree navigation 不會使背景工作失效，舊分支結果可寫入新分支

- **位置：** `modules/blackhole/src/om/consolidation.ts:219–228、544–555、620–632、1266、1304`；`modules/blackhole/src/om/runtime.ts:245–285`；`modules/blackhole/index.ts:68–69`。
- **確定行為：** generation guard 只綁 session identity／generation／abort signal。consolidation 只在 session_start 啟動 identity 管理、session_shutdown dispose；session_tree 的現有入口僅重新解析設定，沒有取消 worker／更新 generation。cursor validation 也只在 session ID 改變時執行。
- **宿主證據：** `node_modules/@earendil-works/pi-coding-agent/dist/core/agent-session.js:3317–3351` 在原 SessionManager 上切 leaf、重建 canonical context/tools，然後發 session_tree，不建立新 session identity。`dist/core/session-manager.js:900–901` 的 appendCustomEntry 會附加到當前 leaf。
- **可確認的控制流程：** A 分支 worker 等待模型 → 使用者在同一 session 導航到 B → 模型完成 → session identity 不變，generation 檢查仍成立 → `appendEntry()` 對當前 B leaf 寫入從 A 計算的 OM 記錄。manual pending 寫入亦沒有 branch generation 授權。這是背景工作 branch ownership 問題，不是現有 settings ancestry 修正失效。
- **影響：** 記憶污染、錯誤 coverage／cursor；如果 worker 還在執行，in-flight guard 也會延後 B 分支自己的 consolidation。
- **修正方向：** 在公開 session_tree 邊界更新 branch epoch、abort 舊背景工作、重新校正 branch-relative cursors；append／pending commit 前再次確認當前 branch 授權。不能要求普通對話每次 leaf 前進都取消 worker，應區分正常追加與導航／分支切換。
- **缺口：** 既有 runtime-generation 測試覆蓋 session change/dispose，且明確驗證 same-session 不增加 generation；尚不足以保護 tree navigation。新增以 deferred mock provider 與事件 barrier 控制 A→B→舊 worker 回覆的 host 測試，不用固定 sleep。

### C3 — JSON Schema 未接收 agent_settled.aborted，取消已提交結果的 run 仍可寫入 stdout／覆蓋檔案

- **位置：** `modules/json-schema/extensions/json-schema.ts:36–39、88–89、109–142、194–207`。
- **確定行為：** 取消狀態只由 SIGTERM／SIGHUP 設定，或由 error／aborted assistant message 使 failure 固化；沒有 agent_settled handler。只要 accepted 已存在，shutdown 的交付 guard 看不到僅發生於宿主 settlement 的取消。
- **宿主證據：** `node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts:773–780` 定義 agent_before_settle 與 agent_settled.aborted；`dist/core/agent-session.js:1909–1918` 的 abort 在 run active／before-settle 時設定取消旗標；`:1458–1463` 停止 continuation；`:684–691` 最終通知 aborted。這條路徑不必再產生一則 stopReason=aborted 的 assistant。
- **具體觸發：** 模型成功呼叫 json_output → 工具已 accepted／terminate → 另一 extension 在 agent_before_settle 呼叫公開 `ctx.abort()`，或 SDK 在該邊界取消 → agent_settled.aborted=true、無 process signal／新 error message → 正常 shutdown 仍採 accepted.data 交付。
- **影響：** 與「中止不交付」契約不符；file 模式可能把舊結果替換為已取消 run 的資料。這是靜態控制流程確認，本次未動態執行該案例。
- **修正方向：** 用 agent_settled.aborted 記錄最後 run 的最終取消狀態，再由 shutdown 交付；多 prompt 必須明確定義每次 run 的取消／accepted reset，不讓前一 run 的狀態污染下一 run。不要在通知型 agent_settled 返回 continue 期待再跑模型。
- **缺口：** `tests/fixtures/json-schema-runtime.mjs:86` 測的是 settlement SIGTERM，`:92` 測 provider 回傳 aborted；兩者都不等於沒有 process signal 的宿主 before-settle abort。新增此案例並驗證 stdout 空白、舊檔不變、其他 shutdown handlers 仍執行。

### W3 — GPT Speed 在 symlink settings 情境未與 Pi 共用同一把鎖

- `modules/gpt-speed/extensions/gpt-speed.ts:78–91` 先 realpath settings，然後鎖實際 target；`:55` 設 realpath=false。

- settings.json 為 symlink，或 agentDir 路徑別名指到同一檔時，extension 與 host 可取得不同 `.lock`。跨 process 的 read/merge/write 不再互斥，可能遺失不相關設定。單一 process 的同步操作通常不會交錯，不能據此推論跨 process 安全。

## 宿主缺陷：與模組缺陷分開

### H1 — Pi 1.1.0 用 summary 相等尋找 session_compact entry，重複摘要可回傳舊 checkpoint

## Suggestions (consider)

### S1 — JSON Schema recovery request 不會自動繼承 Agent 的 provider instrumentation

- `modules/json-schema/extensions/json-schema.ts:160–164` 用 `ctx.modelRegistry.complete()`，只提供 timeout／cacheRetention／sessionId，沒有 payload、response、provider-stream hook。
- 宿主 `dist/core/model-registry.js:77–78` 直接轉交 runtime；`dist/core/model-runtime.js:478–487` 把 caller options 傳給 provider，不自行補 extension runner hooks。對照 `dist/core/sdk.js:225–251、274–276`，主 Agent 的 instrumentation 是另外組裝的。
- 已確認：額外抽取呼叫不會僅因「使用 registry」就自動觸發 GPT Speed 或其他主 Agent payload instrumentation。這不是 registry API 違约，不應以 private runner 攔截器補救。
- 若希望 schema delivery 在抽取呼叫保留企業 tracing／provider customization，需先定義公開支援機制與背景呼叫作用域；否則記錄限制，並用 mock provider assertion 驗證主請求與抽取請求各自的 hooks。不能宣稱本次測過真實 provider 支援的 JSON Schema 子集。

### S2 — GPT Speed 的 model eligibility 是 selected model，不是實際 routed model

- `modules/gpt-speed/extensions/gpt-speed.ts:177–182` 使用 ctx.model；全域 `docs/virtual-models.md:18–25` 指出 ctx.model 是選取的 virtual model。宿主 `dist/core/extensions/types.d.ts:679–683` 的 before_provider_request event 只有 payload，沒有 dispatched-model 欄位。
- 由目前判斷可知：一般 router provider／ID 不符合白名單時，即使實際路由到合格 GPT，仍不注入 tier。若要承諾 virtual-model 支援，應增加 route-aware 測試與有權威的 physical-model 判定；不要單靠 payload.model 字串就推斷 provider。
- 目前 README 對 selected／physical 的承諾不明，本項作能力界限／改善，不武斷當成必修。未查證真實服務當前對 priority／ultrafast 的接受性、計費或效能；本審查只驗證程式的注入規則。

### S3 — Blackhole 成功壓縮後的 500ms 通知 timer 未納入 cleanup

- `modules/blackhole/src/hooks/before-compact.ts:823–828` 建立 raw timeout 並保留舊 ctx；`src/om/runtime.ts:315–320` 只能清自己追蹤的 compaction timer。
- 舊 ctx 在 runner invalidation 後受 `dist/core/extensions/runner.js:613–689` 的 active guard 保護，callback 有 catch，故不把它誇大成未捕捉崩潰。仍可短暫延長 process 存活或嘗試 stale notification；宜改受 lifecycle 管理的 timer／generation check。
- 狀態列自己的 poller／worker settle timers 已在 `src/om/status-bar.ts:367–374` 清理；不能把兩者混為全面 cleanup 缺失。

### S4 — 保持型別與新 tool metadata 的正確用途，不為更新 API 盲目改語意

- JSON Schema `extensions/json-schema.ts:74` 已用 exposure=model-only，符合只供模型提交、避免 codemode 的終止副作用。不是因沒有 outputSchema 就與 Pi 1.1.0 不相容。
