## Warnings (should fix)

### R1 — `resolveHostSession` 的 current-branch replay 沒有隔離 leaf cache，且先從全歷史初始化

**位置：** `modules/blackhole/src/pi-base/config-manager.ts:553-574`，尤其 `:558,562-566,574`；連動 `:410-420,507-532,850-874`、`src/pi-base/config.ts:258-285,294-309`。

**Severity：warning／高優先，blocking settings-isolation acceptance；證據：確定靜態控制流程，未執行本案例runtime reproduction。**

1. Resolver `:558` 先對 **`sm.getEntries()` 全部歷史** 呼叫 `initSession`；後者 `:413-418` 掃所有custom settings records，只比 `data.leafId===current leaf`，並寫入 `process.cwd()` namespace，沒有驗證該settings **record本身** 在current branch。
2. 隨後 `:562-566` 雖只掃 `getBranch()`／ancestor IDs，但只加入／覆寫cache，**沒有撤销先前branch留下的同owner/cwd/session leaf values**。最後 `:574` 的 applySessionOverrides仍由 `getSessionConfig` 讀這個cache；`config.ts:281-285` 只驗cache key leaf在ancestor chain，不知道authority settings record是否仍在branch。
3. Session save `:871-874` 的data.leafId是**保存前的leaf P**，實際settings custom entry C則是P之後的child。因此「leaf key是ancestor」不足以證明C是ancestor。

**最小可推導行為：** 在persisted session的assistant leaf P，以public session save／或合法direct persisted envelope寫 `{leafId:P, config:{memory:true,compaction:"auto"}}` 得custom entry C；正常resolver於P-key建立override。使用真正Pi tree navigation回到P、或從P建另一個不含C的child：`getBranch()`不含C，但舊P-cache仍會被套用。當cwd==process.cwd()時，即使沒有warm cache，resolver的全歷史initSession也可重新從off-branch C匯入override。Pi `navigateTree` 對non-user entry確實branch到selected node並emit session_tree（installed `agent-session.js:3313-3351`），不是假設中的branch API。

**影響：** 新接線明說不import sibling/off-branch config（`:559-561`），而此路徑違反該承諾；rollback到保存之前仍可能啟用memory／改summary participation／worker models。這不會復活BH timing trigger，但可能在後續活動套用使用者當前branch未選的memory/provider configuration；本review沒有證明實際付費呼叫，也不把合理的ancestor inheritance一概禁止——必須有當前branch中的settings record作authority。

**最小修正／回歸建議：** host resolver先取得同一次public identity／cwd／leaf／branch snapshot，只由**active branch中的record**恢復；不要先由getEntries全檔還原，也不要讓未被active record證明的warm persisted cache授權effective設定。可使用owner/cwd/session限定的scratch projection或具record-ID/ancestry authority的cache；不要為此清所有extension/session caches、改host navigation或rewrite JSONL。保留new-session真正pending-unsaved設定的既有語意，但不要把任意initSession(stale/foreign)當host authority。

新增隔離真host回歸：保存後→navigate到保存前P→新sibling→回到C→reload，以及fresh resolver/cacheless的off-branch history；global/env baseline應在無active settings record時恢復，回C時exactoverride才恢復，原JSONL/config bytes不改。另驗same-ID不同cwd、empty/reset-leaf/new-session以及getBranch/getLeaf/getEntries lookup failure，不得沿用前一host的authority。Existing settings-session只驗兩次reload與Escape，沒有這個branch-back case。
