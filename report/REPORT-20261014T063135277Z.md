## 高優先候選說明

### 1. Schedule Prompt 成功統計提交

inline、subagent、command 三條路徑都有相同的 lastRun、lastStatus、鎖內 fresh runCount、nextRun 更新與 fire event。可將這段統計提交集中成私有方法；不合併工作執行或完成通知。不改既有 getNextRun 求值／错误時機、abort 檢查或 marker 順序；若 call site 已先算好 nextRun，可以直接傳入 helper 保持求值位置。inline success 僅代表 prompt 交付，不能升格成模型工作完成。

### 2. JSON Schema 單一 schema-position 遍歷

audit 和 usesPattern 依相同 SUBSCHEMA／SUBSCHEMA_LIST／SUBSCHEMA_MAP 遞迴，compileSchema 先 audit 後又 usesPattern。可由 audit 返回 pattern presence，省掉第二份 walker。最重要限制是不能因第一個 pattern 已找到就短路跳過其他 child 的安全 audit；不能把 annotation/default/enum/const 中的 instance data 當 schema。reference 展開的 admitExpandedSchema 語意不同，應保留。

### 3. File Tools 錯誤碼單一來源

22 個錯誤碼重複存在 union 和 Set 中。以 as const tuple 衍生兩者能消除漏同步風險，同時保留 FileToolErrorCode export 與未知錯誤碼的拒絕行為。這項範圍小，適合作為第一批實作。

- manifest 薄入口、guards、workers、來源 LICENSE 與持久化格式身份。
- owner/cwd/generation、reader 前後重驗、actual-close 和取消要求的分層。
- Pi Runtime admission 證據鏈及 session-wide reservations。
- File Tools hash、fingerprint、Windows rename retry 重驗。
- Web opt-in/runtime validation、來源 correlation 與外部 forced prompt 合成。
- Blackhole before/current branch 不同視窗與 null tombstone。
- PTY transport lifecycle／remote descendants unknown，以及 Note exclusive creation／碰撞規則。
- Skill Tools 實作已足夠簡單；GPT Speed 此輪未找到值得優先抽象化的候選。
