# Architecture

## One deployment unit, twelve local modules

The root `package.json` declares twelve local TypeScript `pi.extensions` entries at `./modules/<name>/src/index.ts`, plus two explicit npm dependency entries (fourteen total): seven current source snapshots (including PTY Terminal, the third-party Schedule Prompt and Blackhole) and five native modules (Note Tools, GPT Speed, the rewritten JSON Schema, Pi Runtime and Monitor). Thin default-export entries forward to existing implementations without moving guards, agents, prompts or workers. Web already uses this layout. There is no aggregator factory or plugin-manager abstraction. Pi controls discovery, ordering, resource filters, tool selection and lifecycle dispatch.

- `modules/subagents/extensions/subagent/` retains the `../../agents` relationship and `child-guard.ts`; bundled agents/prompts ship with the package.
- `modules/shell-tools/extensions/timeout-ms.ts` imports its adjacent MJS adapters and preserves host shell definitions.
- `modules/file-tools/extensions/file-tools.ts` imports the file-operation core; the real `src/diff-worker.mjs` ships unbundled.
- `modules/web-tools/src/index.ts` retains direct TS imports, lazy browser service, schemas and configuration example.
- `modules/note-tools/extensions/note.ts` is a native TypeScript extension, not an imported source snapshot. It registers only `note`, uses invocation `ctx.cwd`, creates category folders and timestamp-only-named (`TYPE-<UTC timestamp>.md`, without a title suffix) UTF-8 Markdown files with exclusive-create (`wx`), then returns a single relative path in text (only `{ relativePath }` in details/structuredContent). It has no settings or lifecycle resources; subsequent operations use File Tools. Hash provenance is recorded separately in `docs/native-modules.json`.

- `modules/schedule-prompt/src/index.ts` is the imported tintinweb/pi-schedule-prompt 0.4.1 snapshot (MIT, LICENSE preserved; the extension registers `schedule_prompt`, `/schedule-prompt` and the `scheduled_prompt` message renderer, starts a croner-based scheduler on `session_start` and stops it on `session_shutdown`). Local adaptations: Pi 1.0.0 `src/subagent.ts` hand-off below, plus a stability pass over `scheduler.ts`/`storage.ts`/`subagent.ts` (timer limits, contained timer errors, per-job overlap and concurrency caps, run timeout, session dispose, locked atomic store writes with corrupt-file quarantine, no self-load in child sessions; see docs/configuration.md). The Pi 1.0.0 change is in `src/subagent.ts`: `createAgentSession` takes `modelRuntime` instead of the removed `modelRegistry`, reusing the host runtime behind `ctx.modelRegistry` when reachable. Jobs with `model` run in-process (not through the Subagents argument builder). Its tests keep the source vitest runner (`npm run test:module -- schedule-prompt`); croner/nanoid are root runtime dependencies and vitest a root devDependency.

- `modules/gpt-speed/extensions/gpt-speed.ts` independently registers three speed commands, persists `pi-gpt-speed.mode`, resolves effective service tier from a strict model-ID pattern and displays it via Pi's status API. Its request hook shallow-clones only eligible OpenAI/Codex payloads. Pattern matching and downgrade are pure; selected preference survives model changes. No timers, provider registrations, model calls or source-project dependency. The existing `proper-lockfile` dependency coordinates global settings writes with Pi; synchronous critical sections contain no await. Hash provenance is in `docs/native-modules.json`; pi-codex-fast was a conceptual reference, not an imported source snapshot.

- `modules/json-schema/extensions/json-schema.ts` is a project-native, opt-in structured-output extension (formerly an import of @nqbao/pi-json-schema, since rewritten; see docs/native-modules.json). Flags are `--json-schema` and `--json-output`; zod 4 (`z.fromJSONSchema`) validates after `src/schema.ts` rejects constructs zod cannot enforce faithfully. It registers a model-only terminating `json_output` tool, strips assistant text blocks from finalized messages through the public `message_end` contract, and delivers at `session_shutdown`: a file (atomic temp + rename) or one JSON line written through the stdout stream's own prototype so the host's stdout redirection is not touched. Without a tool call it parses the last assistant text, then makes one bounded extraction request using the model that actually answered (virtual routers cannot be called directly). Existing tool selection stays authoritative; no global settings/auth persistence.

## Owner-scoped native Monitor v1

`modules/monitor/src/index.ts` registers three defaultActive:true tools without forcing the loadout or starting sources; host allowlists/exclusions/no-tools and manual deactivation remain authoritative. Explicit managed-child identity suppresses registration and rejects execution. A shared bounded core owns TTL, ordered stdout/WS data, coalesced readonly job snapshots, per-owner caps and agent_start/agent_settled submission scheduling. A generation-revocable Symbol rendezvous exposes narrow verified job projections in either load order, never extension factories, executable handles, raw query results, logs or cancellation. Command uses a Pi1.1.0-gated channel-aware Shell seam with trust-aware settings and installed-host resolver/environment/cancellation/close tracking; missing capability/version or legacy stdin transport fails closed, existing Shell execution stays unchanged.

The direct locked ws8.22 transport validates every DNS address, pins actual lookup, preserves hostname SNI/certificate validation, disables redirects/compression, enforces preallocation16KiB and never reconnects. No personal settings, provider calls or durable restart queue. Monitor custom-message details schemaVersion1 is submission evidence, not acknowledgment; actual close is not descendant cleanup. After submitted stop/expiry/fault requests, actual close has its own terminal event with real cleanup evidence and no data replay. Cross-source round-robin selects one event per source per round, prioritizes the first byte-blocked head next batch, and includes terminal receipt metadata with first representation; full JSON retains 32 events/32KiB and 30s throttle. Own URL metadata is redacted, but arbitrary source data and known URL echoes are not secret-scrubbed. Producer fixtures and narrow Blackhole handoff are in the Monitor README; this module does not itself modify Blackhole or certify compaction coexistence.

## Bounded error-aware recovery (Pi Runtime)

`modules/pi-runtime/src/index.ts` uses public Pi 1.1.0 events and `policy.ts`; no private-host mutation or provider replacement. Explicit repairable input errors create one composed `agent_before_settle` custom-message draft/continuation. Generic invalid-request, cybersecurity/policy and unknown failures require an idle actual TUI with dialog support (RPC/JSON/print refuse), purpose/scope clarification and explicit confirmation. Native transient retry, overflow and hard credential/quota failures retain host handling. Diagnostic data is bounded, common credential formats masked, and never treated as instructions or permission to evade safeguards.

Two reservations per task are persisted before submission in `pi-runtime-state`. Active-branch task selection is reconciled with all same-task reservations in the session, so tree navigation/reload cannot refund spend. One-use idle non-extension input→preflight→agent_start→finalized user-object admission creates a new uppercase task ID; handled/queued/preflight-failed input and custom continuation do not refill. Transformed/template/image admission is verified by phase/object identity rather than raw prompt-text matching, with duplicate user objects deduplicated. Public events cannot establish all idle SDK aborts. The six-file baseline has limited static acceptance (reviewer did not rerun tests); its prior 14-mode offline evidence does not certify root release/retry/Blackhole/overflow coexistence; its genuine TUI-approved path still requires the second model call. Model/tree/run/owner changes invalidate and dismiss confirmation. Boundary withdrawal or uncertain send consumes the conservative reservation; sendMessage is submission, not acknowledgement. No session storage means no recovery; corrupt/over-limit history fails closed. Original errors, usage and selected tools remain untouched; no automatic tool replay, polling or personal settings/auth edits.

Root dependencies/lockfile are authoritative: the four Pi development packages are fixed at **1.1.0**. Nested manifests preserve source identity/test commands only; do not install their dependencies independently. Host Pi/AI/Agent Core/TUI/TypeBox remain wildcard peers, not runtime dependencies; fixed dev versions are test baselines only.

Runtime dependency refresh: `diff` is pinned to 9.0.0 and `jsdom` to 30.1.1. The root Node.js engine range is `^22.22.2 || ^24.15.0 || >=26.0.0`, matching jsdom 30; older module README engine claims are historical source metadata, not the integrated package requirement. Source imports remain immutable; the development baseline is now Pi 1.1.0.

No source checkout, node_modules or build bundle is required at runtime.

Blackhole only replaces the summary in public session_before_compact; it installs no private inline adapter, completion trigger, polling or request wrapper. Pi may compact after final output and replay native callbacks. Earlier Blackhole midRun/threshold/minimal-tail timing and cut descriptions are historical, not active controls; Pi and the installed SDK are unchanged. The reviewed cosmetic-output adaptation fixes chronological branch traversal: start just before the successful compaction and scan backwards for the newest omitted non-aborted assistant text. A sanitized 16 KiB-bounded plain custom entry persists a display-only copy; its renderer works after resume and it injects no model messages. It does not restore complete raw-history display or backfill missing copies in existing sessions.

The source Vitest runner and fixtures remain imported. A root wrapper isolates HOME, credentials and bounds parallelism; a separate Pi 1.1.0 native-cut probe uses a readonly public preparation observer and public cut/token helpers on unedited fresh projections. It verifies exact native cut/tokens/input and whole tool pairs: a retained newest final is not copied, while only the newest actually dropped final is persisted/rendered after resume. All plain custom copies have zero LLM projection, duplicate events add nothing and providerCalls stays zero. The test-only observer is copied beside the production probe, not bundled as a user extension or personal-config dependency. Fixture green is not independent source review, project adoption or root release. All provenance hashes distinguish original imports from local adaptations. The upstream pnpm lock hash is recorded but no nested lock/dependency tree is imported.

Repository legacy-peer-deps prevents an extra host SDK from peer auto-install; it is not a compatibility guarantee. FFF native binaries require per-platform installation. Disable existing standalone resource declarations manually; personal preferences, memory, credentials and prior sessions remain untouched. Host integration environments explicitly set PI_BLACKHOLE_PASSIVE=true with empty auth.

## Allowlisted Blackhole notification evidence (2026-10-09)

`core/notification-evidence.ts` consumes persisted `custom_message`, not plain custom state: Shell terminal batches, Subagent task_result/query_result, Runtime diagnostics, Schedule subagent_done/error (including skipped), and recovery notices. Producer-specific validated details own structural status/exit/cleanup/snapshot authority; matching body supplies scalar public display only. Root/nested query lateUsage and snapshotUnavailable booleans preserve false without reviving failed answers. Recovery task state/outcome must agree with the finding and terminal relationship; processTreeState stays unknown. Exclude display copies, log_ready/control_result, start/inline markers, prompt/command/controls, private query/temp fields and credential objects. Common-secret scrubbing is not arbitrary-secret detection or prompt-injection immunity.

Hybrid search and `e:<persisted-entry-id>`/page use a separate stable namespace; numeric expand/#N remain message-only and unchanged. Default lineage and explicit all scope remain. No side index, raw JSONL rewrite, log/artifact access, job replay, provider call or cleanup. Selected data can be partial independently of producer outputTruncated; summary samples, selected projection and raw history are not equally complete. Snapshot opaque toolCall IDs (including `|`) are bounded separately from persisted entry refs; filtering/cleaning/clipping propagates partial.

Summary includes at most 16 recent refs/8,000 structural characters (1,600 per entry), isolated from goal/preference heuristics. Optional compaction details `blackhole.notificationEvidence` version 1 records actual fallback/trailing insertion offsets, length, SHA-256 and refs, without changing outer compaction v1/v2. Carry/strip requires matching latest raw compaction, stored summary/trailing and verified bounded span/digest/refs; only that span is removed and refs are reprojected against raw branch data. Markdown headers/identical quotations are not authority. No metadata means no carry/strip or legacy backfill. This is trusted-writer provenance, not an identity signature; compaction timing/tail remain unchanged.

The new evidence-only scanner bounds pre-parse lines to 64 KiB plus a 64 KiB chunk, at most 32 MiB read and 100,000 lines, skips oversized lines before JSON.parse and finally closes descriptors. Malformed/projection/line/entry/byte/payload reasons remain distinct. Already-host-parsed branch checks (64 KiB record/4 MiB payload) are projection bounds, not host parse protection; unchanged legacy generic recall can still use its old raw scanner. Paging reserves header/footer before exact body slices; only delivered body advances continuation. Insufficient budget returns isError/budget_insufficient, zero delivered chars and no next cursor; tiny text may be `!` with structured details. Unavailable refs return unavailable_in_selected_inspection with missing/excluded/ambiguous/uninspected possibilities, outcomeKnown:false and no cursor, not global absence. Zero disables text clipping only. Command evidence uses the same engine with its documented 48,000-character default rather than the live tool setting.

Offline default/append native compact/persist/resume fixtures concern the consumer only. They do not certify producer lifecycle, exactly-once/delivery acknowledgement, Runtime/Schedule operation, process-tree cleanup, paid providers, manual TUI or root release validation.

## Session-load background reconciliation (2026-10-08)

`modules/shell-tools/src/recovery.ts` is an intentionally shared pure projection/reconciliation/renderer helper, not a shared execution manager. Each module owns its binding and `pi-better-tools-background-state` append-only snapshots in the existing Pi session. Accepted intent precedes runner admission and managed allocation; identity enrichment and started/terminal/shutdown evidence follow. Only IDs, owner/canonical cwd/runtime, allowlisted states and exit/error codes are projected. No commands, prompts, results, control/query text or credentials are journaled. Empty SDK sessions and non-persistent sessions reject background admission: Pi 1.0.0 does not flush setup-only entries; no private host mutation, synthetic conversation, or separate restart queue is introduced. Later journal errors preserve real results and may leave incomplete historical evidence.

Session startup/resume/reload reconciles a bounded session-wide same-owner/cwd inventory without reading child-native files, locks or checkpoints. Newest authoritative evidence cannot be overwritten by older malformed snapshots; malformed newest evidence stays incomplete rather than falling back to older success. Legacy Shell receipts require a correlated assistant background:true call; command output is not lifecycle authority. Forks exclude unowned legacy inheritance. Persisted notice fingerprints in the active branch's compaction-aware buildContextEntries suppress repeated evidence, while changed terminal evidence can produce another notice. Notices removed from model context by compaction cannot suppress fresh context-visible evidence; no conclusions are inferred from compaction summary prose. Bounds are 100,000 entries, 4 MiB aggregate projected/parsed metadata, 32 KiB individual text, 128 jobs and 32 findings per notice; incomplete/omitted inspection is explicit. These are bounded in-memory scans of already loaded host history, not filesystem recovery or a guarantee against host compaction/retention losses.

Module notices (`background-runtime-recovery-shell` and `-subagent`) are model-visible custom messages with display:true and triggerTurn:false, not privileged system instructions or automatic model turns. Fixed English safety text plus compact finding JSON separates recorded terminal results, shutdown cancellation requests, unknown outcomes and unconfirmed starts from historical lastKnownState. The neutral bounded TUI expands full job/task/session IDs, reasons and next actions. No runner/registry is restored, child resume/control replay is forbidden, descendant-process state is unknown, and sendMessage return is not a durable delivery acknowledgement or exactly-once promise. Writer owner/binding fences prevent late callbacks from journaling into replacement sessions. Existing tools, activation, locks, timeout/usage and shutdown cancellation remain.

## Session-owned background execution (2026-10-05)

Shell `src/background-jobs.ts` and Subagent `extensions/subagent/background.ts` own separate bounded job registries, cancellation controllers and owner/generation fences. `background:true` returns acceptance, not completed tool usage/exit status; synchronous calls stay unchanged. Jobs live only while the original Pi runtime/session is alive. Completion is a model-visible custom `followUp` message with automatic turn triggering, not a privileged system instruction. Exit/reload/replacement cancel and suppress obsolete notifications; SDK callers must await runtime disposal. No daemon, durable restart queue, exactly-once delivery or provider/process-tree termination guarantee is introduced. Async Subagent/query usage is explicitly reported rather than falsely attributed to host totals.

Shell completions accumulate in the owned registry while the agent run is active instead of prequeuing a separate followUp for every event-loop completion. `agent_start` sets the activity latch; `agent_settled` clears it and schedules a single immediate that submits all currently completed pending jobs in one unchanged custom-message payload, including aborted runs. Neither `agent_end` nor `agent_before_settle` dispatches prematurely: retries, recovery and other extensions' queued continuation may still be active. Preflight `before_agent_start` does not latch activity because failure there need not emit settlement. Idle completions still coalesce within an event-loop boundary; jobs that finish after submission form the next batch. This is not a global model/compaction mutex: manual compaction/tree operations retain host delivery behavior, avoiding indefinite waits for idle events they need not emit. Owner/generation and synchronous-reentry fences protect dispatch; synchronous submission failure preserves the batch and its retention protection. Submission is not delivery acknowledgement. Pending results cannot be evicted; 32 wholly active/pending records refuse new admission. UI active counts, tool schemas, execution, cancellation and timeout remain unchanged.

Background Subagents retain the existing child argument builder and guard but use a correlated RPC stdin/stdout transport; synchronous dispatch remains JSON print. Child identity is verified by startup guard plus `get_state`, with canonical input logged consistently for wire/native digest. Completion notification follows transcript finalization, native checkpoint commit, child cleanup and writer release. Recursion exclusion now includes all four Subagent tools. Per-task runtime/status exposes log paths only after allocation; queued/chain tasks do not claim files exist.

Control is literal FIFO delegated user input consumed at safe loop boundaries, with queued versus applied/unknown delivery evidence. Query uses a token-bound IPC bridge to make an isolated in-memory, tool-free request from a canonical safe prefix; it never forks/rewrites the managed native file or invokes mainline hooks. Provider metadata and context edits/compaction are replayed, unsafe snapshots fail closed. Query usage, stale-snapshot metadata, cancellation and leases are independent; abandoned resources retain permits until terminal evidence/actual child close. Query tool-call streaming aborts before dispatch.

The owned Subagents module adds no history-reading tool; the separately selected local Blackhole extension provides its own recall tool. `read` keeps its original target and offers advisory same-directory-final/wait guidance only for missing managed `.partial` log paths. Rename/commit semantics stay unchanged; permission/probe failures never imply completion. Offline actual-host tests verify control/query isolation and automatic parent follow-up after managed commit; they do not certify real-provider behavior or the new capability on older hosts.

## Lifecycle and compatibility limits

0.99.1 → 1.0.0 的已使用 hook declarations、dispatcher 與 Agent Core loop 無契約變更；不因此移除 boundary composition 或 Web 的 abort-on-conflict。1.0.0 新增 defaultTools reload／pending tool restoration，以及排除 hidden tool snippets 的 host 行為。`defaultTools` 不限制 default-active extension tools；嚴格 allowlist 使用 explicit `tools`／`--tools`。Subagents durable `hostContract: "0.99.1"` 是格式身份，不是目前 SDK 版本。

Resource factories only register behavior. Web launches browser lazily; shutdown/reload releases owned resources. Different packages with the same tool names are not deduplicated by package identity, so old standalone extensions must be disabled.

Parent-only `-e` paths do not automatically propagate to children. Moving bundled agent files can invalidate saved managed-session fingerprints; no automatic migration is added.
