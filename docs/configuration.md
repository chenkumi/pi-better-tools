# Configuration compatibility

No settings are renamed or automatically migrated. These namespaces are module identities, not the root package name.

| Module | Debug setting | Setting source | Diagnostic location |
| --- | --- | --- | --- |
| Subagents | `pi-subagents.debugLog` | global agentDir/settings.json; honors `PI_CODING_AGENT_DIR`, reread per call | `~/.pi/logs/pi-subagents/` |
| Shell | `pi-shell-tools.debugLog` | fixed `~/.pi/agent/settings.json`, reread on failure | `~/.pi/logs/pi-shell-tools/` |
| File | `pi-file-tools.debugLog` | global agentDir/settings.json; honors agentDir override, read when extension loads | `~/.pi/logs/pi-file-tools/YYYY-MM-DD.jsonl` |
| Web | `<cwd-basename>.debugLog` | fixed `~/.pi/agent/settings.json` | `~/.pi/logs/<normalized-cwd-basename>/tool-errors-YYYY-MM-DD.jsonl` |

Web cwd basenames recognize explicit Windows drive/UNC absolute paths on all hosts; other paths follow native host semantics (including literal backslashes in POSIX filenames). NFKC/safe-character normalization, length bounds and Windows device-name protection apply before selecting the opt-in key and log directory.

Debug logs are opt-in. Subagent/Shell/File diagnostics may contain prompts, commands or file content. Web omits tool parameters but errors can still contain sensitive information. Log retention varies by module; do not claim a shared retention policy or automatic cleanup.

## Local Blackhole and external npm Pi extensions

The suite loads twelve local TS entries and two npm extension entries (pi-open-tui 0.3.11 and @ff-labs/pi-fff 0.11.0). Blackhole 0.5.12 is a reviewed source snapshot at `modules/blackhole/`, loaded through `modules/blackhole/src/index.ts`; root manifest/lock no longer depend on npm pi-blackhole. Root npm ci remains required for runtime dependencies, with no automatic personal settings edits.

Personal settings remain independent: open-tui uses `~/.pi/agent/open-tui.json`; Blackhole retains `~/.pi/agent/pi-blackhole/pi-blackhole-config.json`, project overrides and existing memory/state paths; FFF retains its own configuration/environment/native data. Credentials and old sessions are not copied, overwritten, migrated or backfilled. Review filters to disable standalone copies and avoid duplicate hooks.

### FFF override and File Tools

File Tools registers read/write/edit/ls only; it no longer occupies grep/find. To use native FFF under the builtin names, set `{"mode":"override"}` in global `<agentDir>/pi-fff.json`. Existing other fields must be retained. CLI `--fff-mode` overrides `PI_FFF_MODE`, which overrides the file; a resumed session's last `/fff-mode` selection overrides startup resolution. `/fff-mode override` followed by `/reload` changes the current session, not the config file. No package-load migration or third-party code change. grep/find then use FFF schemas/renderers, not the former host-compatible wrapper; ffgrep/fffind aliases become inactive. If FFF indexing is explicitly disabled for the cwd (home/root opt-outs), upstream retains the FFF alias names rather than taking over builtin search. Read-only/no-tools/exclusions remain host-controlled.

### Blackhole display-copy correction

`showPreCompactionMessage: true` permits one plain `blackhole-pre-compaction-output` custom entry after successful Blackhole compaction. Its selector scans Pi's chronological `getBranch()` backwards from that compaction and ignores retained entries, later messages, aborted assistant output and non-text content. The copy is terminal-sanitized and capped at 16 KiB; it persists for resume with a `[Previous output — display only]` renderer, but contributes no model messages. The correction does not restore the whole history or change compaction boundaries.

Current ownership is Pi-only: Pi's compaction.enabled/reserveTokens/keepRecentTokens (including modelOverrides) control native timing and retained boundary. Blackhole participates only in Pi's public session_before_compact; compaction:auto plus compactionEngine:blackhole selects the Blackhole summary, not a separate trigger. manual/off/pi-default affect summary participation but cannot disable Pi auto; explicit /blackhole remains a public native request alias. Pi may compact after final output and replay callbacks. Older BH midRun/threshold/minimal-tail/retained-output knobs remain readable but do not control timing/cut; earlier descriptions and before-request overrides are historical, not an adoption recipe. The display copy only applies to a genuinely dropped assistant; an already retained newest final receives no extra copy. Old missing copies are not backfilled.

Current precedence is unified global/legacy → project → defaults/migration → PASSIVE defaults once → explicit environment → current session override → environment-pure validation. Opening/cancelling settings does not reapply PASSIVE over explicit environment/session values. The historical precedence warning is cleared within the limited settings/migration reviews, latest `report/REPORT-20261009T200405430Z.md`; core acceptance remains separately scoped by `report/REPORT-20261009T193032883Z.md`. Reviewers did not rerun tests; these are not whole-source safety, adoption or release certifications. Existing auto/blackhole keys govern summary participation only: no new adoption/timing setting, before-request override, .pi/global edit or guessed Pi percentage is introduced.

Blackhole memory workers may incur model costs normally. Host integration tests set `PI_BLACKHOLE_PASSIVE=true`, empty auth and isolated HOME/agentDir/workspace; no test setting is written into personal configuration. Upstream version/peer declarations are historical metadata, not certification beyond the project's Pi 1.1.0 baseline. FFF native dependencies must be installed per target platform; fonts/browsers/OS libraries remain user-managed.

### Blackhole canonical writes and session authority

Existing load/read/reload is read-compatible and diagnostic, not an automatic file or historical JSONL rewrite; the legacy UI rows are readonly explanations. Legacy `passive`/`noAutoCompact`/`overrideDefaultCompaction` are not bulk-delete targets; canonical precedence, false values and environment/session overrides must be checked before any separate semantic conversion.

Status X and memory status use public context usage/capacity or unknown; **native capacity is not a trigger threshold, and native trigger budget is unknown**. Legacy preset ratios, transcript counts and model guesses cannot supply a Pi threshold.

Persisted session overrides require fresh public owner/file/leaf/branch snapshots and ancestry of the actual saved settings record, not a warmed pre-save cache or sibling/descendant full-history record. Lookup failure/foreign initialization falls back to lower file/environment layers. Explicit Session Reset/public session delete appends a branch-local empty override record, preserving older records; navigating back can restore their overrides. Genuine owner-pending data survives append refusal/unverifiable acknowledgement; unmaterialized reset clears only its owner sentinel. Observable still-existing file refusal, cancel/callback failure and refused writes retain original buffers/dirty edits; these are supported postconditions, not atomic filesystem transactions or rollback across external writers.

Legacy warnings are deduplicated only after public `hasUI === true`, a callable `ui.notify` and successful delivery; missing UI/callback, callable no-UI no-op or throws do not count as delivery and may retry. The bounded 512-key set includes cwd and survives reload; warning callbacks that navigate branches reproject final effective values from lower layers. See `modules/blackhole/docs/CONFIG.md` for the current local contract, separate from historical upstream timing prose.

### Blackhole notification evidence and budget

No new tool schema, setting, storage or compaction timing. Hybrid recall selects allowlisted custom_message notifications (Shell completion, Subagent task/query, Runtime diagnostic, Schedule subagent result and background reconciliation); file/touched modes do not index them. Use `query:"e:<persisted-entry-id>"` with `page`, default active lineage or explicit scope:all; legacy message-only #N indices remain stable. Display/state entries, private query/temp fields, prompt/command/controls and credentials are excluded. Validated details alone provide structural authority; body is scalar public display, not instructions. Query lateUsage/snapshotUnavailable false values remain distinct from missing and do not revive failed status.

Existing `recallResponseMaxChars` / `PI_BLACKHOLE_RECALL_RESPONSE_MAX_CHARS` default is 48,000; 0 is unbounded selected text, not unlimited projection/scanning. Command e: pages use the shared engine at the documented default rather than the live tool cap. Exact delivered body determines continuation; insufficient envelope/body budget yields isError with budget_insufficient/zero delivery/no next page. Tiny text can be `!`; consult details.notificationEvidence or raise the budget. Unavailable IDs yield unavailable_in_selected_inspection/outcomeKnown:false and missing/excluded/ambiguous/uninspected possibilities, no body/cursor; absence in selected inspection is not absence in raw history.

Selected payload can be partial even when producer outputTruncated=false; summary (16 refs/8,000 structural chars) is a sample, not raw history. New compactions can attach optional verified insertion span/hash/refs metadata; carry/strip never trusts prose headers, and old unverified summaries are not backfilled or rewritten. Evidence-only pre-parse scanning limits lines to64 KiB, reads to32 MiB and lines to100,000 with distinct incomplete reasons; unchanged legacy raw scanner and host-parsed branch history are outside that I/O guarantee. No log reads, job restart/replay, provider calls or cleanup. See `modules/blackhole/docs/recall.md`; offline consumer probes do not validate producer lifecycle/exactly-once, real providers or manual TUI.

## Subagent RPC startup diagnostics

No new setting or persistence/schema version. RPC startup errors keep their original cause/code and append bounded English failure-time observations: parent phase/checkpoint, elapsed monotonic milliseconds, RPC command ID/deadline/write completion/matching reply, guard milestones, child-reported Pi SDK/Node versions, spawn/close and stdout/stderr byte counts, UI-request/unmatched-response counts, and up to 24 timeline events with omission count. CLI identity retains only executable and a recognizable first JS/TS script path (512 characters each), never full argv/environment, tokens, RPC parameters or reply bodies. Missing child versions are `unknown`, not inferred from the parent.

Guard milestones use the existing token-bound RPC IPC channel with strict field/enum/version/error-code allowlists, duplicate suppression and best-effort sending; they are diagnostic reports, not authorization. All actual startup-file/model/trust/native identity/checkpoint checks remain. No milestone means *not observed*, not proof that the guard never ran. Guard success does not prove all other session_start hooks or the RPC loop are ready. Write completion does not prove the child read the command; a requested initial prompt does not prove acceptance/model completion. Unknown causes remain explicitly unknown, with stage-specific checks instead of naming an unseen faulty extension.

Failure-time evidence is frozen before termination and kept separate from cleanup observations; a cleanup-induced exit is not misreported as the original cause, and child close is not proof of process-tree termination. The 30-second response budget still includes startup/queue time; no added timer, deadline change, automatic retry, status change or ownership release. Error text is available without debugLog; existing run diagnostic/debug-v1 errorMessage strings retain the same observations plus embedded `Startup observation data` JSON. Debug capture stays failure-only/opt-in; original prompt/stderr diagnostics can still be sensitive. Historical logs/settings/auth are never rewritten.

## Subagent model and thinking selection

Omit `model`, `provider` and `thinkingLevel` overrides unless explicitly requested by the user or a skill. For initial single/parallel/chain dispatch, resolve the model in the parent registry **before** checking its supported thinking levels. Unknown or ambiguous model IDs and unknown/unsupported thinking strings are ignored, not dispatch errors. An explicit `provider` only permits an exact lookup on that provider. A single model string prefers a registered `provider/model` interpretation; otherwise its complete bare ID prefers the current provider, then requires a unique registry match. For slash-containing bare IDs that collide with a registered qualified selection, add the full provider prefix to disambiguate. Canonical `provider/model` is passed to child Pi.

Ignoring an override is equivalent to omitting it: use a registered agent model or inherit the parent model. Parent-model inheritance also inherits parent thinking, normalized with the host's thinking-level helper. A valid model override or agent model without a valid thinking override omits `--thinking`, letting child Pi use its default. The thinking schema accepts a string so unknown names can reach this fallback rather than failing enum validation. Invalid parameter shapes and provider/model combinations remain subject to existing validation.

Continuation is requested through `subagent_message` with a saved `subagentSessionId`, literal `message` and optional display-only `title`. The system routes a persistent message to control or asynchronous resume; it never silently replaces saved model configuration. Child startup guard/trust/checkpoint checks remain strict. Registry checks do not issue provider requests or validate credentials, and parent-only provider registrations may still be unavailable in the child. No settings or auth files are changed.

## Subagent display title

Optional `title` describes the subagent's work in at most 50 Unicode code points, not UTF-16 code units (combined emoji/accents can contain multiple code points). Single creation uses the top-level field; parallel/chain items accept their own title, falling back to a top-level batch title. `subagent_message` accepts an optional display title; a resumed invocation uses the new title without changing saved configuration. Blank/control-only titles, over-50-code-point titles and raw UTF-8 over 4 KiB are rejected before dispatch. Runtime repeats the length check because host schema counters can group some combining sequences. Normal Pi argument normalization remains unchanged: optional null can be omitted and number/boolean can become strings; direct execute rejects non-string titles. Call, running and final TUI displays retain agent identity and show sanitized titles; old calls/results without titles retain their former display. Title stays in parent tool arguments/details, never replaces `task`, enters child argv/prompt, or changes the saved managed configuration. Resume requires a fresh optional title; it does not read one from prior runs. Reload to activate the schema/renderer changes; no new settings.

## Background execution and interaction

No new global settings or service. On the main agent, `background` is an optional boolean on `bash`, `powershell` and create-only `subagent`; omission/false preserves synchronous execution. Managed children with the explicitly marked handshake use foreground-only same-name Shell definitions instead (see below). Persistent continuation through `subagent_message` is asynchronous, returning an acceptance receipt and later followUp; it does not accept configuration overrides. Reload the extensions after local changes; reload, exit and session replacement cancel jobs and discard old-owner notifications. Embedded SDK hosts must await `AgentSessionRuntime.dispose()`; directly disposing only the session does not emit extension shutdown. Cancellation requests cannot guarantee process-tree or provider-side termination.

- Shell acceptance returns `{jobId,status:"running",liveLogPath}`, without a pretend exit code. `shell_job_status` / `shell_job_cancel` accept `{jobId}` and are `defaultActive:false`: select them explicitly in the loadout, `defaultTools` or `--tools`. No tool selection is forced. Logs are session-local temporary files (1 MiB cap), removed on eviction/shutdown; output may be truncated and sensitive. Eight active jobs and 32 retained records bound memory/resource use.
- Shell completion batching needs no new setting: while the main agent run is busy, terminal results stay local rather than becoming separate queued notifications. Actual agent_start latches activity; final agent_settled schedules one immediate to send all currently completed pending jobs together, including aborted results. Preflight failures do not latch activity, and pre-settle boundaries do not preempt other queued continuation. Still-running jobs are not awaited, and results completed after submission become a later batch. The footer remains an active-job count, not a pending-message count. Manual compaction/tree delivery remains host-controlled rather than a new model mutex. Pending batches retain their records against eviction; if all 32 records are active or pending submission, new work is refused. Synchronous send failures wait for another lifecycle opportunity; no polling/retry timer, delivery acknowledgement or exactly-once guarantee is added.
- Successful background Subagent creation returns a job with per-task IDs/status and actual managed `subagentSessionId` values allocated before acceptance returns. A queued identity is not an interactive child or ready checkpoint. `liveLogPath` appears only after the log exists; queued/chain tasks retain `logPending` until then. `subagent_status` / `subagent_cancel` keep `{jobId}`; `subagent_message` uses `{subagentSessionId,message,mode?:"control"|"query",title?}`, with mode defaulting to control. Explicit tool allowlists must include the desired tools; message now also authorizes starting a new invocation on that owned session, not arbitrary new-agent creation. Read-only/no-tools/exclusions remain authoritative; no implicit activation. Children exclude all four subagent tools. Up to 32 submitted tasks process-wide share the existing eight active-child permits; 64 retained jobs.
- Read logs with existing `read`, not a new inspect tool. Managed `runs/<taskId>/transcript.jsonl.partial` stays constant during execution, renames to same-directory `transcript.jsonl`, and completed result points to the conversation aggregate. Only missing managed `.partial` paths receive advisory retry/wait guidance. No automatic target substitution, permission-error inference or completion inference; aggregate offsets differ from run offsets.
- Task/query results are custom model-visible `followUp` messages with `triggerTurn:true`, not system-role instructions. Busy agents queue the result; idle agents continue automatically. `sendMessage()` has no delivery acknowledgement; status remains the result authority. Background subagent/query usage is reported separately, not settled into host session totals.
- Expected message refusals (busy/not-running/capacity/cancelled) retain status:rejected/errorCode/observedState/nextAction and preserve isError:true while displaying warning text 'Query/Message not accepted'. The native tool background remains error-colored by Pi; presentation never changes the model-side error flag; they are not accepted delivery or successful queries. Security/configuration/checkpoint/unknown faults remain errors. Historical result flags are not rewritten, so old native tool backgrounds remain host-controlled.
- Persistent messages are routed using current runtime/ownership/checkpoint evidence, not historical capability snapshots. A running interactive invocation receives control; an eligible ready session resumes asynchronously with the same session ID and new job/task IDs. Queued/startup/finalizing/canceling/busy sessions are refused without a cross-invocation waiting queue. Blocked or invalid-checkpoint sessions are not silently recreated. Responses expose the selected action and actionable refusals. Once a control is accepted, unknown delivery must never cause automatic resend via resume.
- Control is literal delegated user input, FIFO at assistant/tool boundaries, never a tool interrupt. `accepted` / `queued` do not establish `applied`; transformed/unmatched canonical input can be `delivery_unknown` and must not be blindly resent. Query supports a currently interactive child or a verified ready checkpoint and never auto-resumes mainline work. Ready query holds an exclusive non-recovering read lease, starts a guarded disposable worker on private copies, and replays the hash-checked frozen checkpoint rather than startup mutations. Its independent job/task IDs support status/cancel; tasks carry readOnlyQuery:true with canMessage:false and no invented subsession log. Only query_result is published, after actual worker cleanup/read-lease release for normal terminal replies. Parent background persistence is required; another message on that session is refused while leased. Original manifest/native/transcript/runs remain unchanged. It runs a tool-free ephemeral in-memory snapshot request using the child's verified model/config; neither question nor answer enters its mainline. A safe-prefix snapshot may lag a running tool. Each query is bounded to 30 seconds / 2048 requested output tokens / 64 KiB streamed output, with separate usage and best-effort abort; no fallback to parent credentials/model.

Complete contracts and additional limits: `modules/subagents/README.md`, `modules/shell-tools/README.md`. New interactive/background behavior is tested on offline Pi 1.0.0 only (the only supported host); real providers have not been verified. Ordinary print-mode CLI shutdown cancels pending jobs; use interactive/RPC or a live SDK runtime when results need to return later.

## Pi Runtime recovery

Native entry `modules/pi-runtime/src/index.ts`; defaults enabled with 2 recovery reservations per recognized user task, shared by automatic and manual feedback. `/runtime-recovery status|on|off` changes only session/branch state, never global settings; off/on does not refill spend. `/runtime-recover <legitimate-purpose and authorized-scope clarification>` requires 8–4096 characters, an idle actual TUI (ctx.mode:tui plus dialog support; RPC/JSON/print refuse even if they expose dialog methods), remaining budget, same model/owner and explicit human confirmation. Explicit invalid arguments/tool JSON may automatically continue once per diagnostic; generic invalid-request, cyber/policy and unknown errors remain paused for review. Host retry/context/auth/quota handling remains separate. Reservation snapshots are session custom entries, not model messages; task spend is reconciled across branches on tree/reload, and corrupt/over-limit inspection disables recovery. Sanitization is bounded common-secret masking, not DLP; raw host errors remain. ## Tool TUI rendering

The original 15 interactive function tools have call/result renderers, including delegated host renderers. File errors show operation/code/message/recovery; successful read and image handling remain host-provided. Write success shows bytes with path/hash on expansion. Note previews category/first line instead of the full document. Web summarizes sources, warnings and truncated-output paths; expansion shows external/untrusted text. The seven PTY tools summarize session/target/local transport PID, bounded terminal text and transport exit/timeout/release; ANSI/control sequences are stripped only for display, write input and spawn args/env are not previewed, and remote process-tree termination is never inferred. Renderers do not change model-visible content/details/structuredContent, activation, trust or tool execution. No new settings are required; reload the extension to load local changes. The five added background management/interaction tools have bounded, control-safe call/result renderers, hide submitted control/query text and never infer process-tree termination. Print-only `json_output` deliberately has no TUI renderer; OpenAI native search is not a Pi function tool.

## Note Tools

No settings, debug namespace or global storage. `note` accepts `{ type, content }`; the five categories map to invocation workspace directories `plan/`, `issue/`, `research/`, `report/` and `task/`. File I/O failure is an error and may leave a partial newly created file; cancellation is checked before writing, not used to interrupt or undo a started write.

Select/filter `modules/note-tools/extensions/note.ts` with the usual Pi package filters. Include `note` in explicit tool allowlists; exclusion/read-only/no-tools stay authoritative. No automatic settings migration or forced changes to Pi's active tool selection are performed. Existing directory symlinks/junctions follow OS semantics, not a sandbox boundary.

## JSON Schema delivery

Opt-in entry `modules/json-schema/src/index.ts`; CLI-only flags, no global settings/auth changes. `--json-schema` must be a JSON object schema with `type: "object"` and activates the feature. `--json-output <path>` selects file delivery; without it the result goes to stdout. Relative paths resolve from the working directory and missing parent directories are created. File output is a same-directory temporary file plus atomic rename; a failed run keeps the previous file, but always check the exit status.

stdout delivery supports print mode with exactly one ordinary prompt: one compact UTF-8 JSON line after the run, diagnostics on stderr (prefix `pi-json-schema:`), nonzero exit on failure. TUI/RPC/`--mode json` are rejected before any model request. Assistant text blocks of final messages are removed in this automation mode so stdout carries only the result. Separate stdout from stderr and inspect the exit code before parsing.

Fallback is always best-effort: parse the last assistant message's JSON and validate; otherwise one extra model extraction request (60 seconds, no retries) using the model that actually answered. A disabled `json_output` tool blocks the extraction request, not validation of direct text JSON. Invalid results, no result, error/aborted runs, SIGTERM and conflicting repeated results fail without delivering anything. The extension never calls `process.exit()`. Extraction usage is not added to session totals. Supported schema scope and caveats: `modules/json-schema/README.md`.

Schema safety: enum/const sibling constraints that zod ignores and conflicting types fail at startup. pattern/patternProperties use a conservative <=200-character linear subset (no groups/alternation/counted repeats; at most one quantifier with leading ^) to protect Pi's synchronous pre-execute validation. Accepted pattern schemas also use a reusable cancellable pool (2 s compute budget, max 4 workers and 256 queued validations); startup has a separate bound, aborted/faulted workers retain capacity until termination is confirmed, and shutdown drains the pool. Worker faults do not deliver data. See the module README for examples and compatibility limits.

## PTY targets

入口 `modules/pty-terminal/src/index.ts`。`pty_spawn.target` 預設 `local`，WSL／SSH target 讀取 Pi 的有效 `pi-pty-terminal.targets` settings；專案覆寫受 host trust 控制，修改設定後 `/reload`。不直接讀取或寫入真實 SSH/auth/settings。

```json
{
  "pi-pty-terminal": {
    "targets": {
      "linux": { "transport": "wsl", "distribution": "Ubuntu", "cwd": "/home/user/projects/pi-better-tools" },
      "macos": { "transport": "ssh", "host": "mac-dev", "cwd": "/Users/user/projects/pi-better-tools" }
    }
  }
}
```

`local` 為內建保留值。遠端 cwd 必須是絕對 POSIX 路徑；工具 cwd 覆寫設定 cwd，env 只轉送明確指定的值。WSL 僅 Windows，SSH 使用既有 host alias／key／agent、`BatchMode=yes`、15s ConnectTimeout，保留 host-key policy；先由使用者確認 known_hosts。需要遠端 POSIX login shell、sh、env；host/target 欄位不接受自由 options 或密碼。未配置 target／錯誤設定 fail closed，不退回 local。

#### PTY 環境變數過濾（選用，`pi-pty-terminal.env`）

預設不變（本機 PTY 繼承整份 `process.env`）。在 Pi settings 同一 `pi-pty-terminal` 命名空間加入 `env.allow`／`env.deny`（變數名稱或結尾 `*` 前綴，如 `LC_*`、`AWS_*`）後才啟用：`allow` 存在時只傳入符合者（空陣列＝一個都不繼承），`deny` 在其後移除符合者；Windows 不分大小寫。設定來源為 trust-aware 的有效 settings（未信任專案層設定由宿主排除），每次 spawn 重新讀取；無效設定（型別錯誤、未知鍵）使 `pty_spawn` 失敗，不退回不過濾。只過濾繼承環境（含 WSL／SSH client 程序，Windows 請保留 `SystemRoot`、`PATH`）；`pty_spawn` 明確指定的 `env` 一律傳入。這是降低意外洩漏的衛生措施，不是 sandbox。詳見 `modules/pty-terminal/README.md`。

`npm ci --ignore-scripts` 後執行 `npm run pty:install`，只 rebuild node-pty 原生依賴，無 prebuild 時需編譯工具。根與隔離 production manifest 的 npm 12 allowScripts 僅核可固定 node-pty@1.2.0-beta.14；npm-run adapter 僅移除 inherited allow-scripts env key，以 active npm CLI／Node subprocess 執行，不修改全域 npm 設定或核可任意 scripts。一般 consumer parent project 仍須自行核可 native setup。PTY spawn 不證明連線成功；用 read/wait_exit 檢查輸出與 transport 結束碼。sessionId 綁定 target，其他 file/shell 工具仍是本機。session shutdown 等待 matcher workers 終止並走確認 exit 的 kill 路徑（Windows 無 signal，POSIX SIGHUP 必要時 SIGKILL），未確認退出者保留 ownership 並回報錯誤，不虛構 exit；不保證遠端背景程序停止。waitFor 在可終止 worker 中比對（單次最多1s，最多16個）；oversized 完整 escape 序列明示丟棄並推進 raw cursor。無自動 Git 同步；完整契約及 buffer 限制見 `modules/pty-terminal/README.md`。

Subagent temporary prompt/task creation and cleanup use cancellable bounded IoGate operations; already-started OS writes may settle later and clean their own directories without spawning after cancellation. Detached retained query receipts reconcile late terminal/close cleanup evidence within their original generation, without reviving answers or double-counting usage.

## Schedule Prompt

Local deadline adaptation: optional `CronJob.endAt` is stored as a UTC ISO timestamp in the existing version-1 store (no migration). `schedule_prompt` add/update accepts an ISO timestamp with seconds and explicit `Z`/`±HH:mm`; add omission means unlimited, update omission preserves it, and update `endAt: null` removes it. New deadlines must be future; once schedules must be strictly before the cutoff. At `now >= endAt` no new delivery/agent start is admitted, enabled becomes false and nextRun is cleared without changing execution statistics. Tool/UI enable rejects expired or invalid deadlines; extending/clearing does not implicitly enable a job. The add UI offers an optional deadline; list/widget/selected-job details show it. Existing jobs without the field retain their behavior.

A separate deadline timer (wall-clock recheck segments capped at 60 seconds) and dispatch guards cover sparse cron/interval ticks, delayed callbacks and restart. Expiration re-reads deadline/scope under the existing storage lock and requires acquiring that lock (as do all mutations and corruption recovery); failed persistence stops local scheduling and reports an error rather than allowing an expired trigger. Shared sessions still do not provide exactly-once execution or strong transaction guarantees. The in-process runner also rechecks after asynchronous initialization immediately before `prompt()` admission; expired setup is disposed/skipped without execution statistics or parent notification (once auto-disabling after admission does not itself block initialization). Already-started prompts may finish/notify; an inline message delivered before cutoff may be processed afterward. This is not forced cancellation or a real-time hard stop. Pi must be open for timers to act; sleeping, blocked event loops and clock changes may delay persisted disabling, not justify catch-up execution. Disabled jobs still follow existing cleanup-on-exit policy. Reload after hand editing; older/mixed extension versions ignore endAt and cannot guarantee enforcement. Details/examples: `modules/schedule-prompt/README.md`.

Settings keys and storage are unchanged from the source: `widgetVisible` and `defaultJobScope` (`"session"` default | `"workdir"`) in `<cwd>/.pi/schedule-prompts-settings.json` (written by `/schedule-prompt` → Settings), with optional manual global defaults in `<agentDir>/schedule-prompts-settings.json` (never written by the extension; the project file overrides it). Jobs live in `<cwd>/.pi/schedule-prompts.json`; session-bound jobs fire only in the creating session. Reload after editing files by hand. Jobs only fire while a Pi session is running; due jobs may call a model and incur cost. A job with `model` runs in an in-process Pi session via the host `ModelRuntime` (credentials from Pi, not read by this extension); it does not use the Subagents module's child process, guard or limits, and `abort()` is a request, not proof that all work stopped. Stability limits (local adaptation): intervals are capped at about 24 days (Node timer limit; use cron or a one-shot time for longer waits), a model job never overlaps its previous run, at most 4 in-process runs are active (extra ticks are skipped with an error event), and one run times out after 30 minutes. A provider error stop is recorded as an error, not a success. Concurrent pi processes in one cwd serialize writes and corruption recovery with an owner-token `<cwd>/.pi/schedule-prompts.json.lock` directory. Contention fails immediately; lock age is never used to steal ownership and writes never proceed unlocked. A crashed owner's leftover lock requires manual removal only after verifying no writer remains; only a missing store (ENOENT) is treated as empty. Other read errors refuse mutation; malformed content must be successfully moved to `schedule-prompts.json.corrupt-<timestamp>` before recovery, and failed quarantine preserves the original. Disabled-job cleanup faults cannot skip scheduler/widget teardown, and cron validation creates no timers. Only the owning token releases the lock; inline queue semantics remain unchanged. Malformed job entries are ignored with diagnostics instead of crashing every operation; valid version-1 entries remain usable. A child session never loads this extension, even with `extensions: true`. No settings or auth files are changed by tests: they use isolated temp workspaces.
