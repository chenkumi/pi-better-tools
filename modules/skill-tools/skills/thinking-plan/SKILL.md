# 釐清想法與系統模型

釐清使用者、問題、核心流程與系統邊界。需求已明確時可直接規劃；不要求先做研究或草稿，也不把探索擴大成實作任務。

## 探索與收斂

1. **理解需求。** 記下使用者要解決的問題、預期成果與已指定的選擇。相關專案事實先自行查閱；查不到的必要資訊與真正影響方向的決策才詢問。依資訊缺口選擇提問方式，避免重問已有答案。
2. **形成模型。** 依需要釐清角色、核心使用情境、資料概念與關係、範圍及外部互動。區分既有系統事實與提案；邊界應有明確責任與互動，無須假設各部分完全獨立。
3. **處理取捨。** 存在重要分歧時說明可行方向、影響及建議。相依決策按順序處理；可一起回答的問題可合併。多子系統可先建立整體模型，再按使用者優先順序深入，不強制每個子系統重跑技能。
4. **確認與保存。** 每段收斂結果立即保存至文件，不等到最後。需由使用者決定的範圍或方向取得答案後標明確認依據；既有明確指示直接沿用，不要求重複整份核准。未回答的選擇保持待決，不代為宣稱定案。

## 最終輸出內容

依任務保留有用的段落：問題與成果、角色與流程、核心概念、系統邊界、取捨與決策、待查證或待決事項，以及修訂紀錄與下一步。重要結論使用 `M1`、`M2` 等 ID，連同理由與來源保存；已明確排除的範圍應記錄，不為填格式而創造排除項。

交付前檢查流程、概念與範圍是否一致，使用者決策是否如實保留，假設與未確認提案是否清楚標示。只解決會影響理解或後續工作的歧義。

## 交付

交付前核對結論、來源、確認狀態與附件均已保存且可讀。回覆重點結論、限制與文件連結；完整內容由文件承接，不要求重新抄進對話。
