# 等價性審查清單

每個整理修改在交付前逐項確認；審查子代理的 diff 時同樣適用。

## 依修改類型

**抽出共用函式（消除重複）**
- 原本每一處的運算式與新函式逐字相同，或差異可證明不影響結果（例如非字串的 `code` 改為 undefined，而所有比較對象都是字串）。
- `this` 綁定、參數順序、預設值的求值時機不變（預設參數仍在每次呼叫時求值）。
- 共用的全域 regex（`/g`）只用在 `replace` 這類會重設 `lastIndex` 的地方。
- 沒有引入循環 import：檢查被引用檔案的 import 清單。

**拆分長函式**
- 敘述與呼叫順序不變；驗證與錯誤的優先序不變（第一個回報的錯誤相同）。
- 旗標語意等價（例如 `committed` 只在原本會成立的位置設定）。
- 原本的 `return`／`continue`／`break` 在拆出後仍有相同效果；早退不會跳過原本必經的清理。
- 非同步邊界不變：原本同步發生的事仍同步發生；`await` 的位置與次數不變。

**刪除程式碼**
- 全 repo 搜尋零引用（含測試、腳本、文件、其他模組、動態載入）。
- 被刪的檢查可證明不可達，而不只是「看起來多餘」。

**命名常數／改名**
- 對外可見的字串逐字相同：schema pattern、HTTP 標頭、SQL、提示與錯誤文字。必要時展開比對。
- 只改內部符號名稱；匯出名稱有其他使用者時不改。
- 數值意義相同才共用常數：兩個值相等但意義不同（設定上限與參數上限）時分開命名。

**型別與聯集**
- 合併過濾條件時，確認型別真的只有那幾種值（例如 `kind` 的型別為 `"shell" | "subagent"`），並找出所有呼叫端。

## 驗證

- 與修改前的基準比較同一組檢查；既有的 skip／todo／預期失敗要和基準一致，不能只看「失敗數沒增加」。
- 被 import 的一方改了，要另外跑引用方的測試。
- 回歸測試的 red 必須在真正修改前的程式上取得；還原舊版時確認位元組一致，否則 red 無效。
- 沒執行的檢查（重型、真實環境、瀏覽器）明講未執行，不算通過。

## 委派（平行整理多個模組）

給 `subagent` 的任務說明（子代理在全新上下文中執行，只知道這份說明）至少包含：
- 範圍：只能修改的目錄；禁止修改的共用檔（中繼資料、文件、manifest、lockfile）；其他子代理同時在同一工作樹工作，不要碰別人的檔案、不跑全 repo 的自動修正。
- 先讀的文件與必須保留的不變量。
- 目標與限制：行為不變；匯出給其他模組的名稱與簽章不改；不弱化或刪除測試；發現缺陷時回報而非自行修正（除非極小且明確）。
- 工具規則：用 `edit`／`write` 修改原始碼；不經由 shell 改寫原始碼；不 commit、stash、reset、checkout。
- 驗證：修改前跑基準、修改後跑型別檢查、lint 與模組測試，且結果至少與基準一樣綠。
- 回報格式：每個變更檔案一行（改了什麼、為何等價）、基準與最終測試數、刻意不改的項目與理由、發現的缺陷或文件不準確處。

協調者收到結果後：
- 子代理的輸出是主張不是證據：逐檔閱讀 diff，依上方清單審查。
- 中繼資料（雜湊、provenance）由協調者統一寫入，避免平行寫入衝突。
- 所有子代理完成後，在完整狀態下依序重跑全部受影響模組與根層級檢查。
