# 交付格式

使用使用者的語言，保留必要的程式識別詞與原始錯誤訊息。先講結論（做了什麼、是否全過、什麼沒做），再展開。

## 整理交付

1. **整理內容**：依模組或檔案列出主要整理（改了什麼、為何行為不變）。審查時特別確認的等價性要點另列。
2. **驗證**：實際執行的檢查與數字，與修改前基準對照；既有的 skip／todo／預期失敗說明其性質；未執行的檢查寫明且不算通過；環境阻礙（例如缺少工具）與其處理方式。
3. **中繼資料**：更新了哪些雜湊／provenance／文件，有無補登錄。
4. **刻意不改的項目**：每項附理由（語意不同、風險、可讀性、超出純整理範圍）。
5. **發現的缺陷**：不在整理中修正；說明影響與修正會改變什麼，請使用者決定。
6. **下一步**：例如是否 commit、是否跑未執行的重型檢查。

## 只做分析時

交付候選清單，每項附證據（檔案與行號）、預期效益、風險與建議的驗證方法，不修改程式。
