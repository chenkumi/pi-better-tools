# 困難問題復現

將難以觸發的故障轉為可重播、有明確失敗判準的案例，支援後續因果調查與修復驗收。可提出並驗證根因假設，須區分觀察、觸發條件、根因候選與已證實的因果關係；不實作產品修復或擅自改變需求。

## 實驗流程

1. **定義失敗。** 指出正確行為、異常特徵與觀察位置，建立能辨識「同一個 bug」的判準。區分產品故障、測試驅動器錯誤與環境故障；任意例外、timeout 或非零退出碼不能一律算作目標故障。記錄正常與異常的預期差異。
2. **捕捉原始案例。** 優先在原實作與已知環境保存一次真實故障及必要上下文。若尚無法觀察，保存使用者提供的證據與待驗證假設。先保留基準再隔離邏輯，不為復現而預先重構產品；人工注入或模擬的故障須標明與原始報告的對應及限制。
3. **設計可區分假設的實驗。** 每次寫明假設、控制條件、改變的因素、預測結果及判定方式。優先改變能區分候選解釋的因素，必要時設計因素組合。記錄控制失敗、instrumentation 對時序的影響及未控制的來源，不把相關性當因果證明。
4. **控制非確定性。** 依需要固定資料、隨機種子、時鐘、環境及外部輸入。競態優先控制事件順序，例如「A 已開始且暫停 → B 完成 → 釋放 A」，而非只等待固定毫秒數。負載或延遲可提高觸發機率，但不能宣稱保證特定排程；固定 seed 也不等於固定執行緒順序。
5. **縮減案例。** 縮小輸入、操作序列、資料、設定差異或排程交錯，每次仍使用相同失敗判準。區分縮減後不再觸發與輸入失效／環境無法執行；保留原始與縮減案例的關係。只有在所選縮減方式下驗證過，才描述其最小性；小案例不等於根因證明。
6. **驗證可信度。** 在明確重設或連續運行條件下重播，記錄觸發數／有效樣本數、無效樣本及條件差異。適用時比較正常輸入、正常版本或其他事件順序。一次觸發不代表穩定；未觸發不代表不存在。保留足以讓下一位執行者重播的案例與限制。

## 依問題選擇方法

| 問題線索 | 可用方法與邊界 |
| --- | --- |
| 非同步覆蓋、競態、取消與生命週期 | 受控請求釋放、barrier、可控 scheduler 或排程探索；保留中間狀態與最終狀態的必要斷言，避免等待最終穩定狀態掩蓋故障 |
| 難以再次捕捉的執行 | 適用平台使用 record/replay 與反向除錯；區分程序執行錄製與 HTTP 回放，記錄工具能捕捉的非確定性範圍 |
| 長操作序列或複雜輸入 | 狀態模型、property-based testing、fuzzing 與 delta debugging；保存 seed、實際失敗輸入及縮減序列，判準獨立於目前實作 |
| 版本回歸 | 在隔離工作區以已知正常／異常版本做 bisect；無法建置或判定的版本跳過，間歇性案例須先建立足夠可靠的分類方式 |
| 記憶體錯誤、資料競爭、死鎖 | 按語言與環境使用 sanitizer、執行緒堆疊、鎖等待圖或追蹤工具；偵測器告警須對照原始症狀，未告警不能排除所有並行錯誤 |
| 重試、部分成功與服務邊界 | 在明確邊界注入故障，例如提交成功後回應遺失；檢查重複副作用、冪等性與恢復，不只檢查 HTTP 狀態或 schema |
| 環境差異、長時間累積 | 比對設定與依賴，保存資料快照、資源趨勢與負載歷史；容器、seed 或直接呼叫 API 須保留觸發條件，不能假設可替代核心／硬體或端到端互動 |

依任務選擇必要方法，不要求逐一嘗試。使用工具前確認版本、平台、可觀測範圍與現有專案慣例；框架查詢、mock 與斷言方式依要驗證的行為決定。

## 預算與操作範圍

區分「改變假設或控制方式的一輪實驗」與「同條件下的一個重播樣本」。開始前在文件定義計數單位、總時間、樣本上限、並行度與停止條件；按環境成本及故障機率選擇有限預算，不能用無限重試追求確定性。

遵守使用者或呼叫方已指定的上限及其計數語意。既有 `Max attempts` 若限制實際執行次數，不得重新包成一個批次來繞過；需要較大樣本預算時先明列差異並取得必要決定。未有指定限制時可在授權範圍內設定合理的有界實驗。達上限、已取得足夠證據或沒有新資訊時停止並交付現況。

研究、復現與修復驗收分開記錄；復現不能清空研究已有輪數，也不能代替正式驗證。跨技能交接保留原始實驗 ID、已用預算與結果，避免同一實驗重複計數或遺失。

使用授權範圍內的隔離資料、環境或工作區，先記錄基準與清理方式。故障注入、重試與錄製可能有副作用，不對正式資料或不可逆外部操作自行擴大授權。清理只移除本次暫時變更與資源；先保存必要證據，保留其他人的工作。

## 結果與交付

每次實驗結果區分 `REPRODUCED`、`NOT_OBSERVED`、`HARNESS_ERROR`、`ENVIRONMENT_BLOCKED` 或 `INCONCLUSIVE`；尚未執行標 `NOT_RUN`。`REPRODUCED` 表示觀察到目標故障，不表示產品驗收通過。批次結果保留每類數量與逐樣本紀錄；觀察頻率需附條件，不能直接推論正式環境機率。

每個案例保留：失敗判準、環境與版本、前置／重設步驟、可執行腳本與輸入、實驗假設與結果、原始及縮減證據、觸發頻率、因果證據強度、清理狀態、未決事項，以及修復後應觀察的行為。未執行的方案可交付，但不能稱為已驗證復現。

交付前核對文件、腳本及證據可讀。文件狀態用 `working`、`ready`、`blocked`、`superseded`；`ready` 僅表示可交接，不代表故障已定位或修復。
