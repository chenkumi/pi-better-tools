# 問題複審

複審用戶交付的問題清單。唯一的成立標準是：**有固定的測試案例或流程，能穩定重現**。沒有就不成立，不進報告。使用者的即時指示優先於本技能內容。

## 輸入與基準

- 輸入是掃描的問題紀錄或報告。逐項取出 ID、描述、位置與原提出者的證據，但這些只是待驗證的主張，不是結論。
- 開始前記錄程式碼基準（commit、分支、未提交變更）。複審期間不修改產品程式碼；重現用的測試與腳本放在任務目錄或隔離副本，不放進產品目錄。
- 驗證環境使用隔離或開發環境，設定資源上限與清理邊界；需要對 production、真實資料或付費服務產生副作用時停下詢問。密鑰與個資只記錄位置與遮罩片段。

## 獨立審查

- **驗證問題使用乾淨的子代理**，不共用上下文。
- 子代理的任務說明只給：問題位置（檔案與範圍）、主張的現況與預期行為、程式碼基準、環境限制與要求的輸出。**不給**原提出者的推論過程、嚴重度或「這大概是真的」之類的傾向，避免錨定。
- 子代理必須自行讀程式碼並嘗試重現，也要主動找反證：既有防護、語言／框架語意、觸發是否可達。
- 子代理不得修改產品程式碼，不得以「推論上成立」代替重現。
- 彼此獨立的審查在同一回合一起派出；遵守宿主的子代理數量上限，超過時分批。沒有子代理能力時，告知使用者無法滿足「乾淨子代理」規則，不以自行審查冒充。
- 子代理回傳固定格式：判定（成立／不成立）、重現檔案與指令、實際輸出與預期輸出、重現次數、反證檢查結果；不成立時給原因。

## 成立標準

同時滿足才算成立：

1. 有**固定**的重現方式：一個測試案例、腳本或逐步流程，輸入、環境與指令都明確寫出。
2. 在乾淨狀態下執行**穩定重現**：
   - 確定性問題：重複三次，每次都出現相同的錯誤結果。
   - 偶發性問題（並行、競態、時序）：必須有固定的併發壓力測試（固定的腳本、併發度、迭代次數與環境），執行三次，**至少兩次**出現相同的錯誤結果才算高機率重現而通過。須記錄每次的參數、樣本數與出現次數。三次中只出現一次或沒有，視為不成立。
3. 重現結果與主張吻合，並能說明正確行為與現況行為的差異。
4. 重現不依賴被測程式碼以外的偶然條件（網路、時間、他人資料）。

不成立的情形，一律不列入報告：

- 只有靜態推論、沒有可執行的重現。
- 偶發出現但沒有固定的併發壓力測試，或該測試三次中出現少於兩次。
- 重現需要修改產品程式碼才能觸發，或前提在實際使用中不可達。
- 既有防護使其無法造成所述後果。

不要為了讓問題成立而放寬標準或調整重現條件；證據不足就是不成立。

## 整合

- 主代理核對每份子代理回報：實際執行重現指令、確認輸出與回報一致，才採信。回報與實際不符，視為不成立並重新審查。
- 同一根因的多個問題合併，列出所有位置；僅表面相似者分開。
- 重現檔案保存在報告旁的任務目錄，使用相對路徑引用，並確認可由乾淨檢出執行。

## 報告

只包含**驗證成立**的問題；不成立的問題不出現在報告內，只在對話交付時以一句話告知數量。每項包含：

- **問題描述：** 正確行為與現況行為的對照。
- **位置：** 檔案與行號範圍（或函式），標明程式碼基準。
- **重現方法（證據）：** 固定的測試案例或流程、執行指令、預期輸出與實際輸出、重現次數（偶發性問題另附壓力參數與三次中的出現次數）。

可附原提出的 ID 供對照，嚴重度依原掃描尺度，不在此重新發明。報告開頭註明程式碼基準、複審日期與時區、輸入問題數與成立數。

## 交付

報告保存後讀回確認內容與連結可用，回覆成立／不成立的數量與報告路徑。覆蓋有限時如實說明未驗證的範圍，不宣稱無遺漏。
