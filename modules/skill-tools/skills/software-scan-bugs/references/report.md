# 報告格式

使用使用者的語言，保留必要的程式識別詞與原始錯誤訊息；密鑰、密碼及個資只記錄位置與遮罩片段。最終摘要直接連結持久紀錄中的完整問題項目與證據；需要獨立報告時依下方結構產出。

## 問題紀錄

每項包含下列欄位；沒有內容時寫「無」，讓讀者能分辨「沒有」與「漏寫」。Low 等級可只寫標題、位置與證據。

| 欄位 | 內容 |
|---|---|
| ID／標題 | 穩定編號（預設 `BUG-001`，狀態修訂時不變更）與一句話描述缺陷與後果；按需標記問題類型（資料完整性、資源、並行、資安等），類型不代表嚴重度 |
| 嚴重度 | 等級與判定理由，含升降級因素（見 `SKILL.md`「嚴重度分級」） |
| 狀態 | 確認狀態（待驗證／已確認／已排除；已確認須有實際觀察或足以證明可達缺陷的靜態證據，排除附理由）與可重現度（高／中／低，見 `SKILL.md`「可重現度」） |
| 位置 | 檔案與行號、函式或元件；同一根因列出所有受影響位置 |
| 觸發條件 | 輸入、操作序列、版本、環境、負載或排程 |
| 行為與影響 | 預期行為、實際行為、對使用者或資料的影響 |
| 證據 | 驗證結果（已觀察／未觀察到／工具錯誤／環境阻礙／未執行；未觀察到不等於已排除）、重現方法（中級附有效樣本數與觸發次數）、相對連結 |

## 報告結構

1. **基準與範圍**：程式碼基準（commit、分支、未提交變更或檔案雜湊）、掃描範圍與入口、掃描時間與時區。
2. **摘要**：依嚴重度與確認狀態統計缺陷數（不含已排除項），列出需優先處理的項目並連結至完整紀錄；ID、嚴重度、確認狀態與證據含意與紀錄一致。資安項可另加摘要索引，不重複完整內容。
3. **發現**：依嚴重度排序；同級時依可重現度由高到低，再依處理急迫性排序。可重現度高的問題能立即修復並驗證，但不因此越過較高的嚴重度。已確認缺陷與待驗證假說分開列示。
4. **限制與未覆蓋範圍**：工具限制、環境阻礙、未查的模組與未執行的驗證。
5. **已排除項**：保留 ID、原判定與排除理由，不計入缺陷總數。
