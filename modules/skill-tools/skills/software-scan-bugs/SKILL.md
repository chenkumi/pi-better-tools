# Software Bug Scan

以程式碼分析與適當的隔離驗證找出缺陷，交付可追溯的問題紀錄。掃描本身不授權修復產品程式碼。

涵蓋一般正確性與安全缺陷的全面掃描。若任務只針對資源生命週期、取消、容量、重試或恢復等可靠性面向，改用可靠性專題審查；掃描中遇到的可靠性疑點仍照本技能記錄為問題項目。已知但難以觸發的缺陷，交給專門的復現流程，本技能只記錄現有證據與狀態。

## 掃描與驗證

1. 確定專案、指定範圍、入口與相關上下游依賴，讀取既有問題。記錄 commit、分支及未提交變更；沒有 Git 時記錄可辨識來源的檔案基準。
2. 優先檢查高影響的資料、狀態與錯誤路徑，按模組分批追蹤。通常排除第三方與生成內容；若疑點涉及鎖定版本或生成流程，讀取相關檔案。記錄實際覆蓋與未查範圍，不宣稱無限深度或完整無缺陷。
3. 每個候選先檢查語言／框架語意、現有防護與觸發可達性。已知問題補充證據；同一根因合併並列出受影響位置，僅表面相似的問題不強行合併。
4. 對重要候選尋找反證，以可重播案例、既有測試、隔離實驗或完整的靜態推導驗證。
5. 交付按影響與處理急迫性排序的結果，將已確認缺陷與待驗證假說分開。明確記錄工具限制、環境阻礙與未覆蓋部分。

## 問題紀錄

每項使用穩定 ID（預設 `BUG-001`），記錄位置、觸發條件、預期與實際行為、影響、依據與驗證結果。以下維度分開判斷：

| 維度 | 記錄方式 |
|---|---|
| 嚴重度 | Critical / High / Medium / Low，依資料損失、服務阻斷、安全影響與波及範圍說明理由；沿用專案已有尺度 |
| 確認狀態 | 待驗證 / 已確認 / 已排除；已確認須有實際觀察或足以證明可達缺陷的靜態證據 |
| 驗證結果 | 已觀察 / 未觀察到 / 工具錯誤 / 環境阻礙 / 未執行；未觀察到不等於已排除 |
| 觸發條件 | 輸入、操作序列、版本、環境、負载或排程；機率性問題記錄有效樣本與觸發次數 |
| 問題類型 | 按需標記資料完整性、資源、並行、資安等，不以類型代替嚴重度 |

推測的高影響問題仍可標為高嚴重度，但必須明示尚未確認及缺少的證據。受影響呼叫點數量不能代替使用者影響。

## 持久紀錄

- 開始即保存原始任務、程式碼基準、範圍與待查項。每完成一批掃描、發現候選、完成驗證或得到阻礙，先更新文件並讀回，再進下一項工作。
- 紀錄包含更新時間與時區、問題 ID、覆蓋進度、證據相對連結與下一步。保留狀態修訂及排除理由；更新前讀取最新內容，避免覆蓋其他工作的紀錄。
- 實驗開始前保存執行中狀態、操作、輸出位置與合理的時間／樣本上限；完成後立即保存結果與清理狀態。中斷後先查既有程序與證據，不直接重跑可能仍在執行的實驗。
- 證據保存於任務目錄，不能只留在對話或暫存檔。含未提交變更時，以相關差異、檔案雜湊或隔離快照補充基準；保存的差異需排除敏感內容。
- 文件寫入失敗時報告未保存內容，停止依賴該紀錄的後續工作。恢復時先讀持久文件，再核對來源是否已改變。
- 如經授權使用子代理，依實際能力與工作量分配獨立範圍，使用不同證據檔避免同時覆寫；主代理核對結果後逐項整合，保留分工與覆蓋紀錄。

## 交付與操作邊界

- 最終摘要直接連結完整問題項目與證據，可按需另產報告；保持 ID、嚴重度、確認狀態與證據含意一致。已排除項保留在紀錄，不計入缺陷總數。
- 報告使用使用者語言，保留必要的程式識別詞與原始錯誤訊息。資安項可加摘要索引，不重複完整內容。
- 驗證使用隔離／開發環境，設定資源與清理邊界。掃描授權不包含對 production、真實資料或付費服務執行有副作用的驗證；需要額外權限時先完成可用的分析並記錄限制。
- 密鑰、密碼及個資只記錄位置與遮罩片段，不寫入報告或證據附件。


## 嚴重度分級

判定順序：先確定最壞可達後果，再依觸發條件與波及範圍調整。專案已有尺度時沿用專案尺度，並記錄與本表的對應。

| 等級 | 判定依據（符合任一即可） | 典型例子 |
|---|---|---|
| Critical | 正常使用、預設設定或任意外部輸入即可觸發，且造成下列任一後果：資料永久遺失或損毀；未授權存取、權限提升或遠端程式執行；主要服務整體不可用；重試或重啟後仍無法恢復 | 啟動或主流程必然崩潰；寫入路徑截斷或覆蓋使用者資料；未驗證輸入造成 SQL injection；預設設定暴露密鑰 |
| High | 需要特定但合理可達的輸入、參數、操作序列、並行時序或環境才會觸發，且造成下列任一後果：程序崩潰或卡死；資料被錯誤寫入且未被偵測；需前置條件（如已登入）的安全漏洞；核心功能失效且無替代路徑；主要建置目標無法編譯或部署 | 特定參數造成空指標或除以零崩潰；邊界值越界存取；並行更新遺失；一般使用者可存取他人資源；死鎖 |
| Medium | 後果可恢復或可察覺：非核心功能錯誤；失敗會明確報錯且可重試成功；資源逐步劣化但不立即中斷；觸發條件罕見；低敏感度資訊外洩 | 錯誤路徑未釋放連線造成緩慢洩漏；偶發競態但重試成功；錯誤訊息洩漏內部路徑或版本；非關鍵報表數值錯誤；選用建置目標失敗 |
| Low | 不影響結果正確性或影響極小：可觀察性與一致性問題；僅在不支援或極端環境出現；輕微效能下降 | 日誌遺漏或誤導；錯誤碼不一致；冗餘或不可達分支內的邏輯錯誤；輕微多餘配置 |

### 調整規則

每項因素最多調整一級，並在紀錄中寫明理由：

- **升一級**：無需權限即可由外部觸發；波及多個使用者、租戶或下游系統；靜默發生，沒有錯誤訊號；錯誤狀態跨重啟持續。
- **降一級**：只能由管理員或受信任輸入觸發；僅出現在除錯或測試設定；既有防護已限制後果範圍；失敗立即顯式中止且無副作用。

### 判定注意事項

- 崩潰不自動等於 Critical；需看是否影響整體服務、能否自動恢復、是否伴隨資料損失。
- 不崩潰也可能是 Critical；靜默資料損毀與安全漏洞通常比崩潰更嚴重。
- 待驗證項依「若成立」的後果分級，並明示尚缺的證據；確認或排除後重新評估。
- 介於兩級時記錄兩者理由，暫取較高等級，驗證完成後複核。
- 受影響呼叫點數量只作為波及範圍的參考，不能直接代替使用者影響。
