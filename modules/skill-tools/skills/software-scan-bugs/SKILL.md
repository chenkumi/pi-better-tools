# Software Bug Scan

找出程式碼中的正確性與安全缺陷，驗證到足以判斷的程度，交付可追溯的問題紀錄。使用者的即時指示優先於本技能內容。

## 範圍

- 涵蓋一般正確性與安全缺陷的全面掃描。任務只針對資源生命週期、取消、容量、重試或恢復時，改用 `software-reliability`；掃描中遇到的可靠性疑點仍在本技能記為問題項目。
- 已知但難以觸發的缺陷交給 `reproduce-bug`，本技能只記錄現有證據與狀態。
- 掃描只交付發現與證據，不修改產品程式碼；修復需使用者另行要求。掃描中途修改會讓基準漂移，證據失去對應。

## 完成條件與何時停下

完成指：指定範圍已按模組追蹤；每個候選都有確認狀態與驗證結果；持久紀錄已更新並讀回；交付摘要列出實際覆蓋與未查範圍。覆蓋有限是正常結果，如實記錄即可，不宣稱無限深度或完整無缺陷。

只在下列情況停下或詢問：驗證需要對 production、真實資料或付費服務產生副作用；需要額外權限；紀錄寫入失敗。前兩種先完成可用的分析並記錄限制；寫入失敗時報告未保存的內容，停止依賴該紀錄的後續工作。其他不確定處合理推斷並繼續，把假設寫進紀錄。

## 掃描與驗證

- **先記錄基準：** commit、分支及未提交變更；沒有 Git 時記錄可辨識來源的檔案基準。沒有基準，結論無法複核。
- **確定範圍再深入：** 指定範圍、入口、相關上下游依賴與既有問題。通常排除第三方與生成內容；疑點涉及鎖定版本或生成流程時讀取相關檔案。
- **高影響路徑優先：** 先查資料、狀態與錯誤路徑，按模組分批追蹤，讓有限時間花在後果最重的地方。
- **候選先過三道檢查：** 語言／框架語意、現有防護、觸發可達性。多數假陽性在這一步就能排除。
- **主動找反證：** 重要候選以可重播案例、既有測試、隔離實驗或完整的靜態推導驗證。
- **合併看根因：** 已知問題補充證據；同一根因合併並列出所有受影響位置，僅表面相似的問題分開記錄，以免一個修正被誤認為修好多個問題。

## 問題紀錄

每項使用穩定 ID（預設 `BUG-001`），記錄位置、觸發條件、預期與實際行為、影響、依據與驗證結果。下列維度分開判斷，彼此不互相代替：

| 維度 | 記錄方式 |
|---|---|
| 嚴重度 | Critical / High / Medium / Low，依 [references/severity.md](references/severity.md) 判定並寫明理由；專案已有尺度時沿用 |
| 確認狀態 | 待驗證 / 已確認 / 已排除；已確認須有實際觀察或足以證明可達缺陷的靜態證據 |
| 驗證結果 | 已觀察 / 未觀察到 / 工具錯誤 / 環境阻礙 / 未執行；未觀察到不等於已排除 |
| 可重現度 | 高 / 中 / 低，依下方「可重現度」判定並附重現方法 |
| 觸發條件 | 輸入、操作序列、版本、環境、負載或排程；機率性問題記錄有效樣本與觸發次數 |
| 問題類型 | 按需標記資料完整性、資源、並行、資安等；類型不代表嚴重度 |

推測的高影響問題可依「若成立」的後果分級，但須明示尚未確認及缺少的證據。

### 可重現度

描述目前能多穩定地重現問題，決定修復後能否直接驗證，以及是否需要進一步的復現工作。

| 等級 | 判定依據 | 需附的證據 |
|---|---|---|
| 高 | 依 test case、script 或明確的操作流程執行，每次都完整重現 | test／script 的相對路徑或逐步操作、預期與實際輸出 |
| 中 | 並非每次出現，但以高併發、壓力測試或重複執行可高機率重現 | 重現方法與參數、有效樣本數與觸發次數 |
| 低 | 低機率偶發、難以重現，或目前只有推論 | 已觀察的現象或日誌、推論依據、已嘗試但未重現的方法 |

- 可重現度描述驗證時能多穩定地重現，不是實際環境的發生頻率，也不代替嚴重度：難以重現的資料損毀仍可能是 Critical。
- 與確認狀態分開判斷：完整的靜態推導可以支持「已確認」，可重現度仍是「低」。
- 隨證據更新：補上穩定的 test 或 script 後調升等級，並保留修訂紀錄。
- 低可重現度的高嚴重度項目，交付時建議轉交 `reproduce-bug`。

## 持久紀錄

掃描可能中斷或跨多個工作階段，紀錄是唯一可靠的狀態來源：

- 開始即保存原始任務、程式碼基準、範圍與待查項。每完成一批掃描、發現候選、完成驗證或遇到阻礙，先更新文件並讀回，再進下一項。
- 紀錄包含更新時間與時區、問題 ID、覆蓋進度、證據相對連結與下一步；保留狀態修訂及排除理由。更新前讀取最新內容，避免覆蓋其他工作的紀錄。
- 證據保存在任務目錄，不只留在對話或暫存檔。含未提交變更時，以相關差異、檔案雜湊或隔離快照補充基準，並排除敏感內容。
- 實驗開始前保存執行中狀態、操作、輸出位置與時間／樣本上限；完成後立即保存結果與清理狀態。中斷後先查既有程序與證據，不直接重跑可能仍在執行的實驗；恢復時先讀持久文件，再核對來源是否已改變。
- 經授權使用子代理時，依能力與工作量分配獨立範圍與不同的證據檔，避免同時覆寫；主代理核對後逐項整合，保留分工與覆蓋紀錄。

## 環境與資料邊界

- 驗證使用隔離或開發環境，設定資源上限與清理邊界。
- 密鑰、密碼及個資只記錄位置與遮罩片段，不寫入報告或證據附件。

## 交付格式

- 使用使用者的語言，保留必要的程式識別詞與原始錯誤訊息。
- 結果依嚴重度排序；同級時依可重現度由高到低，再依處理急迫性排序。可重現度高的問題能立即修復並驗證，但不因此越過較高的嚴重度。已確認缺陷與待驗證假說分開列示；已排除項保留在紀錄，不計入缺陷總數。
- 最終摘要直接連結完整問題項目與證據，ID、嚴重度、確認狀態與證據含意與紀錄一致；按需另產報告。資安項可另加摘要索引，不重複完整內容。
- 明確列出工具限制、環境阻礙與未覆蓋範圍。
