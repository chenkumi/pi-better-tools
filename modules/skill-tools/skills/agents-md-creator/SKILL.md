# AGENTS.md 撰寫指南

撰寫精簡的專案指示，以改善 agent 的決策：必要的限制、不易察覺的陷阱、有用的入口點與完成標準。本指引同樣適用於編輯 `CLAUDE.md`。

## 流程

1. **檢視。** 讀取目標檔案、適用的上層與子專案指示，以及相關的專案文件、manifest、命令與設定。以目前專案的實際狀態核對事實。
2. **選材。** 納入會改變決策、避免錯誤或省下高成本探索的資訊。從專案邊界、環境設定、不變量、入口點、驗證與參考資料中挑選有用內容。省略泛泛的建議與重複的摘要。
3. **組織。** 必要限制與常用命令留在 `AGENTS.md`；情境性細節連結到有維護的來源。只有在能減少無關上下文或改善維護、且值得多一次查找時才拆分。
4. **編輯。** 在要求的範圍內保留使用者明確的要求與既有組織。合併等價的措辭，同時保留語意與出處，包括既有的 `<!-- user-specified -->` 標記。遇到實質衝突或超出授權的變更時先詢問。若重組需要使用者決定，說明問題、擬議的內容位置、閱讀條件、維護影響與具體選項。
5. **驗證。** 檢查事實、命令路徑、連結、指示範圍、衝突，以及使用者要求是否被保留。確認必要的指引在其所規範的動作之前就能被找到。回報變更的檔案、執行的檢查與尚未解決的限制。

## 撰寫規則

- 說明限制、預期結果，以及有助於正確套用的理由。順序重要時使用有序步驟。
- 讓指引可透過可觀察的結果與專案檢查來驗證。只有在專案有依據或使用者明確要求時才使用數值門檻。
- 絕對性語氣只用於真正的不變量或使用者要求。必要時，禁止事項要搭配預期的替代做法。
- 只有在專案或使用者要求時才加入核准邊界；指明受影響的動作，並尊重既有授權。
- 優先使用穩定的入口點或搜尋提示，而非龐大的檔案樹。當概覽能說明不明顯的邊界或有助於定位工作時才納入。
- 準確描述目前的專案；不要把期望中的未來架構寫成既有行為。

## 文件與參考資料

重用既有文件、issue 追蹤器、檔名、位置與大小寫。當內容需要一個有人維護的歸屬處時才建立文件。選擇符合用途且常見的名稱，例如 `RULES.md`、`TESTING.md`、`ARCHITECTURE.md`、`ISSUES.md`、`OPEN_QUESTIONS.md`、`TODO.md`、`PROGRESS.md` 或 `CHANGE_LOGS.md`。

遵循專案的文件配置。小型專案可用單一 `RULES.md`；較大的專案可用 `docs/testing.md` 或 `.agents/rules/` 下的主題檔案。變更歷史放在 changelog，進行中的工作放在其追蹤來源。

說明何時該讀每份參考資料，例如：「變更 session 鎖定前，先讀 [ISSUES.md](ISSUES.md)。」主題文件可自行說明其範圍以供獨立閱讀。前置連結保持直接且無環；經常需要一起讀的文件併列。monorepo 中以清楚的相對路徑區分各文件。

## 載入與時效

變更特定 agent 的目錄或 import 結構前，先透過設定、實作或官方文件確認目標工具的載入行為：

- **自動載入：** 考量上層、專案與被引入的內容、大小限制與優先序。
- **條件載入：** 確認路徑或任務的觸發條件及其範圍。
- **明確讀取：** 把讀取指示放在依賴它的動作之前。

進行中的進度與詳細的 issue 狀態保留在其維護來源。對會變動的事實，指定在依賴它的動作之前重新讀取。若簡短警告直接影響安全作業，可留在 `AGENTS.md`；並標明其來源，以及重新檢查或移除的條件。

## 大小與行為檢查

評估代表性任務所載入的內容、查找成本，以及漏掉必要指引的風險。若要做選用的粗略估算，從本技能套件執行輔助腳本：

```bash
python3 <skill-directory>/scripts/estimate_tokens.py <project>/AGENTS.md
python3 <skill-directory>/scripts/estimate_tokens.py --sum <files-loaded-together...>
```

該腳本以字元數除以 2.2 估算，並回報僅供參考的大小區間。可用 `--help` 查看選項；需要精確計數時，改用適合該模型的 tokenizer。

進行實質修訂時，以代表性任務走查，確認必要的限制與驗證步驟在行動之前就會被遇到。需要行為評估時，在相同的模型、工具與任務下，比較正確性、漏掉的指示、不必要的探索、成本與人工介入。只有實際量測到時才回報效能提升。
