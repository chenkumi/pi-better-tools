# 嚴重度分級

判定順序：先確定最壞可達後果，再依觸發條件、累積速度與恢復方式調整。專案已有尺度時沿用專案尺度，並記錄與本表的對應。

| 等級 | 判定依據（符合任一即可） | 典型例子 |
|---|---|---|
| Critical | 正常負載、常見操作或常見下游故障即可觸發，且造成下列任一後果：持久資料損壞、遺失或重複套用不可逆副作用；崩潰或重啟後無法辨認狀態，需人工修復才能恢復；故障擴散使整體服務或多個依賴系統不可用；資源在正常運行週期內耗盡且無法自動恢復 | 寫入中途崩潰留下半寫檔且啟動時當成完整資料；非冪等的付款或寄送操作在逾時後重試；連線池洩漏使服務在數小時內停止回應；遷移無法回退且失敗後資料格式不一致 |
| High | 需要特定但合理可達的條件才會觸發（超載、取消時序、下游逾時、部分失敗、多實例競爭），且造成下列任一後果：永久等待或死鎖；程序崩潰或須重啟才能恢復；資源耗盡使單一實例失效；重試風暴放大下游故障；殘留子程序、鎖或暫存狀態阻擋後續工作 | 取消未抵達子程序，留下孤兒程序佔用連接埠；下游無回應時無逾時且佔滿工作執行緒；無上限佇列在尖峰時耗盡記憶體；關閉與完成回呼交錯造成重複釋放；多實例同時執行排程任務 |
| Medium | 後果可自動恢復或影響有限：效能或容量劣化但不中斷服務；緩慢累積，通常在既有重啟或保留週期內被清除；清理失敗留下殘餘但不影響功能；錯誤被吞掉或觀測不足，使故障難以察覺或定位；觸發條件罕見 | 錯誤路徑遺漏關閉檔案代碼但每日重啟前不會耗盡；退避無抖動造成短暫尖峰；背景任務失敗只記日誌、健康檢查仍回報正常；暫存檔未清理但有保留政策 |
| Low | 不影響可用性與資料正確性，或影響極小：可觀察性與一致性問題；僅在不支援或極端規模下出現；輕微資源浪費 | 日誌缺少關聯 ID；逾時值寫死但目前合理；關閉時多等一次不必要的期限；使用牆鐘計算短間隔但誤差無實際影響 |

## 調整規則

每項因素最多調整一級，並在紀錄中寫明理由：

- **升一級**：無需特殊權限即可由外部負載或輸入觸發；靜默發生，健康狀態與日誌都不反映；錯誤狀態跨重啟持續；波及多個實例、租戶或下游系統；累積速度快於正常部署或重啟週期。
- **降一級**：只在不支援的規模、平台或設定下出現；既有監督機制可自動恢復，且確認不會遺失資料或重複副作用；受保留政策或容量上限限制；失敗會立即顯式中止且無殘留。

## 判定注意事項

- 可透過重啟恢復不等於低嚴重度，需看重啟頻率、恢復期間的影響，以及是否需要人工介入。
- 未崩潰也可能是 Critical；靜默資料損壞與重複副作用通常比崩潰更嚴重。
- 受保留政策治理的成長、依取消語意管理的長時間等待，不列為缺陷。如有疑慮，記錄為取捨。
- 待驗證項依「若成立」的後果分級，明示尚缺的證據，確認或排除後重新評估。
- 介於兩級時記錄兩者理由，暫取較高等級，驗證完成後複核。
