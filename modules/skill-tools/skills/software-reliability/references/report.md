# 報告格式

## 發現紀錄

每項發現包含下列欄位。不適用的欄位寫「不適用」，不要省略，讓讀者能分辨「沒有」與「漏寫」：

| 欄位 | 內容 |
|---|---|
| ID | 穩定編號（沿用專案既有編號，否則自訂一致格式），狀態修訂時不變更 |
| 標題 | 一句話描述風險與後果 |
| 面向 | 對應 `SKILL.md`「檢查面向」中的一項或多項 |
| 嚴重度 | 等級與判定理由，含升降級因素（見 [severity.md](severity.md)） |
| 確認狀態 | 待驗證 / 已確認 / 已排除；已排除需附理由 |
| 證據等級 | 已觀察 / 靜態推導 / 尚待驗證 |
| 驗證結果 | 已觀察 / 未觀察到 / 工具錯誤 / 環境阻礙 / 未執行；未觀察到不等於已排除 |
| 可重現度 | 高 / 中 / 低（見 `SKILL.md`「可重現度」）與重現方法；中級附有效樣本數與觸發次數 |
| 位置 | 檔案與行號、函式或元件；同一根因列出所有受影響位置 |
| 觸發條件 | 負載、操作序列、時序、下游狀態、版本、環境；機率性問題附有效樣本與觸發次數 |
| 可達路徑 | 從入口到故障點的路徑，以及為何既有防護未攔截 |
| 影響 | 實際後果、波及範圍、累積速度、恢復方式 |
| 既有防護 | 已存在的逾時、上限、監督、冪等等機制及其不足之處 |
| 證據 | 相對連結至程式碼、實驗輸出、日誌或推導紀錄 |
| 建議方向 | 封閉風險的方向與可接受的替代方案；不寫成完整修補 |
| 殘留風險 | 建議落實後仍存在的風險，或無法控制的第三方行為 |

## 報告結構

1. **基準與範圍**：程式碼基準（commit、分支、未提交變更或檔案雜湊）、審查入口、納入的共用元件與部署拓樸、審查時間與時區。
2. **摘要**：依嚴重度與確認狀態統計發現數（不含已排除項），列出需優先處理的項目並連結至完整紀錄。
3. **發現**：依嚴重度排序；同級時已確認先於待驗證，再依可重現度由高到低，最後依處理急迫性排序。可重現度高的風險能立即修復並驗證，但不因此越過較高的嚴重度。已確認與待驗證分開列示。
4. **可接受取捨**：經判斷不列為缺陷的設計選擇與理由，例如刻意不設逾時的互動操作、受保留政策治理的成長。
5. **剩餘風險與未覆蓋範圍**：未審查的模組、未執行的實驗、工具限制、環境阻礙，以及第三方不可取消或不可控的行為。
6. **順帶發現**：審查中發現的非可靠性缺陷，只列位置與依據，不展開調查。
7. **實驗紀錄**：各實驗的設定、時間與資源上限、停止條件、結果、清理狀態及證據位置。
8. **已排除項**：保留 ID、原判定與排除理由，不計入缺陷總數。
