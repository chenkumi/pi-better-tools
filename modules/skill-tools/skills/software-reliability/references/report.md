# 報告格式

使用使用者的語言，保留必要的程式識別詞與原始錯誤訊息；密鑰與個資只記錄位置與遮罩片段。

## 發現紀錄

每項發現包含下列欄位；沒有內容時寫「無」，讓讀者能分辨「沒有」與「漏寫」。Low 等級可只寫標題、位置與證據。

| 欄位 | 內容 |
|---|---|
| ID／標題 | 穩定編號（沿用專案既有編號，否則自訂一致格式，狀態修訂時不變更）與一句話描述風險與後果；標註對應的檢查面向 |
| 嚴重度 | 等級與判定理由，含升降級因素（見 `SKILL.md`「嚴重度分級」） |
| 狀態 | 確認狀態（待驗證／已確認／已排除，排除附理由）與可重現度（高／中／低，見 `SKILL.md`） |
| 位置 | 檔案與行號、函式或元件；同一根因列出所有受影響位置 |
| 觸發與路徑 | 觸發條件（負載、時序、下游狀態、環境），從入口到故障點的路徑，以及既有防護為何未攔截 |
| 影響 | 實際後果、波及範圍、累積速度、恢復方式 |
| 證據 | 證據等級與驗證結果、重現方法（中級附有效樣本數與觸發次數）、相對連結 |
| 建議 | 封閉風險的方向與殘留風險；不寫成完整修補 |

## 報告結構

1. **基準與範圍**：程式碼基準（commit、分支、未提交變更或檔案雜湊）、審查入口、納入的共用元件與部署拓樸、審查時間與時區。
2. **摘要**：依嚴重度與確認狀態統計發現數（不含已排除項），列出需優先處理的項目並連結至完整紀錄。
3. **發現**：依嚴重度排序；同級時已確認先於待驗證，再依可重現度由高到低，最後依處理急迫性排序。可重現度高的風險能立即修復並驗證，但不因此越過較高的嚴重度。已確認與待驗證分開列示。
4. **取捨與剩餘風險**：不列為缺陷的設計選擇與理由；未審查的範圍、未執行的實驗、工具或環境阻礙，以及第三方不可控的行為。
5. **附錄**：順帶發現（只列位置與依據）、實驗紀錄（設定、上限、停止條件、結果、清理狀態、證據位置）、已排除項（ID、原判定與排除理由，不計入缺陷總數）。
