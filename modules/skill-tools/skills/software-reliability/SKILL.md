# Software Reliability

找出會造成資源耗盡、永久等待、故障擴散、資料損壞或無法恢復的具體風險。

範圍是可靠性專題（資源、取消、容量、重試、並行、恢復）。一般功能正確性缺陷的全面掃描不屬於本技能；審查中順帶發現的非可靠性缺陷，只記錄位置與依據，不展開調查。每項發現使用穩定 ID（沿用專案既有編號，否則自訂一致格式）並標明確認狀態。

## 審查方式

- 從指定入口與關鍵工作追蹤資源所有權、共享狀態、下游操作及部署拓樸，納入能影響目標的共用元件。依實際系統選擇相關檢查，不要求全面套表。
- 讀取框架、SDK 與作業系統的相關語意，確認既有防護是否抵達實際工作。針對疑點查證適用版本，不因有較新版本就建議升級。
- 對發現描述觸發條件、可達路徑、影響、既有防護與證據。區分已觀察、靜態推導及尚待驗證的風險。

## 檢查面向

| 面向 | 需要確認的結果 |
|---|---|
| 資源生命週期 | 取得資源即有清理責任；部分初始化、錯誤及重入不遺漏釋放。個別清理失敗不阻止其餘清理，也不掩蓋主要錯誤 |
| 取消與關閉 | 取消能抵達實際 I/O、背景工作及子程序；終止有明確結果，程序樹、退出狀態及終端可恢復。第三方不能取消時記錄隔離方式與殘留風險 |
| 容量與背壓 | 工作量、並行、佇列、快取及日誌有適當容量或保留政策；超載時拒絕、降速或降級，不無限累積 |
| 逾時與重試 | 等待與終止符合操作語意；重試有界且可安全重複，考慮部分成功、退避及既有 SDK 重試，避免重複副作用與重試風暴 |
| 並行與一致性 | 重入、重複完成、競態與關閉交錯不破壞不變量；多實例時依資料與副作用要求選擇協調方式，不只檢查是否存在鎖 |
| 持久化與恢復 | 部分寫入、崩潰與重啟後能辨認已完成／待完成狀態並恢復；版本遷移與實際支援的升級／回退方式一致 |
| 時間語意 | 經過時間與期限使用合適的單調時鐘；日曆排程依日期、時區與夏令時規則處理，睡眠／喚醒行為符合平台與任務要求 |
| 錯誤與觀測 | 設定失敗、外部故障與背景錯誤有可操作的結果；日誌與追蹤本身不阻塞或無限成長。健康狀態與進度能區分正常工作、阻塞與失效 |

## 判斷與驗證

- 持續等待的互動操作可依取消語意管理，不強加任意硬逾時；受保留政策治理的持久資料成長不等於洩漏。timer 是否保持程序存活依清理責任決定。
- 依風險選擇故障注入、長程／容量測試、受控排程或真實程序驗證；訊號、程序樹與退出語意不能只靠函式 mock 證明。
- 實驗設定時間、資源與停止條件，保存基準、操作、證據與清理結果。區分產品缺陷、工具故障、環境阻礙及未執行，不把測試數或覆蓋率當可靠性保證。
- 長程審查每完成一項結論即保存至既有任務紀錄；若無紀錄，採專案文件慣例，碰撞加後綴。記錄來源、狀態與證據位置並讀回；恢復先核對文件與程式碼基準。
- 審查交付實際範圍、依影響排序的發現、可接受取捨與剩餘風險。只有任務包含修復時修改產品程式碼，優先封閉已證實的風險，不擴大成風格、功能或全面依賴審查。
