# Software Reliability

找出會造成資源耗盡、永久等待、故障擴散、資料損壞或無法恢復的具體風險，並以證據支持每項結論。使用者的即時指示優先於本技能內容。

## 範圍

- 可靠性專題：資源、取消、容量、重試、並行、恢復與時間語意。一般功能正確性的全面掃描改用 `software-scan-bugs`；審查中順帶發現的非可靠性缺陷只記錄位置與依據，不展開調查，以免審查失焦。
- 只有任務包含修復時才修改產品程式碼；此時優先封閉已證實的風險，不擴大成風格、功能或全面依賴審查。

## 完成條件與何時停下

完成指：指定入口與關鍵工作已追蹤；每項發現有穩定 ID、嚴重度、確認狀態與證據；結論已寫入持久紀錄並讀回；交付報告列出實際範圍、可接受取捨與剩餘風險。

只在下列情況停下或詢問：驗證需要對 production、真實資料或付費服務產生副作用；需要額外權限；紀錄寫入失敗。其他不確定處合理推斷並繼續，把假設寫進紀錄。

## 審查方式

- **從實際工作出發：** 由指定入口與關鍵工作追蹤資源所有權、共享狀態、下游操作及部署拓樸，納入能影響目標的共用元件。依實際系統選擇下表中相關的面向，不要求全面套表。
- **查證底層語意：** 讀取框架、SDK 與作業系統的相關語意，確認既有防護是否真的抵達實際工作。查證適用版本即可，不因有較新版本就建議升級。
- **說明完整因果：** 每項發現描述觸發條件、可達路徑、影響、既有防護與證據，並區分已觀察、靜態推導與尚待驗證。

## 檢查面向

| 面向 | 需要確認的結果 |
|---|---|
| 資源生命週期 | 取得資源即有清理責任；部分初始化、錯誤及重入不遺漏釋放。個別清理失敗不阻止其餘清理，也不掩蓋主要錯誤 |
| 取消與關閉 | 取消能抵達實際 I/O、背景工作及子程序；終止有明確結果，程序樹、退出狀態及終端可恢復。第三方不能取消時記錄隔離方式與殘留風險 |
| 容量與背壓 | 工作量、並行、佇列、快取及日誌有適當容量或保留政策；超載時拒絕、降速或降級，不無限累積 |
| 逾時與重試 | 等待與終止符合操作語意；重試有界且可安全重複，考慮部分成功、退避及既有 SDK 重試，避免重複副作用與重試風暴 |
| 並行與一致性 | 重入、重複完成、競態與關閉交錯不破壞不變量；多實例時依資料與副作用要求選擇協調方式，不只檢查是否存在鎖 |
| 持久化與恢復 | 部分寫入、崩潰與重啟後能辨認已完成／待完成狀態並恢復；版本遷移與實際支援的升級／回退方式一致 |
| 時間語意 | 經過時間與期限使用合適的單調時鐘；日曆排程依日期、時區與夏令時規則處理，睡眠／喚醒行為符合平台與任務要求 |
| 錯誤與觀測 | 設定失敗、外部故障與背景錯誤有可操作的結果；日誌與追蹤本身不阻塞或無限成長。健康狀態與進度能區分正常工作、阻塞與失效 |

## 判斷原則

- 持續等待的互動操作依取消語意管理，不強加任意硬逾時。
- 受保留政策治理的持久資料成長不等於洩漏。
- timer 是否保持程序存活，依清理責任決定。
- 有疑慮但屬設計取捨的項目記為「可接受取捨」，不列為缺陷。

嚴重度依 [references/severity.md](references/severity.md) 判定；專案已有尺度時沿用並記錄對應。

## 可重現度

每項發現另外標示可重現度，說明目前能多穩定地重現，決定修復後能否直接驗證。

| 等級 | 判定依據 | 需附的證據 |
|---|---|---|
| 高 | 依 test case、script 或明確的操作流程執行，每次都完整重現 | test／script 的相對路徑或逐步操作、預期與實際輸出 |
| 中 | 並非每次出現，但以高併發、壓力測試或重複執行可高機率重現 | 重現方法與參數（並行數、負載、時長）、有效樣本數與觸發次數 |
| 低 | 低機率偶發、難以重現，或目前只有推論 | 已觀察的現象或日誌、推論依據、已嘗試但未重現的方法 |

- 可重現度描述驗證時能多穩定地重現，不是實際環境的發生頻率，也不代替嚴重度：難以重現的重複副作用仍可能是 Critical。
- 與證據等級分開：證據等級說明證據的種類，可重現度說明重現的穩定性。「靜態推導」與「尚待驗證」的項目，可重現度為「低」。
- 時序類問題常停在「中」；若以受控排程、故障注入或 hook 固定交錯順序後每次都重現，可調升為「高」，並記錄固定時序的方法。
- 隨證據更新等級並保留修訂紀錄。

## 驗證

- 依風險選擇故障注入、長程／容量測試、受控排程或真實程序驗證。訊號、程序樹與退出語意只能用真實程序證明，函式 mock 無法重現作業系統行為。
- 實驗設定時間、資源與停止條件，保存基準、操作、證據與清理結果。
- 區分產品缺陷、工具故障、環境阻礙與未執行。測試數或覆蓋率不等於可靠性保證。

## 持久紀錄

長程審查每完成一項結論即保存至既有任務紀錄；沒有紀錄時依專案文件慣例建立，檔名碰撞加後綴。記錄來源、狀態與證據位置並讀回；中斷後恢復時先核對文件與程式碼基準。

## 交付格式

依 [references/report.md](references/report.md) 的欄位與結構撰寫報告：使用使用者的語言，保留必要的程式識別詞與原始錯誤訊息；密鑰與個資只記錄位置與遮罩片段。發現依嚴重度排序，同級時再依可重現度排序（細則見報告格式）；已確認與待驗證分開列示。
