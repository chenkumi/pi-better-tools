# Software Reliability

找出會造成資源耗盡、永久等待、故障擴散、資料損壞或無法恢復的具體風險。

範圍是可靠性專題（資源、取消、容量、重試、並行、恢復）。一般功能正確性缺陷的全面掃描不屬於本技能；審查中順帶發現的非可靠性缺陷，只記錄位置與依據，不展開調查。每項發現使用穩定 ID（沿用專案既有編號，否則自訂一致格式）並標明確認狀態。

## 審查方式

- 從指定入口與關鍵工作追蹤資源所有權、共享狀態、下游操作及部署拓樸，納入能影響目標的共用元件。依實際系統選擇相關檢查，不要求全面套表。
- 讀取框架、SDK 與作業系統的相關語意，確認既有防護是否抵達實際工作。針對疑點查證適用版本，不因有較新版本就建議升級。
- 對發現描述觸發條件、可達路徑、影響、既有防護與證據。區分已觀察、靜態推導及尚待驗證的風險。

## 檢查面向

| 面向 | 需要確認的結果 |
|---|---|
| 資源生命週期 | 取得資源即有清理責任；部分初始化、錯誤及重入不遺漏釋放。個別清理失敗不阻止其餘清理，也不掩蓋主要錯誤 |
| 取消與關閉 | 取消能抵達實際 I/O、背景工作及子程序；終止有明確結果，程序樹、退出狀態及終端可恢復。第三方不能取消時記錄隔離方式與殘留風險 |
| 容量與背壓 | 工作量、並行、佇列、快取及日誌有適當容量或保留政策；超載時拒絕、降速或降級，不無限累積 |
| 逾時與重試 | 等待與終止符合操作語意；重試有界且可安全重複，考慮部分成功、退避及既有 SDK 重試，避免重複副作用與重試風暴 |
| 並行與一致性 | 重入、重複完成、競態與關閉交錯不破壞不變量；多實例時依資料與副作用要求選擇協調方式，不只檢查是否存在鎖 |
| 持久化與恢復 | 部分寫入、崩潰與重啟後能辨認已完成／待完成狀態並恢復；版本遷移與實際支援的升級／回退方式一致 |
| 時間語意 | 經過時間與期限使用合適的單調時鐘；日曆排程依日期、時區與夏令時規則處理，睡眠／喚醒行為符合平台與任務要求 |
| 錯誤與觀測 | 設定失敗、外部故障與背景錯誤有可操作的結果；日誌與追蹤本身不阻塞或無限成長。健康狀態與進度能區分正常工作、阻塞與失效 |

## 判斷與驗證

- 持續等待的互動操作可依取消語意管理，不強加任意硬逾時；受保留政策治理的持久資料成長不等於洩漏。timer 是否保持程序存活依清理責任決定。
- 依風險選擇故障注入、長程／容量測試、受控排程或真實程序驗證；訊號、程序樹與退出語意不能只靠函式 mock 證明。
- 實驗設定時間、資源與停止條件，保存基準、操作、證據與清理結果。區分產品缺陷、工具故障、環境阻礙及未執行，不把測試數或覆蓋率當可靠性保證。
- 長程審查每完成一項結論即保存至既有任務紀錄；若無紀錄，採專案文件慣例，碰撞加後綴。記錄來源、狀態與證據位置並讀回；恢復先核對文件與程式碼基準。
- 審查交付實際範圍、依影響排序的發現、可接受取捨與剩餘風險。只有任務包含修復時修改產品程式碼，優先封閉已證實的風險，不擴大成風格、功能或全面依賴審查。

## 嚴重度分級

判定順序：先確定最壞可達後果，再依觸發條件、累積速度與恢復方式調整。專案已有尺度時沿用專案尺度，並記錄與本表的對應。

| 等級 | 判定依據（符合任一即可） | 典型例子 |
|---|---|---|
| Critical | 正常負載、常見操作或常見下游故障即可觸發，且造成下列任一後果：持久資料損壞、遺失或重複套用不可逆副作用；崩潰或重啟後無法辨認狀態，需人工修復才能恢復；故障擴散使整體服務或多個依賴系統不可用；資源在正常運行週期內耗盡且無法自動恢復 | 寫入中途崩潰留下半寫檔且啟動時當成完整資料；非冪等的付款或寄送操作在逾時後重試；連線池洩漏使服務在數小時內停止回應；遷移無法回退且失敗後資料格式不一致 |
| High | 需要特定但合理可達的條件才會觸發（超載、取消時序、下游逾時、部分失敗、多實例競爭），且造成下列任一後果：永久等待或死鎖；程序崩潰或須重啟才能恢復；資源耗盡使單一實例失效；重試風暴放大下游故障；殘留子程序、鎖或暫存狀態阻擋後續工作 | 取消未抵達子程序，留下孤兒程序佔用連接埠；下游無回應時無逾時且佔滿工作執行緒；無上限佇列在尖峰時耗盡記憶體；關閉與完成回呼交錯造成重複釋放；多實例同時執行排程任務 |
| Medium | 後果可自動恢復或影響有限：效能或容量劣化但不中斷服務；緩慢累積，通常在既有重啟或保留週期內被清除；清理失敗留下殘餘但不影響功能；錯誤被吞掉或觀測不足，使故障難以察覺或定位；觸發條件罕見 | 錯誤路徑遺漏關閉檔案代碼但每日重啟前不會耗盡；退避無抖動造成短暫尖峰；背景任務失敗只記日誌、健康檢查仍回報正常；暫存檔未清理但有保留政策 |
| Low | 不影響可用性與資料正確性，或影響極小：可觀察性與一致性問題；僅在不支援或極端規模下出現；輕微資源浪費 | 日誌缺少關聯 ID；逾時值寫死但目前合理；關閉時多等一次不必要的期限；使用牆鐘計算短間隔但誤差無實際影響 |

### 調整規則

每項因素最多調整一級，並在紀錄中寫明理由：

- **升一級**：無需特殊權限即可由外部負載或輸入觸發；靜默發生，健康狀態與日誌都不反映；錯誤狀態跨重啟持續；波及多個實例、租戶或下游系統；累積速度快於正常部署或重啟週期。
- **降一級**：只在不支援的規模、平台或設定下出現；既有監督機制可自動恢復，且確認不會遺失資料或重複副作用；受保留政策或容量上限限制；失敗會立即顯式中止且無殘留。

### 判定注意事項

- 可透過重啟恢復不等於低嚴重度，需看重啟頻率、恢復期間的影響，以及是否需要人工介入。
- 未崩潰也可能是 Critical；靜默資料損壞與重複副作用通常比崩潰更嚴重。
- 受保留政策治理的成長、依取消語意管理的長時間等待，不列為缺陷。如有疑慮，記錄為取捨。
- 待驗證項依「若成立」的後果分級，明示尚缺的證據，確認或排除後重新評估。
- 介於兩級時記錄兩者理由，暫取較高等級，驗證完成後複核。

## 報告格式

報告使用使用者語言，保留必要的程式識別詞與原始錯誤訊息。密鑰與個資只記錄位置與遮罩片段。

### 發現紀錄

每項發現包含下列欄位。不適用的欄位寫「不適用」，不要省略：

| 欄位 | 內容 |
|---|---|
| ID | 穩定編號，狀態修訂時不變更 |
| 標題 | 一句話描述風險與後果 |
| 面向 | 對應「檢查面向」中的一項或多項 |
| 嚴重度 | 等級與判定理由，含升降級因素 |
| 確認狀態 | 待驗證 / 已確認 / 已排除；已排除需附理由 |
| 證據等級 | 已觀察 / 靜態推導 / 尚待驗證 |
| 驗證結果 | 已觀察 / 未觀察到 / 工具錯誤 / 環境阻礙 / 未執行；未觀察到不等於已排除 |
| 位置 | 檔案與行號、函式或元件；同一根因列出所有受影響位置 |
| 觸發條件 | 負載、操作序列、時序、下游狀態、版本、環境；機率性問題附有效樣本與觸發次數 |
| 可達路徑 | 從入口到故障點的路徑，以及為何既有防護未攔截 |
| 影響 | 實際後果、波及範圍、累積速度、恢復方式 |
| 既有防護 | 已存在的逾時、上限、監督、冪等等機制及其不足之處 |
| 證據 | 相對連結至程式碼、實驗輸出、日誌或推導紀錄 |
| 建議方向 | 封閉風險的方向與可接受的替代方案；不寫成完整修補 |
| 殘留風險 | 建議落實後仍存在的風險，或無法控制的第三方行為 |

### 報告結構

1. **基準與範圍**：程式碼基準（commit、分支、未提交變更或檔案雜湊）、審查入口、納入的共用元件與部署拓樸、審查時間與時區。
2. **摘要**：依嚴重度與確認狀態統計發現數（不含已排除項），列出需優先處理的項目並連結至完整紀錄。
3. **發現**：依嚴重度排序；同級時已確認先於待驗證，再依處理急迫性排序。已確認與待驗證分開列示。
4. **可接受取捨**：經判斷不列為缺陷的設計選擇與理由，例如刻意不設逾時的互動操作、受保留政策治理的成長。
5. **剩餘風險與未覆蓋範圍**：未審查的模組、未執行的實驗、工具限制、環境阻礙，以及第三方不可取消或不可控的行為。
6. **順帶發現**：審查中發現的非可靠性缺陷，只列位置與依據，不展開調查。
7. **實驗紀錄**：各實驗的設定、時間與資源上限、停止條件、結果、清理狀態及證據位置。
8. **已排除項**：保留 ID、原判定與排除理由，不計入缺陷總數。
