# 計畫可行性稽核

依使用者要求或重要風險，檢查計畫的前提、依賴與驗收是否可行。此技能可選；已有充分且仍有效的證據可重用。可提出有依據的修正建議，不擅自改寫計畫、替使用者決策或實作產品修復。

## 查證與判定

1. **辨識前提。** 覆蓋受委託的 checkpoint 或扁平項目，拆出會影響執行的技術假設。區分目前必須存在的依賴與預計新增的產出；新檔案、新介面或新測試尚未存在，不構成不可行證據。
2. **核對證據。** 讀取相關原始碼、設定及適用版本的官方文件；必要時執行授權範圍內的探測。驗證指令須判斷在對應階段完成後能否執行，不要求所有未來檢查現在就通過。遇到會阻礙執行的格式或命名問題仍須指出。
3. **保存判定。** 每項使用 `PASS`（有證據成立）、`NEEDS-ADJUSTMENT`（可行但需調整）、`BLOCKED`（已確認的阻礙）或 `INCONCLUSIVE`（證據不足）。尚未查證標 `NOT_CHECKED`，不混入 PASS。

探測優先查詢，必要暫時操作使用隔離環境並記錄基準與清理方式；只清除本次變更，保留證據。每次實驗前保存進行中狀態，完成後保存指令、輸入、結果與清理狀態，再進行下一次。遵守指定的 `Max attempts`，未指定時同一斷言最多 3 次實驗嘗試；一般讀檔搜尋不計入。稽核輪數不計入執行驗證輪數。

## 回報

回覆重點發現、受影響項目、未查範圍及下一步，並提供 `Plan path`、`Audit path` 與修訂號。完整證據由已保存的報告承接。交付前核對引用可讀、未決事項如實呈現。
