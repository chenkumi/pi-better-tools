# Test Case Creator

依行為契約與缺陷風險選擇案例、測試邊界及判定標準，沿用專案測試工具與慣例。

只在測試本身是交付內容時使用。執行既有計畫、重構或修復時順帶執行既有檢查，不需要啟動本技能；需要為該變更新增或補強測試時才使用。

## 工作方式

- 從使用者請求判斷需要測試程式、案例文件或覆蓋審查。讀取相關規格、實作、測試及執行設定；只詢問影響預期行為或交付形式的實質歧義。
- 建立測試時，優先覆蓋高影響行為、已知 bug 與缺少保障的邊界。審查時檢查案例實際執行與斷言內容，不因測試名稱或存在某個檔案就判定已覆蓋。
- 選擇能捕捉目標缺陷且成本合理的最小邊界；跨元件契約、程序生命週期或外部整合需要相應層級的驗證。測試比例依系統而定。
- 依需要考慮正常與錯誤輸入、邊界、狀態與操作順序、並行、依賴故障、權限、資源容量、時間與資料格式。呈現重要缺口與取捨，不為分類齊全而補案例。

## 案例品質

- 每個案例有明確的前置狀態、操作與可觀察結果。相關斷言可共同驗證一項契約；長流程與狀態機案例保留定位失敗所需的步驟資訊。
- 預期結果來自規格、獨立參考模型、不變量或可解釋的性質。避免複製待測演算法計算答案，也避免用受測結果自行生成預期值。
- 依輸入與狀態空間選用代表性案例、參數化、property-based、model-based、metamorphic 或 differential testing。組合覆蓋依交互作用風險決定，不宣稱 pairwise 能涵蓋所有高階交互作用。
- 測試替身用於控制相關邊界；需驗證真實整合語意時使用相應實作或隔離環境。只驗證有契約意義的互動，不將內部呼叫順序綁成需求。
- 明確呈現案例關心的資料；共用 fixture 隱藏無關設定，避免共享可變狀態與案例間的執行順序依賴。
- 控制適用的時鐘、亂數、排程與外部狀態；並行測試以事件或可觀察條件協調，保留重播所需的種子、操作序列與失敗輸入。
- 新案例應增加缺陷偵測能力或契約保障；以風險、等價類與邊界判斷，不能只看是否增加程式分支覆蓋。

## 驗證與輸出

- 實作測試後執行適當的測試範圍。回歸案例應在可行時確認能暴露原缺陷，再確認修正結果；不為通過而弱化判定條件。
- 區分產品失敗、測試工具錯誤、環境阻礙與未執行。跳過或無斷言的 stub 不算驗證通過。
- 案例文件記錄目標行為、前置條件、操作、預期結果及必要的追溯資訊；沿用既有 ID 與格式，沒有需求時不另建編號體系。
- 覆蓋審查交付已查範圍、重要缺口、影響與建議案例。只有實際量測才提供覆蓋率數字，不把行覆蓋率等同於行為完整性。
- 沿用既有文件位置；長程工作逐項保存已確認案例、判斷與證據，完成後回報實際驗證結果與未涵蓋的高風險部分。
