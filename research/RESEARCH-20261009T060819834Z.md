# Pi 對 cybersecurity API 錯誤與可續跑錯誤的分類調查

## 結論

使用者提供的「This content was flagged for possible cybersecurity risk ... Daybreak ... before retrying」文字，在目前專案及全域 Pi 1.1.0 的實際 `isRetryableAssistantError()` 均得到 false。此分類器不是對所有 API error 重試，也沒有專門的 cyber_policy 停止分支；它對 errorMessage 做可重試字串白名單匹配，先排除帳務／配額等明確非暫時性限制。使用者文字未匹配白名單，因此一般情況下結束當次 run，而非自動同請求重試。

## 已讀取的本機證據

- 專案與全域 pi-coding-agent 均為 1.1.0，全域巢狀 pi-ai 也是 1.1.0。
- 專案與全域 `dist/core/agent-session.js`、pi-ai `dist/utils/retry.js` bytes 相同。
- `node_modules/@earendil-works/pi-ai/dist/utils/retry.js:4-92,188-195`：先排除 insufficient_quota、billing、subscription usage limit 等，再匹配 overloaded／rate limit／429／500／502／503／504／520／524／network／stream drop／明確 transient retry wording 等。不是只看 HTTP status，更不是模型推理決定是否重試。
- `node_modules/@earendil-works/pi-coding-agent/dist/core/agent-session.js:2978-2982,3028-3062`：context overflow 先交給 compaction；普通 retry 仍需 settings.enabled、未超過 maxRetries、未取消，再 exponential backoff。
- `.../agent-session.js:1380-1450`：低層 agent 結束後，外層依序檢查 retry、compaction recovery、queued work；最終 emit agent_settled。停止當次模型 run 不代表 CLI process crash，也不保證既有 background jobs 被取消。
- `node_modules/@earendil-works/pi-agent-core/dist/agent-loop.js:141-154,155-207`：assistant stopReason=error/aborted 結束低層 loop，不執行其中 tool calls；普通 toolResult isError 可進入模型下一輪，由模型處理工具失敗。
- `node_modules/@earendil-works/pi-ai/dist/api/openai-responses-shared.js:642-655`：stream error／response.failed 轉成 Error，保留 code/message 於文字；不同 provider transport 格式可能不同。
- 已完整讀取全域 README.md、docs/settings.md。官方 settings 文件預設 retry.enabled=true、maxRetries=3、baseDelayMs=2000、maxAgentDelayMs=60000；provider.maxRetries=0。這些是文件預設，不代表使用者失敗 session 的 effective settings 已確認。

## 離線分類驗證

直接呼叫專案與全域實際分類器，兩者結果相同；未呼叫 provider、未讀取或修改 credentials、未改 source/settings：

| errorMessage | retryable |
| --- | --- |
| 使用者完整資安警示 | false |
| cyber_policy: This content was flagged for possible cybersecurity risk. | false |
| 429 Too many requests | true |
| 429 insufficient_quota | false |
| 503 Service unavailable | true |
| stream ended before a terminal response event | true |
| 401 Invalid API key | false |
| maximum context length exceeded | false（外層另走 compaction 判斷） |

## 官方 API 文件

以 web_fetch 實際讀取：

- OpenAI《Cybersecurity checks》：https://developers.openai.com/api/docs/guides/safety-checks/cybersecurity
- OpenAI Help Center《OpenAI Daybreak - Common Issues and Troubleshooting》：https://help.openai.com/en/articles/20001259-openai-daybreak-common-issues-and-troubleshooting

官方文件說明 cyber safeguards 可回傳 cyber_policy，streaming 也可能在串流途中收到。官方區分 system-level safety block 和 model-level refusal；合法防禦工作可能誤判，Daybreak access 也不代表取消所有 safeguard。此類情況應檢查 approved access／model／project 或向 Support 提交去識別化 request ID、時間與錯誤，而不是當作一般網路故障無限重試。

## 範圍與限制

- 目前未取得使用者該次 session 的原始 HTTP／SSE payload、實際 error.code、HTTP status、model/provider 與 effective retry settings，因此不將 cyber_policy 或 400/403 等當作該次已證實的 wire metadata。
- 實際分類器使用文字 pattern；若 gateway 包裝成含 503 或其他 transient pattern 的訊息，分類可能不同。上述 false 是對使用者提供文字及明確 cyber_policy 範例的實測。
- 有排隊訊息或 extension continuation 時仍可能有後續 run；一般 non-retryable API failure 不會自行以相同 context 重試。
- 未新增 retry policy、未嘗試重送受阻請求、未替換模型或修改 safeguards。
- GitHub upstream retry source 的 web_fetch 曾回 HTTP 504；本次程式行為判斷依據是已安裝的 1.1.0 source，未用線上 HEAD 代替本機版本。
