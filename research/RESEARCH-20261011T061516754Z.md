# MXC 1.0 三路徑讀寫政策：Pi 啟用條件分析

日期：2026-10-11。新政策為預設 readonly，僅 session workspace、真實 ~/.pi、系統預設 TEMP 讀寫。本文件是分析與最小補測，沒有修改 production code 或真實 settings，也沒有重跑完整三路徑政策 matrix。

## 現有證據與重要修正

前次完整報告：report/REPORT-20261011T060512423Z.md。

本次讀取固定 MXC 1.0 npm package README、本機 Pi 1.1.0 dist/utils/shell.js 及 shell-tools factory。重跑 native --probe：base-container、needsDaclAugmentation=false、baseContainerSupportsIngressHostLoopbackAllow=false。

Pi 1.1.0 getPowerShellConfig 優先 pwsh.exe，其次 powershell.exe；原生參數含 -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command。最小對照：相同 MXC 政策下，Windows PowerShell 5.1 不加 Bypass 時 npm --version 發生 AuthorizationManager 錯誤／無版本輸出；加 Bypass 後輸出 11.13.0。兩者都可能返回 0，不能只看 exit code 宣稱前者成功。前者未設 ErrorActionPreference Stop，與前次完整 direct-tools script 的失敗 exit 1 不矛盾。

這是行程層級旗標，不是修改全域 ExecutionPolicy。正式 adapter 應保留宿主參數、UTF-8、cwd/env/command prefix 和 stdin command transport 語意，而非照搬簡化研究 wrapper。補測只證實 launcher，可降低前次對 5.1 npm.ps1 的阻礙判斷；symlink 與完整 npm workflow 未因此驗證。

## 先確定 sandbox 邊界

1. 只包 shell：Pi UI、provider 和 extension loader 保持 host 執行；目前較小風險與較低啟動成本。但 read/edit/write、PTY、pi.exec、! 指令、subagents、extension 自行 spawn 並不因 bash/powershell 被包裝而自動受限。
2. 整個 Pi：應用 native containment 啟動 Pi，才有機會涵蓋 Pi 及其本機 descendants。但原測試只驗證 offline RPC ready；provider/auth refresh/MCP/PTY/browser/所有 extensions 仍未完整驗證。啟動中位數約 15.812 秒，相較 baseline 7.066 秒，必須明確接受這個成本或先調查快取影響。

不能把 shell-only feature 宣稱為全 Pi 權限限制；需要逐條標示哪些執行途徑被覆蓋／不支援。若保留 Bash 名稱，其語法和設定不能偷偷改成 PowerShell。

## 啟用的必要條件

### A. 可運作 shell 與 OS backend

- 固定 executor／schema 版本；native probe 和實际工作命令皆成功。
- 保留 allowDaclMutation:false，不為相容性默默改 host ACL。
- 本機 PowerShell 7 是已成功的起點，ui.disable:false 是實測必要條件；這不要求放行剪貼簿／injection。
- Git Bash 仍 0xC0000142；新增 host TEMP 未完整實測，不能推定會解決 DLL 初始化。若要同時支援 Bash，這仍是 blocking issue。
- Native executor 方案不因本機 Node 24.15.0 而必須先升級；若改用 MXC Node SDK stdio/PTY，固定 1.0 package README 需要 Node 24.21.0+（24 系列）或 26.8.0+，並補實際 SDK lifecycle tests。

### B. 三個 RW 範圍與 runtime 路徑

- 在 host 啟動 sandbox 前解析／正規化 workspace、真實 home 和 host os.tmpdir；不要在 sandbox 內再解析已被改寫的 home/localappdata/temp。
- workspace grant 應綁 session／明確核准的工作根，不因 shell cd 到其他地方就自動新增 readwrite grant。
- 主機 user TEMP 與 MXC 私有 TEMP 是不同範圍；不得默默把整个 AppData 或 Windows 系統資料夾加入可寫。
- 前次 runtime TEMP/LOCALAPPDATA 被改到 Packages/sandbox.{GUID}/AC；private npm cache 曾在 AC/npm-cache，而非 AC/Temp。故允許 host TEMP 不等於已解決全部 private runtime writable storage 的字面政策问题。須明確允許 backend-managed private scratch 或確認是否能限縮。
- HOME/USERPROFILE/PI_CODING_AGENT_DIR 不應為日常執行改成隨每次命令消失的身份，否則 session、credentials、設定與工具 cache 可能找錯；需測實際檔案解析與 OS private env 改寫後的效果。
- npm/pip/build/extension cache 盡量導向 workspace、~/.pi 或 TEMP，不以放寬整个 host LOCALAPPDATA 作為捷徑。
- readonly grant 仍須涵蓋 executable、DLL、node_modules、Python stdlib、Git config、憑證、workspace 父目錄等所需讀取路徑。磁碟根 grant 不當作跨版本全路徑保證，需覆蓋實際 backend 與 path alias/junction 測試。

### C. 網路政策

- 新政策是 filesystem restriction，不代表要禁網；必須獨立明確決定是否允許 shell egress。
- 前次 offline 通過不代表 npm registry、git clone/fetch、DNS/TLS、proxy/CA、provider streaming 或 OAuth refresh 可用。
- shell-only 時 Pi host provider 本身不受 shell sandbox 的 network policy 限制；whole-Pi 時需要驗證 provider/auth refresh 及 catalog update。
- 本機 probe 的 ingress hostLoopback allow 能力為 false。localhost MCP、local model、debug/dev server connectivity 不能只填 allow 就宣稱支援，需 request-specific probe＋實際 loopback 測試；必要時改 backend 或把該宿主服務留在 sandbox 外。

### D. 工具 compatibility

- Node/Python/rg/Git 基本操作已有 green，但尚未包含全部 hook、SSH credential helper、native addons、process workers 或 build toolchain。
- npm tarball pack/install/test 通過；file:dir symlink 與 npm workspace/link 類操作需要另外解決或明列不支援。增加 TEMP 是檔案 grant，不會自動補足 symlink/OS token/IPC 能力，不應以提升全 Pi admin 權限來處理。
- PowerShell launcher 應保留 Pi 的行程旗標；npm.cmd 或 direct Node npm CLI 為已測的替代方式，且不得重寫 Bash 命令為 PowerShell。
- 安裝 package lifecycle scripts／有 bin shim 的 package 尚未完整實測，不能把 ignore-scripts 的小型 tarball fixture 當所有 npm install 都正常。
- global npm/pip 安裝、外部 git worktree、外部虛擬環境、專案外輸出在此政策下可能刻意不可寫；只有使用者明確核准才新增小範圍 grant。

### E. Pi runtime 正式整合

- 正式 adapter 在既有 shell-tools execution seam 中整合，不能再註冊衝突工具。只啟用被使用者選取的工具，保留設定/trust/managed-child exclusions。
- 保留 timeoutMs 輸出停滯語意、streaming/backpressure、輸出截短／退出碼及既有 foreground/background schemas。
- 測 AbortSignal、timeout、job cancel、reload/shutdown、native executor 和 descendant cleanup；不可只殺 wrapper 就宣稱 process tree 全停。
- background 記錄、log/journal、monitor publisher 和 subagent startup/resume/query 等需測真實 host，不允許父層限權而子層默默裸跑。
- spawn/validation failure 必须 fail closed，不在 MXC 不可用時回退 unsandboxed host。
- shell-only 模式須明確標示 PTY/WSL/SSH/Web/extension spawn 等未覆蓋範圍；whole-Pi 模式也要驗證實際 descendants/IPC/service boundaries，而不是假設所有系統服務都繼承 containment。

## 最小可用起點

建议以显式 opt-in 的 shell-only + PowerShell 7、native executor、ui.disable:false、禁止 DACL mutation、lazy launch、三個 host RW 根加明確管理的 private scratch 作起點。這不是完整 Bash 相容或全 Pi sandbox 的完成宣告。若要求 Bash 与所有 extensions 透明相容，不宜立即預設啟用。

正式啟用前最小驗收：
1. 新政策完整 RW/RO/host TEMP/private scratch/path alias matrix。
2. 真實 Pi dispatcher shell call、foreground/background/cancel/reload/subagent propagation。
3. 一個實際專案 npm ci/build/test（含必要 lifecycle/native/bin scripts）、git clone/fetch 或替代離線 credential-helper probe。
4. provider/auth/MCP/localhost/PTY/browser 依選定 sandbox scope 分項驗收。
5. 同配置啟動及 shell 成本對照；cache 調整不能以額外全機 RW 掩蓋問題。

本次僅分析與最小 native probe／npm launcher 對照，不是上述驗收已通過，也未跑專案單元／整合套件。
