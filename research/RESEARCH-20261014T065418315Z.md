# Fork 輸入欄上方動態面板可行性研究

## 結論
可行。Pi 1.2.0 已支援 `ctx.ui.setWidget(..., { placement: "aboveEditor" })`；本專案 Subagents 與 Shell 已共用 BackgroundPanel。Fork 目前僅更新 footer status，尚未接入此面板。建議將 Fork 加入既有共用面板，而非建立另一套 UI。

## 程式證據
- `modules/fork/src/manager.ts:258-265`：`refreshUi()` 僅呼叫 `setStatus("pi-fork", "Fork: N active")`，沒有 `setWidget`。
- `modules/fork/src/manager.ts:56,93,129,209,241`：受理、狀態轉換、child phase、session_start 與取消已有 UI 更新入口。
- `modules/subagents/extensions/subagent/live-widget.ts:23-50`：Subagents 以 owner-bound adapter 呼叫共用面板 attach/update/detach，UI 失敗不控制 job。
- `modules/shell-tools/src/background-panel.ts:89-112`：共用面板使用 aboveEditor widget。
- `modules/shell-tools/src/background-panel.ts:12,161-169`：目前種類與指令只包含 subagents/shell。
- `modules/shell-tools/src/job-view.ts:5,47-59`：PanelKind、標籤與摘要計數目前只支援兩種類；加入 Fork 時必須同步修改，否則會被當成 SA 或誤算成 Shell。
- `modules/fork/src/child.ts:114-121`：stdout reader 僅處理 RPC response 與 assistant message_end，尚未提供工具執行／串流活動投影。
- 本機 Pi 1.2.0 `docs/tui.md` 與 `examples/extensions/widget-placement.ts` 證明官方 widget API 支援輸入欄附近的持續內容。

## 建議範圍
1. 共用 PanelKind 新增 fork，更新摘要計數、種類標籤、/background-jobs 篩選及說明。
2. Fork 增加小型展示 adapter，將既有 Job/ForkRecord 投影為 PanelJob；不把 manager 或程序管理合併到 Shell/Subagents。
3. 使用既有 refreshUi 事件入口更新，session_start bind、session_shutdown detach；Fork 跨 session 持續執行，但面板只呈現符合目前來源 session/file/canonical cwd 的工作。
4. 初版可显示 title、短 job ID、awaiting_snapshot/starting/running/finalizing/cancelling、完成與用量；執行中尚無用量時顯示 pending，不能顯示為零。
5. active 判斷須包含 unreleased permit：即使 runner 已報終態但 childClosed 未確認，也不能呈現為已完全清理。cancelling 不等於已退出。
6. 若「動態」包含目前執行工具／模型輸出活動，另在 child RPC reader 增加有界、節流的純展示事件 callback；只保存安全活動摘要，無須輪詢 fork_status 或重讀整份 JSONL，也不改變完成判定。

## 驗證建議
後續實作後驗證狀態轉換、與 Shell/Subagents 共存、切換 session 不串台、舊 binding callback 不污染新畫面、取消／清理未確認語意、無 UI／RPC 不建立 widget、UI failure 不影響任務。因涉及 Fork 與共用 Shell presentation helper，依專案規則使用相關模組分組及 test:cross；實際修改範圍確定後再選定精確命令。

## 本次界線
僅靜態研究與閱讀本機已安裝 Pi 1.2.0 文件／範例，未修改程式碼，未執行測試，未做人工 TUI 重現。可確認未接入面板的程式原因；無法僅憑本次研究確認 footer 狀態是否另受使用者 UI 設定影響。
