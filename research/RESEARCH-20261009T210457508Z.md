## 實際執行的探針與結果

### 1. FFF 異根並發容量（受控 Promise，不用 native）

使用真實 AuxFinderPool、fake picker factory，在四個異根 acquire 都等待時才逐一 resolve。MAX_AUX=3，但全部完成後 size()=4。Assertion 通過；隨後 destroy 清掉全部 fake finders。

### 2. FFF destroy 與 late creation（受控 Promise，不用 native）

開始 acquire → pool.destroy() → resolve finder → await acquire。實際 size()=1、late finder.isDestroyed=false；證明既有程式會在 teardown 後重新發布 resource。最後再次 destroy，沒有留下真實資源。這個動態證據只涵蓋 aux pool，不直接證明 host reload + main finder 全流程。

### 3. Note 合法內部 junction（真實隔離 filesystem）

臨時 cwd 建立 `..archive/`，`plan/` junction 指向同 cwd 的 `..archive/`；呼叫真實 noteTool.execute。實際拒絕 NOTE_DIRECTORY_ESCAPE，符合誤判路徑。整個臨時 home 最終移除；沒有在 repository 或 cwd 外建立文件。

### 4. Schedule 不存在 job 的錯誤旗標（真實 tool、fake storage）

getJob 返回 undefined，remove action 實際回 `details.error='Job not found: missing'`，但沒有 isError 欄位。這證明 return shape，不是另跑真實 host/codemode rejection 流程。

### 5. Schedule false-trust start/fire（真實 scheduler、受控外界操作）

有效 interval job：type=interval、intervalMs=3600000、schedule=1h、unbound+enabled。ctx.isProjectTrusted 固定 false，並記錄呼叫次數。scheduler.start 確認真的建立 nextRun；顯式呼叫受控 fire（不等待 timer，不新增固定 sleep/idle test），pi.sendUserMessage 僅攔截，不執行 provider。觀察 interceptedSubmissions=1、projectTrustChecks=0、providerCalls=0。finally scheduler.stop 清掉 timer。這是模組邊界證據，**不是**完整 CLI 未受信任專案利用實測；child trust 不繼承另由來源確認。

### 6. PTY terminate reject 仍釋放容量（fake EventEmitter workers）

真實 matchPattern，fake worker 回 matched=true，但 terminate rejects 且不發 exit。連續17次都被 admitted，配置 MAX=16，證明 cleanup 失敗也釋放計數。沒有生成 OS threads，亦不將 fake failure injection 宣稱為真實 Node worker leak 重現。

上述初版隔離探針 runner exit0、臨時 home 清理完成。初版 Schedule fake job 漏 intervalMs、fake remove storage 漏 getJob，產生 fixture shape 診斷；相關兩項以隨後修正探針為準。修正版 runner exit0，使用有效 interval 與真正 missing-job lookup，所有 timer 已 stop。初版假資料造成的「cron parse 1h」不是產品 bug，不納入缺陷數。
