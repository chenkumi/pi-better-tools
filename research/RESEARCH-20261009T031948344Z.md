## 建議修法（尚未實作）

宿主保留該次 API 中斷對應的 assistant／未执行工具卡片，分離 provider-interrupted 與實際 tool_execution_end failure。按真正 auto_retry_start/end 事件更新顯示，避免依 command/error 文本推測。

- API 中斷但尚未排程重試：API interrupted（是否重試尚未確認）。
- 確認 auto_retry_start：Auto-resume · attempt N/M，neutral/pending 色。
- 重試已恢復：API resumed；舊未执行卡片標示 previous attempt interrupted／superseded，不把舊 toolCall 宣稱已執行成功。新 call 依新 toolCallId 的真實 execution 結果呈現。
- 重試耗盡：API retry failed，error 色、保留最後原因。
- 使用者取消：Auto-resume cancelled，不冒稱 retry exhausted 或 success。
- 真實 tool failure：原 error／exit code 保留，不因主對話恢復而消除。

需隔離 offline provider/TUI 回歸，涵蓋 partial toolCall→error→retry→成功、耗盡、取消、不重試、真正工具失敗、不同 toolCallId、歷史 session 重畫／reload；只改呈現與必要顯示 metadata，不改工具副作用、重試策略或模型可見錯誤語意。
