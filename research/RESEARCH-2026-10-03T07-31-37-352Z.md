# WSL 與 Mac PTY 實連檢查

使用者提供 Mac SSH `ckm@192.168.50.5`，WSL／Mac 專案路徑均為 `~/GitHub/pi-better-tools`，並授權確認連線。本次只執行唯讀探測，未修改遠端檔案、SSH／Pi settings、known_hosts 或 Git，未提供或輸入密碼。

## 結果
- 透過 local PTY 啟動 `C:\Windows\System32\wsl.exe --exec sh -lc ...` 成功，實際輸出 `Linux`、`DISTRO: Ubuntu`、`PROJECT: /home/ckm/GitHub/pi-better-tools`。已確認 WSL 可啟動且專案目錄存在；未驗證 Linux dependency installation 或全套測試。
- 分別以 Windows OpenSSH 與 Git bundled OpenSSH 的絕對 executable path 啟動 local PTY，使用 `-tt -o BatchMode=yes -o ConnectTimeout=10 ckm@192.168.50.5`，保留 host-key verification。兩者均回報 `Permission denied (publickey,password,keyboard-interactive).`。SSH endpoint 可達，但此次非互動驗證失敗，無法確認 Mac 專案目錄。不能推定已登入或單一根因（可能為公鑰尚未授權、私鑰／agent 不可用、使用者或伺服器驗證設定問題）。
- 初次僅傳 command `ssh` 時 pty_spawn 回傳 `File not found`；PowerShell Get-Command 找到 Git SSH。改成明確 executable paths 後已能啟動 SSH，故此問題與遠端驗證錯誤分開記錄。
- 三個成功建立的探測 PTY sessions 都已釋放。此次是直接啟動 local SSH／WSL transport 探測，不等同具名 target settings 端到端驗證；未讀取或新增真實 target settings。

## 使用者調整公鑰後重新驗證
使用者詢問將 `.pub` 放到 `~/.ssh/authroized_keys/` 是否正確；已說明正確名稱為 `authorized_keys`，且應為含公鑰內容的檔案，而非資料夾。使用者隨後明確要求再連線。

透過 local PTY 啟動 Windows OpenSSH，以相同 `-tt -o BatchMode=yes -o ConnectTimeout=10` 與保留的 host-key verification 唯讀探測成功，輸出：

```text
CONNECTED: macOS
Darwin
PROJECT: /Users/ckm/GitHub/pi-better-tools
Connection to 192.168.50.5 closed.
```

`pty_wait_exit` 回傳 `exitCode: 0`，探測 session 已釋放。已確認 Mac 非互動 SSH 登入成功及專案目錄存在；未輸入密碼、修改遠端檔案或執行測試／Git 同步。先前驗證失敗為歷史結果，不再是目前登入阻礙。具名 target settings 端到端驗證及跨平台測試仍未執行。
