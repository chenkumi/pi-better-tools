# Blackhole 掛載後 legacy timing settings 警告：唯讀原因調查

## 結論
使用者所貼警告是新 Pi-owned 模式的明確相容性診斷，不是該訊息本身表示掛載失敗。原生壓縮時機／切點已交 Pi，但既有全域 Blackhole JSON 還保存四個旧控制鍵，正好對應警告中的鍵名。調查未修改設定、程式或 credentials，未呼叫 provider、未執行新的驗證分組。

## 來源與條件
- `modules/blackhole/src/core/pi-owned-settings.ts:1–7`：legacy key 集合中，只要 explicit value 非 undefined 即產生警告，無須值錯誤或壓縮實際發生。
- `modules/blackhole/src/core/unified-config.ts:757–805`：讀 global config，必要時 fallback legacy sources，再合併 project override；在 defaults merge 前檢查 explicit legacy keys。環境 legacy keys 另於 900–906 診斷。
- `modules/blackhole/src/pi-base/blackhole-settings.ts:543–545`：ConfigManager diagnostics 使用相同 helper。
- `modules/blackhole/src/pi-base/config-manager.ts:488–491,540–574`：explicit global/project/env/session layers 合併後產生 warnings；host session resolve 經 ui.notify(warning)，以 session/message bounded 去重；settings command 也會讀 warnings。

## 處置界線
- 可以暫時保留鍵值；訊息只是告知它們不再控制 Pi timing/cut，不能藉它們要求禁止 final 後 native threshold。
- 若只消除這個 legacy-key 診斷，需經使用者授權移除 explicit obsolete keys（不是把值改為 off/0/null），保留其他有效 BH 設定；project 覆寫值仍是存在的 key，不能視為刪除 global key。
- 不做自動遷移。若要實際改時機／保留，另配置 Pi `compaction.enabled/reserveTokens/keepRecentTokens`（含 model overrides）；retainedToolOutputMaxTokens 與 keepRecentTokens 意義不同，不能 20000 原值一對一照抄。
- 本警告與獨立 review 的 core R1/R2 問題不同：`report/REPORT-20261009T163726243Z.md` 的無證明方括號 header merge／malformed span sorting 仍需另外修正，掛載診斷沒有證明 source 完整接受。
