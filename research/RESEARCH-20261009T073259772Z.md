## 建議測試 ownership / acceptance（尚未實作）
- pi-runtime unit：error classifier；有限次 recovery；不可恢復/未知/政策 cyber 阻擋 fail closed；manual confirmation 未收到前無重試/重寫/改模型/工具繞過；確認不能取消政策限制；per-user-task budget 不因內部 follow-up、compaction、retry 重設；取消先於 recovery；重複 error 不雙重扣款/重入。
- pi-runtime integration：隔離 Pi 1.1.0 真實 session/CLI，mock/offline error 注入與 lifecycle/reload/shutdown、取消、confirmation、兩個 user task budget 分界。不使用真實 provider，不讀個人設定。不得新增靠 idle/watchdog/sleep 的 timeout 語意測試。
- cross：所有 manifest entries + SDK composition + provenance，不把新 module-owned stage 標成 all-modules；新 hook case 若擴充 tests/fixtures/sdk-hooks.mjs，需同步 tests/integration/sdk-hooks.test.mjs 和 package-smoke.mjs L248–250 固定 14 cases/21 hooks，僅實際數量變動才改。
- package：因這次未來實作會改入口及 tarball files，應依 AGENTS 執行 npm run build/typecheck、npm test、npm run test:module -- pi-runtime、npm run test:cross、npm run test:package；完整 integration/check 依發布或明確完整驗證要求。所有 provider-related 測試只能 offline fixtures，不是付費 provider 驗證。

## Architecture / Start Here
package manifest → Pi loader 直接 TS entry；run-checks task label → module owner → evidence；package-smoke npm pack required assets → isolated production loader fixture；verify-sources 同時核對 immutable imports、native files、added integration files 與 active root hashes。先改 manifest 與 task ownership，再補 count/assets/provenance。以上是整合變更清單，不宣稱新 recovery 實作已存在或已通過驗證。
