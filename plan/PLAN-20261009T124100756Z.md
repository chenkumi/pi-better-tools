## 必要 decision：不能只做 public event happy-path

### 不採用的 shortcut

1. 把 agent_end/turn_end/agent_settled callback 改名 before-request。
2. 在 context event 呼叫中斷式 ctx.compact。
3. handler throw 或 ctx.abort 後宣称必定沒有 provider dispatch。
4. before_provider_request 中進行 compaction，然後繼續使用已建立的舊 wire payload。
5. 關閉 native enabled／overflow、改成固定 90%、隱式忽略 midRunCompaction:off。
6. 使用 throwing transformContext 或覆寫 native private _checkCompaction/_runAutoCompaction/_installAgentRequestProjection。

### 推薦需核准的限縮方案

在 **既有 captured owning-session adapter** 中，新增僅 Pi 1.1.0 契約支持的 SDK boundary 能力：

- 串接 public `Agent.prepareRequest`，先 await/preserve previous callback，取得 canonical context 與已決定的 physical model，才做壓力與 paired-tool/owner/session/branch/generation/signal 檢查。
- 在確定下一 conversational request 已選定時，使用既有 inline compact 能力；成功回傳更新後 context 給同一低階 loop，不 abort、不另開 run、不合成 continuation、不多 poll queue。
- 維持 original AgentSession request projection/router/state/queued messages；不得 reroute、重做 admission 或重放任何 tool。
- 需要保護最後實際 provider input：考慮在 public `Agent.streamFunction` 外建立 **不 throw** 的 guarded dispatch，驗證經全部 context transforms/LLM conversion 後的真實 physical model／prompt／tool declarations／output reserve。拒絕時回符合 StreamFn contract 的 non-retryable error/aborted event stream，絕不先呼叫 original provider。此能力是本輪必須明確確認的 captured Agent 控制擴張，不把它偽裝成既有 compact adapter 已有的保證。
- 最後 dispatch guard 不重新執行其他 extensions 的 context handlers，不二次扣 Runtime reservations；外部 transform 新增不可預估壓力時 fail-closed/report，而不冒險重播 transforms/quotas 或 sending stale context。
- virtual selection 與 physical compaction engine 不一致、unknown adapter shape、外部 replacement/ownership mutation 必須具體 support/reject；尚未有 live proof，不能預先宣稱涵蓋。
- Public `session_before_compact` 在 before-request mode 下，拒絕未被本 adapter 授權 request scope 的 native `reason:threshold`（含 completion 的 threshold）；manual/overflow 另行通過原 ownership/safety，避免关 enabled。需要 real-host proof cancellation dispatch order，不只 fake handler assertion。
