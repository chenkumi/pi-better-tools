# MXC 1.0 Windows shell sandbox 實測

日期：2026-10-11。本機 Windows 11 build 26200.9457、Node 24.15.0、Pi 1.1.0。

## 範圍
- 使用固定 @microsoft/mxc-sdk@1.0.0，另建隔離測試資料夾，不改根 dependencies／全域 settings／auth。
- 測試 bash 與 PowerShell 權限：volume readonly，僅 C:/GitHub/pi-better-tools 與真實 ~/.pi 可寫；只在專用 fixture 內寫入。
- 先 probe Windows 後端。T3 DACL fallback 會變更 host ACL；先以 allowDaclMutation:false 試跑，若只能 T3，不在整個磁碟／真實 ~/.pi 上遞迴修改 ACL。改以限定 fixture 測試並明確列出無法完成的完整政策。
- 測試 git、npm、node、python、rg，不僅 --version，加入離線實際操作。
- Pi 啟動比較：無付費 provider，隔離 agentDir、禁 credentials，測至 RPC readiness／TUI readiness；区分 lazy shell wrapper 與整個 Pi sandbox。
- 先保留最小範圍研究 harness，不預設修改 production shell module。所有腳本定期英文進度。

## 初始風險
- 本機 Node 24.15.0 低於本機 MXC checkout 所述 Windows SDK Node 最低版本；以 native executor 避免先升級全域 Node。
- readonly root 與 readwrite 子目錄是否能由 host backend 真正表達須實測；不以配置已接受等同安全限制成功。
- readonly 全機仍允許讀取 secrets，不是 credentials isolation。

## 驗證策略
研究 harness 不更改 manifest／production code；執行最小實測，不跑無關全量 suite。後續紀錄命令、退出碼、原始證據、測量樣本及限制。
