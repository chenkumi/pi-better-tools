# billion-context-pi 與 pi-blackhole 壓縮機制對照

## 範圍

唯讀檢視本機 C:/GitHub/billion-context-pi 0.1.83（HEAD f9dc713，working tree clean，acp-kernel devDependency pin 0.0.98）與 C:/GitHub/pi-blackhole 0.5.12（HEAD a2e4c13）。pi-better-tools 實際仍安裝 Blackhole 0.5.11。另讀取兩專案公開 GitHub README 與對應 commit 的 runtime/index/compress/decompress/before-compact 原始碼作補充，未 fetch、安裝、執行 extension 或模型。

## 核心差別

Blackhole：以 agent_end（persisted session + midRunCompaction=off）或 turn_end inline/pause 觸發 Pi compact pipeline；session_before_compact 回傳 deterministic structural summary + observational-memory projection + firstKeptEntryId；Pi append 原生 compaction entry，模型與 TUI resume 都採 compaction-aware projection。Observer/Reflector/Dropper 額外呼叫模型，compaction compile 本身不呼叫 LLM。minimal 可 compact-all，最後回答 cosmetic copy 的 host branch 順序缺陷在 0.5.12 未修正。

ACP：src/index.ts:187-191 session_before_compact 在 active/non-refused 時無條件 cancel（不只 auto；該 hook 不判斷 manual reason）；每次 context event 前由 runtime.stateFor 讀 host context entries、載入 ACP sidecar，core.processTurn 產生 request-time projection + nudge；模型呼叫 compress，自己提供 startId/endId/summary，kernel applyCompression 後把 state save 到 sidecar。主 pipeline 不需等 agent_end。摘要層級 T1→T2→T3 由 block/message range 操作形成。emergency truncation 是另外的機械後備，不可聲稱永遠沒有截斷。

## resume 判斷

ACP 不用 Pi 原生 compaction entry 作為自己的壓縮機制，因此在未被其他 compactor 裁切的新 session，模型看摘要、TUI 仍可呈現原始歷史，是從兩個系統投影路徑推導的結果；未做真實 TUI resume 驗證。切換現有 Blackhole session不會還原舊 compaction 界線：ACP runtime.ts:35-39 / 827-880 仍從 buildContextEntries() 起算，不是 getEntries() 的全歷史。

## 歷史查詢與持久化

ACP search_context 查 summaries 與 historical message index；decompress 從原始 session entries/ancestors 回收內容，block 預設寫 ~/.cache/pi/acp-decompress 檔，inline:true 是工具結果回傳並記錄 refold metadata，不是無損編碼或自動還原整份 context。

ACP state 存 <sessionFile>.acp.json，遷移仍應成對保存 JSONL/sidecar。新版 runtime.ts:843-855 在無 block 且有 compress history 時嘗試 rebuildStateFromLog；README 聲稱 sidecar 缺失必然完整重送的描述不完整，不能忽略這個 source fallback，也不能保證 replay 等價完整備份。

## 整合注意

不應雙壓縮：ACP context projection、compaction cancellation 與 Blackhole hooks 會競爭。使用者若日後評估整合，應隔離 session 測試、停用 Blackhole 壓縮入口；delegate:false 保留專案既有 subagents，不假設 ACP 第三方偵測會識別本 suite 的 snapshot。ACP autoUpdate 預設 true，updater 依 registry tag/range 策略且有 exact stable version pin 不更新的 gate；可顯式 autoUpdate:false，勿讓套件背景更新破壞 root lockfile 管理。

## 限制

未執行任何測試分組、真實 Pi loader/TUI/RPC resume、費用/cache/模型品質 benchmark；沒有證據支援哪個必然更便宜或摘要更準。套件名稱 Billion 不代表單次模型 context window 能容納十億 token。
