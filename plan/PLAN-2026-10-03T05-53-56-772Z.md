# 重複測試盤點與移除紀錄

## 範圍與方法
使用者要求檢查並移除重複測試。掃描 `modules/` 與根 `tests/` 的 `.test.ts`／`.test.mjs`，以 TypeScript AST 辨識 516 個 test／it 宣告（參數化宣告計一次），比對去除空白／註解後的 callback tokens：未發現完全相同的 callback。再核對相似情境的輸入、被測函式、斷言與 runner；保留不同 fault、平台、單元／整合／production matrix 層級。

三個唯讀 scout 派遣均失敗（incomplete JSON protocol），未取得有效盤點結果；本紀錄依父 session 實際靜態掃描與讀檔，不採用失敗 child 作為證據。

## 已移除：2 個冗餘案例、1 條相同斷言
1. `modules/file-tools/tests/file-operations.test.ts` 的 `allows identical text elsewhere outside the range`：同一 `editTextFile` 範圍選擇契約已由 `uses the line range as a search window rather than a whole-line replacement` 覆蓋；後者同時驗證範圍外原文字不變、範圍內子字串替換、hash、位置與 diff，故保留較強案例。
2. `modules/subagents/tests/child-args.test.ts` 的 `all dispatch modes share the same protected child arguments`：此迴圈未傳 dispatch mode，只換 `/tmp/single.txt` 等檔名，三次调用同一 builder 分支。保留 `worker-style child with no tools excludes recursive dispatch`、`session-store.test.ts` 的 ARG-01（new／resume 均驗證 exclusion／@file／persistence），以及 `always-managed.test.ts` 真正不同 dispatch modes 的測試。
3. File operations 的 `formatFileToolErrorForDisplay("plain failure", false)` 斷言：`error-display.test.ts` 的 malformed table 對完全相同文字與 false／true 模式已有同一斷言。保留整個 structured error／registered renderer 案例及其獨有斷言。
