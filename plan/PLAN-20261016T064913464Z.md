# 有界限的近期檔案增量檢查 Extension 實作計畫

## Title
有界限的近期檔案增量檢查 Extension（模組名稱暫定 file-audit）

## Goal
在本專案新增可單獨載入、排除與測試的原生 extension。僅追蹤目前 session 成功的 read／write／edit／note，以對話窗口及最後 N 個不同檔案限制底層記錄量；使用者手動執行時，才對候選檔案進行有讀取量上限的 provenance 雜湊比較。它不取代全專案 sources:verify，也不自動修改任何 provenance、檔案內容或模型對話。

本輪只建立計畫；以下模組、檔案、命令及設定名稱均為預計新增，除 References 列出的既有項目外，不代表目前已存在。

## Scope 與假設
- 模組暫定 modules/file-audit/，統一入口 src/index.ts。維持單一根 package 與 lockfile，不新增 plugin manager、建置產物或 runtime dependencies。
- 第一版只有手動 slash command，沒有模型工具、自動任務結束掃描、watcher、排程、額外模型呼叫、跨 session 彙整或活動資料庫。
- 窗口採 before_agent_start 次數：user/custom 啟動均前進，單次 run 內多次模型／工具往返不額外計數。這是明確定義的 run 窗口，不冒稱 assistant 訊息數或人類對話輪數。
- 狀態只存在本 extension 的 session/generation 記憶體。session_start、session_tree、session_shutdown 清空；reload／resume／切分支不回掃完整歷史。UI 明示覆蓋起點，因此不混入放棄的分支。
- 範圍為目前 cwd 本身的專案，不向祖先猜測專案根。外部路徑不做內容掃描。Shell／搜尋結果／其他 session／上述四種工具以外的活動不納入；支援宿主及本專案同名 read/write/edit，以及本專案 note，含宿主正常發出的 nested tool events。
- read 成功只代表工具讀過檔案，部分 read 不代表完整審閱；write/edit 成功代表工具成功完成，不保證 bytes 必然改變，不推論唯一修改作者。note 成功屬於新增檔案的寫入活動，與 read/write/edit 共用同一窗口、不同檔案容量及最後活動排序，不因是計畫／報告文件就排除。
- note 的路徑只能從成功結果的 structuredContent.relativePath／details.relativePath 取得，搭配執行時 cwd 解析；兩者皆存在時必須一致。結果缺失、型別錯誤、衝突或路徑逃逸均略過並計數，不從 content 文字解析、不用 type／時間戳猜檔名，也不保存 note.content。note 新增文件沒有 provenance 時分類為 untracked，不自動建立 hash 紀錄；其後 read/edit 同檔案須合併同一 canonical identity。
- 數值為本計畫建議的第一版預設，可修訂；不新增持久化全域設定。

## 預計介面與限制

### 手動指令
- /file-audit 或 /file-audit status：不讀取候選檔案內容；顯示目前 session 覆蓋起點、窗口、容量、候選數與有界列表。
- /file-audit check：固定當下候選快照，最近操作優先逐檔檢查；命令執行期間的後續活動不加入本次結果。
- /file-audit clear：清空記錄及統計，開始新的觀察區間。
- /file-audit limits --window 4 --max-files 50：只修改目前 session 限制；參數錯誤不改狀態，縮小限制立即淘汰。未提供的值保留；新 session/reload 恢復預設。
- status/clear/limits 不掃描 provenance。命令僅在 TUI 實際執行；非 TUI 不啟動檢查、不寫 stdout、不呼叫模型。事件追蹤本身不依賴 UI。

### 硬上限
| 項目 | 第一版預設／硬上限 |
|---|---|
| windowRuns | 預設 4，可設 1–30 |
| maxFiles | 預設 50，可設 1–500；0 不代表無限 |
| 單一路徑與識別欄位 | path 最多 4096 UTF-8 bytes，toolCallId 最多 1024 UTF-8 bytes；超限拒絕記錄並計數 |
| 待完成工具關聯 | 最多 128 筆，只保存 ID、工具名、執行時 cwd、已知路徑與 owner/generation/run；note 起始時沒有路徑，等成功結果再取；不保存完整 args/result 或 note.content |
| provenance metadata | 三份 JSON 總讀取上限 8 MiB，解析後檢查的有效 inventory 項目最多 50000；不足時停止／標示，不截斷後 JSON.parse |
| 候選內容掃描 | 每檔最多 8 MiB，每次總讀取最多 32 MiB，循序串流；同時最多 1 次 check，不排隊 |
| 顯示 | 最多 10 筆明細、每條顯示路徑最多 200 字元、整份輸出最多 8 KiB；明示隱藏及未檢查數 |

容量限制在每次納入紀錄時生效，不是輸出前才 slice。相同檔案重新操作必須更新最後活動順序；超限真正刪除最舊項目。窗口過期移除整個項目；項目只保留最後活動資訊，不累積無上限事件歷史。分類使用最後活動工具與目前保留項目的近期變更資訊，不能讓窗口外的歷史 write 永久污染目前分類。

只有 scalar 統計，不保存被淘汰項目清單；容量／過期／無法解析等計數標明為淘汰或略過次數，不誤稱精確的歷史不同檔案數。不以無上限去重集合計算 omitted。

### 檢查結果
- matched：候選檔案與有效紀錄一致。
- mismatch：候選檔案與有效紀錄不符。
- expected-absent：候選對應有效 removedFiles 記錄，當下確認不存在。
- missing：應存在的候選檔案不存在。
- untracked：沒有有效 provenance 記錄；不是通過，也不自動登錄。
- skipped／unavailable：外部路徑、超限、非一般檔案、權限／metadata 錯誤、讀取中變動、取消等，附原因。
- 結果固定標示「近期增量檢查，非全專案驗證」。零候選、缺 metadata、全數未檢查均不能顯示驗證通過。

## 驗證範圍與環境
- 前四個 checkpoint 先執行對應定向測試，runner 整合後以 file-audit 模組分組收斂，避免每個 checkpoint 重跑全專案。
- 最後跑 npm test 作基本單元檢查；typecheck/lint 為 TS 與 JS correctness；cross 因 manifest、scripts、docs/*.json 與跨模組文件整合必需。
- test:package 因本次新增 manifest 入口與 package files 必需，須能存取 npm registry；不把 build no-op 當驗證。不執行全量 test:integration 或 npm run check，除非另有必要或明確要求。
- Cross／production smoke 須有 rg 或測試專用 PI_BETTER_TOOLS_TEST_RG；不下載 binary、不更改個人設定。Blackhole passive、credentials 隔離，不呼叫真實 provider。
- 本計畫建立階段只做唯讀調查，沒有執行上述未來驗收，也沒有修改產品程式。

## 非目標與已知限制
- 不自動修正 provenance、不自動追蹤 Shell、不導入 pi-behavior-control 的 edit gate／verifier、不安裝 pi-session-files 作 runtime dependency。
- 不拆分既有 metadata、不重構全量驗證器、不新增共用 plugin manager、跨 session 鎖或任務所有權資料庫。
- 沒有開始基線，因此不判定差異何時或由誰引入；只報當前候選與紀錄的比對。
- N 及窗口以外的項目可能未經檢查就被淘汰；只保留可負擔的摘要計數，不保存完整遺漏清單。
- 總讀取 bytes 與 inventory 數量是可驗證的 admission 上限，不宣稱精確 JavaScript heap 上限或固定毫秒完成保證。宿主載入歷史的成本不由本模組控制；本模組本身不主動回掃。
- 生產 package 不包含 repository provenance JSON；獨立載入可追蹤檔案，只有在使用者 cwd 提供相應 metadata 時才能檢查。缺少時明確 unavailable。
