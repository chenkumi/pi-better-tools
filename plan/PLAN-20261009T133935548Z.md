# Blackhole Pi-owned compaction：用戶確認的最終方向

## 明確授權與取代範圍
用戶確認：「blackhole 確定修改為只複寫 pi 原生的壓縮行為，啟動時間點由 pi 控制」。同時明確禁止修改 Pi 原始碼。

此決策取代 before-request 計畫與 request-admission 擴張（PLAN-20261009T122651766Z、124100756Z、124516332Z），不採用先前四鍵 before-request+resume override。Pi 的原生時機包括可能在 final 後發生的 threshold 壓縮；本輪不承諾禁止該時機、不攔截 threshold 來自行延後、不改 SDK callback replay。

## 最終責任分工
- Pi：context threshold／reserve、何時啟動、自動與手動／overflow lifecycle、壓縮 preparation／保留邊界、持久化 compaction entry、重建後續 context、重試與取消。
- Blackhole：只在 Pi 公開 session_before_compact hook 已啟動壓縮時，產生結構化摘要、選擇性加入 Blackhole memory/evidence，回傳 Pi 可接受的結果。
- 保留 recall 與 display-only pre-compaction output，但它們不額外觸發壓縮、不修改模型上下文保留策略。

## 實作不變量
1. 不修改 Pi 原始碼、installed SDK、host packages或 root supported version，不新增 public prepareRequest／streamFunction wrapper 或私有 request/compaction method patch。
2. 停用／移除 Blackhole 自行 agent_end／turn_end threshold 排程、idle polling／deferred compact、inline auto trigger；無其他 observer／completion hook 偷偷啟動 native compaction。
3. 沿用 preparation.messagesToSummarize、turnPrefixMessages／previousSummary 與 firstKeptEntryId／tokensBefore。pure native-owned 模式不使用 aggressive buildOwnCut/minimal 重新選切點，保留原生 context-edit omissions／完整工具配對／split-span 邊界。Pi 的準備資料是 authoritative projection，不將未投影的 raw history重新納入摘要。
4. compaction summary provenance/details、OM evidence及display副本仍與既有 consumer 安全性相容；記憶處理不能暗自變成另一個 compaction trigger。
5. Pi auto／manual /compact／overflow 已啟動時可用 Blackhole hook；/blackhole 如保留只作明確手動原生 compaction request alias／origin marker，也尊重 native-owned 模式邊界。不自行另開 run／provider retry／換 model。
6. 明確規劃 config auto/manual/off、blackhole/pi-default engine，以及 legacy BH threshold/midRun/tail keys 的新模式互動；不能用 compactionEngine:pi-default 代替本模式，因那會連摘要也交回 Pi。用戶本專案須真的採用 pure Pi-owned 模式，而非只新增未啟用選項。
7. 舊設定鍵／持久化格式保留讀取相容；舊 BH threshold/midRun keys 在此模式不控制 Pi timing，文件／診斷明示其無效或不適用，不修改個人全域設定。Pi 原生 reserve／keepRecent 設定不被 Blackhole覆寫。

## 被取代的測試與證據
before-request normative 四個 red cases反映已被用戶取代的需求，不能繼續作本方案驗收義務；也不能 skip／降斷言假稱舊方案 green。保留 red logs與報告於 history，將測試重新歸屬成正確的 Pi-owned contract tests，或移除失效 normative suite並在交接精準列理由。Native-chain diagnostic 若留存，僅證明宿主既有行為、非本方案需修 bug；不要更改其 assertions來製造功能 green。

## 分工
Blackhole worker 獨占 modules/blackhole/**，先提出精簡設定採用策略並實作／驗證；不寫 repo .pi／全域設定，也不改 Monitor／Runtime／其他 modules、root docs/provenance/manifest。父於獨立review後處理最小 project adoption與根整合。Monitor core最新復審仍各自進行。Windows8.3 alias 保留 blocked；不擴 B2/B3／Monitor allowlist。
