# Pi Runtime failure debug logging

## 需求
依現有 opt-in config logging 模式，在 policy 暫停及 runtime-recover 參數拒絕時保存可追溯原因與參數，位置 ~/.pi/logs。

## 實作範圍
- 只修改 pi-runtime 模組、root README、docs/configuration.md 與 native provenance。
- 全域 agentDir/settings.json 的 pi-runtime.debugLog 僅 boolean true 啟用，尊重 PI_CODING_AGENT_DIR，不讀 project override、不改真實 settings。
- JSONL failure-only：API error、automatic pause、manual rejection。session/task/entry/model、budget、reason、command args/length、request hook snapshot；遮罩常見秘密，明示 snapshot 非最終 wire payload 與 truncation。
- 同步小型設定讀取／failure append，保留既有 recovery event ordering；寫入失敗警告，不取代原始失敗或改變 budget、安全／approval 行為。
- 請求只在開啟 logging 時捕捉 bounded snapshot；成功不寫 log，跨 turn/owner/run 不沿用舊 request。

## 使用與限制
- 未啟用真實設定；使用者須在全域 settings 合併 `{"pi-runtime":{"debugLog":true}}` 並首次 `/reload` 載入新程式，後续 logging 開關每次重讀。
- Failure-only logs `~/.pi/logs/pi-runtime/YYYY-MM-DD.jsonl`，沒有回填／自動刪除。正常成功不落盤；實際寫入失敗 warning，不承諾磁碟滿／權限拒絕時仍能記錄。
- API 只回報分類原因，無法推出未揭露的精確 policy 觸發片段。Request hook observation 非最終 wire payload，未捕捉及截斷均明示；常見秘密遮罩不是完整 DLP。
- 不改 policy、安全檢查、同模型／owner、人工確認或恢復額度。無 provider 呼叫、設定／auth／舊 session 改寫。
