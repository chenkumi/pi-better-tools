首次 Fork job `01M4WAZ5FD4ZBGVP7ZMN4WZPKH` 啟動 guard 以 CHILD_REJECTED: CAPABILITY_MISMATCH 拒絕，終態 failed、cleanup.childClosed:true、exitCode:1。此 Fork 未完成原任務；後續由目前 parent 直接查證與修正，不重啟失敗 Fork、不放寬 guard。此啟動問題是另外一項未修復事項，不併入本次修改。

## 查證與根因

1. 原案例單獨執行：1 fail、0 pass、0 skipped，退出碼1，nested.marker 不存在。
2. 在現有案例保留所有原斷言，額外從最後 captured child request 取 Shell 通知，解析單一 job，斷言 status completed、exitCode0。
3. 仍未修環境時，同案再次 red，取得：
   - status: failed。
   - exitCode: 127。
   - command: `node nested-job.mjs`。
   - output 含 `/bin/bash: line 1: node: command not found`，另有 WSL systemd user session warning。
4. 本機 Pi1.2.0 `dist/utils/shell.js:66–85` 以 ProgramFiles／ProgramFiles(x86) 探索 Git Bash，否則搜尋 PATH 中 bash.exe（可能 WSL）。本機 `C:\Program Files\Git\bin\bash.exe` 存在，而 Fork 隔離 env allowlist 未保留這兩個目錄變數。
5. 因此問題是測試隔離環境遺漏 OS 安裝目錄，導致選到 WSL Bash，WSL 中找不到 node，測試腳本未成功執行，不是本次證據顯示 Fork 提前回報。

## 最小修正

- 隔離 env allowlist 補 ProgramFiles 與 ProgramFiles(x86)，沿用 `tests/helpers/environment.mjs` 已有原則，不繼承 real HOME/auth/settings/child markers，不指定某台電腦的絕對 shellPath。
- 保留新增的實際 Shell 完成通知／單一 job／status completed／exitCode0 斷言；原有 marker、後續回答、非 early-settle、工具繼承／禁止 Fork、metadata completed 與 childClosed 斷言全部保留。
- 未更改 timeout、增加固定等待、skip 或弱化斷言；原 nested-job 的2.5秒行為未改。

## 實際獨立驗證

同案命令（red 與 green 皆相同）：

```powershell
node --import tsx --test --test-name-pattern='Fork waits for its own background shell job' modules/fork/tests/real-host.integration.test.ts
```

- 原案 red：退出碼1，1 failed、0 skipped。
- 新增診斷後、修環境前 red：退出碼1，1 failed、0 skipped，確認 WSL/node-not-found/exit127。
- 補環境後 green：退出碼0，1 passed、0 failed、0 skipped，完整 runner 結束；案例本身約6.2秒，runner 含既有清理計時器約40.4秒。
- `node node_modules/typescript/bin/tsc -p modules/fork/tsconfig.json`：退出碼0，涵蓋 Fork src/tests 的 strict typecheck。
- `npm run sources:verify`：退出碼0，當前 provenance 完整性通過；保留既有45筆歷史內容不可取得警告，不宣稱歷史差異等价。
