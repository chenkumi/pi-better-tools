# 已結束 Subagent 的唯讀 query 與拒絕呈現

## 目標

讓 subagent_message(mode=query) 同時支援 live interactive child 及已完成、可安全讀取的 ready managed session。已結束 query 只執行一次唯讀模型問答，不續接 child 主線、不改 native leaf/checkpoint、不把問答寫入原對話；保留 owner/cwd/config/trust/model/checkpoint驗證、獨立usage與query_result通知、無工具與容量/取消限制。

另區分TUI「請求未受理」與真正執行故障，不偽裝accepted或放寬安全條件。依Pi1.0.0實際render契約決定expected refusal的isError分類，明確更新契約/測試。

## 步驟

1. 讀取Subagents、query bridge、managed session與Pi canonical replay/query API，確認既有安全界線。
2. 建立回歸測試，覆蓋ready query、未提交/busy/blocked/owner/config/trust/checkpoint拒絕、無原主線寫入、與resume競態、query通知/usage/取消，以及TUIexpected拒絕與實際錯誤。
3. 重用既有唯讀query引擎，增加ready session載入/保留read lease與query生命周期，不用control或空白context冒充。
4. 更新README、configuration/architecture與provenance；保留既有未提交修改。
5. 執行targeted unit/integration、Subagents module與cross；依實際影響範圍決定package重跑。所有provider測試offline/isolated，Blackhole passive，不用真實credentials。已知Blackhole完整來源suite101fail不計入本功能通過。

## 非目標

不修改Blackhole時機/tail、個人設定/auth、既有歷史/IDs、不新增工具或放寬跨owner存取，不宣稱readonly query等於無模型成本，不把process隔離稱作OS sandbox。
