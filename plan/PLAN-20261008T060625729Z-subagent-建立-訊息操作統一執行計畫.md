# Subagent 建立／訊息操作統一執行計畫

## Goal

將對外操作統一為：
- `subagent`：建立新子代理，保留 single／parallel／chain 派遣方式。
- `subagent_message`：向既有子代理發送指示，由系統依當前安全狀態選擇 control 或 resume。

主 agent 不再需要根據可能過期的狀態自行選擇工具。內部保留現有 resume 的 checkpoint、配置、信任及 ownership 驗證。

2026-10-08：使用者確認 OQ1=A 並保存計畫，隨後授權實作。保存時為待執行基準；當前進度、失敗與驗證狀態見文末執行追蹤。

## 已確認決策與規劃預設

### 已確認：OQ1=A
建立受理時必須立即回傳完整 `subagentSessionId`。在回傳前建立 managed session；queued 尚不可發送工作指示，但具有穩定身份，拒絕回覆應明確指出尚未 ready。CP2 的建立時機決策阻塞已解除，仍須先完成 CP1 契約。

### 其餘沿用前版計畫的建議預設
- 以 `subagentSessionId` 作為訊息目標；jobId／taskId 保留為 invocation 追蹤身份。
- `mode` 預設為 `control`，代表持久主線指示；系統可將其路由為 control 或 resume。
- `mode:"query"` 保持一次性唯讀查詢，不自動 resume 主線。
- 初版訊息工具保持非同步：resume 受理後回傳 receipt，完成後 followUp。
- queued、startup、finalizing、busy 狀態先明確拒絕，本輪不新增跨 invocation 等待佇列。
- 移除 `subagent.resume` 公開參數；舊呼叫明確回覆遷移指引，不偷偷轉成新建。
- 不改寫歷史 session／工具結果，不變更 managed 儲存格式身份。

此為公開介面變更提案；不得以一般內部重構為由省略 migration、schema、prompt 與呼叫端測試更新。

## 公開契約

以下介面已於本次來源碼實作；目前執行中的 Pi 仍須重新載入 schema，實際驗證範圍見執行追蹤：

```json
{
  "subagentSessionId": "<完整 session ID>",
  "message": "根據前次結論，繼續調查並回報結果。"
}
```

回覆應說明實際採用的 `action:"control"|"resume"|"query"`，以及該路徑適用的 messageId／queryId／jobId／taskId。message 受理狀態與 job／task 執行狀態分開，accepted 不代表工作完成。

### 路由表

| 實際狀態 | 處理 |
|---|---|
| 有可互動的 running invocation | control |
| 無活動 invocation，且 session 可安全續接 | 驗證後 resume |
| queued／startup／finalizing | 暫時不可送，不建立第二個 invocation |
| 已要求取消，但尚未完成清理 | busy／暫時不可送 |
| blocked／checkpoint 不符 | 拒絕，提供診斷 |
| owner／cwd 不符或 session 不存在 | 拒絕 |
| query 指向非互動中 session | 拒絕，不啟動主線工作 |

路由必須依當前 registry、磁碟與 ownership 證據決定，不能使用 parent 先前收到的 canMessage／canResume 快照作為授權。session ID 已配置不代表 checkpoint ready 或有可互動 child。

- 自動修復 blocked session 或繞過 checkpoint。
