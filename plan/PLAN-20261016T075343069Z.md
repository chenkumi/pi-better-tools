# File Audit 真實 PTY TUI A/B 與 token overhead 驗證

## 目標與界線

以 node-pty 啟動真正 Pi 1.3.0 TUI，不以 SDK callback 代替畫面。A 不掛載 File Audit，B 明確 -e 掛載；兩者使用相同 File Tools、Note Tools、測試觀察 extension、離線合成 provider、相同檔案內容與操作。各使用隔離 home/agentDir/cwd/credentials，不修改使用者全域設定，不呼叫付費模型。既有 extension 選取已是開關，不新增產品 setting。

## 案例

- [x] 1. 建立可重播 TUI fixture 與 A/B driver：regular A→B、fullscreen B→A，四個真實 PTY CLI；每組獨立工作目錄。透過 PTY 輸入 prompt／slash commands，觀察實際 rendered lines、模型請求與工具結果；使用事件／檔案 watch 同步，不以固定 sleep 判斷完成。Max attempts: 3。
- [x] 2. 基本與實用性：相同腳本成功 read/control、edit/seed、note 新增、失敗 read。B 應呈現 3 個不同檔案，check 定位 seed mismatch、control matched、note untracked；A 無命令／專屬報告，檔案結果相同。實際顯示、命令可用與診斷價值分開判斷，不推論 agent 智能品質提升。Max attempts: 3。
- [x] 3. 限制：B 設 max-files=2，新增多檔後保留不超過2且淘汰可見；window=1 後下一個 run 過期為0；A 執行同樣檔案腳本。Max attempts: 3。
- [x] 4. Token／請求：擷取 provider 實際收到的 messages/tools；B status/check 前後不得新增請求，之後相同 follow-up 用於偵測 context 污染。保留 raw bytes 與正規化差異（僅已知 workspace/home 路徑、note 產生時間戳、非語意時間欄位），不能用正規化掩蓋 audit 訊息。若可取得隔離 tokenizer，另報原始／正規化 serialized messages/tools 的 tokenizer estimates，非 provider 計費 token；合成 usage 不作消耗統計。Max attempts: 3。
- [x] 5. 將測試歸屬 file-audit 模組、執行新測試／必要 lint/typecheck，更新本次新增檔案 provenance 與交付紀錄。不跑全專案完整 suite，不改產品行為除非實測發現本功能缺陷；失敗不放寬斷言。Max attempts: 3。

報告每組命令是否掛載、成功／失敗／note 路徑、候選數、診斷命中、容量／窗口、TUI mode、模型請求數、context/tool schema bytes、tokenizer 型號／方法、估計 token delta、實際外部 provider calls=0，以及退出／cleanup 證據。小樣本不是可靠速度 benchmark，也不是實際付費模型行為或計費認證。
