# Blackhole before-request：父代理設計決策 Q1／Q2

## 背景
用戶已明確選擇方案二。調查與提案：`plan/PLAN-20261009T124100756Z.md`、`report/REPORT-20261009T124343692Z.md`。本決策授權實作與驗證，不代表設計已被實測證明，亦不代表政策已生效。

## Q1：核准限縮 request-admission capability
核准在既有 captured-owning-session adapter 上，僅對 pinned Pi 1.1.0 經驗證形狀，串接公開 Agent.prepareRequest 與合規、non-throwing guarded Agent.streamFunction。不新增 private _checkCompaction／_runAutoCompaction 等方法 patch，不更換 provider、不重播工具／context handlers、不更改其他 extensions 的 admission／reservations。

要求：
- 保留 previous callback／stream function chain、physical routing、canonical projection、model/options、abort signal 與所有權；不使用 selected ctx.model 假充 physical request model。
- prepareRequest 在確定下一請求存在且壓力到門檻时，沿用既有安全 inline 能力壓縮並更新同一 loop 的請求 context。
- dispatch guard 檢查 transforms 後實際 context／system／tools／輸出 reserve；不能安全派送時，在 original provider 被呼叫前回合規 non-retryable 拒絕 stream，不丟 throw 到禁止 reject 的 transform。
- 拒絕診斷須辨識為本地 request admission failure，不能誤觸 transient retry／overflow／Runtime automatic repair。必要時明確 unsupported，而非完成後 fallback。
- before-request mode 的 session_before_compact 只拒絕未授權 scope 的 reason:threshold；保留 manual／overflow 的原所有權與必要恢復語意。
- unknown shape、replacement 或無法保留舊 chain、physical routes 未可驗證時 fail closed，請求 providerInvocations 必須為 0。不擴權為任意 captured Agent 存取工具。
- 若真實 host 證明此能力仍不能保證要求，回報 blocked，不強行弱化斷言。

## Q2：核准驗證後採用的最小 project override
實作及獨立復審通過後，由父代理建立 `.pi/pi-blackhole-config.json`（若屆時已存在，先 read 並合併，不覆蓋使用者資料）：

```json
{
  "compaction": "auto",
  "compactionEngine": "blackhole",
  "compactionTiming": "before-request",
  "midRunCompaction": "resume"
}
```

核准新增顯式 timing key 且 legacy 為舊格式相容預設。本專案以 explicit before-request+resume 採用用戶選擇，不改全域、不增任意門檻數值、不更改 memory／retention／tail／display。

before-request+auto 要求 blackhole engine 與 resume；off／pause／pi-default 衝突必須清楚診斷／拒絕，不忽略舊選擇、不偷偷切 engine。manual／off 模式仍保留其自身控制，不能被 timing key 重新啟用自動壓縮，也不能宣稱它們符合完整新方案。effective 設定受 env／session override 影響必須明示，不能聲稱 repo 檔存在就保證已採用。

## 分工與驗收
Blackhole worker 仍只改 `modules/blackhole/**`。Repo `.pi` 與 root docs／provenance 由父及根 owner 在復審後採用。Monitor／Runtime 檔案不得修改；以真正 host red／green與新 request 前的 provider stream assertions驗收。未執行 full module、獨立復審、根整合及採用前保持「未生效」。
