# 獨立 Fork：完整能力繼承與跨 session 背景接手

## Goal

新增原生 `fork` module，以獨立 Pi process 接手指定任務，繼承來源對話的歷史、有效設定與工具能力（包含 `subagent`），保存可由原生 `/resume` 找到的新對話；原 Pi 行程持續開啟時跨 session 切換繼續工作，完成後回報來源 session，quit／`/reload` 時要求中止。Fork 程序與所有 Subagent 都禁止呼叫新增的 Fork 建立功能。

## 已確認需求與邊界

1. Fork 是獨立對話、獨立 Pi process，不是清空 context 的普通 Subagent，也不替換 parent 的 active session。
2. 複製來源 active branch 的完整紀錄，保留 compaction、context edits、圖片與 opaque provider metadata；不混入其他 abandoned branches，不回復已移出的模型 context。Parent 後續新訊息不自動同步到 Fork。
3. 繼承 parent 當時有效的 model／thinking／cwd、工具選取、prompt customization、可重新載入的 resources 與設定；保有相同能力及權限上限，不提權、不自動啟用其他 tools。唯一新增的建立能力限制是不得再次 Fork。不能重建的重要能力須啟動前明確拒絕，不能默默縮成 worker 預設工具。
4. Fork **可以呼叫 `subagent`**，並由自己的 session 擁有新派遣的子代理；普通 Subagent 的既有遞迴排除與權限政策保留，另外禁止它們呼叫 Fork。
5. 身份限制須由可信啟動資料、工具排除與 execute guard 落實，不靠 prompt 提醒或會被宿主吞掉的一般 hook throw；順序不因 extension 載入先後而失效。Fork 對話被重新 `/resume` 時仍保留禁止 Fork 的來源身份。
6. 跨 `new`／`resume`／原生 session fork 等 replacement 保留工作；quit／reload 停止受理、要求取消全部未完成 Fork。工具回合結束不取消已接受工作。重新啟動 Pi 不自動重跑舊任務。
7. Parent 在前景時送完成通知；不在前景時保存待回報資料，切回原 session 再投遞。不能將內容送進別的 session，也不在背景額外啟動 parent 模型。
8. 原生 `/resume` 能找到、完成後能載入 Fork 對話。執行中禁止第二個 writer；預設以唯讀紀錄／預覽查看，不將原生 `/resume` 當成安全的 live attach。
9. 完整能力不是複製開啟中的 OS handles、parent 執行中的 jobs 或一次性 approval；新程序重新驗證 trust／provider／tools。不得保存 credentials 到專案資料或 diagnostics。
10. 禁止 Fork 是本專案工具契約，不是 OS sandbox；有 shell 權限者仍可能自行啟動 Pi。任務與 parent 共用 workspace，不自動建立 worktree 或合併檔案。

### 能力矩陣

| 程序 | 新 Fork 建立工具 | subagent 工具 | 其他能力 |
|---|---|---|---|
| 一般主 Pi | 可用，須已選取 | 依原選取 | 原設定 |
| Fork Pi | 禁止 | 依 parent 原選取繼承，不能套用普通 Subagent 的排除 | 繼承 parent 有效能力 |
| 普通 Subagent／resume／ready-query | 禁止 | 保留原有禁止規則 | 既有 agent／guard 政策 |

## 預計介面與架構

- 新入口：`modules/fork/src/index.ts`。不建立 plugin manager、不 bundle host SDK。
- 建議工具：`fork({ task, title? })`，固定非同步；`fork_status({ jobId? })`、`fork_cancel({ jobId })` 作為唯讀狀態與取消要求。此為提案；沒有 agent／cwd／model override，以避免偏離繼承語意。工具是否啟用沿用 host 選取機制。
- Receipt 使用真實已配置的 `jobId`／`forkSessionId`（新 ID 為 uppercase ULID），區分 queued 身份與實際啟動；只有檔案已存在才提供 sessionPath。
- 行程層級 Fork 管理器擁有 child／controller／permit／result；session binding 只負責工具、UI 與投遞。Pi 行程 epoch 與 active session binding generation 分開，replacement 不換掉工作 epoch，reload／quit 則關閉它。
- 管理 extension 須在受支援的每個 session 全域載入，即使 Fork 工具未選取。不得暗中載入被使用者排除的 extension；若公開 API／部署方式不能覆蓋 lifecycle，CP1 必須回報阻塞，不以失效 callback 或 private host monkey-patch 補洞。
- 共用現有可分離的 RPC、背壓、取消、child permit 與純呈現 helper；不直接呼叫整個 `runSingleAgent()`，不重寫 Subagents registry／managed 格式。共享 parent Pi 的 child permits 不等於整棵程序樹的全域配額；Fork 自己派遣的 Subagents 仍遵循該 Pi process 的既有上限。
- 每份原生對話只有一個可寫權威檔案。來源 relation／role／設定 fingerprints／結果與待回報狀態持久化；原生 JSONL 保存於來源 session 的有效 sessionDir，header.cwd 指向同一 workspace；工作目錄保存 Fork metadata／結果，不另建立第二份可寫原生對話。活躍工作與 registry 不從舊磁碟紀錄復活。
- 完成要核對 child 主線 settled、它自己建立的 Subagent／Shell jobs 已收尾、結果保存與 writer／child close；不能在首次 `agent_settled` 就殺掉仍必要的子工作。第三方任意 OS 工作不宣稱可完整追蹤。
