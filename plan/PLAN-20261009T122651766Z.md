# Blackhole：用戶授權的請求前壓力壓縮

## 授權與目標
用戶明確選擇方案二：不在 final text／agent_end／agent_settled 後主動壓縮；只在下一次模型請求前確有 context 壓力時先壓縮再繼續，或用戶明確輸入手動命令時壓縮。此授權取代先前「不變更壓縮觸發時機」的限制，但不授權修改個人全域設定、刪除／回填歷史、改 retention／summary／display-copy 政策、關閉必要 overflow recovery 或繞過 safety policy。

## 實作契約
- 必須核對實際 Pi 1.1.0 請求／事件／run admission 時序與公開 API；不能把 agent_end、agent_settled、turn_end 後事後壓縮重新命名為 before-request。
- 新用戶任務、工具循環及可用的 continuation/recovery 路徑：在後續模型請求送出前判斷 context 壓力；未達門檻不得自動壓縮。
- final text 已輸出、沒有下一請求時，即使已超門檻也不能僅因完成事件自動壓縮。
- 保留 `/blackhole` 明確手動行為，釐清 `/compact` 與 Pi 原生 threshold／overflow 所有權；不得讓原生 auto threshold 在完成後繞過新政策。
- 使用 context window 與有效輸入／工具宣告／輸出 reserve 的安全預算，不把達到硬上限才行動當安全設計；既有數值門檻及其優先序需明確，不擅選新比例。
- 僅在工具配對完整、session／branch／generation 正確的安全邊界執行；active run 的壓縮必須不終止後續請求。不能將中斷式 ctx.compact() 當透明操作。
- 成功後下一請求必須使用更新後摘要/context，失敗或 adapter unavailable 必須誠實 fail-closed／回報，禁止失敗循環與不安全 fallback 到完成後壓縮。
- 保留取消、原生 overflow recovery、Runtime recovery reservations、工具副作用證據與無 provider 測試隔離。new policy 不允許重試安全拒絕來繞過限制。

## 設定／相容性
- 修改前明確記錄既有 compaction auto/manual/off、midRunCompaction、pi-default engine 與新政策的互動；不能默默忽略 midRunCompaction:off 或擅改其既有語意。
- 若需要新增顯式 timing 設定，設計要能讓本專案實際採用用戶選擇，且舊格式有明確相容策略；不修改使用者真實全域設定。repo-local 設定若有必要，只能在確認 loader merge／precedence 後以最小範圍操作。
- 公開 host API 若無法保證逐請求時序，先提出限縮 adapter 的可行性／風險，不透過脆弱私有 patch 假稱已達需求。

## 分工
- Blackhole worker：独占 `modules/blackhole/**`；可讀其他模組／host，但不能修改 Monitor、Runtime、Shell、Subagents、根 manifest/docs/provenance。
- Monitor worker：仍獨占其既有 scope 與根 provenance；告知 Blackhole 新輪會改源，本輪根結果須版本化，不能自動簽新 Blackhole diff。
- Runtime worker：仍獨占 `modules/pi-runtime/**`；本輪請求前壓縮整合只能在固定版本和明確 handoff 後驗證，不以並行 root pass 宣稱最新版。
- 父代理：設計決策、根整合與獨立 reviewer。Windows 8.3 alias 保留 blocked，不擴大本輪。

## 驗證
1. 在目前實作上先建立真實行為 red：超門檻 final-only 不應事後壓縮；下一請求壓縮先於模型讀取，包含新任務與工具循環。
2. 低壓不壓縮、手動仍有效、完整工具配對、取消／owner reload／branch／模型切換、失敗／adapter unavailable／原生 overflow／必要 reservation 共存回歸。
3. 單元用 FakeClock 或事件 barrier；真實 host 測試使用 Pi 1.1.0、隔離 settings/auth、synthetic provider、零外部 provider，不固定 sleep 驗 timeout、不還原來源造 red。
4. 執行適用 Blackhole module、typecheck，保留 runner／依賴 fingerprints；根 cross/package 等待 source freeze 與根 owner，不借用歷史 logs。
5. 原 args／fixture 強斷言不得為 green 降低；每個結果列 terminal exit、skip 與未執行。獨立復審後才交付。
