# 原生 Monitor module 完整規格與實作驗收（v1）

## 1. 授權、目標與分工

使用者已要求保存完整規格並派遣 subagent 實作。新增獨立原生 `modules/monitor/`，直接透過根 Pi manifest 載入 `./modules/monitor/src/index.ts`。不新增 plugin manager；不將 session 內監控稱為 OS service／sandbox。

Monitor 支援四種來源：Command stdout、WebSocket 文字訊息、既有 Shell 工作快照、既有 Subagent 工作快照。共用 ownership、期限、事件緩衝、限流、投遞與停止核心，各來源只提供薄 adapter。第一版完整納入四種來源；若安全的連線或 adapter 缺少必要宿主能力，必須回報 blocked／提出具體方案，不以 mock 或降級偽裝支援。

既有 Blackhole B1 worker 僅修改 `modules/blackhole/**`；Monitor worker 不得修改 Blackhole。Monitor 的 Blackhole allowlist 適配是後续窄交接，不阻礙初始 module 實作，但完整 compression acceptance 尚不能宣稱完成。

目前 `sources:verify` 已因未完成 Pi Runtime source hash 漂移失敗（`report/REPORT-20261009T103342801Z.md`）。Monitor worker 不得重簽或修正不屬本功能的 Runtime 變更。

## 2. 非目標

- 不增加 managed child 的非同步工具能力；不允許 child 用 Monitor 繞過 foreground Shell 限制。
- 不自動取消／重啟被觀察的既有 Shell/Subagent 工作，不自行送控制／query 模型請求。
- 不輪询真實 provider，不以付費模型分析每條 log。
- 不自動重連 WebSocket、不復活 reload 前的監控、不重播 delivery_unknown。
- 不提供 PTY／WSL／SSH target 配置；Command 使用本地共用 Shell backend。使用者指令可自行呼叫遠端工具，但不因此宣稱遠端 process tree 可清理。
- 第一版不提供任意 WS headers／secret credential store。URL userinfo 一律拒絕；URL token 不保留在回報。認證擴充需另行設計。
- 不追求通用 regex 過濾引擎；Command 輸入端先過濾。WS adapter 不執行使用者程式碼。

## 3. 模組與依賴

- 所有 runtime code 在 `modules/monitor/src/`；README、MIT LICENSE、模組 metadata、tests/fixtures 保留清楚原生身份。
- `src/index.ts` 為直接 TS 入口，無建置需求；Pi SDK／AI／Agent Core／TUI／TypeBox 保持 host peers。
- 可重用 `modules/shell-tools/src/` 的 trust-aware backend、process cancellation/close 與 explicit managed-child identity。若必須抽共享 helper，精準移動／導出核心並保留原 Shell 行為與回歸，不複製不同的 settings／取消實作。
- job adapters 透過小型 readonly capability interface 取得 owner/cwd/generation 驗證後的快照。不載入 Shell/Subagent extension factory 作為依賴，不存 executable child handles，不改既有工具 activation。
- 可採 runtime registry／Symbol.for 之狹窄 capability handshake 支援載入順序，必須有 generation 與 revoke；不是新 plugin manager。
- 只有新監控工具被選中才可執行；遵循 host defaultActive:false／既有工具選取方式，不能默默啟用新 tools。
- WebSocket 若原生 API無法提供 pre-allocation payload cap、受控 DNS 連線及 TLS 策略，可新增明確 root direct runtime dependency `ws`，查官方來源與 registry 後固定 lockfile。不得只使用 transitive dependency；禁止 optional binary addon成為必要条件。根唯一 lockfile，`npm ci --ignore-scripts`；不得在 modules npm install。

## 4. 工具契約

提供 `monitor_start`、`monitor_status`、`monitor_stop` 三個工具，不改已有工具名稱/schema。第一版先以啟動後獨立註冊方式支援 jobId，不向 bash/subagent 增加 monitor 參數。

### monitor_start

Input（JSON Schema／TypeBox discriminated union，additionalProperties:false）：

```ts
type Start = {
  source:
    | { kind: "command"; tool: "bash" | "powershell"; command: string }
    | { kind: "websocket"; url: string; allowPrivateNetwork?: boolean; allowInsecure?: boolean }
    | { kind: "shell_job"; jobId: string; intervalMs?: number }
    | { kind: "subagent_job"; jobId: string; intervalMs?: number };
  durationMs?: number;
  wakeAgent?: boolean;
  stopAfterEvents?: number;
  label?: string;
};
```

- durationMs 預設 300000，合法 1000–1800000 的整數（包含 startup 時間），超限拒絕、不默默clamp。
- wakeAgent 預設 true：使用者明確啟動 Monitor 就選擇事件回報可喚醒。false 仍提交可顯示的 custom message，但不要求模型 turn；提交不是持久化／送達 acknowledgement。
- job source intervalMs 預設60000，最短30000、最長300000；Command/WS 不接受該欄位。
- stopAfterEvents 若提供為1–600整數，計實際採納的資料事件；系統事件不计。達數量後停止 Monitor 自己的來源，不取消被觀察工作。
- label 最多80 characters，純文字清除控制碼，不用 label 決定 scope。
- 註冊及 startup成功返回 uppercase ULID monitorId、owner scope的安全摘要、state、startedAt、deadline、limits。pending startup亦須有可辨識的 receipt，失敗要可保留查詢診斷。
- AbortSignal 取消 acceptance／startup 時不得留下未受管理來源；receipt回傳後 Monitor由其owner runtime管理，不能因原工具call signal後續變動誤終止全部工作。
- Managed child 不註冊 start/status/stop（不能僅靠工具description）；執行端亦拒絕偽造直接start請求，依既有明確 managed-child marker，不以 RPC/cwd 推測。主 agent 的 RPC 模式仍可使用。

### monitor_status

`{ monitorId?: string }`。省略則列目前session/cwd/generation的可見監控，最多32筆；提供ID查完整有界receipt。未知／其他owner一律拒絕，錯誤isError:true。readonly不啟動來源／timer／模型。

Receipt包含 monitorId/source kind/label/state/stopReason、created/started/deadline/elapsed、event counts、buffered/submitted/omitted counts、lastEventAt、source診斷、last system event、cleanupPending、cleanup evidence、notification submission state。source URL／command只能有經遮罩且有界preview，不包含secret headers或完整private上下文。

### monitor_stop

`{ monitorId: string }`。要求停止該Monitor，冪等；可能先返回 stopping/cancelRequested/cleanupPending:true。只在实际來源close／cleanup完成後返回terminal cleanup evidence。停止 job adapter僅unsubscribe／clear timer，不取消原工作；停止Command只要求結束Monitor擁有的指令，並保留process-tree unknown界線。無 stop-all，避免誤停。

## 5. 資料與狀態模型

- monitorId/events IDs新產生ULID一律`ulid().toUpperCase()`；保留既有job IDs讀取相容性。
- owner key：canonical cwd＋parent sessionId＋runtime generation。每次取樣、enqueue、timercallback、提交與stop均核對，不使用舊canMessage判斷。
- lifecycle：starting→running→stopping→completed/failed/stopped/expired/limited。不得用result已產生代替來源cleanup完成；terminal可保留cleanupPending:true及truthfulunknown證據。
- 系統事件：started、source_error、source_closed、stop_requested、duration_exceeded、rate_limit、total_limit、buffer_limit、payload_limit、owner_lost等。
- 資料事件：`{ eventId, monitorId, sequence, observedAt, kind, text?, snapshot?, partial }`。sequence per-monitor單調；batch preserve順序，無重試後重新编号。資料與系統事件明確區分。
- command/WS內容是untrusted returned data，不是系統／控制指令。快照的權威欄位只來自verified provider capability，不從log prose推導status。

## 6. 限制與有界性

固定v1 defaults/hard limits，不新增全域settings：

| 項目 | 限制 |
|---|---|
| active monitors/owner | 4 |
| retained receipts/owner | 32，active及pending通知不可evict；全滿拒絕start |
| 資料事件速率 | rolling 60秒最多60筆；第61筆停止來源並產生單一system event |
| 採納資料事件總數 | 600；到達600正常limited stop，不能無界續跑 |
| 單事件payload | 16KiB UTF-8；超限停止，明示payload_limit，不能靜默裁掉failure行 |
| 待投遞資料 | 每monitor 128筆／256KiB，全部owner 512KiB；滿時停來源，保留counts，不無界繼續 |
| 每monitor source診斷stderr | 有界8KiB tail，保持輸入byte計數及truncation |
| 文字通知preview | 每event最多2048 UTF-8 bytes；保留partial＋原event大小，不稱完整輸出 |
| 批次通知 | 最多32event／32KiB，owner每30秒最多一次progress提交；terminal system事件仍合併而非每job一則 |

限制在decode/JSONparse/長line拼接前生效；不可僅最後slice。通知只提交selected有界資料，不將stderr或整個receipt/log無限搬入model context。

## 7. Command source

- 使用明確tool backend，不用臨時指定shellPath繞過trust-aware settings。powershell不可用需清楚拒絕；不回退另一shell。
- stdout逐行事件：UTF8跨chunk、CRLF、空行（忽略但監測byte流）、EOF未newline的一行、非法UTF8明示partial／診斷而不升權。
- 16KiB line cap需逐byte有界buffer；oversized line停止來源，stderr不產生資料事件。使用者可在輸入command明確`2>&1`合併，Monitor不偷偷合併。
- command沒有輸出不等於stalled／failed；期限是total lifetime，与现有Shell timeoutMs idle语意独立，不新增同名timeoutMs。
- stdin關閉／ignore，非PTY；需要互動輸入的command不在v1保證。
- close code/signal才是來源終結依據，exit≠close。spawn failure/nonzero close→failed system event；zero close→completed；取消／期限／限流保留真正stopReason與close結果。
- process取消使用既有best-effort backend，不宣稱所有後代停止。shutdown清除事件與等待實際close/cleanup；无法确认时保留unknown不得宣稱成功。

## 8. WebSocket source與網路安全

- 只接受ws/wss；拒絕userinfo、過長URL、非法port、opaque scheme、UNIXsocket等另類路徑。
- 預設wss、公網；ws須明確allowInsecure:true。本地/private地址須明確allowPrivateNetwork:true，是針對本次URL的使用者請求，不放寬web-tools既有policy。
- 對未授權localhost/RFC1918/link-local/metadata/IPv6私有及IPv4mapped位址拒絕，reuse既有address classification可只讀純helper，不能載入browser/auth。
- DNS解析／實際connect需使用同一組驗證後IP（自訂lookup/pinning），hostname保留TLS SNI與證書驗證；redirect不跟隨；不能用一次預檢後讓transport再次無約束resolve。無法達成此契約先blocked而非宣稱已防SSR F。
- TLS rejectUnauthorized不得關閉；connection/handshake timeout15秒且不超deadline。message maxPayload16KiB在library receive前限制；compression禁用，避免decompression bomb。
- 一個完整文字message為一個事件；fragment由transport重組，不能把frame fragment當完整text。binary為unsupported_payload terminal failure，不靜默當文字。
- ping/pong非資料事件；remote close保留code/reason有界，不自動重連。error/close關係以實際transport close確認。
- 第一版不接受任意headers，URL query/fragment摘要一律移除；不能將認證值persist/log。保留必要endpoint定位但不公開token。

## 9. Shell/Subagent adapters

- 監看當前owner/canonicalcwd/generation的既有jobId；找不到adapter／工具未載入／job不屬owner，拒絕且isError:true，不能猜global舊log。
- interval取樣readonly權威快照；每次tick算一個data event，使用內部timer，不使主agent自行poll。可標無狀態變更，不能將未變更說成failure。
- Shell保留status、elapsedMs、output byte/tail摘要、cancelRequested、exitCode（只有實際已存在時），不讀任意log、不算假的完成百分比。
- Subagent保留job/task狀態／目前可證明的公開摘要、cleanupPending、asOf等有界欄位；不呼叫模型query，不讀privateworking snapshot，不標待lease release為completed。
- adapter注意readonlyQuery的provisional保護必須走既有view，不直接讀內部task.result。
- job變terminal立即產生system event並停止adapter；現有completion服務保持原行為，monitor通知明說觀察到terminal不是另一份task_result，避免混淆duplicate completed results。
- 不向Shell/subagent既有schema新增monitor參數，本版不要求launch-time sugar。

## 10. 投遞、喚醒與持久化

- 使用專用`customType:"monitor_event"`、display:true；details含窄結構events/monitors及partial/omitted/submission資訊。不用shell-job-completed/subagent_background冒充既有結果。
- wakeAgent:true→triggerTurn:true/followUp；false→triggerTurn:false，不因監控要求新模型run。
- 用agent_start/agent_settled lifecycle維持agentActive；不用agent_end當最終空閒，不在before_agent_start立不可清除latch。busy時enqueue、settled排程flush；idle事件由core timer調度。flush前generation/owner recheck及reentryguard。
- 每批progress rate受控，busy期間資料事件保留有界序列；job snapshot可coalesce為最新但需記omitted採樣數。Command/WS歷史預設不可只保留last-event。
- 同步send throw保留batch待下一合法機會，retry至多3次且不tightloop；非同步send無ack，只能標submitted，不宣稱delivered/persisted。不能因延迟通知重播已submitted事件。status保留可讀submission evidence；無可靠關聯的host async error只可報delivery_unknown，不能歸因其他module消息。
- shut down/owner lost後不得再投遞旧owner，pending counts與清理結果可供terminal記錄，不自動跨session replay。
- 不新增個人settings/auth或schedule儲存。v1 Monitor本體session-local；歷史只經真正host custom_message持久化。未persist通知不保證resume可recall。

## 13. 測試與驗收

### 必要red→green

新core功能先寫失敗回歸，修runtime再green，不回退已修code造red、不弱化assertion/skip/延長timeout。無provider／真實外部監控端點，隔離home/agentDir/credentials，英文定期progress。

### 單元

- schema、managed-child拒絕、owner/generation、TTL/expiry、stopAfterEvents、rate/window/eventbytes/buffercaps。
- line parser chunk/CRLF/UTF8/EOF/oversize/invalid；stderr資料隔離。
- 排序/合併/忙碌latch/preflightfail/reentry/同步sendfail/無acktruthfulsubmission/shutdown/ownerrebind。
- stop冪等/cleanupPending/exitvsclose、adapter不可取消job或呼叫模型。
- WS scheme/privateIPv4IPv6/mapped/DNSpin/redirect/TLS/messagepayload/binary/errorclose。
- 用注入clock/mocktimer同步barrier，不新增靠idle/watchdog/sleep驗timeout的測試。

### 離線整合

- 真實Pi1.1.0主agenthost定義/選取及managedchild無Monitor（含直接execute拒絕），new/reload/shutdown與兩種載入順序。
- 有限stdout fixture實際child close、stderr/nonzero/expiry/cancel/stopAfterEvents；無固定sleep成功條件。
- 本地WS server＋明確private/insecureflags，text/fragmented message/close/binary/oversize、拒絕未授權loopback；server/socket清理以實際close。
- 真實Shell/Subagents離線job lifecycle adapter、owner錯誤、cleanupPending與job自身不被停止；合成provider只能本地stub，實際外部providercalls=0。
- busy/idle/wakeAgent:false, batch與limit，host持久化事件可查monitor status；不稱send submission等於ack。
- production tarball在乾淨production deps真實Pi loader跑command＋WS probe與來源capabilityloading，不需要付費credentials。

### 分組命令

`npm run build`、`npm run typecheck`、`npm test`、`npm run test:module -- monitor`；涉及Shell/Subagent helper則跑各module；根manifest/scripts/shared helper變更須`npm run test:cross`；入口/package files/dependencies變更須`npm run test:integration`、`npm run test:package`及sources:verify。

既有Runtime source hash/safety或Blackhole B1並行漂移要明列blocked/未完成，不重簽來製造green、不輪詢/重跑outcome_unknown前工作。並行B1期間不能把整根sources結果當stable驗收；需在相關來源穩定後父agent收斂。

## 14. 交付與獨立審查

worker以note(report)交付一行結論＋路徑、精確files/source契約、每個stage真實exit/log/skip、最終fingerprints與blocked。父agent另外派reviewer（note唯一報告輸出），核對安全/identity/網路/bytebounds/noack/managedchild/cleanup與productionevidence。不得把receipt/progress/partial log當runner completion。

第一版只有上述範圍可實作，新增secret header、OS排程、跨session自動恢復、自動控制工作須另授權。
