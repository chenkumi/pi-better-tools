# 非同步 Shell／Subagents 實作與最終驗證紀錄

## 已交付範圍

依使用者授權實作 session-owned 非同步模式，保留同步預設。未修改 Pi 核心、依賴版本、public entry／package files、真實 settings/auth 或來源專案；未建立 daemon、發布或 Git commit。工作目錄沒有 `.git`，不能提供 Git diff/status 證據；檔案工具已記錄實際修改 diff 與 hash。

- `bash`／`powershell` 支援 `background:true`：即時接受 receipt（jobId、running、liveLogPath），不偽造完成 exit code；沿用 host shell 設定、structured completion 與輸出停滯 timeoutMs。
- 新增 `shell_job_status`／`shell_job_cancel`，預設 inactive，須明確選取；不自動修改 loadout。工作自有取消 controller、owner/generation fence、有界輸出與資源、shutdown cleanup。
- `subagent` 支援背景 single／parallel／chain／resume；立即回 queued job/task receipt。取得 permit 並建立 session/log 後，log_ready 通知／status 才提供 liveLogPath；未建立者誠實標 logPending，不預回 finalLogPath。
- 新增 `subagent_status`／`subagent_cancel`／`subagent_message`。背景 child 使用 correlated RPC，仍經原 argument builder、guard、trust/config/identity、wire/native digest 與 checkpoint；child 排除全部四個 subagent 工具。
- Control 是 literal FIFO delegated user input，於 assistant/tool 邊界消費，不打斷正在執行的工具；accepted/queued 不等於 applied，canonical correlation 不明時 delivery_unknown，不自動重送。
- Query 從 canonical 安全配對 prefix 建立 tool-free inMemory 一次性請求，不 branch/改寫 child 主線、不 dispatch tools，不保存問題／答案於 child 主線；回報 stale/asOf、獨立 usage、取消與 cleanup 證據。有界 concurrency／retention，abandoned lease 等實際 terminal/child close 才釋放。
- 結果經 model-visible custom followUp + triggerTurn 回送原 parent，讓忙碌／閒置 agent 接續；不提升不可信輸出為 system 指令。Subagent 結果通知在 transcript finalize、managed commit/rollback、child cleanup 與 writer release 後送出。
- `read` 僅對缺失的 managed ULID／舊 UUID run `.partial` log 提供 same-directory final／等待通知提示，不自動替換目標、讀取其他檔案或把權限／probe 錯誤解釋為 rename；保留現有 rename/commit。
- 五個新工具補齊 call/result renderer：有界文字、控制碼清理、窄螢幕、不預覽 control/query input，取消不冒稱程序樹已停止。保留既有所有 renderer assertions，新增 actual-loader probes。
- 更新 README、configuration、architecture、File/Subagent/Shell README 與 adaptations provenance；immutable sources.json 未重新簽署。新 agent-visible IDs 遵循 lowercase ULID 政策。

## 型別與驗證修正

根 typecheck 原本不包含 Subagents。本次新增 `modules/subagents/tsconfig.json` noEmit strict stage；既有 session-store 的 never-returning arrow 改為 function declaration，readable transcript 改為 explicit content guard，以支援嚴格 narrowing，不改 checkpoint／鎖／rename 行為。

根 Subagent concurrency=4 時，runner-io 的 close-stall、rename-failure、spool-read cleanup 在進入注入點前耗盡 300ms test I/O setup budget。改為 unit files 序列執行，保留所有斷言、fixture budgets、個別 parallel/chain tests 與 production deadline。最終 root 及 module 重跑均 220/220；不宣稱所有 Windows 時序 flakiness 從此消失。

首次 cross loader 失敗是新工具缺少 renderer，已以實作五個 renderer 修復，而非豁免新工具或削弱既有断言；後續 cross 全數通過。

## 未執行／剩餘限制

- 未執行 root `npm run build`、完整 `test:integration`、`test:package`、`test:matrix`、`check` 或 browser install/tests：沒有變更 Scheduler、dependency／entry／package files，也非發布工作；依分組政策僅執行受影響模組與 cross。File module packaged regression使用既有 development dependency link，不代替 root production tarball verification。
- 新背景／RPC/query 能力尚未在 Pi 0.99.1／0.99.2、Linux/macOS、真實 provider 或人工 fullscreen TUI 驗證；不得以 wildcard peers／原 smoke matrix 宣稱這些已通過。
- 背景主工作／query usage 明確保存在結果，但未自動加入 Pi session totals；不能宣稱 billing/accounting 已 settlement。
- 離開 Pi、reload、session replacement 取消背景 jobs、抑制舊 owner 通知；reload/replacement 是已說明的保守政策，不是使用者明確提出的獨立需求。SDK 必須 `await runtime.dispose()`；單獨 `session.dispose()` 不保證 shutdown。
- kill／abort 是 best-effort；不保證完整 process tree／遠端 provider 工作停止，不宣稱 process isolation 為 OS sandbox。強制關閉仍可能留下 bounded logs／blocked locks/orphans。
- sendMessage 無 delivery acknowledgement，通知非 exactly-once；status 是保留結果 authority。Print CLI 正常 shutdown 會取消 jobs，需 live interactive/RPC/SDK runtime 才可稍後接收結果。
- query 可能只看見前一個安全 prefix；背景共用 workspace，避免同時修改同一檔案。完整 resource/transport/usage 限制見模組 README。

## 使用

`/reload` 或重新啟動 Pi 載入 TS 修改，不必 build extensions。需要管理 shell 工作時明確選取 `shell_job_status`、`shell_job_cancel`；explicit tools allowlist 同樣要加入需要的 subagent 管理/互動工具。用 `background:true` 啟動，讀執行中路徑；完成後使用通知中的最終 logPath，切換 conversation aggregate 不沿用 run-local offset。
