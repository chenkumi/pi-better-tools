# Pi-owned 模式仍以舊 Blackhole 門檻顯示狀態

## 結論與證據分級
唯讀靜態確認：本專案 Blackhole 已不註冊自行壓縮 trigger，但目前掛載的狀態列及 /blackhole-memory 仍以 legacy 門檻函數顯示壓縮進度／觸發文字。`compactAfterPreset` 因此仍影響 UI，但不控制實際 Pi 壓縮。未執行 TUI／provider／新測試，未修改程式或使用者設定。

## 精確來源
- `modules/blackhole/index.ts:28–29,62–75`：不安裝 private inline adapter，不註冊 turn_end/agent_end threshold；仍註冊 status bar 及 memory command。
- `modules/blackhole/src/om/status-bar.ts:138–150`：`autoCompactThreshold(cfg, model)` 仍作為 X gauge 的分母。
- `modules/blackhole/src/commands/memory.ts:72–87,235–238`：preset ratio 仍作 suffix，輸出 `triggers at ... (preset: ...)`。
- `modules/blackhole/src/hooks/before-compact.ts:400–424`：active cut/input 來自 nativeCompactionInput(preparation,...)，不是 legacy own-cut helper。
- Legacy compaction-trigger.ts、old-cut helper 與對應測試仍存在，不等於 production wiring 重新啟用。

## 影響
UI 所示 Blackhole threshold/preset 或 X gauge 不應解讀為 Pi 真正的 enabled/reserve/keepRecent/modelOverride 門檻。即使刪除使用者 explicit compactAfterPreset，DEFAULTS 的 preset 仍可能被舊顯示函數使用，所以只清設定不會修復此 UI 合約。

## 後續建議／範圍
在既有 Pi-owned 設定與時機審查中核對此殘留，補對應回歸後再遷移 UI：顯示真正可證明的 Pi budget，或明確標示 context 使用量而不宣稱 Blackhole triggers。無法取得 host effective settings 時應標 unknown，不用舊 preset 假造 native 閾值。不重新註冊 Blackhole trigger、不改 Pi SDK／全域設定。

本 issue 是新靜態 UI finding，非原 C1 或 core R1/R2 的重現，也不撤銷已通過的 ROOT counter／display fixture 限定接受。尚未交付修正，不是 release 放行。
