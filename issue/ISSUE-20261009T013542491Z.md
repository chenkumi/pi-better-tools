本輪本地 Blackhole 0.5.12 的核心顯示修正與離線 Pi 1.0.0 compact/persist/resume/renderer probe 已通過，但完整來源 Vitest suite 仍失敗。根 `npm test` 結果 10/11 stages pass，唯一 failed stage 為 `blackhole:test`；其最新 suite 為 139 files：123 pass / 16 fail，2618 tests：2517 pass / 101 fail。不能以 targeted51項與 actual-host probe 通過取代完整 suite，也不能宣稱所有失敗都是上游既有 baseline。

## 已定位分類

1. 根 isolatedEnv 強制 `PI_CODING_AGENT_DIR`/`PI_AGENT_DIR`，來源 config/runtime 測試卻用 mocked `getAgentDir()` 指向每案例 tempDir，形成測試路徑覆寫衝突。
2. suite-wide `PI_BLACKHOLE_PASSIVE=true` 改變 config default/migration/command 的期待值；來源部分案例只在 afterEach 移除此旗標，第一案例仍受影響。修正 harness 時須區分 pure/mock unit contracts 與真實 host integration（後者必须 passive/empty auth），不得改變 production defaults 或放行真实 credentials/provider。
3. Windows path separator 與 `/tmp/...` 固定字串、以字串切割而非 dirname 建目錄、chmod/read-only 假設、git path annotation probes。
4. Vitest 4 在 Windows 的 file URL dynamic import fake-host fixture 載入；準備能力 probe 因缺少 owning fake host helper而不符預期。不能跳過已支援 Pi 1.0.0 的實際 host probes。
5. 上游 TS6 指令 `--ignoreConfig` 及 module-root fixtures 假設與根 TS5.9／runner cwd 不符。
6. 三項 worker hard-timeout tests 超時，仍需釐清環境／test hook/mock 與實際回歸，不以拉長 deadline掩蓋。

首輪 changelog package-root discovery 失敗已由保留 `modules/blackhole/package.json` identity 解決，最新 suite 由102降至101 failed。原有測試未skip、未改斷言；本輪僅更正 cosmetic branch-order fixtures。
