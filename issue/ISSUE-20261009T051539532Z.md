# Blackhole Git 路徑 identity：Windows 8.3 短名與 Git 長名

## 狀態

待隔離回歸驗證的既有 runtime 風險；不是本輪新增的安全漏洞，也不是2623個來源測試通過已涵蓋的能力。來源：`research/RESEARCH-20261009T051142747Z.md`。目前沒有新增 end-to-end red／runtime 修正。

## 證據與推論

本輪本地probe觀察到Node temp/realpath為 `C:/Users/CHENKU~1/...`，Git rev-parse為 `C:/Users/ChenKuanMing/...`。`src/extract/git-status.ts`以Git repo root建立slash-normalized Map；`src/extract/files.ts` consumer僅slash normalization／cwd resolution，使用exact lookup。`src/hooks/before-compact.ts`直接將ctx.cwd、fileOps及真Git Map傳给compile。因此同檔案的short/long alias可能不相等，推論可能遺失new tag、Created歸類或Git annotations。

本輪fixture修正保留producer canonical repo-root契約；consumer的injected normalized maps與native fileOps測試仍通過，但不是short-cwd＋真Git長名Map端到端證據。不能將此fixture適配宣稱runtime alias問題已修復。

## 後續驗證／限制

先新增真producer→extractFiles→compile的short/long alias red，涵蓋subdir／deleted與nonexistent files。8.3不可用平台以可控mock補契約，不依賴固定sleep或默默skip。設計使用安全repo-root相對identity mapping／共用canonicalization並保留display path；避免全盤lowercase、basename比對、手工展開~1或對deleted檔無條件realpath。

保留Git env stripping、bounded exec timeout/size、non-repo fail-closed，不改個人Git設定。此項另行追蹤，不把來源suite green當成全runtime無缺陷證明。
