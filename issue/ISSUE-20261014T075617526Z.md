# 真實 PTY／Pi TUI Fork 實測：已清理工作被錯誤顯示為 cleanup unconfirmed

## 結論
確認為 Fork Jobs 顯示摘要缺陷；本次只測試與記錄，未修改程式碼。

- Windows、Node v26.8.1、Pi 1.2.0。

- 完成 Fork 後，在 TUI 輸入 `/background-jobs fork`，選擇已完成工作，按 Enter 查看詳情。

## 實際觀測
`PTY-FK-subagent`（job `01M4WPC5SCC5MWJNJC7SY0A4JR`）詳情同時顯示：
- `State: completed · completed · cleanup unconfirmed · child close not observed`
- `Cleanup: child closed · exit 0`

## 證據
- PTY 清單觀測：cursor 964149–966639。
- PTY 詳情觀測：cursor 966639–969529。
- `.pi/forks/01M4WPC5SCC5MWJNJC7SY0A4JR.json`：`status=completed`、`cleanup.childClosed=true`、`cleanup.exitCode=0`。
- 本次證據目錄：`plan/evidence/fork-pty-20261014/`。

## 原因（已由來源碼確認）
`modules/fork/src/live-widget.ts:13–18` 的 `activity(job)` 對所有 terminal status 無条件回傳 `cleanup unconfirmed · child close not observed`，未檢查 `job.record.cleanup.childClosed` 或 permit 是否 released。`forkPanelJob` 同時將此 activity 與正確的 cleanup details 提供給保留紀錄面板，因此清單與詳情 State 與 Cleanup 相互矛盾。

## 影響與建議
- 使用者會誤認 completed／cancelled 工作仍洩漏子行程；目前實測並非真正的 cleanup 失敗。
- 後續修正時依實際 cleanup 證據產生 terminal activity，保留真正未確認 cleanup 的警示。
- 補充已完成且 childClosed=true／permit released 的 retained More 清單與詳情回歸案例；既有模組測試通過仍未捕捉本例。
- 不應只為消除警示而改動取消、結果通知或 permit 契約。
