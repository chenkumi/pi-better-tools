# Fork CP1 prototype 卡住與執行期限失效

## 結論

本輪 CP1 prototype 未通過，第三次 invocation 已由工具回報 `Command aborted`，沒有 runner exit code／完整 suite 結果。約四小時等待是測試 harness 錯誤與缺少總執行期限造成，不是預期的 Fork 工作耗時，也沒有證據將它歸因為 Pi 產品缺陷。不得自動開始第四次嘗試。

## 已確認原因

- `plan/evidence/fork-cp1/probe.mjs` 在切回來源 session 後等待 `registry.deliveryObserved`；該 callback 掛在 `pi.on('message_end')`。
- Pi 1.1.0 `node_modules/@earendil-works/pi-coding-agent/dist/core/agent-session.js:1817–1825` 的 idle、triggerTurn:false custom-message 路徑直接 append native entry 並呼叫 `_emit`。
- 同檔 `650–653` 的 `_emit` 只呼叫 SDK session subscribers，不派發 extension hook。因此本 fixture 的等待沒有完成路徑。
- 保留下來的實際 native records 已有來源 session 一筆 `cp1-fork-result`，其他 session 零筆，獨立 child 一筆 `CP1_CHILD_COMPLETED`。這支持停在回報觀察 Promise 的診斷，不代表整套 lifecycle／能力驗證完成。
- Shell `timeoutMs:120000` 是 idle timeout；每10秒心跳持續重置它。不能把它當總測試上限。這是本輪代理的測試管理疏失。
